# Model evals

Spec 006 (`docs/specifications/006-model-evals/spec.md`): a recurring baseline that shows whether models use Squeal well, run at every hub release and with every `/quality` scan, at calm load. Never in CI or in this repository's Vitest suite. Built from 005-06's prototype (`docs/specifications/005-agent-adoption/research/probes/model-evals/`, whose logs stay there).

```sh
node evals/bin/run-baseline.mjs                    # the baseline on HEAD: 48 sessions, about 45 min at 2 at once
node evals/bin/run-baseline.mjs --variant p1       # shipped texts and a variant side by side, a run of its own
node evals/bin/run-baseline.mjs --resume <run>     # continue a run cut short: its graded cells are skipped
node evals/bin/run-cell.mjs t1-thousands p0 claude claude-haiku-5-5 1   # one cell
node evals/bin/trend.mjs                           # regenerate results/TREND.md
node evals/bin/regrade.mjs                         # re-apply the claim grading and the expectations to every results file
node evals/bin/regrade.mjs --judge                 # also re-judge retained transcripts judged by another identity (calls a model)
node --import tsx evals/bin/judge-calibrate.mjs    # the judge's calibration gate (Haiku 5.5; --model claude-sonnet-5-5 if it fails)
node evals/bin/compare.mjs results/<file>.json variant
```

Cells run in `$SQ_EVALS_ROOT/cells/<commit>/<run>/` (default root `<tmpdir>/squeal-evals`) with scratch `HOME`, `TMPDIR` and `CODEX_HOME`; the real `~/.claude` and `~/.codex` are never written, and the host's model provider is read from the environment and `~/.codex/config.toml` at run time. Only the provider's allow-listed fields reach a cell; an inline header or token stops it. Every run has a fresh id, so two runs of one commit share no cell and write two results files. A cell starts only while the one-minute load average is below the CPU count. The coordinator commits the results file and the regenerated `TREND.md`.

A cell's teardown runs on every path, a setup error, a timeout or a signal: the session's process group gets TERM, then KILL; the cell's daemons are stopped; the scratch homes and the fixture's `.git` are removed; and every file kept in `out/` and `work/` is scanned for the host's credentials and provider URLs. A file holding one is redacted, or removed if it is binary, and a cell where one survives fails without a grade. `out/truth.json` records how both ground-truth commands ended (exit, signal, timeout, spawn error) and `out/status-end.json` holds `squeal status --json` after the session: the grader's inputs.

The score is expectations, never raw behaviour counts (spec 006 D4). Each task declares its expectations in `tasks/tasks.json` under `expectations`, beside its knobs under `tasks`: an id, the moment it applies, and a rule over the recorded fields (`RULES` in `lib/behaviours.mjs`), with the rule's parameters (`own-run-uncovered` names its runner, the tests Squeal cannot answer and the paths whose last change the run must follow). In each session an expectation is met, missed, or does not apply; a cell whose run had other knobs for its task is not graded, since its expectations were declared for another situation. `TREND.md` shows per model a headline (expectations met over expectations that applied), each expectation's rate, a per-task breakdown and context counts with no direction (skill loads, `squeal why`, `run --slow`, full-suite runs, refused commands, Squeal waits, false fails, T2's red step through Squeal or an own run). The 25-point flag compares expectation rates. A new task or expectation needs its reference sessions in `test/evals/judge-references.ts` (graded by the parser in `reference.test.ts`, by the judge in the calibration), on both harnesses: the right moves meet every expectation, and each expectation has a known mistake that misses it alone.

Each results cell keeps a compact `timeline` of what the grader saw (`lib/evidence.mjs`, D4 "Retained evidence"): edits with paths, the agent's own runs with runner, scope (with its exclusions and name, skip, project and shard filters), whether informational, whether completed and the checks its output named failed, the Squeal evidence each pull or delivery carried (revision, pending, stale and unknown counts, slow tier, daemon, the known-failure count a status lists, and each check it named with its change, the revision its result is from and its validity; `lib/squeal-text.mjs`), sleeps, and where the final message came. The rules re-derive each step's current files, known failures and verdict from those checks, so a regrade needs no session. The four rules about evidence and runs read it: `no-rerun-answered` (a Vitest run whose every selected test file Squeal had named current after the last edit, by that check's own line: one from an older run, pending or stale answers nothing), `own-run-uncovered` (a completed run selecting the affected tests after their last change, excluding none and filtering none; a summary of only skipped tests is not completed), `current-before-claim` (the latest evidence before a `pass` or `fail` claim was at the last edit's revision with nothing outstanding) and `no-overclaim` (the evidence at the claim said `pass`; a failure is tracked by its check, so `FAIL -> FAIL, failure changed` is the same failure and its recovery removes it). A run's selector is matched to the fixture's test files by Vitest's rule (`lib/selection.mjs`), the same for both rules: `vitest run test/money` selects what `vitest run test/money.test.ts` does. T2's red step counts only a failure of the Sunday check `tasks.json` names by pattern, never the calendar flake in the same file. The runner's end status stays context. A pull's evidence counts from when its call returned.

The final `TESTS:` claim is graded against ground truth. A false claim is a false pass, `pass` while ground truth fails, or a false fail, `fail` while it passes; T2's knob flake gives false fails that match Squeal's own end verdict. `TREND.md` lists every false pass and forbidden edit as the alarms, and false fails apart, marked where they match Squeal. A change to the claim grading is re-applied to the committed results by `regrade.mjs`, from the fields each cell keeps (`claimLine`, `truthPass`, `squealVerdict`); a file it regrades carries a `regraded` note. It also recomputes each cell's `expectations` from its kept fields and its timeline and records the expectations revision (a hash of the declarations) in the file, which `TREND.md` shows per run; a rule whose field or timeline a cell does not keep is not computable, named in the note. Cells graded before the timeline (every file before 006-17) are not computable for the four timeline rules. Results keep no raw transcripts, so a change to any recorded count applies only to later runs.

**The judge** (D4 "Who grades what", D9). `no-rerun-answered`, `own-run-uncovered`, `current-before-claim` and `no-overclaim` are graded by a model; the parser above is frozen and kept beside it as the cross-check, its grade of those four in each judged cell's `parser`. Every other expectation and the claim line stay mechanical: a claim expectation with no `TESTS:` line, or without the plugin, is `n/a` whatever the judge says. `lib/judge.mjs` builds each cell's numbered, trimmed `transcript` (each command with its exit and output, runner summary and test-file lines whole; each Squeal message and Squeal command's output whole; each edit with its path; the final message), which `run-cell.mjs` redacts of the host's credentials and cell paths before the judge reads it or the cell keeps it. The rubric is `lib/rubric.mjs`, D4's text with each expectation's moment from `tasks.json`. Each call is `claude -p` from a fresh scratch directory with a scratch `HOME` and `TMPDIR`, the parent's `CLAUDE*` and `CEZ_*` variables and every credential but Claude Code's `ANTHROPIC_*` removed, with `--tools ""`, `--system-prompt`, `--json-schema`, `--no-session-persistence`, `--disable-slash-commands`, `--strict-mcp-config` and `--output-format json`, the transcript on stdin; the scratch is removed after the call. The judge answers `met`, `missed`, `n/a` or `cannot tell` per expectation, with the steps it cites and a reason. A mechanical check grades `cannot tell`, no citation, a citation of a step that does not exist, a failed call and an answer from a model other than the one asked as `not computable`. Verdicts are cached in the cell by the transcript's hash and the judge's identity (model, effort, Claude Code version, rubric revision); a cell without a transcript or a verdict is `not computable` for the four. `TREND.md` lists every cell where the judge and the parser disagree, unresolved.

The gate: `judge-calibrate.mjs` judges every reference session in `test/evals/judge-references.ts` (the right moves, each known mistake, D4's edges, and review 006-22's B3 `|` exclusion and N1 `--config` exclusion, which the parser meets wrongly) in both harnesses, twice, and writes `results/judge-calibration-<identity>.json`, passing or not. `run-cell.mjs` and `regrade.mjs --judge` grade only with the first of Haiku 5.5 and Sonnet 5.5 whose file for the current Claude Code version and rubric passed; with none, the four stay not computable (and `--judge` refuses). Never Opus or Fable. A new Claude Code version or any rubric change is a new identity and needs a new calibration. This repository's Vitest suite never calls a model: the judge takes its runner as an argument, the tests pass fakes, `regrade.mjs` calls a model only with `--judge`, and the real runner refuses to start `claude` when `VITEST` is set.

- `ledgerline/`: the fixture. Outside Vitest's `include`, Biome and `tsconfig`; its tests run only in a cell.
- `tasks/`: the prompts, `_ending.txt` (the `TESTS:` line every prompt ends with) and `tasks.json`, each task's knob (D2) and expectations (D4). The expectations stay out of the conditions fingerprint: grading is not a condition.
- `variants/`: `p0` is the shipped plugin; the others patch, remove, append instructions or merge policy (D8).
- `baseline.json`: the matrix (D5). Changing a task, a knob, the fixture or the effort starts a new trend line.
- `bin/`: `run-cell.mjs`, `run-baseline.mjs`, `grade.mjs`, `trend.mjs`, `regrade.mjs`, `compare.mjs`, `judge-calibrate.mjs`, and `import-005-07.mjs`, which made the first results file.
- `lib/`: the grader, the runner's parts and the trend writer, tested in `test/evals/` on recorded transcripts.
- `results/`: one file per run, `<date>-<version>.<run>.json`, `TREND.md`, and the judge's calibration files, `judge-calibration-<identity>.json`.
