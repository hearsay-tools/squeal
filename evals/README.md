# Model evals

Spec 006 (`docs/specifications/006-model-evals/spec.md`): a recurring baseline that shows whether models use Squeal well, run at every hub release and with every `/quality` scan, at calm load. Never in CI or in this repository's Vitest suite. Built from 005-06's prototype (`docs/specifications/005-agent-adoption/research/probes/model-evals/`, whose logs stay there).

```sh
node evals/bin/run-baseline.mjs                    # the baseline on HEAD: 48 sessions, about 45 min at 2 at once
node evals/bin/run-baseline.mjs --variant p1       # shipped texts and a variant side by side, a run of its own
node evals/bin/run-baseline.mjs --resume <run>     # continue a run cut short: its graded cells are skipped
node evals/bin/run-cell.mjs t1-thousands p0 claude claude-haiku-5-5 1   # one cell
node evals/bin/trend.mjs                           # regenerate results/TREND.md
node evals/bin/regrade.mjs                         # re-apply the claim grading and the expectations to every results file
node evals/bin/compare.mjs results/<file>.json variant
```

Cells run in `$SQ_EVALS_ROOT/cells/<commit>/<run>/` (default root `<tmpdir>/squeal-evals`) with scratch `HOME`, `TMPDIR` and `CODEX_HOME`; the real `~/.claude` and `~/.codex` are never written, and the host's model provider is read from the environment and `~/.codex/config.toml` at run time. Only the provider's allow-listed fields reach a cell; an inline header or token stops it. Every run has a fresh id, so two runs of one commit share no cell and write two results files. A cell starts only while the one-minute load average is below the CPU count. The coordinator commits the results file and the regenerated `TREND.md`.

A cell's teardown runs on every path, a setup error, a timeout or a signal: the session's process group gets TERM, then KILL; the cell's daemons are stopped; the scratch homes and the fixture's `.git` are removed; and every file kept in `out/` and `work/` is scanned for the host's credentials and provider URLs. A file holding one is redacted, or removed if it is binary, and a cell where one survives fails without a grade. `out/truth.json` records how both ground-truth commands ended (exit, signal, timeout, spawn error) and `out/status-end.json` holds `squeal status --json` after the session: the grader's inputs.

The score is expectations, never raw behaviour counts (spec 006 D4). Each task declares its expectations in `tasks/tasks.json` under `expectations`, beside its knobs under `tasks`: an id, the moment it applies, and a rule over the recorded fields (`RULES` in `lib/behaviours.mjs`), with the rule's parameters (`own-run-uncovered` names its runner, the tests Squeal cannot answer and the paths whose last change the run must follow). In each session an expectation is met, missed, or does not apply; a cell whose run had other knobs for its task is not graded, since its expectations were declared for another situation. `TREND.md` shows per model a headline (expectations met over expectations that applied), each expectation's rate, a per-task breakdown and context counts with no direction (skill loads, `squeal why`, `run --slow`, full-suite runs, refused commands, Squeal waits, false fails, T2's red step through Squeal or an own run). The 25-point flag compares expectation rates. A new task or expectation needs its reference sessions in `test/evals/reference.test.ts`, on both harnesses: the right moves meet every expectation, and each expectation has a known mistake that misses it alone.

Each results cell keeps a compact `timeline` of what the grader saw (`lib/evidence.mjs`, D4 "Retained evidence"): edits with paths, the agent's own runs with runner, scope, whether informational and whether completed, the Squeal evidence each pull or delivery carried (revision, pending, stale and unknown counts, slow tier, daemon, known failures, verdict, the test files it named), sleeps, and where the final message came. The four rules about evidence and runs read it: `no-rerun-answered` (a Vitest run of a scope Squeal had answered current after the last edit), `own-run-uncovered` (a completed run covering the affected tests after their last change), `current-before-claim` (the latest evidence before a `pass` or `fail` claim was at the last edit's revision with nothing outstanding) and `no-overclaim` (the evidence at the claim said `pass`). The runner's end status stays context. A pull's evidence counts from when its call returned.

The final `TESTS:` claim is graded against ground truth. A false claim is a false pass, `pass` while ground truth fails, or a false fail, `fail` while it passes; T2's knob flake gives false fails that match Squeal's own end verdict. `TREND.md` lists every false pass and forbidden edit as the alarms, and false fails apart, marked where they match Squeal. A change to the claim grading is re-applied to the committed results by `regrade.mjs`, from the fields each cell keeps (`claimLine`, `truthPass`, `squealVerdict`); a file it regrades carries a `regraded` note. It also recomputes each cell's `expectations` from its kept fields and its timeline and records the expectations revision (a hash of the declarations) in the file, which `TREND.md` shows per run; a rule whose field or timeline a cell does not keep is not computable, named in the note. Cells graded before the timeline (every file before 006-17) are not computable for the four timeline rules. Results keep no transcripts, so a change to any recorded count applies only to later runs.

- `ledgerline/`: the fixture. Outside Vitest's `include`, Biome and `tsconfig`; its tests run only in a cell.
- `tasks/`: the prompts, `_ending.txt` (the `TESTS:` line every prompt ends with) and `tasks.json`, each task's knob (D2) and expectations (D4). The expectations stay out of the conditions fingerprint: grading is not a condition.
- `variants/`: `p0` is the shipped plugin; the others patch, remove, append instructions or merge policy (D8).
- `baseline.json`: the matrix (D5). Changing a task, a knob, the fixture or the effort starts a new trend line.
- `bin/`: `run-cell.mjs`, `run-baseline.mjs`, `grade.mjs`, `trend.mjs`, `regrade.mjs`, `compare.mjs`, and `import-005-07.mjs`, which made the first results file.
- `lib/`: the grader, the runner's parts and the trend writer, tested in `test/evals/` on recorded transcripts.
- `results/`: one file per run, `<date>-<version>.<run>.json`, and `TREND.md`.
