## Blockers

### B1. Proven: the relative-fs repair reuses results with the old meaning

**Location:** `src/core/lint/provider/rooted.ts:70`, called by
`src/core/lint/provider/worker.ts:27`. The unchanged key discriminator is
`src/core/lint/provider/protocol.ts:17`, `PROVIDER_VERSION = 5`.

**Contract:** D5 keys the provider's own version. The protocol's rule is:
"Raise it when what the worker reports changes meaning." Vision principle 2:
"An old result never gets to pose as the current truth."

The 017-27 change fixes relative probes, but keeps provider version 5, which
0.1.391 already released. Adding `ESLINT_FLAGS` does not move keys when it is
unset: `environment()` omits unset variables. Adding `configFiles` to
`lintKey` also does not move an ESLint key whose closure already holds them.

**Reproduction:** use ESLint 10.13.0, no nested config, no `ESLINT_FLAGS`, and
start the provider from outside the project. Write `marker.txt`, `src/a.js`
(`export const a = 1;`) and this `eslint.config.js`:

```js
import { existsSync } from "node:fs";
const rule = {
  meta: { schema: [] },
  create(context) {
    return {
      Program(node) {
        if (existsSync("marker.txt"))
          context.report({ node, message: "marker exists" });
      },
    };
  },
};
export default [{ plugins: { probe: { rules: { r: rule } } }, rules: { "probe/r": "error" } }];
```

Run the old committed worker, then the candidate committed worker, at these
same bytes. Ask for the file's inputs and refreshed environment and compute
its key. Both snapshots have env `{ TSESTREE_SINGLE_RUN: "false" }`, closure
`["eslint.config.js"]`, and the same config and provider version.

```text

candidate: key 5ae1d0fb11960c83f406c6a96e7270373ea75d032a207c98d1db393d535eed7c, findings [probe/r: marker exists]
```

The pass takes the old target result by key and presents it as current. The

### B2. Proven: a tracked nested config in a dot folder is not used

**Location:** `src/core/lint/provider/lookup.ts:37`.

**Contract:** D3 step 4: "With ESLint 9 and a nested `eslint.config.*` in the
listing, add `v10_config_lookup_from_file` to `ESLINT_FLAGS`, so each file
uses its nearest config." Row 017-24 requires the nested config's findings.

`hasNestedConfig` skips every folder whose name starts with a dot. Such
folders can hold tracked source and configs. ESLint flat config does not
exclude them by default. The pass offers and stores these files normally.

**Reproduction:** real ESLint 9.39.5, no other nested config, these files in
the git index:

```text

eslint.config.js                export default [{rules:{"no-debugger":"error"}}];
.storybook/eslint.config.js     export default [{rules:{"no-console":"error"}}];
.storybook/a.js                 debugger;console.log(1);
```

Run the candidate's real pass with `lint.include: [".storybook/a.js"]` and
`lint.tools: ["eslint"]`. Compare with the CLI from the project root:



**One-worker fix:** detect nested configs in tracked dot folders too. Skip
