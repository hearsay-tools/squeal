## Blockers

### B1. Proven: Squeal's policy removes import targets from the program key

`src/core/lint/pass/rekey.ts:90` filters candidates through the Squeal policy before asking for inputs. `lintableAfter` at `:200` builds the program's lintable set from only those inputs and stored states. `src/core/lint/pass/keyer.ts:59` combines that set with the TypeScript program. A JavaScript project has no TypeScript program to supply an excluded import target.

D5 requires the segment to contain **every file ESLint lints in the worktree**. D1 says Squeal's include/exclude narrows which files it checks. It does not remove dependencies of checks that remain on. This breaks D5 and the current-state promise. The gap disclosed in 017-05's notes is a break, not just extra work.

Reproduction, using the real provider and pass:

1. Copy `test/fixtures/lint/project` with its test dependencies, as the provider tests do. Use `lint.exclude: ["src/b.js"]`. The fixture's `src/a.js` imports `x` from `src/b.js`; its `import-x/named` rule reads that target. Run the first pass.

4. A fresh `eslint -f json src/a.js` adds `import-x/named`, message `x not found in './b.js'`.

Fix scope: the pass and its program tests. Build the dependency segment from ESLint's lintable files before applying Squeal's selection policy. Keep the policy for checks and results only. Cover both include and exclude, with no TypeScript program. An excluded target edit must re-key or mark the importer stale. Keep one segment per pass. Change the lint-key version when its meaning changes.

### B2. Proven: jiti-loaded config modules never enter the closure or refresh decision

`src/core/lint/provider/worker.ts:15` records Node resolve-hook events only. jiti can load TypeScript config dependencies without those events. `src/core/lint/provider/session.ts:159` reports only the resulting recorded closure. `src/core/lint/pass/keys.ts:89` hashes that closure, and `src/core/lint/pass/session.ts:22` uses it to choose a thread refresh.

D4 requires the config's module closure. D5 says its hashes are not optional. This breaks both. The disclosed jiti gap in 017-04's notes is a break for a supported flat config.

The plugin has no version or rule implementation in config JSON to save the key. The resolved root config is also absent from this closure; its declaration alone does not put its bytes in `lintKey`.
