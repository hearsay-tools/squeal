## Blocker

### B1. Proven: the named wait can return an old lint pass before lint keying reaches the edit

**Location:** `src/core/lint/surface/named.ts:95`, `src/cli/wait/named-lint.ts:48` and `:86`; the call is at `src/cli/wait/named.ts:168`.

**Contract:** row 017-37 item 2 says a named wait "also waits for the lint of the named paths that lint includes". Spec D2 defines `pending` as "while Squeal has not linted the current bytes". Vision principle 2 says: "An old result never gets to pose as the current truth."

The new reader treats a stored `pass` as a current pass without checking the lint cursor against the wait's synced revision or checking the judged blob against the named file. `namedLintWaits` then finds nothing pending, so the wait ends with `done: 1`, `pending: 0`, `outcome: "pass"`.

Test synchronization does not close this gap. `src/core/daemon/daemon.ts:1673` reconciles the scheduler and returns its revision/readers. Its batch callback at `:1391` nudges lint without awaiting it. The lint pass can still be awaiting provider refresh or inputs before it writes pending states. Thus tests can be current while lint still holds the previous revision's pass.

**Reproduction:** a throwaway test appended to `test/cli/named-lint-wait.test.ts` reused its public `waitForNamed` fixture and helpers:

1. Call `lintedRepo("pass")`. The test store and injected daemon sync are current at revision 4, with an alive daemon.
2. Create `src/b.test.ts`'s directory. Seed its lint state as `pass`, with a judged revision of 3 and `blobHash("export const a = 1;\n", "sha1")`. Record the ESLint cursor as `{ revision: 3, environment: "old-environment" }` through `writeCursor`.
3. Write `export const a = missing;\n` to that file. Leave lint keying behind the test sync, as an asynchronous lint provider can do.
4. Schedule the fixture's current lint failure 250 ms later. Call `wait(repo.main, [B], 5_000)`. Expect the named lint outcome to be `fail` after that update.


```text
Test Files  1 failed (1)
```

Only the throwaway test changed for this probe. Product sources stayed at the candidate. The probe and its timer were removed. This is a deterministic read of an old saved result, not a timing-threshold failure.

The four committed named-lint tests miss this case. They seed the edited check as already `pending`, or seed a final pass without judged-byte provenance. They do not test the interval before lint writes the pending state.

**One-worker fix:** make the named lint read establish that each relevant tool has processed the wait's requested revision before accepting its saved verdict. Represent a tool that has not caught up as pending with a reason. Preserve that uncertainty at the deadline, while retaining the test channel's exit code and verdict. Also check named-file byte provenance so an older blob cannot count as done. Do not require every judged revision to equal the latest revision: an unchanged file can retain a valid older result. Keep off, held and unavailable behavior explicit. Add the regression above and a config-change control where the named file's bytes stay equal but lint keying is behind. Confine the repair to the named reader/wait contract and focused tests; no scheduler redesign is needed.
