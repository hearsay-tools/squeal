## Blocker

### B1-R4. Proven: `a+` descriptor reads escape the observer and share findings at the wrong input bytes

`src/core/lint/provider/observe.ts:275` recognizes a string open flag as readable only when it starts with `r`. Node's `a+` flag also permits reads. Thus `wrapOpens` at `:290` records no unobserved input for `openSync(path, "a+")`. The read wrapper at `:235` passes a numeric descriptor straight to the original `readFileSync`, because `absolute(descriptor)` is null. Neither operation reports the file. Its bytes never enter the closure or the key.

D5 says: **"Every byte ESLint used for a stored result is either text the pass gave the worker or bytes whose blob the worker reports."** It also says: **"A path read through an API the worker does not observe makes every key that holds it store nothing."** The stored answer violates that rule and vision principle 2.

Reproduction:

1. Create two `FakeWorktree` roots on one `commonDir()`. Populate each with `fixture(tree, "ts-config", edit, [], major)`, for major 9 or 10. Replace the listed `rule.ts` with the same local rule in both roots:

   ```js
   import fs from "node:fs";
   export default {
     meta: { schema: [] },
     create(context) {
       return {
         Program(node) {
           const fd = fs.openSync(new URL("./data.txt", import.meta.url), "a+");
           let text;
           try {
             text = fs.readFileSync(fd, "utf8");
           } finally {
             fs.closeSync(fd);
           }
           context.report({ node, message: text });
         },
       };
     },
   };
   ```

2. Write `data.txt` with `onDisk` only, outside each listing. Root 1 contains `before`; root 2 contains `after`. All listed bytes, computed config, plugin metadata and install fingerprints match. `a+` leaves each existing file's bytes unchanged.
3. Run `daemon(one).run("src/a.js")` and close it. It stores `["before", "inline before"]`.
4. Run the real pass in root 2. It reports **`keyed: 1, hits: 1, linted: 0, stale: 0`**. Its state is `fail`, `stale: false`. It uses root 1's exact judged key and stores the same `before` findings as current.
5. Run fresh `eslint -f json src/a.js` in root 2 through `cli`. It reports **`["after", "inline before"]`**.

The failure reproduces on Node 22.23.3 and 24.21.0, each with ESLint 9 and 10. For ESLint 10, the shared key is `380db16c0d6be0312f420505c66616a31b92997383ff2705b334efe19b058229` on Node 24 and `1b0d68fd2ee2c61c26afbfc92cbfb5a471524376517a3a3ef7b35e94bd98a448` on Node 22.

This is outside all five accepted boundaries. One JavaScript reader reads one version of the input. It reads actual bytes through public `node:fs` APIs in the worker thread. There is no existence-only probe, typed program, child process, native addon or edit under `node_modules`. This is a local custom rule, not a claim that a common plugin crosses an accepted boundary.

**Fix scope, if the human authorizes it:** one provider-observer repair and a real-provider/pass regression. Recognize all read-capable string flags, including the `+` forms, for sync, callback and promise opens. Mark an unsupported descriptor input unobserved and refuse storage, or observe its exact bytes. Test this two-root case and require fresh findings or no stored result. Test representative read/write flags so the flag decoder does not regress. Existing version-3 lint results can contain the wrong association; prevent their reuse if this is repaired. The shared test-key encoder needs no change.
