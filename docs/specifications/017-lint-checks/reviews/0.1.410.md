## What fits

### Closure growth, row 017-29

`grownByLint` (`src/core/lint/pass/grown.ts:22`) requires the cursor's own recorded environment, at least one newly added closure path, and lint-read provenance for every added path. It recomputes the old environment with those paths removed. Changed recorded bytes, changed declarations, packages or keyed policy, and closure shrinkage therefore do not take the shortcut. Missing input records also fail closed to the existing full keying.

`ProviderSession.observe` records additions only after a lint report; open and thread refresh clear that provenance, and a report that loses a closure path clears it too. A fresh read introduced by refresh has no lint provenance. `planOf` separately preserves config-path changes as `config`. The two changed existing assertions change only the expected keying mode; their lookup and cross-worktree assertions remain.

The storage boundary is unchanged: `lint-part.ts` stores nothing from a part whose report adds a closure input its keys lack. That part remains pending and gets keys with the added input on the next pass. Checks judged earlier keep keys whose own lint thread had not read that input. A later change to recorded bytes moves the environment; the shortcut cannot hide it. The new regression checks the stored results' actual input sets, restart invalidation and an edited file's retained transition. `run.ts` preserves the `onKeying` wrapper and transaction ordering.

### Ignored config folders, row 017-30

`findConfigs` obtains one Git list per walk, skips only whole ignored directory entries, and keeps every folder when Git fails. It still visits tracked nested configs, dot folders and ignored-pattern folders containing force-added files. Explicit `extends` and plugin inputs continue through `configFacts`, independently of the skipped discovery walk.

The async call is awaited by `readConfigs`. `ConfigSet.missed` checks each linted file's nearest config. `Provider.lint` re-reads configs before linting a missed one. Its held bytes join the pass's closure, so the grown part cannot store a result at the old key. The new real-oxlint regression verifies a later edit of that ignored config changes the force-added file's findings. The steady path performs config-chain probes but no extra Git call or config reload.
