It omits a duplicate own segment and retains missing-blob behavior. `Keyer.#list()` discards the cached builder when it clears the blob cache. Later calls from `parts.ts` therefore use rebuilt config segments. No key-version change is needed.
- **D11, chunking and observation.** `chunkDebugPaths` counts UTF-8 bytes plus one separator, keeps order, emits no empty chunk and keeps an oversized path alone. Tests cover both platform budgets and real oxlint set equality. `lintedFiles` passes the original context to every child and returns immediately on a D3 failure. `Provider.ready()` still enables observation for JS plugins and TS configs.
- **Row 017-30, config discovery.** The folder map is allocated inside each serialized `Provider.inputs()` call. Cached `null` entries work correctly. Neither `ConfigSet.missed()` nor later calls reuse it. Newly created configs remain visible to the existing missed-config reload and held-byte checks before storage.
- **D7, selection and program inputs.** `inputsOf` offers picked paths and unknown-extension extras together, learns from every returned path, then filters the returned map to picked paths. Unselected files teach extensions without gaining checks. Ignored files and dependency paths still pass through `offeredSet` first.
- **D7, yields and state.** Provider input mapping, key computation and result judging yield every 256 files. No yield occurs inside `store.transaction`. States, transitions, cursor and program metadata still commit together. Passes remain serialized per tool; a nudge during a pass requests another pass. The new yields do not create a second state writer or advance the cursor past the captured revision. Held-byte and on-disk file checks remain before result storage.
- **Row 011-302, status honesty.** `onKeying(true)` follows the provider-input await. A null plan or refused inputs never sets it. Local keying, judging and commit are enclosed by `try/finally`; the exception probe confirms cleanup. Existing callback-order and daemon holder tests pass.
