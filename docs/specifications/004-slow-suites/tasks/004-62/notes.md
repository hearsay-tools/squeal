## Seam map (residue)

- The policy as the line shows it: `stopText` in `src/core/state/slow-text.ts:138`. With the policy on, every form says "Stop waits up to <bound> for them or holds the agent once", including all-current and no-files-listed. With it off, the line never says "Stop": it says "Squeal runs them when the agent pauses", "Squeal has not queued them", or "Squeal runs the pending ones …". So step 4's marker `Stop waits` separates the two values in every state. When every slow file is current there is nothing to run under either value: step 4's "while one is not current" covers that.
- Budgets are tight, and this row used most of what was left:
  - Skill body: under 5000 chars (`skill.test.ts`, "stays within its budget"). It was 4998 before this row and is 4995 now. Step 4 had to stay at its old length, so it dropped "it runs them and waits for their results as well as your edits'" and "Then claim only what the latest header or `squeal status` shows" (the done-when keeps "every claim about tests matches a line of `squeal status`"). `commands.md` still documents what `run --slow --wait` waits for.
  - Primer: `PRIMER_CAP_CHARS` 1500. The old slow sentence was 226 chars under `squeal`; off is now 275 and on is 264. The Claude Code "all three, with Vitest projects" matrix case fits at 1495 with every project named.
  - The Codex primer at the test path (121 chars) was 1499 to 1500 before, so any policy wording folds it. "Vitest and slow files" now names the slow step as "the CLI's `run --slow --wait 60000`", and "all three" counts its node:test projects as "node:test (2 projects)" instead of naming them. That is the primer's designed fold order (projects first, then naming), and the matrix now pins it (`codexFirstOnly`, `codexCovers`). Real Codex plugin-cache paths are about as long, so Codex users with node:test projects and slow files lose the project names. Keeping them would mean cutting another 005-owned sentence. The reviewer should weigh it.

## Decisions the spec did not settle

1. On-wording: "and Stop waits for them". D8 says "Stop waits for them (D9)". Until a harness's waiting entry has run, Stop holds once instead of waiting, which the line says and the primer does not.
2. Off-wording ends "`run --slow --wait 60000` runs them now". The brief named the command with `--wait`, and its waiting is implied, not spelled out, to stay within the cap.
3. Under the 5000-char budget, the skill marks the policy with the substring `Stop waits`, not the whole ending. `commands.md` carries the full ending.
4. `research/probes/issue-5/probe.ts` is outside W1's ownership. Its hand-built `Coverage` needed `requireSlowSuite` to show the two primers. That one-line edit stands alone in commit `776af0a7`, and the coordinator was asked (request `41ef74b0`). `output.txt` stays as the triage's record. This row's output is below.
5. The brief says to read `docs/styleguide.md` on agent-facing text, but it has no section on that (it has `## Agent work` only). I followed the existing primer and skill voice.
