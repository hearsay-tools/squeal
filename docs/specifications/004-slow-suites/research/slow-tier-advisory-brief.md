# Research brief: the slow tier's value in practice, and an advisory slow tier

Use /researcher. Shape: research, read-only on the product. Decided by the human on 2026-10-18 (row 004-75), after `slow-tier-role.md` (004-74). That file recommended keeping the slow tier with better wording; the human doubts it adds enough over the agent running the suites itself at the end, given that a rebuild re-keys nearly every build-output file. The human's middle ground, to weigh rather than to confirm: **Squeal does not run slow files; it tells the agent live which of them its changes affect, and which it should run at minimum before finishing.** Run probes only when the one-minute load is below the CPU count; never write under the real HOME.

Read first: `slow-tier-role.md` (all of it, especially 3, 5 and its open questions), `slow-tier-role-brief.md`; 004 `spec.md` D2, D5, D8, D9 (`stop.requireSlowSuite`); `research/issue-4-signals.md` and D2's token ranking (row 004-73); 011 C4 (closures) and C6 (`why`); `../005-agent-adoption/lessons.md`; cezarion's `squeal.config.json` and its browser e2e config.

Questions, each with its evidence tag:

1. **Reuse in practice.** In real cezarion and dogfood sessions and the eval cells (read-only), how often a slow file's stored result was reused instead of run: across edits outside its inputs, docs-only sessions and other worktrees through the shared store. Count runs saved and their minutes.
2. **The transition signal.** How often a slow failure was delivered `PASS -> FAIL` against a baseline recorded before the agent's change, rather than `first observed`; and whether any session built after a slow baseline was current. If never, say what it would take to see one.
3. **Advisory: naming the affected files without running them.** For each kind of slow suite (build output, self-preparing browser specs, only slow), how well Squeal can say which slow files an edit affects from what it already has: stored closures, declared inputs, D2's token ranking. Measure precision and recall on real edits from the history of this repository and cezarion (cezarion #1076 and E5 in `issue-4-signals.md`, the 004-74 rebuild probes), against the files whose result actually changed.
4. **Advisory: the minimum set and the text.** Which affected files the agent should run before finishing, and how Squeal words it live (per edit, in deliveries, in `status`, at Stop) without naming a build command (004-71's rule). How the agent's own run feeds back: through `squeal run <file>` (stored and keyed) or a plain `npm` run (unseen).
5. **What agents do with an advisory.** From the 0.1.199 and 0.1.215 eval cells and the dogfood transcripts, whether agents ran the named slow files when told, and how much of them. If no data exists, design the smallest eval cell that would measure it (do not run a new eval; eval runs take turns across coordinators).
6. **The options, compared.** For each, the evidence, the cost to build and to maintain, and what it loses: (a) keep with better wording (004-74); (c) on request plus the finish gate; (e) advisory, the human's middle ground; (d) exclude the slow suites from Squeal. Include whether (e) can keep `stop.requireSlowSuite` meaningful, and what of D1 to D10 (e) would delete.

Own only `research/slow-tier-advisory.md` and throwaway probes under `research/probes/slow-tier-advisory/`. Edit no board, spec, status or product file. Done when the findings file answers the six questions with tags (`verified by experiment`, `read in source code`, `read in official docs`, `inferred`), recommends one option with its numbers, and states the limits. Commit when done. Budget: about two hours of wall time; stop and write what you have when it runs out.
