# 004 Slow suites by policy

Stage: shipped 2026-10-09 (0.1.85; released in hub 0.1.86). Amendments: `status.md`. Research: `research/slow-suite-policy.md` (Opus), `research/slow-suite-runtime.md` (Astra), both measured on this shared Linux host at load 5 to 36, never at calm load. Specs 001 (D2 to D12), 002 and 003 hold unless a section here says otherwise.

## Problem

End-to-end and integration suites take about a minute: this repository's `test/e2e` 60 to 70 s in full and 7 to 66 s per file, cezarion's `test:package` 63 s and 0.3 to 42.7 s per file (load 13 to 23). Today Squeal treats them as ordinary test files. An edit that reaches one queues it beside the edit's own fast tests, so the agent waits a minute for a unit result. Two worktrees running the same e2e suite at once collide on fixed ports (reproduced in cezarion on `::1:4321` and `127.0.0.1:4322`). A suite that tests a build output Squeal does not produce cannot be tied to the code state (vision principle 2), so Squeal names it out of scope rather than promising provenance for an input it refuses to control (goal 8); both suites measured above are such suites, and the slow files Squeal runs are those that are only slow or prepare themselves from the sources, such as cezarion's browser specs and the eval fixture's `test/slow` (amended 2026-10-18, the human, 004-79). The human named e2e tests as a blocker; the promise holds as for 003: only what is needed runs, only the delta reaches the agent, and no slow result poses as current for code it did not run against.

## Goals

Each goal is testable, on a repository shaped like the eval fixture (a Vitest `test/slow` directory keyed on sources) and one shaped like cezarion (Vitest browser specs that prepare themselves from the sources) (amended 2026-10-18, the human, 004-79).

1. An edit never waits behind a slow file: the edit's fast tests run and report first, whatever slow files its closure reaches.
2. Slow files run when no edit's fast work is pending at the current revision and the revision has been quiet for `slow.quietMs` (`slow.trigger: "continuous"`), or when the consumer is idle (`"idle"`), or on `squeal run --slow` or `run --all`; at most `slow.maxParallel` slow files run per user on the host at a time, at low priority, and a fast revision preempts the slow tier between tiers (amended 2026-10-09, D2; amended 2026-10-18, the human, 004-79).
3. A slow file re-runs when its keyed inputs change; a slow file whose keyed inputs changed during its run is discarded and queued again, never stored as current (001 D5).
4. A slow failure reaches the agent with its revision: in a continuous lane with the next tool call, otherwise through the idle waiter in an interactive Claude Code session or with the next prompt (amended 2026-10-18, the human, 004-79); Stop never waits for a slow tier.
5. A slow result is inherited as any file's is (001 D5) (amended 2026-10-18, the human, 004-79).
6. Status and headers state the slow tier honestly: current at which revision, running since when, pending, or not run at this revision.
7. Under host pressure a slow file waits, up to a bound, then runs with a note; it is never skipped silently.
8. Squeal never builds anything and covers no test of a build output it does not produce; `setup --check` names such suites as excluded (amended 2026-10-18, the human, 004-79).

## Non-goals

- Building or refreshing the artifact a slow suite tests (vision: not a CI system).
- Covering, keying or pre-checking tests of a build output Squeal does not produce: no preconditions, no declared artifacts, no stale-artifact wording. Such a suite sits in its runner's `exclude` (D7) and belongs to CI or to the agent after it builds (amended 2026-10-18, the human, 004-79: in the measured window every one of its 152 failures was a missing build, `research/slow-tier-advisory.md` 2).
- Cancelling a slow run on a revision (001 D5 never cancels; `research/slow-suite-runtime.md` 3 measured finish-and-revalidate as the bounded default).
- cgroup quotas (`systemd-run --user --scope -p CPUQuota=`): they work on this host, but not on macOS or in every container; a later opt-in.
- Fixing a project's fixed-port tests; Squeal's slot reduces their collisions between worktrees of one user, the project owns the rest.
- Marking by measured duration or by per-test tags: duration moves with load (12 of 191 files changed side of a 10 s bound between two runs) and some fast-tier files are slower than e2e files (51.9 s, 47.5 s); Vitest tags still import a tagged file and act per test, while Squeal schedules and keys whole files.

## Design

### D1. Marking

`squeal.config.json` gains a `slow` object whose `include` lists test-file globs (`"slow": { "include": ["test/e2e/**/*.test.ts"] }`), matched against every runner's test files, and a `nodeTest` entry gains `slow: true`, which marks every file its `include` lists. A file matched by `slow.include` is a slow file in every worktree; the 001 D11 loader rules apply (a glob matching no test file is one note). Measured duration stays an ordering input inside a tier (001 D5) and adds one note per project naming fast-tier files whose last run exceeded 30 s, so a human can decide to mark them.

### D2. The slow tier

Slow files form their own tier class in the scheduler (001 D5). The fast tiers run as today and never include a slow file. The slow tier is eligible only when no edit-caused fast work is pending or running at the current revision (the runner part, 001 D2, and recent files, 001 D5); background fast work (the baseline, an environment change, `run --all`) holds it back too (amended 2026-10-14, task 004-60) unless `squeal run --slow` asked; a backlog tier that arrives while a slow tier runs starts beside it in its own lane. It then runs one slow file at a time per worktree, in D5's order, and before each next file it checks again: a new revision with fast work, or a fast file pending, takes precedence and the slow tier resumes after it. When the machine is idle (no fast work pending or running in the worktree and the load per CPU below `slow.maxLoadPerCpu`, D3), a slow tier takes up to `slow.maxParallel` files (default 4) at once instead of one. A slow file in flight finishes (D4). Amended 2026-10-09 by the human after dogfooding (`lessons.md`: a 51-minute baseline held cezarion's slow tier back, defect 3, and one file at a time cost about 4x the files' parallel run time). It also waits while its own daemon's fast backlog (a baseline, a checkpoint or `run --all`) is queued or running, so a warm-up's slow files never contend with its fast ones; an explicit `squeal run --slow` still runs at once (D3 as amended) (decided by the human, 2026-10-14, task 004-60: cezar's browser files ran beside its whole unit-suite baseline and failed under the load). During a departure drain (011 C9) it waits only for the fast work the drain runs, not for the backlog the drain leaves queued. A draining daemon leaves no waiter mark and takes no permit while another worktree's mark is fresh, so a live session's slow files never wait behind a departed one's (amended 2026-10-21 on the human's acceptance, row 011-84). Slow files take their workers from the per-user pool of 001 D11 Capacity like every other lane (task 001-386).

Triggers: (a) by `slow.trigger` (D7): with `"continuous"`, the default, the fast lane of the worktree has nothing pending or running at the current revision and the latest revision is at least `slow.quietMs` old, whether or not a consumer is in a turn; with `"idle"`, a consumer of the worktree is idle (001 D9 turn state: a silent Stop) or no consumer is registered. Under both, the end of a `codex exec` or `claude -p` session counts, and its daemon drains its pending slow files before it exits (001 D10 as amended, task 004-29); (b) `squeal run --slow`, new, which runs the slow tier now, still behind pending fast work; (c) `squeal run --all`, which includes slow files as today's full-suite checkpoint does. With `"idle"`, while a consumer is in a turn and no explicit trigger asked, slow files stay pending. The scheduler pumps the slow lane when a fast tier ends or a revision ages past `slow.quietMs`, not on `SLOW_RECHECK_MS`. Amended 2026-10-18 (the human, 004-79; `tasks/004-79/amendment.md`): the idle-only rule came from the time slow files shared the fast lane (`research/slow-suite-policy.md` 3); 004-18 gave them their own lane and `research/slow-tier-role.md` 4 measured the fast lane's median unchanged beside it, so the lane runs continuously by default and `"idle"` is the opt-out. The lane, its width, D3's guard, D4's finish-then-discard, (b), (c) and the exit drain are unchanged.

The slot: at most `slow.maxParallel` slow files at a time per user on the host (one permit per file), through lock files (`slow.lock` the first permit) in `squeal/` under the daemon's `XDG_RUNTIME_DIR` when it is set, as its socket follows it (001 D1), else in `/tmp/squeal-<uid>` (D10's per-user directory, 001 D10), held for one slow tier and released between tiers, so two worktrees' slow tiers interleave tier by tier; an idle tier of several files takes as many of `slow.maxParallel` permits per user as it has files. A daemon that cannot take the slot within its turn keeps its slow files pending and retries on the next scheduling pass. Each daemon uses up to its own repository's `slow.maxParallel` permits, numbered from `slow.lock`; with different values across repositories, the user-wide total is the largest value among the running daemons (review wave 4, S1).

Execution: a slow file runs in its own runner process, never in the instance that serves fast tiers: for Vitest a second instance created for the slow tier and closed when it drains, for node:test the same per-file spawn as 003 D5. It runs with `nice` 10 and, on Linux, `ionice -c 3` where permitted (`research/slow-suite-runtime.md` 1: the full e2e took 71 s plain and 84 s at low priority), and with runner concurrency `slow.maxWorkers` (default 2) inside the file. A slow tier of several files starts them all at once (the slow Vitest instance with that many workers; a node:test project with that concurrency, never `runner.tierSize`), so no file of it starts after an edit or a close; and it holds files of one node:test project only, since node:test projects run one after another (004-37). It holds no more files than its run starts at once: the runner reports that width, for Vitest the project's own `maxWorkers` (001 D11 Runner ceiling) within one task group, and the files past it stay queued for a later tier (review 001-394, B2). `runner.timeoutMs` applies per slow file.

Amended 2026-10-15 (task 004-61, the human's choice): `run --all` runs both lanes; `--fast` runs only the fast lane and `--slow` only the slow one, and both flags are both lanes. A `--fast` request is a one-lane checkpoint: its verdict and the header name the lane, never a full suite, and its lane is kept as long as the checkpoint is stored (review 001-417 B1). A fast-only request joined to an open full checkpoint ends with its own files and is not held by the slow lane (S1), except after an owed checkpoint resumes on a successor daemon: a stopping daemon does not keep the request's own files, so the resumed request ends with the checkpoint it joined (review 001-417 round 2, S1). `run --all --slow` is the existing `run --slow` request and no checkpoint, since a slow-lane checkpoint would abandon an open baseline and an older daemon would read a slow lane label as both lanes. Under host pressure the fast lane comes first only by the pool's order (001 D11); the slow lane still narrows and never holds.

Amended 2026-10-18 (the human, gh-4, row 004-72; `tasks/004-72/design.md`, `research/issue-4-signals.md`, signal b2): within the slow tier, after C15's promoted files and the runner's `direct` importers, slow files are ordered by **evidence**: tokens taken from each file the revision changed and its local imports (the `./` and `../` specifiers its closure holds), matched whole against each slow file and its own local helpers. A token is a `data-*` attribute value, an `aria-label`, or a hyphenated class name; one that more than 20 slow files match is dropped. More evidence runs first, then the order before this amendment (shortest last-known duration). Ranking only reorders: every slow file the revision invalidated still runs, none is skipped or deferred, and a file with no evidence keeps its place behind those with some. It is on by default (the human: it costs little, 7 to 35 ms an edit with the slow side cached, 40 to 89 ms cold, and a repository whose slow files carry no tokens sees its order unchanged); `"slow": { "rank": "duration" }` turns it off. One token set per slow file is kept in the store, keyed by the hashes of the file and its helpers. The slow-tier line and `status` say nothing about evidence; `why <slow file>` names the tokens that ranked it. Ranking stands and is built with the continuous trigger, row 004-80 (amended 2026-10-18, the human, 004-79): under a continuous lane a long suite is re-keyed before it finishes, so ranking decides which files get a result mid-turn.

### D3. Load guard

Before each slow file the daemon reads the 1-minute load average per CPU (`os.loadavg()[0] / os.availableParallelism()`). Above `slow.maxLoadPerCpu` (default 1.0) the file waits, rechecking every 15 s, at most `slow.maxDeferMs` (default 600000) per tier; past that it runs and the run carries one note saying it ran under load L. The guard is a hint, not proof of contention (`research/slow-suite-runtime.md` 2: on this 24-CPU host a raw threshold of 4 would defer most of a working day), so the bound is what makes it safe: a slow file is delayed, never skipped. An explicit `squeal run --slow` (trigger b) skips the guard for the tier it starts, so its files run now, behind pending fast work, within `slow.maxParallel` permits and at `nice` 10, one file at a time while the load is above `slow.maxLoadPerCpu` and up to `slow.maxParallel` below it (D2's width); the line that offers it is then true (decided by the human, 2026-10-14, task 004-59, found by 006-54). The guard decides whether the slow lane runs, not which worktree runs it (amended 2026-10-21, the human's row 004-84): while another worktree holds every permit of the slot, a file waits at the slot as a marked waiter instead (D2) and takes the slot at the handover without a guard wait, since that wait would lower no load, the slot staying busy, and would only pick which worktree runs; such a run carries no load note, and time waited at the slot does not count against `slow.maxDeferMs`. With a permit free, the guard decides as above; it checks the slot only above `slow.maxLoadPerCpu` with budget left.

### D4. Interruption and stability

001 D5 holds unchanged for slow files: a revision does not cancel a run; when a slow file completes, its result is stored only if none of its keyed inputs changed on disk or in a revision during the run, else it is discarded and queued again; an install overlapping the run stores nothing (001-107, 001-113). Measured on a representative file each: finishing then retrying cost 14 s and 70 s, cancelling then retrying 10 s and 43 s (`research/slow-suite-runtime.md` 3); finishing is kept because it needs no process-tree cleanup on every edit and keeps one rule for every tier. A slow tier yields between tiers (D2), so the cost of discarded slow runs is bounded by one tier: one file, or up to `slow.maxParallel` files when the tier started idle. Under a continuous lane (D2) a mid-turn edit discards the slow file in flight more often than at a pause; the cost stays bounded by one tier, and ranking (D2) puts the files most likely to matter first (amended 2026-10-18, the human, 004-79).

### D5. Keys: what a slow file ran against

A slow file is keyed as any file (001 D3, 003 D3), its declared `inputs` included when the repository names them. For a slow node:test project the recorder is also placed in the child's `NODE_OPTIONS` (003 D5), so processes the test spawns are observed and their loads join the file's observed closure (003 D3); for fast projects nothing changes. Amended 2026-10-18 (the human, 004-79): a slow file declares no artifact, and a test of a build output Squeal does not produce is excluded (D7).

### D6. Inheritance

A slow result is inherited from another worktree under 001 D5 step 4 as any file's is: by a byte-identical key. A worktree reuses its own slow results under their keys as for any file. Claims follow the same rule (001 D5 step 4 and D8 as amended, task 001-205): a slow file waits on another worktree's claim of its key as any file does. Amended 2026-10-18 (the human, 004-79), replacing the human's 2026-10-08 rule that a slow result is inherited only when its key holds a declared artifact: one rule for every file, which widens inheritance for a slow file with no declared inputs to the rule fast files already live under.

### D7. Policy

New keys, all optional, 001 D11 loader rules, grouped as the existing `stop`, `runner`, `daemon` and `store` keys are: `slow.include` (globs, default `[]`), `slow.maxWorkers` (2), `slow.maxLoadPerCpu` (1.0), `slow.maxDeferMs` (600000), `slow.maxParallel` (4, the most slow files at once when the machine is idle; added 2026-10-09), `nodeTest[].slow` (default `false`), `stop.requireSlowSuite` (`false`) and `stop.slowWaitMs` (120000): when `requireSlowSuite` is true, a main agent's Stop waits for its slow files as D9 says, and a SubagentStop blocks, as `stop.requireFullSuite` does, while a slow file is not current at this revision, naming the slow files and that `squeal run --slow --wait` runs them and waits for their results. No key controls inheritance (D6). Amended 2026-10-12 by the human's 004 D9 decision (001 `status.md`, task 001-285): the main agent's block moved to D9's wait; `stop.slowWaitMs` is new, its default from `research/slow-claims.md` 4 in spec 001 (13 to 28 s from Stop to slow-current on the eval fixture, a four-file e2e tier 63 s at the median and 106 s at p90), capped at 600000 by the hook timeout.

Amended 2026-10-18 (the human, 004-79): `slow.trigger` (`"continuous"`, the default, or `"idle"`; D2's trigger a) and `slow.quietMs` (3000, the quiet window of the continuous trigger; set 2026-10-19 by row 004-80 from the gaps between real edits, `tasks/004-80/notes.md`) are new, beside `slow.rank` (D2, 004-72). `vitest.exclude` (globs relative to the worktree root, default `[]`) names Vitest test files Squeal does not list, run, key or count, with the meaning `nodeTest[].exclude` and `pytest[].exclude` already have; `squeal setup --check` and the primer's "not covered" clause (D8) name them. ### D9. Stop and the idle waiter

With `stop.requireSlowSuite` off, Stop never waits for slow files (2 s budget). A silent main-agent Stop records the slow files pending at that moment like any pending file (001 D9), so in an interactive Claude Code session the idle waiter wakes the agent with a slow failure; in Codex and `-p` sessions, which have no idle wake (002), the failure arrives with the next prompt or tool call, which the status line says. A `codex exec` or `claude -p` session never idles: the slow files pending when it ends run before its daemon exits, for at most `daemon.idleExitMinutes` (001 D10, task 004-29), and their results reach the next session in that worktree. `stop.requireSlowSuite` (D7) is the opt-in for a project that wants an agent held until its slow tier has run.

With `stop.requireSlowSuite` on, in every session, a main agent's Stop waits for its slow tier. Both harnesses run a Stop's entries in parallel, so the wait is a second Stop entry, `stop-slow`, with `timeout` 630 in both plugins' hooks.json, above the 600000 ms cap of `stop.slowWaitMs` plus its handoff; the 2 s entry stays as it is and its silent end nudges the slow tier (001-281). The 2 s entry leaves a main agent's slow files to the waiting entry only once that harness's waiting entry is known to run in the worktree at this Squeal version (a `stop-wait:` row in the store, which the waiting entry writes each time it runs); until then, as for a Codex user who has not yet trusted the new hook, it blocks at once while a slow file is not current, as before, so a missing or untrusted waiting entry degrades to the old hold, never to none. The waiting entry acts only once the 2 s entry ended the turn silently (the consumer, heard from since this Stop began, is idle), so the two never both block; a 2 s entry that blocked or spoke leaves it silent. It then waits until its slow tier settles (no slow file pending and the runner part of the revision applied), up to `stop.slowWaitMs`, or until the daemon has been down for 10 s, and decides at the live revision, in the transaction that would take the turn. Any slow check that is a current failure this session has not been told, whatever revision or key it ran at: one block naming it, with the delta. None: silent, the turn ends. Still not settled at the bound: one block naming the files and that `squeal run --slow --wait` waits for them. A block first puts the consumer back in a turn in one transaction with the check that it is still idle, so a wake by the idle waiter or a new prompt meanwhile leaves the waiting entry silent. A Stop with `stop_hook_active` and a SubagentStop never wait. The drain at session end (004-29) stays for what the wait did not finish. Amended 2026-10-12 by the human (001 `status.md`, task 001-285; `research/slow-claims.md` in spec 001 and the `stop-slow` variant: Haiku's current-before-claim from 0 of 9 to 8 of 9). Amended 2026-10-12 by the human (task 001-305, after 001 `reviews/wave-13am.md`, `wave-13an.md` and `wave-13ap.md`), replacing task 001-302's list of the slow files the waiting entry owed, which every review round found a narrower race past: told means what the consumer's delivery has already delivered (its view holds that failure), so a failure told before the turn ended, or the same failure again at a newer key, never blocks, and a failure the agent did not cause and was never told blocks once. The idle waiter's rule (001 D9) is unchanged. Under a continuous lane (D2) the wait is shorter, since the tier is already running at Stop (amended 2026-10-18, the human, 004-79).

A requested wait (`squeal status --wait`, with or without paths, and `run --slow --wait`) does not take a stale heartbeat for a stopped daemon (amended 2026-10-17, task 004-66, issue #12). On a heartbeat older than its grace it pings the daemon's socket: an answer, or a socket that accepts and does not answer (a stalled daemon), keeps the wait going, and the wait decides neither quiet nor a verdict until the heartbeat is fresh again; a cleared record ends it at once as "the daemon stopped"; a socket nobody listens on ends it once it has been dead for 10 s, the waiting Stop entry's bound, counted from the heartbeat's lapse. A wait that went on through a lapse says so on its verdict line, which prints last since task 011-10, with the lapse's length. `run --slow --wait` exits 3 when there is no verdict: it returned without a daemon, or its deadline passed with a queued slow file still pending; 0 otherwise, 1 when status is unavailable.

A main agent whose session changed nothing is not held for slow files (amended 2026-10-17 by the human, task 004-67, issue #19). Under `stop.requireSlowSuite`, both Stop entries skip the slow requirement for the main agent when the worktree's latest revision is still the one recorded when the consumer registered, and the daemon recorded now is the one that had finished its start scan then (an edit made while no daemon ran is in no revision until a later start scan, so a restarted daemon counts as a possible edit). Any revision counts, another session's included, and a consumer that registers again keeps its first registration's revision. The 2 s entry applies it in its own transaction too, so the exemption holds where no waiting entry runs (Pi, OpenCode, an untrusted Codex hook, a worktree before its `stop-wait:` row). A SubagentStop still blocks. Limit: an edit the watcher has not yet made a revision (its debounce, at most 500 ms) reads as none.

### D10. Isolation

Each slow run gets the daemon's fresh temp directory (001 D10) and its own process group, killed at the deadline (003 D5). The slot (D2) bounds one user's slow files across worktrees to `slow.maxParallel` at once; with the default of 4, two worktrees' slow files can run at the same time, so the cross-worktree port collisions the research reproduced for this user are possible again, at that bound, and a project whose slow files share fixed ports sets `slow.maxParallel` to 1; fixed ports across users or repositories, hard-coded `/tmp` paths and shared caches remain the project's (`research/slow-suite-runtime.md` 4), and the first time a slow file fails with `EADDRINUSE` the note says so.
