# 007 pytest runner: lessons

## Dogfooding on briefcase

Task 007-18, 2026-10-14. Squeal 0.1.174 (main at `7debdef9`, plugins built from it and byte-identical to the committed bundles) validated [beeware/briefcase](https://github.com/beeware/briefcase) at `bffc7303` while a Claude Code agent (`claude-sonnet-5-5`) and a Codex agent (`gpt-6.1-sol`) each worked in a worktree of it. Briefcase is BSD-3-Clause, has a `src/` layout, 408 test files under `tests/`, pytest 9.1.1 pinned in a `test` dependency group, and a second pytest project, `debugger/`, with 4 test files. Python 3.13.14, environments made by uv. Everything ran as the throwaway user `squeal-e2e` in `/home/squeal-e2e/runs/sq07-18`, with credentials passed by name only. Scripts, the prompt and trimmed logs are in `research/probes/dogfood/`, and its README lists every rule followed and every source. The load was 20 to 95 on 24 CPUs throughout, from other coordinators' work, except where a number says otherwise.

### Open question 5: batch size

Batch size is not a policy key in 0.1.174 (defect 5). `DEFAULT_BATCH_SIZE = 5` in `run.ts` is the only value. So `bench.sh` ran sizes 1 and 10 from a copy of the plugin with that constant changed. Each row is a full baseline of a separate clone (`bench/`) with a fresh store. The tier size is 4 (the policy default), and a run starts only while the one-minute load is below 8.

Pending: the bench waits for a load below 8. The table and its reading follow when it has run.

### Open question 7: a run reading a half-synced environment

Not seen. Three syncs ran under a live daemon, and none stored a result from a partial environment:

- `wt-claude`, daemon started before any environment (`wtsync.sh early`). Two 200-file root tiers began during `uv pip install` (19:02:59.4 and 19:02:59.9). They ended `crashed` in 0.4 s and 0.2 s and stored 0 results. The root project was admitted at 19:03:01.18, 2.7 s after its install ended. `debugger` was refused mid-install, with "pytest is not installed in debugger/.venv (a sync in progress…)". It was admitted only 49.8 s after its install ended (defect 8).
- Codex ran `.venv/bin/python -m pip install -e . --group dev` at +80.0 s, which added tox, pre-commit and their dependencies. That produced no revision and no note. A 2-file run overlapped the command's first 2.8 s, while pip was still building the editable wheel; pip writes site-packages at the end. The next revision re-ran all 402 files under the new environment hash. Its results match the project's own run.

So these syncs give no case for taking uv's `.venv/.lock`. One limit: every sync here took 3 to 8 s from a warm uv cache. A cold sync that pauses for more than D2's 1 s hold after pytest is installed, but before the editable package lands, was not exercised.

### Defects

Numbered from 1 for this report. Each reproduction runs in the case root as `squeal-e2e` (`research/probes/dogfood/`).

1. **Test files under a directory named `build`, `dist`, `venv`, `node_modules` or `__pycache__` are never listed, whatever `include` and pytest's `norecursedirs` say, and nothing notes it.** Adapter, `src/runners/pytest/adapter-files.ts:13` (`SKIPPED`). Briefcase sets `norecursedirs = []` exactly so that pytest collects them. The result is 6 files, 67 passing tests and 3 skips that Squeal never runs: `tests/commands/build/test_call.py` and five files under `tests/integrations/virtual_environment/venv/`. Status says 406 files and 0 known failures, and an edit that broke those tests would show nothing. Both agents trusted that silence. Repro: `setup.sh dirs pin clone sync install setup`, `baseline.sh`, then `store.py repo files` lists the 6 files. Fix direction: walk the directories the include globs and the project's `norecursedirs` allow, and skip `SKIPPED` only when `norecursedirs` is unset.
2. **A first pass runs most files two or three times.** Adapter with core, 007-14's "first run stores under the static key". In `repo/`'s first baseline, 406 files took 1,002 file-runs (208 files twice, 194 three times), so the 92 s baseline is about 2.5 passes of a 43 s suite. In `wt-claude`'s session, two source edits took 1,202 file-runs for 402 files, 400 of them three times. The first edit was to `flatpak.py`, a start-up path, so every file re-keyed; the second was to `cmdline.py`, which 2 closures hold. That is why the agent's 60 s wait timed out with everything pending. Each run's observed paths re-key its own files, and the next run observes more. It settles once the observed set stops growing: after it, a `cmdline.py` edit ran only its 2 files (probe A2). An over-run, never a stale pass. Repro: `rm -rf bench/.git/squeal`, then `squeal run --all --wait` in `bench/`, then `store.py bench runs`; the bench logs show it at each batch size. Fix direction: store a run's results under the key that includes the paths it observed, when their content at run time equals the current content (003 lessons defect 4's direction).
3. **A project versioned from git never shares results across commits.** Adapter, D2's environment hash. setuptools_scm, like hatch-vcs and versioneer, names the editable install after the commit: `briefcase-0.4.6.dist-info` in `repo/`, `briefcase-0.4.7.dev2+g0aa6a5eea.dist-info` in `wt-claude/`. D2 hashes the sorted site-packages entry names, so two worktrees synced at different commits never match. By the same rule, one worktree re-synced after a commit would re-run everything (inferred, not run). `wt-claude` inherited 0 of 406; `wt-codex` at the same commit inherited 404. Repro: `wtsync.sh wt-claude … early` against `repo/`, then `store.py wt-claude checks` shows every origin `own`. Fix direction, a spec decision: for the distribution whose `direct_url.json` is an editable install inside the worktree, hash its name without the version. The closure already keys the code. A test that reads `importlib.metadata.version()` would then share results across versions, so say so in D2.
4. **The observed start-up set holds the test packages' `__init__.py` files and a nested `conftest.py`, so editing any of them re-runs every file.** Adapter, D5. `pytest.observedSession.pytest` lists 50 `tests/**/__init__.py` files and `tests/commands/base/conftest.py`. These are imported while a batch collects, and are filed as session imports. Probe C: a comment in `tests/commands/base/conftest.py`, which 18 test files sit under, ran all 402 files. D5 says a changed conftest affects its directory and below. An over-run, never stale. Fix direction: attribute a collection-time import of a test package or conftest to the test files below it, not to the session.
5. **Batch size is not a policy value.** Daemon wiring. D6 says "Batch size is a policy value, default 5", and the adapter takes `batchSize`, but `src/core/daemon/pytest-runners.ts:153` never passes it and no policy key exists. `DEFAULT_BATCH_SIZE` (`run.ts:61`) is the only value. Open question 5 could be measured only with a patched bundle.
6. **Python worktrees are told "No dependencies are installed".** Core delivery, `src/core/delivery/attribution.ts:141`. `dependenciesInstalled` looks only for Node's installed lockfiles, so a pytest-only repository with synced environments gets "No dependencies are installed in this worktree; failures that cannot find a package are expected until an install." beside every reported failure. Both sessions' start texts carried it next to the 2 known failures (`logs/sessions/*squeal*`). Fix direction: count an admitted pytest environment as installed, or omit the sentence when no Node project is configured.
7. **pytest's per-run temporary directory makes failure fingerprints differ between runs of the same failure.** Adapter. The failure text holds `/tmp/squeal-1002/tmp/<id>/pytest-of-squeal-e2e/pytest-76/test_distribution_path0/…`, and `pytest-76` changes each run. So the new-failure re-run in `wt-claude` recorded `fail-changed` (failed differently) for an unchanged failure: `store.py wt-claude transitions`, revision 1, 1792004618.4. During a session that is a spurious delivery. Fix direction: give each batch a fixed `--basetemp` under the run's log directory, or normalise `pytest-<n>` before fingerprinting.
8. **An environment that gains pytest after its `pyvenv.cfg` is admitted only by the interval recheck, here 49.8 s late, and `run --all --wait` meanwhile ends without a verdict that names it.** Adapter, D2. `debugger` was refused mid-install at 19:03:00.15, its install ended at 19:03:00.69, and it was admitted at 19:03:50.49. The tier holding its 4 files ended `crashed` although 196 root files in it completed. The checkpoint was abandoned, and `run --all --wait` exited 3 with "a newer request replaced it, a tier crashed or timed out, or the daemon stopped", which does not name the environment. Repro: `wtsync.sh <new worktree> … early`.
9. **The no-environment note names `uv sync`, which fails on this project.** Adapter, D2's note. With no lockfile present it says "run `uv sync` in the worktree root". `uv sync` cannot lock briefcase (its `docs` group needs Python 3.12 or later against `requires-python` 3.11 or later), and the project's documented route is `pip install -e . --group dev`. D2 says the command is "chosen from the lockfile present". Without a lockfile, the note could name the project's own route or say "create `.venv`".
10. **`squeal setup --yes` tells the user twice to trust the Codex hooks by hand in the TUI, then trusts them itself.** CLI text. `logs/setup-setup.txt`: "squeal init: kept squeal.config.json / Then trust its hooks once: open the Codex TUI, run /hooks…" appears twice before "Codex wrote the trust… trusted" ×10.
11. **Resolved environment notes stay in status as if current.** Core notes. After "its Python environment is ready", `squeal status` and the `status --wait` output the Claude agent read still listed "no Python environment … run `uv sync` … Its checks stay unknown until then" for both projects. They are timestamped, but nothing marks them resolved.
12. **The skill's trigger names only Vitest and `npm test`.** Harness text, `plugins/*/skills/squeal/SKILL.md:3`: "Use when about to run tests (vitest, npm test)". An agent about to run `pytest` does not match it. The body names pytest projects correctly. Codex loaded it anyway, because the primer names it.
13. **`squeal_pytest` never closes its events file, so every batch's stderr ends with a `ResourceWarning`.** Runtime, `src/runners/pytest/runtime/squeal_pytest.py:40` (module-level `open`). This was in 40 of 40 batches of run `9a70c6b3`: "Exception ignored … ResourceWarning: unclosed file …/events-N.jsonl". Harmless at exit, but it is noise in every stderr log, and in a project that turns warnings into errors (briefcase's `filterwarnings = error`) it reads like a failure.

Not defects, for the record: the first edit in `repo/` after the sessions re-ran 402 files once, because other worktrees' runs had grown the shared observed paths (probe A, 007-14's documented spare run). The revert and a second edit ran 2 files. A new `changes/*.md` file runs nothing (probe B). Squeal's daemon exits 3 s after its last session (001-122), here leaving 2 files queued.

The case root `/home/squeal-e2e/runs/sq07-18` (clones, environments, the store) and its processes were removed after the measurements. The commands above rebuild it.
