### 001-352: the complete marker is published without weakening the assertion

At `test/daemon/slow-lane.test.ts:22-24`, `writeFileSync(started.tmp, value)` completes before synchronous `renameSync(started.tmp, started)`. Both paths are siblings in the unique temporary directory. The reader at lines 58-59 still waits only for existence and asserts `/^[^:]+:slow:vitest$/`. A missing or incorrect daemon-child mark therefore fails rather than being hidden by an existence-only assertion or a nonempty-content wait. The fast failure must arrive before `priority` exists; the slow result must then pass and its priority must be exactly 10. The changed publication does not remove any of those checks.

Same-filesystem rename publishes the directory entry atomically on Linux and macOS. The old temporary name is not polled. Neither an empty intermediate destination nor a cross-device copy is introduced: the only write finishes and closes before the name becomes visible. This follows the POSIX rename contract and both platforms' documented rename semantics:

- [POSIX rename](https://pubs.opengroup.org/onlinepubs/9799919799/functions/rename.html): the operation is atomic; replacement entries remain visible throughout.
- [Linux rename(2)](https://man7.org/linux/man-pages/man2/rename.2.html): a destination is atomically replaced.
- [Apple rename(2)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/rename.2.html): both paths must reside on the same filesystem, and replacement preserves an instance of the destination.

Runtime evidence here is Linux only. No macOS execution is claimed. This is a publication guarantee for concurrent readers, not an fsync durability claim.

The cause note's product-path account agrees with the current code: `daemon.ts:346-352,377-381` supplies the slow lane's child environment, `escaped.ts:78-79` creates the nonempty token and lane mark, and `adapter.ts:142-157` passes that environment to Vitest. Historical external probe counts (2/569 and 0/1283) cannot be independently recovered from the note's uncommitted scratch probe; those counts are unverified here. The code and five loaded runs support the repair without treating those historical counts as this review's experiment.
