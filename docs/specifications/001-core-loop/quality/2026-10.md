## Drop candidates

### X1. `runner.maxConcurrentRuns`

Fails vision principle 8, "Resource limits, allowed commands, timeouts, concurrency [...] are all visible and enforceable", and decision filter 5, "Can project policy govern it?". The key is visible but not enforced. It is typed (`src/core/types/policy.ts:45`), defaulted (`policy.ts:89`), validated (`src/core/daemon/policy.ts:77`), documented as "Runs at a time." (`plugins/claude-code/skills/squeal/SKILL.md:91`), and written into every new config by `squeal init` (`src/cli/init.ts:107`, which writes `DEFAULT_POLICY` whole). No code reads it: `grep maxConcurrentRuns src` finds only those three lines. A project that sets it to 4 gets 1 run at a time and no note. Drop the key, its validator, the skill row, the D11 mention and the two test lines (`test/types.test.ts:12`, `test/daemon/policy.test.ts:56`). A config that `init` already wrote then reports one unknown key; v1 is unreleased (`package.json` `private`, `0.0.0`), so that is acceptable.

### X2. `Scheduler.status()` beyond `revision`

Fails decision filter 6, "push transitions, pull state", where pulled state is the store (D7): no agent, hook or CLI reads these counters. `SchedulerStatus` (`src/core/types/scheduler.ts:11-45`) says it is "for the daemon log and tests", and D12 says the daemon has no log. In production only `.revision` is read (`src/core/daemon/daemon.ts:328`). Its test-file and check counts (`src/core/scheduler/status.ts:6-15`) classify through `src/core/scheduler/files.ts:83`, which puts `pending` before `current`. `src/core/state/derive.ts:49`, which calls itself "the one validity rule of a check", keeps a current result current during a forced re-run. So during `run --all --force` the two counts disagree. The cost of the drop is 17 assertions in 7 test files (`test/scheduler/*`, `test/runners/vitest/broken.test.ts`), which would read the store (`readStatus`, the `runs` table) instead. Keep a `revision()` accessor and the `files.ts` rule that `tiers.ts:225` uses to pick work. Row 001-67 removes the `notes` field on its own, so it does not wait on this decision.
