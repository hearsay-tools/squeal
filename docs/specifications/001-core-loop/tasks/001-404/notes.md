# 001-404 notes: a known failure says how old it is

- **Store.** Nothing new. The load per CPU was already kept per failing run in `meta` `failed-run-loads` (`src/core/retry/load.ts`, newest 1,024 runs, written by `recordFailedLoad` at the tier's start load). `withRecorded` joins it on the stored row's `provenance.runId`. The age is the row's `provenance.recordedAt`, now carried as `RecordedFacts.recordedAt?` (additive, optional).
- **Text.** `recordedText(facts, here, now)` now reads "recorded 3 h ago in this worktree at revision 12, load 3.33 per CPU when it ran; no retry asked at these inputs". `agoText` gives "just now" under a minute, then "N min ago" up to 119, "N h ago" up to 47, then "N d ago". The verdict stays the stored one.
- **Registration.** `formatRegistration(registration, max, command, now = Date.now())`. The harness callers (`primer.ts`, `stop.ts`, Pi and OpenCode) keep the default, since they format right after registering.
- **Status.** `snapshot` now runs `withRecorded` over its known failures, so `StatusSnapshot.knownFailures[].recorded` is filled in status JSON too (additive). `formatStatus` prints the recorded line under each FAIL's location line.
- **Tests.** `test/delivery/format.test.ts` covers registration, 2 h old with load and fresh "just now" with load not recorded. `test/status/failure-age.test.ts` covers status, 3 h old with the load joined from `failed-run-loads`, and fresh. `test/scheduler/retry-delivery.test.ts` adds an `agoText` table and `recordedText` with an age, and its end-to-end registration expectations now read "Recorded just now in this worktree …".
- **Not done.** Delta headers after registration carry only the "Known failures: N" count, with no failure lines, so nothing there was dated. W3 (001-411) can take the load range from these same facts.
