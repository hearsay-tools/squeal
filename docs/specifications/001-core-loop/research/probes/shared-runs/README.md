# shared-runs probes (THROWAWAY)

Throwaway experiments for row 001-201, written up in `../../shared-runs.md`. Not product code. Do not import from here. All of them ran under `/tmp/sr201`, outside every repository.

- `query.cjs <db> <sql>...`: read-only queries against a store, with timings. Used on the copy of cezar's store (`VACUUM INTO` from a read-only connection) and on the probe clone's store.
- `claim-cost.mjs <copy>`: on a copy of cezar's store, the time to check 651 keys and to write and release 200 and 4 claims. It compares three storage options: a claim derived from `test_file_keys` `running` rows joined to a fresh heartbeat, a `meta` row per key, and a `claims` table. Each runs idle, then beside three writer processes holding `BEGIN IMMEDIATE` transactions like a tier commit. Output: `claim-cost.out`.
- `claim-race.mjs`: four processes take 600 keys, 10 per tier, in the same order. One mode checks and claims in one `BEGIN IMMEDIATE`; the other checks first and claims in a later transaction. It counts keys taken twice. Output: `claim-race.out`, three rounds.
- `prototype.patch`: the claim prototype, against Squeal `8ca16a14`, active only with `SQUEAL_PROBE_CLAIMS=1`. `selectTier` runs in one write transaction. After a lookup miss, it skips a file that is not forced, not recent, may inherit, and whose key another worktree with a fresh heartbeat holds `running`. While any file is skipped, the pump looks again every second.
- `cezar-subset.diff`: the probe commit on the cezar clone (`c07b0bfc` + `933dd908`). It drops the `packages/cezar` project (418 files, about 6,200 s of summed file time in the live store) and sets `maxWorkers: 2`, which bounds host load. That leaves 243 test files: web, contract and api-client.
- `four.mjs <squeal cli> <arm> <backlogTierSize|-> <roots>...`: deletes the clone's store and starts `squeal daemon` in four worktrees at once. Each daemon gets only `HOME`, `PATH`, `USER` and `LANG` in its environment and runs under `/usr/bin/time` and `nice -n 5`. Every 2 s it polls the store read-only, until every worktree's baseline checkpoint has ended with nothing pending. It then sends SIGTERM to each daemon, `time`'s direct child (SIGKILL to the whole tree after 60 s). It prints runs, files run, outcomes, and CPU per daemon (its Vitest workers included, since `time` counts the children the daemon reaped), and keeps a `VACUUM INTO` copy of the store outside the repository. `arms.sh` runs the arms `today` (base build), `proto` and `proto64` (prototype with `runner.backlogTierSize` 64) in sequence. Each arm starts only once the 1-minute load is under 30. Outputs: `four-<arm>.out`. `four-today-run1.out` is an earlier today arm at load 140. Its wall time is valid, but its CPU was lost: that driver signalled `time`, not the daemon, and the orphaned daemons were then killed by PID.
