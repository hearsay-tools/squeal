# Cursor runs the Claude Code plugin's hooks without their `args`

Question (the human, 2026-10-20): a Cursor session of Cezar task toolkit-dev `3ce877c6` had every Edit of two Markdown files blocked with `Hook blocked with message: sh: 1: Syntax error: end of file unexpected`, three retries in a row. Is that Cursor, the model, or Squeal? Squeal 0.1.228 from the `hearsay` marketplace, Cursor CLI `2026.10.16-e3cb207` in print mode. toolkit-dev has no `squeal.config.json` and no store. Evidence is in `probes/cursor-dropped-args/`. The task and its logs were deleted after they were read; the log lines are kept in `cursor-hook-log.txt`.

## Findings

1. **Cursor loads the installed Claude Code plugins.** Each session imports `~/.claude/plugins/marketplaces` and runs the hooks of every enabled Claude Code plugin, Squeal's included (`hookSource: "claude-plugin"`, `plugin: "squeal"`, `marketplace: "hearsay"`). It skips a plugin that the user's or the project's `.claude/settings.json` or `settings.local.json` sets to `false` in `enabledPlugins`. Claude Code reads the same key, so that switch turns Squeal off in Claude Code too. *Read in source code; the log lines are in `cursor-hook-log.txt`.*
2. **It keeps `command` and drops `args`.** The converter for a Claude Code hook entry builds `{type, command, timeout, matcher}` and never reads `args`. Both installed builds have the same converter, `2026.10.16-e3cb207` and `2026.10.01-e373342`. It maps `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `SessionStart`, `SessionEnd` and `PreCompact`, but not `PostToolBatch` or `SubagentStart`. *Read in source code (`cursor-source.txt`).*
3. **The payload is the command's stdin.** Cursor runs `command` through its shell executor, with `CLAUDE_PLUGIN_ROOT` and `CURSOR_PLUGIN_ROOT` set in the environment. The JSON payload goes to the command's stdin, either written directly (`transportMode: "stdin"`, every Squeal line in the log) or as `<command> <<'CURSOR_HOOK_EOF'`. Exit 2 blocks the tool, with stderr as the message, and Cursor adds "Agent note: Do not suggest workarounds to the blocked tool." Any other non-zero exit lets the tool run. *Read in source code; the transport and the note are also in the session's log.*
4. **So Squeal's PreToolUse is a bare `sh` that runs the payload.** CC1's fast path is `command: "sh"` with the script in `args`. Without `args`, `sh` reads the payload as its script: one line of compact JSON, whose strings `sh` reads as double-quoted words. If that line does not parse, nothing runs and `sh` exits 2, so Cursor blocks the tool. The blocked Edits' payloads carried the edited file's text, and one span in it was `` `<owner>/<repo>` ``. Inside double quotes that is a command substitution made of redirections, whose last `>` has no target. `sh -n` on a payload with that span prints the session's exact message and exits 2 (`redirect-span.json`). An odd backtick gives `EOF in backquote substitution` instead. Retrying cannot clear it. *Verified by experiment (`output.txt`, dash).*
5. **A payload that parses runs its substitutions.** `sh` runs every `$(...)` and backtick span in the payload's strings, then tries to run the JSON as a command name and exits 127, which Cursor counts as a failed hook and lets the tool run. *Verified by experiment (`substitution.json`).* Every Squeal `preToolUse` in the logs exited 127 or 2, so each one was the payload run as a script. The other Cursor task of that day, `f358836d`, logged 52 exit-127 runs, and its Bash calls included `$(pwd)` and `$(gh project item-add 3 ...)`. Each of those most likely ran once in the hook, before Cursor's own permission check, and once more as the tool. *Inferred from the exit codes and the tool inputs.*
6. **The Node hooks fail without running anything.** A bare `node` reads the payload as a program, and a JSON object is never a valid one, so it exits 1 with a SyntaxError (`session-end.json`; `sessionStart` and `sessionEnd` exit 1 in the logs). *Verified by experiment.*
7. **Squeal does nothing under Cursor.** CC1 promises that an enabled plugin exits 0 silently in a repository without Squeal, but that check lives in the dropped `args`, so it never runs under Cursor. *Follows from 2 to 6.*
8. **Codex dropped `args` too.** `../../002-codex-adapter/research/wave-0-checks.md` found that Codex drops `args` when the Claude Code plugin is installed into it, and listed `"command": "sh"`, but it only weighed a bare `node`. Codex now installs its own plugin through `.agents/plugins/marketplace.json`, so the hazard is any harness that imports Claude Code plugins. *Read in this repository.*
9. **The exec form is load-bearing in Claude Code.** With `args`, Claude Code spawns `command` directly. The fast path ends in `exec "$@"`, so the hook's Node process has `claude` as its parent. A shell-form string leaves a `sh` between them under dash (`../../001-core-loop/research/harness-process-liveness.md`). Claude Code expands `${CLAUDE_PLUGIN_ROOT}` in an exec-form `command` too (`../../001-core-loop/research/claude-code-integration.md`, probe `plugin`). *Read in this repository.*
10. **The model was not at fault.** The model in `3ce877c6` traced the block to the dropped `args` and the payload on `sh`'s stdin. It stopped, as Cursor's note asks, and retried only when the human chose to. Two of its side claims were wrong. It blamed a recent cezarion change, but finding 2 puts the converter in both builds. It set the older build apart for having no stdin transport, but finding 3 shows the heredoc gives `sh` the same stdin. *Read in the session's transcript.*

## What this asks of the plugin

Every entry's `command`, run on its own with a payload on stdin, must run nothing and exit 0 without output. A lead: name an executable file of the plugin as `command`, kept outside `bin/` (which is on the Bash tool's path), that exits 0 when it gets no arguments. With its arguments it runs today's fast path and `exec`s Node. Two alternatives are out. A shell-form string loses finding 9 and would run Squeal's hooks on Cursor payloads they were never built for. Setting `enabledPlugins` to `false` also turns Squeal off in Claude Code (the human, 2026-10-20). A Cursor adapter of its own would be a new spec.
