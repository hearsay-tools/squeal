## Blockers

### B1. Proven, unresolved: a whitespace prefix executable runs, reads stdin, and can exit 2

Locations: `plugins/claude-code/hooks/hooks.json:9` (all 12 entries), `test/harness/dropped-args.test.ts:98`, `docs/specifications/012-claude-code-adapter/spec.md:31`.

Amended CC1 accepts exit 127 and a shell "not found" line for whitespace roots but still requires: "It still runs nothing and reads nothing, and it never exits 2." The repair's test says "The first word names no file" and constructs only that case. That condition is not guaranteed by a plugin install path.

Concrete reproduction: copy the executable launcher to `<scratch>/plugin with spaces/hooks/run`. Place a harmless executable at `<scratch>/plugin` containing:

```sh
#!/bin/sh
IFS= read -r payload
printf '%s\n' "$payload" > '<scratch>/stdin-read'
exit 2
```

Set `CLAUDE_PLUGIN_ROOT` to `<scratch>/plugin with spaces`. Run every manifest command unchanged through both `sh -c <command>` with a payload on stdin and `<command> <<'CURSOR_HOOK_EOF'` with that payload. The shell splits the expansion into `<scratch>/plugin`, `with`, and `spaces/hooks/run`, and executes the existing prefix. The intended launcher's early no-argument guard never runs.

Independent probe at the pinned candidate, using the manifest's actual 12 commands:

```text
prefix executable absent:
  stdin:   12/12 exit 127; stdout empty; stderr "sh: 1: <scratch>/plugin: not found\n"; no stdin-read
  heredoc: 12/12 exit 127; stdout empty; same stderr; no stdin-read
prefix executable present:
  stdin:   12/12 exit 2; stdout/stderr empty; stdin-read contains the exact payload
  heredoc: 12/12 exit 2; stdout/stderr empty; stdin-read contains the exact payload
payload: {"tool_input":{"content":"safe probe"}}
```

This is the same B1 path-interpretation boundary, not an unrelated new finding. It disproves the repair's remaining safety guarantees, including the exit code Cursor uses to block a tool (`research/cursor-dropped-args.md`, finding 3). No payload substitution or malicious program was needed. Scratch files were removed; product code was untouched.

Fix scope: one launcher/manifest-boundary repair with a regression that adds an executable at the whitespace prefix and checks that it never starts, consumes no stdin, and cannot choose the hook's exit status. Keep the existing no-prefix case and both transports. If the direct-exec and shell interpretations cannot meet that rule together, the coordinator must return the exact unsupported-path behavior and this counterexample to the human under `docs/process.md` step 6, since this is a second FAIL. A further amendment must acknowledge execution of an unrelated prefix, not describe all such roots as harmless exit 127.
