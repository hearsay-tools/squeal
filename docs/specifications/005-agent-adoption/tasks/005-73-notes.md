# 005-73 notes: the seam map of the version copies

Worker notes, 2026-10-21. Brief `005-73.md`; spec 005 D3 as amended 2026-10-21; `research/plugin-cache-cleanup.md`.

## Where the copies enter

- `src/harness/shared/version-copies.ts`: `keepVersion` copies `<PLUGIN_ROOT>/dist` and `skills` once into `<PLUGIN_DATA>/versions/<version>/` (a temporary `.<version>.<pid>.tmp`, then one rename), writes `<PLUGIN_DATA>/bin/squeal` from `<PLUGIN_ROOT>/bin/squeal-launcher` (when missing, or when this version is the newest copy and the text differs), and prunes only after it made a copy: the newest other copy and every copy whose path `ps -A -o args=` shows stay. When `ps` fails, no copy is removed (`install.sh` `in_use` removes then; this keeps instead).
- `src/harness/codex/kept.ts`: `keepCodexVersion` (SessionStart, only where `usesSqueal`) swaps `deps.cli` to the copy's CLI, so the daemon `ensure` spawns runs from the copy; `observeRecorder` and `nodeTestRuntime` then resolve beside it with no change in `src/runners/`. `keptCodexCli` gives every other hook's `main.ts` the same CLI once the copy exists. `skillLine` is the line before the primer.
- `src/harness/codex/command.ts`: `codexCommand` names `<data>/bin/squeal` when it exists; `data` is `PLUGIN_DATA` in a hook, or derived from a CLI that runs from a copy (`dataOfCopy`), which is how `statusCommand` in a Codex shell names the launcher.
- `src/harness/codex/output.ts`: `capContext(text, command, keep)` keeps `keep` whole with the trailing primer. A text that is the primer alone (`compact`) gets `keep` before it.
- The launcher (all four plugin copies, one file): `node -e '...' "$0"`; copies are `<dirname $0>/../versions/*`, so only `<PLUGIN_DATA>/bin/squeal` sees any. No format bump: `~/.local/bin/squeal` has no `versions/` beside it.

## What stays as before

- The first hook of a new install, a hook without `PLUGIN_ROOT` or `PLUGIN_DATA` (a launcher's `thread/start` hooks), and a data directory that cannot hold a copy all run from the cache and name it.
- `hooks.json` is unchanged, so no trust grant changes.
- Another Codex process's hooks still name the deleted cache until it restarts (option 3 not taken).
