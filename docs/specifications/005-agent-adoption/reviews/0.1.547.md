### B1. A second session changes the reported start time and hears the slow notice twice

**Proven, blocking.** Changed boundary: `src/core/delivery/delivery.ts:588`
through `:605`, especially `:597`. The now-correct row-less presence read brings
an observed `startingSince`, `startMark: "start"` and `startSlow` into the old
registration overlay. `withToldStart` (`src/core/presence/views.ts:120`) replaces
that observed time with this session's synthetic start time while retaining
`startSlow`. Then `tellAtRegistration` (`delivery.ts:640` to `:642`) stores only
that synthetic `{ startingSince }`, discarding the slow note the header just said.
These old helpers are implicated by the newly changed call boundary, not findings
against unrelated pre-existing code.

Contract, wave 22 W2: "one message says the daemon is still starting and since
when"; "The message while it starts repeats nothing". Vision principle 2 also
requires recorded facts to retain their provenance.

Reproduction on the clean candidate, using the production `runHook` and the
held-start fixture from `test/harness/starting-no-row.test.ts`:

1. Start session A at `T = 2026-11-18T09:00:00.000Z`, with no worktree row.
   Hold and mark the daemon lock at T. A's boundary at T+85 s says the slow start
   once, with T as its time.
2. Start session B at T+90 s in the same worktree. Give it a different
   `session_id`. Its ensure must not spawn: the marked start is current.
3. Call B's tool boundary at T+101 s. Keep the same lock and process throughout.

Actual output, primer omitted:

```text
B registration:
SQUEAL · registered at revision 0
Revision 0: A daemon has been starting since 2026-11-18T09:01:30.000Z, and Squeal has no results in this worktree yet.

B tool boundary, 11 seconds later:
SQUEAL · a daemon is still starting at revision 0
Revision 0: A daemon has been starting since 2026-11-18T09:00:00.000Z, and Squeal has no results in this worktree yet.
```

The first time is wrong by 90 s. The second report repeats a condition B's
registration already reported. No daemon restart or liveness change occurred.

A small regression can be appended to the existing held-start test file:

```ts
const { r, batch, lockFile } = await newWorktree();
holdStart(lockFile);
await batch(85_000);
let clock = T + 90_000;
const deps: HookDeps = {
  env: {}, now: () => clock,
  ensureDaemon: async () => { throw new Error("must not spawn"); },
};
const input = (name: string) => recorded(name, r.root, { session_id: "second-session" });
const start = text(await runHook("session-start", input("session-start"), deps));
expect(start).toContain(new Date(T).toISOString());
clock = T + 101_000;
expect(text(await runHook("post-tool-batch", input("post-tool-batch"), deps))).toBe("");
```

**One-worker fix:** preserve an observed marked start's time when applying the
registration's grace fallback. Record that the registration already said the
slow-start note. Preserve the grace fallback for a spawn with no observed start.
Do not introduce another clock or another source of presence facts. Add the case
above and the matching re-registration case, plus death and successful-registration
checks so the retained note cannot hide either change. Keep row 005-106's seed
and mark unchanged. This is one repair of the registration/presence seam.

### What fits

- The row-less common-dir option reaches registration, live headers and both
  liveness-change reads. Status finds the same lock through `resolveCommonDir`.
- A current marked start suppresses additional spawns. A dead spawn loses its
  grace, a dead process's stale mark is ignored, and the next hook can start a
  daemon. Linux checks both PID and process start time; a reused PID cannot keep
  the old start current.
- Stop says no action is needed while the start is current. Status says a daemon
  holds the lock and is starting or stopping. Neither names `squeal start`.
- The fixed 60 s is explicitly permitted: six times the 10 s grace. It is a
  notification threshold, not a deadline that kills a start or declares it dead.
  A machine-derived threshold is not needed for this contract.
- SIGSTOP before registration remains a start while the process lives, then gets
  the slow notice. This is acceptable under W2's explicit process-lifetime rule:
  it claims no validation and status says the process does not serve. A registered
  SIGSTOPped daemon remains a late heartbeat, covered by the existing new test.
  Detecting Linux state T would be a separate policy change, not a blocker here.
- The row-less lock read adds no socket wait or lock acquisition. The measured
  guard read is much smaller than the hook budget; this is host evidence, not a
  universal latency guarantee.
- `evals/lib/squeal-text.mjs` recognizes both new sentences as no daemon validating.
  The held-start test checks that parser. The existing `test/e2e/agree.ts` matcher
  is used at settled points or the registered-daemon death case; it does not
  parse this slow-start case. Skill step 5 in every copy already says to wait
  while starting. No changed literal in a skill needs replacement.
