### B1: proven, a prior quiet rest hides the stopped-start notice

Location: `src/core/presence/views.ts:68` and `:73`, followed by the quiet-rest
return at `:76`. Test gap: `test/harness/starting-stopped.test.ts:48` starts
with no prior daemon rest.

W1 requires: “A stopped starting process: one message, at the first boundary
that sees it stopped, not repeated while the state holds.” It also requires
the hook and status to agree.

Failure scenario:

1. A daemon stops unused. Its record is cleared, its last heartbeat remains,
   and `markRest` leaves a quiet rest with no `spawnedAt`.
2. An external start takes the lock and writes the start mark, then stops
   before registration. It did not pass through a hook's spawn path.
3. An existing session reaches PostToolBatch after its told-start grace.
   The hook sees the locked start and spawns no second daemon.
4. `withStartState` correctly sets `startStopped`. `newsChange` admits that
   new state at line 73, then discards it at line 76 because the old rest
   remains quiet. The hook says nothing. Status reports the stopped start.

The old rest cannot become overdue on this path: the start-current early
return in `src/harness/shared/ensure.ts:60` precedes `spawnedAfterRest` at
`:72`. Thus later boundaries can remain silent too. This finding concerns
the new stopped-start promise, not the older slow-start behavior.
