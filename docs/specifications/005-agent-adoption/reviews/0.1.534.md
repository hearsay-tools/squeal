## Blockers

### B1. Proven: Stop and owed full counts consume an own count they do not show

Locations: `src/core/delivery/edits.ts:124`, `:132`; `src/core/delivery/delivery.ts:342`, `:351`; `src/core/delivery/header.ts:177`. Rendering boundary: `src/harness/shared/stop.ts:327`.

Contract, wave 16 review brief: “`since` moves only when a delivered header shows the own count with no file owed.” W1 also says to keep the registration and Stop full header unchanged.

`editNotes.tell()` advances `since` and prunes resolved re-key entries whenever `own.owed === 0`. `deliver()` calls it before it pays `countsOwed`, and regardless of the caller's full header. Stop renders `formatDelta(..., "full")`, which shows worktree counts rather than `ownEdits`. The one owed-count delivery also replaces the own count with full counts. Both therefore erase the window without showing the count that permits that reset.

Proof sequence: register with passing A and B; edit A; deliver its first-edit line while A is owed; finish A; fail B at its unchanged key; deliver B at Stop. Then change B's failure message and deliver at a normal boundary. Actual output:

```text
Stop ownEdits: {files:1, owed:0}
Stop header: Revision 1 (changed src/a.ts): 2 current (2 tests), 0 pending, 0 stale, 0 unknown. Full-suite checkpoint: none completed at any revision (the counts are for revision 1; `squeal run --all` requests one).
After Stop: edits state {since:1, said:true}; re-key record []
Next boundary ownEdits: absent
Next header: Revision 1 (changed src/a.ts).
```

No delivered header said A had run. The same proof with a consumer's owed-count slot set, as registration before listing does, gives:

```text
Owed-count ownEdits: {files:1, owed:0}
Owed-count header: Revision 1 (changed src/a.ts): 2 current (2 tests), 0 pending, 0 stale, 0 unknown.
After owed counts: edits state {since:1, said:true}; re-key record []
Next boundary ownEdits: absent
Next header: Revision 1 (changed src/a.ts).
```

Fix scope: one delivery worker repairs the acknowledgment of the own count in `edits.ts` and `delivery.ts`, with public-delivery tests. Advance and prune only when the delivery will show that count. Preserve the full Stop header and the owed full-count exception. Recording the first-edit line as said must remain independent of acknowledging the count. Prove both sequences retain `since` until later news actually shows the own count, then reset once. Do not add a delivery solely to announce completion.

### B2. Proven: a regression deny's news header omits the own count while a file is owed

Locations: `src/core/delivery/delivery.ts:323`, `:380`; caller: `src/harness/shared/deny.ts:58`.

Contract, W1: “a change delivery's header counts the agent's own test files.” The review brief explicitly includes `peek` among the delivery paths to judge. `reports.md:15` in each changed skill copy promises the count in every other SQUEAL message after registration and Stop, with the listed owed-count exception.

`peek` calls `deliver` without `liveness` or `idle`. The retained notes guard therefore returns no notes on this path. The candidate obtains `ownEdits` only from those notes. A real deny uses this delta with the news formatter, so a consumer with an outstanding edit gets the same count-free line as a consumer with no edit.

Proof sequence: register; edit A; deliver the first-edit line; keep A owed; fail B at its unchanged key; call `peek(C, {kinds:["pass-to-fail"]})`. Actual output:

```text
peek ownEdits: absent
peek header: Revision 1 (changed src/a.ts).
edits state: {since:0, said:true}
re-key record for A: {open:1, last:1}
```

Expected header: `Revision 1 (changed src/a.ts): the 1 test file your edits affect has not run.` The denied edit in the same call remains outside the count; A is an earlier, recorded edit. This is an omitted count, not a proven false pass. After A finishes, the next ordinary news correctly shows its count and resets; `peek` itself was missed.

Fix scope: the same delivery worker can repair this with B1. Read the own count for a delivered peek without granting it unrelated liveness, code, lint or first-edit-only news. Use the same display/acknowledgment rule as the normal boundary. Add regressions for owed A, completed A and no prior edit through the public peek or deny interface. Keep its restricted transition selection.
