## Blockers

### B1: proven, another group's change repeats an unchanged group's line

Location: `src/core/delivery/slow-told.ts:79` and `:85`, connected to `src/core/delivery/header.ts:222`.

Contract: wave 14 part 4 says, “A news delivery carries a group's line the first time for a consumer, then only when the group's state changes kind”. The review brief repeats “first time and on a change of kind only”.

The new stored value records kinds, but `groupTiersChanged` still returns one boolean for the entire array. When any group changes kind, the news formatter emits every non-current group's line. A group that stayed waiting repeats because another group finished. The same array-wide flag also selects every non-current group for the new title helper.

Reproduction through `createDelivery`, a real store, `createStateSink` and `formatDelta`:

1. Configure two manual groups, `browser` and `integration`, with one test file each, plus a unit test file outside those groups. Give all three current passing results and register a consumer.
2. Re-key and queue both group files. Fail the unit test to produce a delivery. It prints both group lines, each with kind `waiting`.
3. Complete only the integration file and recover the unit test to produce the next delivery. Leave the browser file and its key unchanged.

Observed second delivery:

```text
SQUEAL · 1 check changed (1 test) at revision 3
Revision 3: 1 pending (1 test).
browser: 1 test file; 1 pending, waiting for `squeal run browser`. Squeal runs them only on request; `squeal run browser --wait 60000` runs it now and waits for its result.

PASS  unit.test.ts > test
      FAIL -> PASS
```

The probe printed `BROWSER KIND UNCHANGED, LINE REPEATED: true`. `browser` stayed `waiting`; only `integration` changed to `current`. The single-group tests cannot discriminate this case. This is incomplete implementation of the row's per-group rule.

Worker-sized fix: compare and carry changed group names, then filter group lines and their title words by those names in news form. Read the previous kinds before acknowledging the delivery, within the existing transaction. Keep the full registration/Stop headers and the slow-tier rule unchanged. An old counts-based stored value must select each group once, then converge to the new representation. Add a two-group regression in which one group's kind changes while the other's kind and counts do not. Also keep the same-kind count-movement test.

### B2: proven, summary-only code deliveries still have a bare revision title
