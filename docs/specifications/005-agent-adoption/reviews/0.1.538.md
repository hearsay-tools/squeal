## Blocker

### B1. Proven: re-registration delivers a new failure without ending an open late state

Locations: `src/core/delivery/late.ts:70`; `src/core/delivery/edits.ts:255`; integration gap at `src/core/delivery/delivery.ts:554` and `:594`. Production caller: `src/harness/shared/session.ts:65`.

Contract: the candidate-review brief requires caught-up **“never after a failure delivered during the delay, on any path”**, and explicitly includes registration in the path audit. Design section 4 says: **“A failure during the delay is a failure report, and it ends the late state: no caught-up follows it.”** The three changed skill copies promise the same behavior.

The new lifecycle closes late through `tellEdits` for delta deliveries. `registerNow` is a separate reporting path. For a consumer still registered, it preserves the edit and late slots, overwrites its views with the current states, and returns all known failures. It never closes late for a failure it has just reported. This is reachable through a session start with source `resume`: `startSession` keeps this consumer, calls `delivery.register`, and formats the registration. The `compact` shortcut does not protect the resume path.

Independent proof: `pnpm exec tsx /tmp/squeal-review-538/proof.ts`, exit 0. It used private scratch stores, the real state sink, re-key record, delivery API and formatters. The setup copied the existing test helpers to `/tmp`, replaced only their Vitest cleanup/assertion dependencies, and kept their production imports. No product method was replaced.

1. Register C with passing A and B.
2. Edit A, deliver its first-edit line, and advance the injected clock 61 s. Deliver one late notice while A is owed.
3. Fail B at its unchanged key. Call `delivery.register(C, {atStart:true})`, as the resume path does. Its `knownFailures` contains B; the real `formatRegistration` prints B as FAIL. The late slot remains open.
4. Finish A successfully. The next ordinary boundary emits caught-up:

```text
RE-REGISTRATION: {"knownFailures":1,"lateOpen":true}
AFTER RE-REGISTRATION: SQUEAL · caught up at revision 1
Revision 1 (changed src/a.ts): the 1 test file your edits affect has run.
The 1 test file your edits affect has run at revision 1, with no new failure.
```

The new failure was already delivered in step 3, after the late notice. Step 4 therefore violates the stated suppression rule. The new registration view also consumes the transition, so the normal delta path cannot close this state later. This is an integration defect of the added late lifecycle, not a request to change registration's existing full header.

**One-worker fix:** include a still-registered consumer's registration in the late-state failure acknowledgment. Determine whether registration reports a newly observed failure before replacing the prior view, and close the late slot in that same reporting transaction. Preserve the own-count start: a full registration header does not show the own count. Do not suppress caught-up merely because an unchanged failure was already known before the late notice.

Add a public-delivery regression using `late-fixture.ts`: `late(); failB(); register(C1, {atStart:true}); finishA(); boundary()`. Require the registration to retain B and require no subsequent caught-up. Include controls for re-registration without a new failure and with an unchanged, already-known failure; both must retain the successful-completion notice. Keep first registration, leaving, expiry and the prepared-report handoff behavior intact. No scheduler, store, bound or count-format change is needed.
