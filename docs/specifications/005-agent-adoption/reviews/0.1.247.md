Location: `plugins/codex/bin/squeal-launcher:92`, also present in the three identical launcher copies.

The notice uses `newest.version` from installed harnesses before line 95 chooses between that version and the newer kept copy. During Codex cache replacement, a kept copy can be newer than every remaining install. A throwaway probe used this layout:

```text

Codex cache: absent
<data>/versions/0.1.3/dist/cli/squeal.mjs: prints 0.1.3
<data>/bin/squeal: candidate launcher
```

Running that launcher with `--version` returned exit 0 and:

```text
stdout: 0.1.3
stderr: squeal: Claude Code has squeal 0.1.1 and Pi has 0.1.2; running 0.1.2. Run squeal update to bring them to one version.
```

The installed-version facts are correct; the running-version claim is false. This conflicts with the vision's preference for trustworthy state. It does not stop the newest CLI from running or break the copy, skill, and recorder survival that row 005-73 requires, so it is non-blocking.

One-worker fix: choose `run` before formatting the notice and use `run.version` in it. Keep the harness list and update advice. Change all four launcher copies together and add a launcher test with a newer kept copy plus two different older installed versions. The test must compare the notice with the CLI that actually ran.
