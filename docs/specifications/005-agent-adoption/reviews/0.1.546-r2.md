## B1: closed. Pi remembers the registration its host received

`src/harness/pi/handed.ts:43` keeps the consumer key and `registeredAt` in worker memory. Each request collects registration clears. `src/harness/pi/worker.ts:105` keeps them only at the host's commit verdict; an abandoned verdict adds nothing. The legacy no-slot path keeps them after posting its answer.

Before a later start, run or tool boundary reads the owed mark, `entered` checks whether it is the same registration. If its text was already handed over, it prepares another clear through `registrationSent`. The existing held-meta overlay makes that clear visible to the shared `sayOwed` read. The clear commits with this request's answer. A failed write does not erase the worker's memory. A cleared mark or a different registration drops the old entry. A replacement worker starts without it and can replay an owed header.

This closes the seam in the first review without changing shared delivery behavior or adding a second store record. It does not treat every failed report as delivered. The original write-order gate remains in place for successful commits.

Independent proof repeated the first review's real-process SIGSTOP experiment with the candidate's built worker and daemon. The host factory created exactly one worker. The start header reached the host before the next request. The daemon was resumed only after the frozen-case observation.

## New work: OpenCode waits for the prior bridge's commit outcome

`src/harness/opencode/bridge.ts:194` now awaits `handOff.sent()` after the verdict. `src/harness/opencode/bridge-client.ts:144` resolves the accepted held answer at the bridge's exit or at the commit grace, rather than at the verdict. Both ends are needed: waiting inside the old process alone would not order the next process's read.

The original deadline still bounds receipt of the answer. Once the answer is accepted, the client gives the bridge at most `COMMIT_GRACE_MS` (2,000 ms) to finish. The grace kills the process group and returns the accepted answer if the bridge does not exit. The foreground grace timer is referenced, so a host with no other work does not exit before its promise resolves. Background calls leave it unreferenced, matching their existing child and pipe handling. No timeout was added to an idle wait before it has an answer.
