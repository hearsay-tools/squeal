# 006-100 notes: which Squeal a Codex cell runs

Worker notes, 2026-11-01. Brief `wave-17.md`; spec 002 D7 to D9; `plugins/codex/bin/squeal-launcher` header. Commits `acbd2b3bf` (the cell) and `e7ff86a5c` (the run guard).

## The seed is frozen at 0.1.368

Since `e34c9bc1f` (0.1.368) a pin holds three Codex trees:

- `plugins/codex`: the fixed adapter (manifest 1.0.x), `hooks/hooks.json`, its `dist/` dispatcher bundles, `bin/squeal-launcher`, skill bridges, and `seed/`.
- `plugins/codex/seed`: a whole runtime, `runtime.json` version 0.1.368. Its `dist/cli/squeal.mjs` is the same blob, `91c45ee`, at `squeal--v0.1.368`, `v0.1.381`, `v0.1.387` and HEAD (2026-11-01). D7: an ordinary release never rewrites the seed.
- `plugins/codex-runtime`: the commit's runtime. Its CLI equals Claude Code's at each tag (`98d9ad1` at v0.1.387).

The brief's lead, "the seed, which a fresh install runs", is true only for `codex plugin add` alone, and that cell would measure 0.1.368 under every later pin. The coordinator confirmed: the cell measures the pin's own runtime (reply to request cd70235b).

## What a cell does now

- `pinSqueal(pin, harness)` (`evals/lib/prepare.mjs`): Claude Code, and Codex without the adapter markers (`hooks/hooks.json` and `seed/`, the launcher's own test), get the plugin's `dist/cli/squeal.mjs`. With the markers, Codex gets `plugins/codex-runtime`, which must be whole as the launcher reads one: `runtime.json` and `.codex-plugin/plugin.json` name one plain version, and the CLI exists. Otherwise `MissingPinCli`, message `missing pinned Squeal CLI for <harness>: <why> (pin <dir>)`.
- `retainCodexRuntime(codexHome, runtime)`: copies the runtime to `<cell>/codex/plugins/data/squeal-hearsay/versions/<v>/` and writes `runtime/current.json` `{ "schema": 1, "version": "<v>" }`. That is the state `install.sh` leaves after `codex-runtime ensure` and `update` (D8). The cell cannot run `update`: it downloads the release from GitHub, not the pin.
- The adapter's hooks (`selectRuntime` in `src/harness/codex/adapter/store.ts`) take `current.json`'s runtime unless the seed is newer. The launcher does the same. `CLI` in `run-cell.mjs` is the retained copy, so the trust step, the warm-up, the session's bare `squeal` and the end status run one file. The runner log names it: `squeal cells/<hash>/<run>/<id>/codex/plugins/data/squeal-hearsay/versions/<v>/dist/cli/squeal.mjs`.
- A plugin-less arm (`noplugin-block`) retains nothing; its `CLI` is the pin's runtime path.
- Selection checks the manifest versions and the required entries, not file hashes (`checkRoot`). So a variant that patches `plugins/*/dist/**/*.mjs`, which also reaches `plugins/codex-runtime/dist`, still selects. Publication (`publishRuntime`) hashes every file, but nothing in a cell publishes the pin's runtime.
- `run-baseline.mjs` calls `pinSqueal` for each arm and each harness of the plan after its pins are built, and exits 2 on `MissingPinCli` before any cell. It runs after the judge calibration, as the coordinator placed it.

Verified on real pins (scratch HOME, no session, no daemon): v0.1.367 resolves to `plugins/codex/dist/cli/squeal.mjs`; v0.1.368 and v0.1.387 to their runtimes. In a scratch cell with the adapter in the Codex cache, the shipped launcher's `squeal --version` printed `0.1.368` and `0.1.387`.

## Open for the next worker or the smoke

- The session's SessionStart may schedule a background runtime update (`scheduleRuntimeUpdate`, D8). It downloads the newest release into the cell's data directory and moves `current.json`. The session keeps its pin: Codex shells carry `CODEX_SESSION_ID`, which the launcher reads first (`research/codex-sessions-and-wake.md`). The harness's commands use the fixed `CLI`. So the cost is one download per cell, with no effect on what is measured. Not suppressed here: the update state cannot hold a check off for more than an hour.
- `squealBin` still copies the adapter's `bin/squeal-launcher`. `install.sh` copies the runtime's. Both are blob `8ba1352` at v0.1.368, v0.1.387 and HEAD.
- `noskill` removes `plugins/codex/skills/squeal`, which since 0.1.368 is the adapter's skill bridge. The retained runtime keeps its own `skills/squeal`. Whether a Codex session then sees no skill is for the smoke or a later row to confirm.
- No test runs `run-baseline.mjs`'s exit 2: the bin starts a run when imported. `test/evals/pin-cli.test.ts` reads its wiring, as `eval-root.test.ts` does.
