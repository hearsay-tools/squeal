## Blocker

### B1. Proven: a background update changes the runtime measured by a later turn

Changed boundary: `evals/bin/run-cell.mjs:203` to `:205`, `evals/lib/prepare.mjs:112`. These retain the pin's runtime and set `runtime/current.json`, but leave background updates active for the cell.

Contract: R1 requires that a Codex cell run the pin's own runtime for its commands, hooks and bare `squeal`, and that a background download cannot change the runtime under measurement. Spec 006 D3 says the plugin comes from the commit under test. Spec 006 D10 includes multi-turn cells; `a1-break` and `a4-pending` each have two turns.

Failure sequence:

1. A cell pinned to 0.1.387 retains that runtime. Its first SessionStart pins the Codex thread to it, then schedules a background update. No update state exists in the fresh data directory, so a check is due.
2. The update publishes a newer released runtime and advances `current.json`. During the first `exec`, hooks and bare `squeal` correctly keep 0.1.387.
3. The first `exec` ends. SessionEnd deletes the thread's runtime pin (`src/harness/codex/adapter/index.ts:80`, `releaseSession`). This is the shipped lifecycle, not an eval assumption: `002-codex-adapter/research/codex-sessions-and-wake.md` section 7 records SessionEnd on every `exec` end.
4. `runTurns` (`evals/lib/atomic.mjs:237`) launches the second turn with `codex exec resume` (`evals/lib/session.mjs:53`). Resume keeps the thread id but its runtime record is gone. The next hook selects the newer current runtime and bare `squeal` follows that new pin. The runner's warm-up, settle, end status and stop still use the old fixed `CLI`.

Thus one cell can measure two runtime versions while its result names only the requested commit. This breaks provenance even if every command succeeds. It occurs when a background update completes before a later turn's first hook; the proof establishes the version switch deterministically rather than asserting that a particular network race occurred in the smoke. The adapter, skill and update source used by the proof are unchanged between 0.1.387 and this candidate (`git diff squeal--v0.1.387..HEAD --` those files was empty).

Fix, one worker: make the eval's selected runtime immutable for the whole cell, including all `exec` lifetimes. Prevent the cell's updater from selecting a different runtime; do not rely only on a thread record that SessionEnd removes or on an update delay that expires during a long cell. Keep this in eval pin/cell preparation, without changing shipped adapter behavior. Add a library/fake-runtime test for first turn, completed update, SessionEnd, resume and bare launcher resolution. The old pin must remain selected throughout, and the runner's CLI must agree. No real model call is needed.

## Should-fix and notes

### N1. Proven, nonblocking: `noskill` now means no catalog bridge, with a discoverable runtime skill

Changed boundary: `evals/lib/prepare.mjs:115` copies the runtime's `skills/` into the cell; `evals/bin/run-cell.mjs:205` enables this for Codex cells. `evals/variants/noskill.json:4` still removes only the Claude skill and the fixed Codex adapter's bridge.

On a real 0.1.387 pin, the adapter bridge is absent after `buildPin(..., "noskill", ...)`, but `versions/0.1.387/skills/squeal/SKILL.md` exists after retention. `skillLine` names that exact readable path, and `sessionStart` includes that line in its context. The arm therefore measures removal of the skill catalog entry, not removal of Squeal's instructions from the session. R1 explicitly asks to name this meaning; it is not a blocker for the row's CLI and daemon repair.

Fix, one worker: either define and label the arm as removing only catalog discovery, or implement an actual instruction-free arm and test the context the model receives. Simply deleting the retained skill is not enough: the adapter's `REQUIRED_ENTRIES` includes it and would reject the runtime. Any semantic change to the arm must follow spec 006 D6's conditions-fingerprint rule.

### N2. Proven, nonblocking: missing-CLI preflight can spend on judge calibration first

Changed boundary: `evals/bin/run-baseline.mjs:154`. The check iterates every arm and each harness in the narrowed plan, catches `MissingPinCli`, and exits 2 before the plan or any subject cell starts. It meets that requirement.

It runs after `ensureCalibrated` at line 114 and `fixtureModules` at line 147. In a long baseline without a passing calibration, the runner can make paid judge calls, including both model attempts, before discovering that its subject pin has no CLI. With cached calibration, there are no new calibration model calls; atomic runs skip the judge entirely. Dependency preparation can also run before the error. This order was explicitly assigned by the coordinator, so this is an efficiency note, not a row failure.

Fix, one worker: move pin construction and cheap CLI preflight before judge calibration and fixture dependency installation, while keeping calibration before every subject cell. The existing source-order test proves wiring only; a testable preflight function would allow behavioral coverage of the exit reason without running a bin script.

```js
import assert from 'node:assert/strict';
import { existsSync, mkdtempSync, readFileSync, rmSync } from 'node:fs';
import { join } from 'node:path';
import { pinBase, pinSqueal, retainCodexRuntime } from './evals/lib/prepare.mjs';
import { buildPin } from './evals/lib/variant.mjs';
import { selectRuntime, releaseSession } from './src/harness/codex/adapter/store.ts';
import { scheduleRuntimeUpdate } from './src/harness/codex/runtime-update/schedule.ts';
import { skillLine } from './src/harness/codex/kept.ts';
const root = mkdtempSync('/tmp/review-006-100-');
try {
  const variant = JSON.parse(readFileSync('evals/variants/noskill.json', 'utf8'));
  const pin = buildPin(pinBase(root, 'squeal--v0.1.387'), join(root, 'noskill'), 'noskill', variant);
  const { runtime } = pinSqueal(pin, 'codex');
  const codexHome = join(root, 'cell/codex');
  const cli = retainCodexRuntime(codexHome, runtime);
  const data = join(codexHome, 'plugins/data/squeal-hearsay');
  const retained = join(data, 'versions', runtime.version);
  const skill = join(retained, 'skills/squeal/SKILL.md');
  const line = skillLine({ env: { PLUGIN_DATA: data }, squealVersion: runtime.version });
  assert.equal(existsSync(join(pin, 'plugins/codex/skills/squeal')), false);
  assert.ok(existsSync(skill));
  assert.ok(line.includes(skill));
  console.log('noskill: adapter skill absent; retained skill present; SessionStart skillLine names it');
  const options = { pluginRoot: join(pin, 'plugins/codex'), data, sessionId: 'review-thread' };
  assert.equal(selectRuntime(options).version, '0.1.387');
  const args = scheduleRuntimeUpdate({
    env: { PLUGIN_ROOT: retained, PLUGIN_DATA: data, SQUEAL_ADAPTER_ROOT: options.pluginRoot },
    start: () => {},
  });
  assert.ok(args?.includes('--background'));
  console.log('SessionStart: background runtime update is due (start intercepted; no network)');
  const newer = pinSqueal(process.cwd(), 'codex').runtime;
  assert.equal(newer.version, '0.1.389');
  retainCodexRuntime(codexHome, newer);
  assert.equal(selectRuntime(options).version, '0.1.387');
  console.log('after simulated update to real 0.1.389 runtime, active hook selects 0.1.387');
  releaseSession(data, options.sessionId);
  assert.equal(selectRuntime(options).version, '0.1.389');
  console.log('after exec SessionEnd, resumed hook selects 0.1.389');
  assert.equal(cli, join(retained, 'dist/cli/squeal.mjs'));
  console.log('runner CLI still names 0.1.387; resumed hooks now name 0.1.389');
} finally {
  rmSync(root, { recursive: true, force: true });
}
```
