## Decisions the brief did not settle

1. Keyed by module, not by test file. One walk of a glob module keys every closure that holds it, including lists stored by an older release.
2. Recursive folders are expanded at record time with `Listings.below`, as an observed recursive listing is. A subfolder added later moves its parent's listing; the next walk records the subfolder.
3. Repair (reviews/wave-2.md B2): a module the parser cannot read (not a script by its extension, as a Vue file or a plugin's own format, or a parse error) lists the worktree root recursively, so any add or delete re-keys its tests. Vite 8's parser reads TypeScript, enums, decorators, JSX and TSX. Vite 6 and 7 give `vitest/node` a JavaScript-only parser, so there a TypeScript module with a glob takes this path: an over-run, never a false pass.
4. A pattern that starts with `**` is not listed. Vite globs it from the common base of the call, which is the file system root when it stands alone; no real project relies on it.
5. A non-relative pattern (alias, `#` subpath) and a non-relative template import resolve through the project's `ssr` plugin container `resolveId`, with Vite's `vite:import-glob` custom flag. Vite's own template-import path uses a separate resolver; for an alias the two agree.
6. Another worktree's new glob entries reach a running daemon only at its next own walk of the module, or its next start. No refresh path was added (keep the `keying.ts` change to the merge).
7. Repair (B3): no import from another runner's folder. The type strip and node:test's `quietly` are gone from the Vitest parser; `enumerate.ts` is as on main.
8. Repair (B1): a listing of the worktree root is reported as `""`, which the core keys as `./`.
