# Row 023-67 (X2) notes: the hook names files that an `--at --run` queued

Wave 32, worker B, brief `tasks/wave-32.md`. Spec D7.3; round 8 X2 (`../lessons.md`, "Round 8 (023-63)"). Branch `cez/a2cf10c6`, base `fbbd232bc`.

## Cause

A group at `manual` (or `commit`) keeps its files queued but held: they run only when a request asks for them (`heldUntilAsked`). The group line (`src/core/state/group-text.ts`) read only the store's pending rows and the group's activity. With no activity yet, every pending file read as "waiting for `squeal run browser`. Squeal runs them only on request", also after `status --at … --run` had asked for them. Which files a request asked for lived only in the daemon's memory (the lane's asks).

## What the store already holds

A narrow request (`squeal status --at <c> --run` on the working-tree side, `squeal run <group> <path>...`) puts its selected files in a batch (`promoteNarrow`). The live daemon publishes its batches in the `promotions` meta row (`publishPromotions`), and a batch lives until its files settle. `publishedBatches` reads it, and drops a row written before the live daemon started. So the hook can tell a requested file from a held one without a new write: a queued file of a held group in a published batch was asked for.

## Change

- `GroupTierState.requested?` (additive): at `commit` and `manual`, the pending files in a batch the live daemon published. `groupTiersOf` (`src/core/state/groups.ts`) reads it once per header.
- The group line (`group-text.ts`):
  - all pending files requested: `browser: 97 test files; 97 queued by a request (`squeal status --at <commit> --run` or `squeal run browser <path>...`). Squeal runs them now; `squeal run browser --wait 60000` waits for their results.`
  - some: `…; 2 queued by a request (…), 1 pending, waiting for `squeal run browser`. Squeal runs the requested ones now, the other pending ones only on request; …`
  - none: as before.
  - While a file of the group runs, the daemon publishes the group's activity, and the line reads as before (`pendingText`).
- The hook (`src/core/delivery/slow-told.ts`): `groupKind` gains `"queued"`, so a group last told as waiting for `squeal run` is told again when a request queues it. A delivery title reads "browser group queued".

## Decisions the spec did not settle

- **The commit is not named.** The brief's example is "97 queued by `squeal status --at <short commit> --run`". The daemon's batch row does not say which request made it, and naming the commit needs a new write: the call writing a meta row (the store is read-only in the call today), or the daemon keeping the request's origin in its batch row (scheduler, worker A). The line names both requests that queue such files instead. If round 9 shows agents need the commit, that is a follow-up row.
- **`squeal status --wait` text.** `src/cli/status-wait-groups.ts` (not in this row's ownership) still words a held group "Squeal runs them only on request"; its run text comes from `groupRunText`, which now says "waits for" when every open file is requested. Not changed.
- **A named wait on a manual file.** A plain `squeal status --wait <path>` also forms a batch. If it names a manual group's file, the line now says "queued by a request" although that wait does not run it. Not seen in any round; left.

## Type changes (additive)

- `GroupTierState.requested?: number`.
- `GroupKind` gains `"queued"`.
