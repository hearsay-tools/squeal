`KeyAt` is `{ key, via: "unchanged" | "walk", stored }` or `{ notDetermined: { reason, detail } }`. Reasons: `absent` (the commit, or the side's test version, lacks the file; no checkout), `unlisted` (no adapter in the checkout keyed it), `checkout`, `install`. `stored` is the main store's `results.byKey(key, 0)` for that file, read-only; empty for no result. `KeysAt.store` is false when the store could not be read.

`KeysAt` also gives `current` (each file's key in the worktree now, for D3's comparison), `changed` (why each file did not keep its current key) and `checkoutMs` (the checkout's whole time; `null` only when every asked file is absent at the commit).

## Flow

1. `withKeyer` in the user's worktree: the gate's `openKeyer` (now exported from `src/core/code/gate/stored.ts`, with `readStores`, `Keyer`, `Keyed`, `Stores`; no behaviour change) keys the asked files by a fresh walk over a scratch store. Its `keys.stabilityPaths(ref)` are the inputs and `keys.cache.hashOf` the current hashes, so a dirty tree is compared by its files now.
2. The fast path's git checks compare those inputs with `git ls-tree` of the commit, `git diff --name-status <commit>` against the working tree, and the untracked files. Condition 6 is structural (re-review of wave 5, B1; the human, 2026-11-17, "Shortcut: structural rule"): a file keeps its key only when no file of any name was added or deleted, between the commit and now, in a folder that holds one of its closure files or in that folder's parent (where an import of the folder itself, `../src/a` for `src/a/index.ts`, has same-named file candidates). An added or removed folder is an entry change in its parent. No extension or name list remains: a configured `resolve.extensions` (`.custom`) is covered. Condition 4 compares the policy's declared inputs of the test matched over the commit's files and over this worktree's files; a modified declared file is a closure input, so its blob is compared.
3. Every call with a file present at the commit then makes the checkout (`withCheckout`: sweep of dead owners first, D6), installs it, and opens the keyer there, which loads each project's config (review wave-5 B2: a config can read files no key input lists). A file that passed the git checks keeps its current key only when its project's environment hash there equals the one here; otherwise it is walked with the files that failed them. The checkout is removed in `finally`. No daemon, no `test_file_keys`, no shared write.
4. Review wave-5 B3: the default install reports its process group (`InstallOptions.started`), which the checkout's marker records (`CheckoutMarker.group`, `recordGroup`). `removeTree`, which both removal and the sweep run, stops that group first (`stopRecordedGroup`): when its leader still lives, or the leader's pid is free while the group has members. A SIGKILL between the spawn and the record leaves the group unrecorded.

Fast-path share, measured on 2026-11-17 with the full `keysAtCommit` and the real adapters (`daemonAdapters`), first-parent main commits, load 6 to 20 on 24 vCPUs:

| Repository, tip | 1 back | 10 back | Main reasons a file was walked |
|---|---|---|---|
| Squeal `cf1c51c53` (1,914 files) | 98.4% (1,883) | 64.8% (1,240) | 10 back: 641 by condition 6, 19 listings, 10 blobs |
| squawk `fd1e7f658` (1,876 files) | 0% | 0% | 1 back: `squeal.config.json` changed (1,842); 10 back: widely read sources changed (`catalog.ts` 536, ...) |

The walk set's time: Squeal 48 s and 66 s in all (40 s keying here, 10 s and 27 s in the checkout); squawk 87 to 98 s (48 to 56 s in the checkout). Condition 6 alone costs at most the 641 files at 10 back in Squeal; the name-based rule it replaced was unsound (`.custom`).

Cost of step 3 when every file keeps its key: 165 to 286 ms on the test fixture (a link for an install, 2 files; load 24). On a real repository it is inferred from `keys-by-walk.md` 1 and 3, not measured: checkout 0.5 to 1.8 s, warm install 0.5 to 0.9 s, keyer open (runner start, config, file hashing) 3.7 to 4.6 s, removal 1 to 1.5 s: about 6 to 9 s added to each call.

So `keysAtCommit` always walks the asked files once in the user's tree: research open question 2 ("the source of the current key inputs when no daemon runs"). That costs 4 to 6 s fixed plus the walk. 023-06 could read a running daemon's index instead; not done here.

## Decisions the spec did not settle

- Adapters come from the caller (`KeyingOptions.adapters`, the CLI's `daemonAdapters`): nothing under `src/core` imports a runner.
- The policy of each tree is read as a daemon there reads it (`readPolicy(tree)`), with no coverage override (the gate's `storedFiles` forces `coverage.children`; these keys do not).
- Default files: those this worktree's adapters list. A file that exists only at the commit is keyed only when named.
- A tenth fast-path condition: a changed `squeal.config.json` sends every file to the walk. The policy steers declared inputs and the environment's variables, which the current inputs do not list. The research's nine conditions did not name it; policy changes are rare.
- A listing that holds no names on either side is refused (its key reads names on disk there).
- The install's default budget is 300 s (`installTimeoutMs`); D4's whole-run budget is 023-07's.
- Side keys: a test version from a commit is written from its blob into a temporary folder and copied in with `copyIntoCheckout`; `tests: null` copies from the worktree. Only the named files are copied: D5.2's helper copy and import refusal are 023-08's.

## Left over

- The keyer leaves a `squeal-links-<hash>` folder (4 to 8 KB) in `$TMPDIR` when a tree has symlinked folders (`src/core/watcher/links.ts`); D4.4's per-run `TMPDIR` is a process-wide variable and is not set here.
- The key fixtures' install is a link to this repository's Vitest (`test/commit/at-keys-fixture.ts`, `linkInstall`); the real `installCheckout` runs only in the B3 kill test (`npm ci` of a dependency-free lockfile).
- The stored-descriptor refusal of D2.2 (a project whose stored descriptors show a config-only difference) is not applied: the environment read in the checkout every call replaces it.
