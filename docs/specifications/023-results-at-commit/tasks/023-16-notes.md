# 023-16 notes: keys at a commit (for 023-06, 023-07 and 023-08)

| File | Exports | Use |
|---|---|---|
| `at-keys.ts` | `keysAtCommit(options)` → `KeysAt`; `sideKeys(options)` → `Map<testFileId, KeyAt>`; `KeyAt`, `NotDeterminedReason` | D2 as amended, D5.1 |

`KeyAt` is `{ key, via: "unchanged" | "walk", stored }` or `{ notDetermined: { reason, detail } }`. Reasons: `absent` (the commit, or the side's test version, lacks the file; no checkout), `unlisted` (no adapter in the checkout keyed it), `checkout`, `install`. `stored` is the main store's `results.byKey(key, 0)` for that file, read-only; empty for no result. `KeysAt.store` is false when the store could not be read.

`KeysAt` also gives `current` (each file's key in the worktree now, for D3's comparison) and `changed` (why each file left the fast path).

## Flow

1. `withKeyer` in the user's worktree: the gate's `openKeyer` (now exported from `src/core/code/gate/stored.ts`, with `readStores`, `Keyer`, `Keyed`, `Stores`; no behaviour change) keys the asked files by a fresh walk over a scratch store. Its `keys.stabilityPaths(ref)` are the inputs and `keys.cache.hashOf` the current hashes, so a dirty tree is compared by its files now.
2. The fast path compares those inputs with `git ls-tree` of the commit, `git diff --name-status <commit>` against the working tree, and the untracked files.
3. The rest: `withCheckout` sweeps dead checkouts (D6 at start), makes the checkout, runs the install, and `withKeyer` keys only those files in the tree; the checkout is removed in `finally`. No daemon, no `test_file_keys`, no shared write.

So `keysAtCommit` always walks the asked files once in the user's tree: research open question 2 ("the source of the current key inputs when no daemon runs"). That costs 4 to 6 s fixed plus the walk. 023-06 could read a running daemon's index instead; not done here.

## Decisions the spec did not settle

- Adapters come from the caller (`KeyingOptions.adapters`, the CLI's `daemonAdapters`): nothing under `src/core` imports a runner.
- The policy of each tree is read as a daemon there reads it (`readPolicy(tree)`), with no coverage override (the gate's `storedFiles` forces `coverage.children`; these keys do not).
- Default files: those this worktree's adapters list. A file that exists only at the commit is keyed only when named.
- A tenth fast-path condition: a changed `squeal.config.json` sends every file to the walk. The policy steers declared inputs and the environment's variables, which the current inputs do not list. The research's nine conditions did not name it; policy changes are rare.
- A listing that holds no names on either side is refused (its key reads names on disk there).
- The install's default budget is 300 s (`installTimeoutMs`); D4's whole-run budget is 023-07's.
- Side keys: a test version from a commit is written from its blob into a temporary folder and copied in with `copyIntoCheckout`; `tests: null` copies from the worktree. Only the named files are copied: D5.2's helper copy and import refusal are 023-08's.

## Left over

- The keyer leaves a `squeal-links-<hash>` folder (4 to 8 KB) in `$TMPDIR` when a tree has symlinked folders (`src/core/watcher/links.ts`); D4.4's per-run `TMPDIR` is a process-wide variable and is not set here.
- The fixtures' install is a link to this repository's Vitest (`test/commit/at-keys-fixture.ts`, `linkInstall`); the real `installCheckout` is not run by these tests.
