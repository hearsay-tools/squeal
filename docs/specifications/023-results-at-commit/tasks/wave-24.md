## Row 023-40c: the commit daemon owns setup (D7.3 amended)

- **The call** (`status --at <c> --run`, `--wait` forms unchanged): computes the changed paths (`git diff --name-only <c>..HEAD` plus the working tree's changes, as D4.5's selection input) and the named files; creates the commit worktree without installing (`ensureCommitWorktree` gains a no-install mode); starts its daemon (spawn, detached, as `squeal start` does); sends the commit daemon one request carrying the changed paths, the named files and `--all-missing`; asks the working-tree daemon as today; waits; reads both sides; reports. No temporary checkout, no install and no keying in the call for the commit side; the B3 re-key in a temporary checkout goes (the daemon's live keys answer). Plain `status --at` without `--run` keeps its temporary-checkout lookup.
- **The commit daemon**: claims the worktree first (seconds after spawn), then installs (frozen), then keys and selects the files with no result at the commit (D4.5; named files first), queues them, and records the request so a later call or `--wait` joins it (B2's recorded requests). A new read request answers, per selected file: its live key, its result or its state (setting up: install; queued; running; setup failed with text). A file whose run observed new inputs is answered at its completed key.
- **Ownership gap** (re-review): the creator writes the spawned daemon's lease into the marker as the starting owner at spawn, so the sweep keeps the worktree while that process lives, even if the call ends before the claim.
- **One bound**: every step the call takes (checkout and install-lock waits, worktree add, the ceiling's place wait, daemon spawn and claim wait, the working-tree daemon start whose 30 s spawn wait becomes `min(30 s, remaining)`, requests, waits, reads) gets the remaining time; a small reserve for the report. At the end the call reports what is known and what is still setting up or running: "still setting up at <c> (install)" and Q7's line with the `--wait` command.
- **Ceiling**: default estimate 2 GB per commit daemon in `commit-places.ts`.
- **Tests** (the re-review's required regressions): return before the bound plus a small allowance when the commit install blocks (production-like install, e.g. a 125 s postinstall, cut by the call; the daemon finishes it and a later `--wait` reads the result), when another caller holds the install lock with a longer wait, when a worktree daemon start is late; an unclaimed start left at expiry is owned (sweep keeps it); keep the passing ceiling, early-death, claim-cap and shared-bound tests; the B3 fixture (tracked runtime read, fresh store, real commit daemon) answers in the same call.
- **Ownership**: `src/cli/status-at*.ts`, `src/core/checkout/**`, `src/core/daemon/commit-mode.ts`, the daemon's commit-mode start sequence and the new request handlers (`daemon.ts`, `handlers.ts`, `protocol.ts`, `types/daemon.ts`; spec 011 files, coordinator-approved, subjects say "(spec 023 D7; 011 files, coordinator-approved)"), tests beside them, `tasks/023-40-notes.md` (a "Wave 24" section). ## Row 023-46: the commit daemon starts in seconds

- **Goal**: a commit daemon serves its first request within a few seconds of its install, not after walking the imports of every test file (`tasks/023-40-measure.md`: about 25 s of a 31 s start on 4 CPUs).
- **First**: read where the walk runs (runner host listing, keyer, lookup pass) and find the cheapest correct way: for example, key only the files a request selects; reuse the import graph the store already holds for files whose content and closure are unchanged between the commit and an already-walked revision; or walk lazily and serve requests first. Keys must stay exactly D2's (no shortcut that can change a key). Write the design in `tasks/023-46-notes.md` before you build. If the choice changes what users see or what is stored, send the coordinator a request first.
- **Then build it** for commit mode (the ordinary worktree daemon may profit too, but do not change its behaviour unless the notes show it is the same code and safe; say so).
