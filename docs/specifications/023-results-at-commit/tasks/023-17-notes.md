# 023-17 notes: CI's published results at a commit (for 023-06, 023-07 and 023-08)

## API

| File | Exports | Use |
|---|---|---|
| `src/core/commit/at-keys-ci.ts` | `ciSettled(input, asked, call)` → `CiSettled`, `CiCall`, `CiInput` | the CI step before the checkout |
| `src/core/commit/at-keys.ts` | `KeysAtOptions.ci?: CiCall \| false` (on by default), `KeysAt.ci?: { source, settled, missed }` | additive |
| `src/core/types/store-records.ts` | `ResultRecord.origin?: "ci"` | the contract with 023-06 (coordinator, 2026-11-17) |
| `src/core/store/transfer-rekey.ts` | `proven`, `keyOver`, `commitSegments`, `NO_PARTS` now exported | read-only reuse of 018 D11 |

A file CI settles is `{ key, stored }` with every stored record `origin: "ci"`, outcome `pass` or `skip`, `key` the file's key. Its provenance: worktree `ci`, run id the export's source label, commit and dirty from the export's header, recorded time the export's creation time. Store rows leave `origin` absent.

## Flow

1. `upstreamOf(root)` (local: `refs/remotes/<remote>/HEAD`). None: no CI step.
2. The ref `<shared.ref or refs/squeal>/<sha>` read locally (`rev-parse`, `cat-file`). Absent locally and `shared.ref` set: one `ls-remote` of that one ref (018's `LIST_TIMEOUT_MS`) and one `fetchExport` (018's `FETCH_TIMEOUT_MS`), which writes no ref, config or `FETCH_HEAD`. Absent and `shared.ref` null: no network.
3. 018 D14's checks: the commit on the default branch's first-parent line, the header names the commit, the key format (`importRefusal`), and a GitHub source in the header (review wave-6 B3: a `local` export at the results ref is refused, `missed` `<ref>: local export at <commit8>, not CI's`). A refusal or a failed fetch settles nothing and is `KeysAt.ci.missed`.
4. Per exported file (named files only, when named), all of these, else the checkout (`at-keys-ci-proof.ts`, review wave-6):
   - Environment (B2): the worktree's recorded descriptor (`worktreeEnvironment`, read-only) exists, names this process's Node, platform and arch, and its variable part equals the call's variables (`KeyingOptions.env`) read through the commit's own `env.allowlist` (its `squeal.config.json` blob, else the defaults). Then 018 D10 compares it with the export's (`rekeyedHash`), with D10's CI-field tolerances.
   - Observed inputs (B1): the repository store's shared `observed`, `observedDirect` and `observedModules` rows of the file, and its project's `observedStartup` row, equal the export's (as sets; absent is empty). The checkout's keyer copies those rows in, so a row CI's run lacked moves the checkout's key.
   - The exported key reproduces from its own closure over the commit's blobs (`proven`), and at least one result is at it.
   Then the key is `keyOver(<hash here>, file, <exported closure>, <commit blobs>, <exported key parts>)`.
5. Settled named files are not sent to the checkout; no checkout when CI settles every named file. With no named files the checkout still runs (only it lists the commit's files) and CI's answer replaces its answer for a settled file.

## Decisions the spec did not settle

- The key is the export's closure re-keyed to this worktree's environment hash, not this worktree's closure list (018 D11 uses that for imports): the export's closure is the runner's resolution at the commit, which a list from today's tree is not.
- The environment here is this worktree's recorded one, so the CI step needs a daemon to have recorded it once; without a record every file goes to the checkout. A record from another Node, platform or arch counts as none.
- The trust bound of 018 D14 holds for a local ref too: a clone with no `origin/HEAD` (or other remote's) uses no export.

## Limits

- Exactness: every accepted CI key is proved equal to the checkout's under the rules of step 4; the tests compare against `ci: false` with a fresh store, with shared observed rows (busy store) and with a changed allow-listed variable. A busy store whose observed rows differ from the export's sends the file to the checkout, so the CI step helps little in a repository whose runs record many observed reads.
- The fixture's export is made by the daemon keying in a worktree at the commit and `keyPartsOf`, not by `squeal ci record` + `squeal ci export`; results are one `file` pass per file.
