# 023-09 notes: end-to-end suite for `status --at` and `squeal proof`

## Files

| File | Holds |
|---|---|
| `test/e2e/at-commit-kit.ts` | `bench` (one throwaway folder per test file, its own `HOME`, a clean environment), `clone`, `checkoutAt` (detach and frozen install), `squeal` (runs the shipped bundle), `proof`, `assertionOf`, `timed`, `leftovers`, `checkoutsLeft`, `sweep` |
| `test/e2e/at-commit-status.test.ts` | Before/after on a copy of Squeal and of squawk |
| `test/e2e/at-commit-proof.test.ts` | One red proof per case on squawk fixes, each with a control |
| `test/e2e/at-commit-proof-own.test.ts` | A red proof of a real Squeal fix, and the synthetic `--without` HOME case with `--home-keep` |

## The suite's command

```sh
SQUEAL_E2E_AT=1 SQUEAL_E2E_TMPDIR=$TMPDIR SQUEAL_E2E_TIMINGS=$TMPDIR/at-e2e-timings.txt \
  timeout 1200 pnpm exec vitest run test/e2e/at-commit-status.test.ts \
  test/e2e/at-commit-proof.test.ts test/e2e/at-commit-proof-own.test.ts --no-file-parallelism
```

- `SQUEAL_E2E_TMPDIR`: Vitest's setup (`test/global-teardown.ts`) moves `TMPDIR` to `/tmp/squeal-vitest-*`. On this host `/tmp` is another mount than the home folder, so a hardlinked clone fails with `Invalid cross-device link`, pnpm cannot hardlink from the store, and Squeal would put its checkouts beside the repository. The kit probes a hardlink to the repository at the start and stops with one line naming the variable when the folder cannot hold one.
- `SQUEAL_E2E_TIMINGS`: Vitest hides a passing test's output; each case appends its line (`023-09 <case>: <s> s, load <l> at start`) there.
- `--no-file-parallelism`: the three files run one after the other, so each case's time is its own and the suite adds no parallel load.
- `SQUEAL_E2E_SQUAWK` overrides the squawk path (default `~/projects/cezar`). Without it, each squawk case is skipped with the title `squawk cases skipped: <path> is absent`.

## Isolation

- Every copy is a `git clone --local --no-checkout` under `<SQUEAL_E2E_TMPDIR>/squeal-at-e2e-*`, then `git checkout --detach <commit>` and `pnpm install --frozen-lockfile`. Squawk's repository is shallow, so git ignores `--local` and copies it (about 9 s, 550 MB); this repository's clone hardlinks its objects (about 1.5 s). Fixture commits write new object files and never rewrite a linked one, and `git` runs with `gc.auto=0`, so `--no-hardlinks` (8 GB here) is not used.
- Each test file has its own `HOME` in that folder. From the real `HOME` the kit only reads: Corepack's cached pnpm versions and pnpm's `lockfile-verified.jsonl` are copied in. Without the copy a fresh `HOME` spends about 40 s on pnpm 12's supply-chain check of each new lockfile over the network; with it, about 2 s. The package store stays the normal one (`pnpm_config_store_dir`; pnpm 12 ignores `npm_config_store_dir`).
- Commands get a clean environment: `PATH`, `HOME`, `TMPDIR`, a private `XDG_RUNTIME_DIR`, `LANG`, the store path and two Corepack switches. No `CEZ_*`, `HSQ_*`, `SQUEAL_*`, `XDG_*` or `GITHUB_*` value of this session reaches them.
- `sweep` (after each file): fails the run when a process has its command line or working folder under the throwaway folder (zombies aside), or when a checkout remains under `<HOME>/.cache/squeal/checkouts/<repo>/`; then removes the folder. No daemon is started: every `status --at` reads "No daemon runs in this worktree".

## Product defects found (not fixed in this row)

### D1. `status --at --run`'s first report says a run file was not stored, with a key the run did not use

Reproduction (squawk copy, throwaway `HOME`, no stored result):

```sh
git clone ~/projects/cezar sw && cd sw && git checkout --detach 8be977ad6 && pnpm install --frozen-lockfile
squeal status --at HEAD~1 packages/cezar/src/lint/ast-rules-active-run.test.ts --run --json
#  run.stored 0; at: { state: "pass", key: "fffcdc8e…", origin: { kind: "run", stored: false } }
#  text: "1 not stored: the gate keeps a result only with coverage on at d8abcfe46; the next --at has no result for it"
#  stderr: "the 1 completed test file is kept in the stores"
squeal status --at HEAD~1 packages/cezar/src/lint/ast-rules-active-run.test.ts --json
#  at: { state: "pass", key: "625e0d0d…", origin: { kind: "worktree" } }
```

A worktree at `d8abcfe46` computes `625e0d0d…` for the file (`status --at 8be977ad6` there reads it as "now", `pass`). So the result is stored, at the key of the closure the run recorded; the report looked it up at the key from keying before the run (the static closure, `fffcdc8e…`), found nothing and gave coverage as the reason. The state shown is right; the stored count, the `stored: false` origin, the key and the "no result next time" sentence are wrong. The same happens with `--all-missing` at `HEAD` for `active-run-write-index.test.ts`. The suite does not assert `run.stored` on squawk for this reason (`runReportsItsStores: false`).

### D2. A file the gate does not keep reads "keeps a result only with coverage on", with coverage on

Reproduction (Squeal copy at `20f03a431`, throwaway `HOME`):

```sh
squeal status --at HEAD test/daemon/mark-binding.test.ts --run --all-missing
#  stderr: "0 of 1 completed test files are kept in the stores; the next run on the same bytes runs it"
#  "1 not stored: the gate keeps a result only with coverage on at 20f03a431"
squeal status --at HEAD test/daemon/mark-binding.test.ts   # no result
```

Coverage is on (the default; the same kind of call stores `test/store/open.test.ts`). At `HEAD~1` the same file was kept by `--run`. Why the gate does not keep it at `HEAD` is not diagnosed here; the reason the report gives is wrong either way.

### D3. A `.gitattributes` `eol` conversion reads as "The install changed the checkout"

```sh
squeal status --at e64ce2cf2 packages/contract/src/waits.test.ts     # in a squawk copy at c1ba6f5bf
#  The install changed the checkout (packages/mobile/android/gradlew.bat differs from e64ce2cf2), so its keys and results are not e64ce2cf2's and nothing from it is stored.
```

`packages/mobile/.gitattributes` says `android/gradlew.bat text eol=crlf`: git's own checkout writes CRLF over the LF blob before any install runs. 023-07's notes list `eol` filters as a known limit (every run reads not stored); the defect is the text, which sends the reader to the install. Its reach in squawk: every commit that holds `packages/mobile` (removed by `47cb377ed`, 2026-11-14): no stored result there, and every proof side under a condition reads `not comparable` (023-11 B3).
