## The rule as built

A path in `ObservedGrowth.firstSeen` leaves it, so the run is stored, when all of these hold (`observedGrowth`, `src/core/scheduler/observed.ts`):

1. The recorder recorded that every read of the path in the run found it absent, and no read found it present (`ObservedInputs.absent`, from `absentOf` in `src/runners/observe/inputs.ts`).
2. The run recorded no write, create, rename or remove of the path or of a path below it. A failed attempt counts: the recorder records a write before the call. A path the run wrote is no input at all (`observedInputs` drops it), so the case that matters is a write below a probed path.
3. After the run, the stat cache holds the path as absent, and `lstat` finds nothing at it, not even a dangling link, and no directory above it (below the worktree root) is a link (`nothingAt`).
4. Git does not ignore it. An ignored absent path keeps the re-run.
5. No revision during the run names it. `storeDecision` checks `unstable` before `first-seen`, so such a file is discarded and re-queued as before.

A first-seen path whose reads the recorder did not see keeps today's rule: it has no `absent` entry. A listing of an ignored directory (row 016-23) stays first-seen as before.

## The recorder: read outcomes

`src/runners/observe/absent.cjs` (new), `fs.cjs`, `recorder.cjs`, `read.ts`. Two new kinds in the observation lines: `a` (a read found the path absent) and `p` (a read found it present, or the recorder cannot tell). A path is absent only with `a` and without `p`, over every process of the test file.

- Outcome read: `stat`, `lstat`, `access`, `realpath`, `readFile`, `exists`, `readdir`, `opendir` and `open` (no `O_CREAT`), in sync, callback and promise forms. Absent: ENOENT; ENOTDIR for a call that is no listing; `statSync`/`lstatSync` with `throwIfNoEntry: false` returning `undefined`; `exists`/`existsSync` false only when the recorder's own `lstat` also finds nothing (`existsSync` is false for a dangling link or a refused path too).
- Counted as present: any other result or error; a read through a descriptor or a FileHandle; `createReadStream`; the source of `copyFile` and `cp`; a module load, an entry point, a failed `file:` or relative import, an existing file named by a spawn's arguments, a Worker's file; a symlink target the recorder resolved; a read whose outcome code throws.
- The spelling guard: an absent outcome counts only when the argument has no `.` or `..` segment and no trailing separator. The kernel walks `missing/../data.txt` (ENOENT, though `data.txt` exists) and `file/` (ENOTDIR, though `file` exists) apart from `path.resolve`.
- A listing's ENOTDIR counts as present: the path itself may be a file.
- An async read that never settles leaves no outcome. The test saw no result of it.
- The outcome is recorded for the test file current when the call started, so a callback that runs after the next file began is not misattributed.

The recorder also marks a test file whose processes started a child it may not follow (`u`): a shell (`exec`, `execSync`, `shell: true`), any command that is not a Node, or a subtree another Squeal's recorder takes. Nothing reads the mark now (the coordinator, 2026-11-24: keep it for a later row).

## Where the argument fails, and what refuses

The argument: the result depends on what the run read. If every read found the path absent and it is absent now, the key over "absent" describes what the run saw, whatever happened between the reads.

| Case | What happens |
|---|---|
| A read through a link whose target appears | A link above the path at run end refuses (`nothingAt`). A link at the path itself is found by `lstat` and refuses. A dangling link removed by run end: the run's reads saw "absent" through it, which is what the key says. |
| A directory read and a file read | `readdir` ENOENT counts as absent for the directory path; its ENOTDIR counts as present. A directory standing at the path at run end refuses (`lstat` finds it, though the stat cache holds a directory as absent). `readFile` on a directory gives EISDIR: present. |
| Case-insensitive names | The end check runs through the file system with the run's own spelling, so on a case-insensitive file system a `Foo.json` at run end refuses a read of `foo.json`. A read that found it through another case is recorded as present. Not testable on Linux; no test. |
| A spelling the kernel walks differently | The spelling guard: present. |
| A read by a child the recorder does not see | Accepted risk, below. |
| A path present at one read and absent at another | `p` and `a`: refused. |
| A write attempt at or below the path | Refused (`absentOf`). |
| A path present at run end | Refused: the stat cache has its hash, and `lstat` finds it. |
| An ignored path | Refused. |
| A revision during the run that names the path | The file is `unstable` first, as before. |

## The accepted risk: reads by a child the recorder does not follow

The brief asked to refuse when a child the recorder does not see may read the path. Built that way, it saved almost nothing: most test files that probe absent paths also start `git`, `sh`, a launcher script or `ast-grep` (5 of 36 re-runs saved here, 0 of 2 in squawk). The coordinator chose to drop that refusal (2026-11-24, option B) and keep the `u` mark. The risk it accepts, as put to the coordinator:

> A path that something outside the run creates and then removes during the run, that a non-Node child of the test reads while it is there, while every read by the test's own Node processes finds it absent, and no revision names it. The run is then stored at the key with the path absent though the child saw it. Today's rule already accepts exactly this race for every path the stat cache already holds as absent (only first-seen paths are protected now, and only on the first run). A path the run itself makes and removes through a child is the run's own scratch.

Where today's rule accepts it: `diffCandidates` in `src/core/revision/reconcile.ts`. A path the stat cache holds as absent has no entry (`cache.get` is `undefined`), so when the watcher's candidate is gone by the time the diff reads it (`if (!read)`), the diff pushes no change and no revision names the path. `tierEnd` in `src/core/scheduler/store-decision.ts` then finds the path stable (`unstable` reads only changes on disk, the tier's revisions and `observed.changed`), and the run is stored at the key with the path absent, whatever the run read while the path was there. Row 023-81's scratch test showed the same diff result for a path in neither cache state (`tasks/023-81-notes.md`, the paragraph on the watcher). Row 023-85 extends that acceptance from known-absent paths to first-seen paths whose every recorded read found them absent; every other refusal above stays.

Tests: `test/scheduler/absent-first-seen.test.ts` keeps a run that probes a path and starts `sh` to probe it too (`unseen-child`), keeps a run whose shell makes and removes a path of its own (`child-scratch`), and re-runs a run whose shell leaves the path behind (`child-leaves`, present at run end).
