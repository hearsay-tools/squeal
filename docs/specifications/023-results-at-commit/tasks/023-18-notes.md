# 023-18 notes: repairs from the end-to-end suite (D1, D2, D3, N1)

The defects are described with their reproductions in `023-09-notes.md` ("Product defects found"); N1 is in `reviews/wave-9-rereview.md`.

## D1. A run's outcome is read at the key its result was kept under

**Cause.** The gate keeps a file whose run read paths its static closure lacks at the key with those reads (020 row 020-39, `atStoreKey` in `src/core/code/gate/keep.ts`). `outcomesOf` read the store at the key from keying before the run, found nothing, and fell back to the gate's answer with `stored: false`.

**Fix.** `BeforeRemove` gets a fourth argument, `rekey` (`src/core/commit/at-keys-checkout.ts`): it opens a new keyer in the same checkout over the shared store as it is after the run, so the keyer sees the reads the run recorded, and keys the given files again. `rekeyed(files, rekey)` swaps each file's key for the new one. `status --at --run` (`status-at-run.ts`) and proof sides (`proof-run.ts` `runOnce`) re-key the run files (and, for `--run`, the siblings of a run path) after a storing run (no checkout change, not forced, the gate answered), then read states, origins and stored failures at those keys. The state shown carries the new key: the one the next `--at` gives.

**Cost.** One more keyer open in the open checkout after each storing run: no checkout, no install. See the suite's times below.

**Tests.** `test/cli/status-at-run-rekey.test.ts` (a test that reads `data/a.txt` through `fs`: `run.stored` 1, origin `stored: true`, no "not stored" line, the key equal to the next call's) and `test/cli/proof-rekey.test.ts` (both sides `stored: true`, `notStored: null` on the first call; the second call reads both from the store, 0 runs). Both fail on `12bcf84a3`.

## D2. A file the gate does not keep is reported with the gate's reason

**Cause, diagnosed.** At `20f03a431`, `squeal status --at HEAD test/daemon/mark-binding.test.ts --run --all-missing` prints the gate's own note: `1 completed test file was not kept in the stores, because it read paths first seen during the run (src/core/daemon/package.json, src/core/package.json, src/package.json)`. Node's module resolution probed those absent `package.json` files; a path hashed only during the run is "first seen" (`src/core/scheduler/observed.ts`), and the keeper does not keep such a file (row 011-320). That is right: the key could not have held those paths. The run records them as seen, so the next run keeps it (in 023-09's sequence the `HEAD~1` run kept the file because the `HEAD` run had recorded them). The defect was only the report's reason: the CLI had no reason per file and always said coverage.

**Fix (gate files touched, for this reason).** The keeper already had each file's reason for its note. `NotKept` (`src/core/code/gate/keep-reasons.ts`) also keeps a per-file reason in its note's words for one file; `Keeper.notKeptFiles()` (`keep.ts`), `StoredFiles.notKept()` (`stored.ts`), `Collected.notKept()` (`src/cli/code-gate-stored.ts`) pass it on; `runGateFiles` (`src/cli/code-gate-files.ts`) answers `notKept: { path, reason }[]` when it stores. `outcomesOf` gives an unstored run state `origin.notStored`: `the gate did not keep it: <reason>`; when the gate gave none, `the gate keeps a result only with coverage on` only when the checkout's policy has coverage off, else `the gate did not keep it and gave no reason`. `--run`'s text groups the unstored files by reason (`1 not stored (<reason>); the next --at has no result for it`); JSON adds `run.notStored` (one reason per unstored file) and `origin.notStored`. A proof side's `notStored` takes the same reason.

**Tests.** `test/cli/status-at-run-not-kept.test.ts`: a test that tries to read `src/package.json`, which no commit holds. Text: `1 not stored (the gate did not keep it: it read paths first seen during the run (src/package.json))`, no "coverage"; JSON `origin.notStored` and `run.notStored`; proof: the red side's `notStored` names it. Each on a first run (a second run keeps the file, as the gate intends). Fail on `12bcf84a3`. `status-at-run-review.test.ts` B7 (coverage off) keeps the coverage reason, in the new line's form.

## D3. Git's own checkout rules are named, not the install

**Fix.** `withCheckout` (`src/core/commit/at-keys-walk.ts`) runs the whole-checkout check before the install too: a difference there is `{ path, by: "git" }` (a `.gitattributes` `eol`, `text` or filter rule wrote it), one found only after the install is `{ path, by: "install" }` (`Changed`, `changedText`). The storage rule is unchanged: with either, nothing is stored and the keys are not the commit's. Texts: `git's checkout rules changed <path>` per file, and the header `Git's checkout rules (.gitattributes) wrote <path> otherwise than <commit> holds it, so its keys and results are not <commit>'s and nothing from it is stored.`; the install's texts are as before. JSON keeps `changed` as the path and adds `changedBy` (`"git"` or `"install"`) at the top level and in `run`.

**Cost.** One more pass of the check before the install: 1.06 to 1.17 s on this repository (023-07's measure), 0.12 s on squawk.

**Test.** `test/cli/status-at-run-gitattributes.test.ts`: `*.bat text eol=crlf` and a committed LF `tools/run.bat`: the header and the per-file reason name git's checkout rules and the path, never "install changed"; JSON `changed`, `changedBy: "git"` at the top and in `run`, `stored: 0`, the run file `not comparable` with `ran: pass`. Fails on `12bcf84a3`.

## N1. `--home-keep` checks and copies count toward the one `--timeout`

**Fix.** `placeKeep` and `ownHome` (`src/core/proof/own-home.ts`) take the command's deadline (`performance.now()` time; the clock starts before `locate`, so the checks already counted, they only never stopped). Past it, the check's walk stops (no side runs then, and `ownHome` refuses a link itself), and the copy throws `OutOfBudget` at the next file or folder; a byte copy under way finishes. `runFiles` (`proof-run.ts`) checks the budget before it makes the own `HOME` (it made it first), and maps `OutOfBudget` to `not run (budget)` for the side's files, as other budget cuts read.

**Tests.** `test/proof/own-home-budget.test.ts`: past the deadline `ownHome` copies no kept file and throws `OutOfBudget`; before it, all 50 files are copied; `placeKeep` finds a link deep in a kept tree in time and stops walking past the deadline. Two of the three fail on `12bcf84a3` (the third is the control).

## Decisions the brief did not settle

- D1 re-keys in the same checkout rather than reading the store by path for the newest record: the keyer gives exactly the key the next `--at` computes, and a by-path read could take another commit's record.
- D2's reason is the keeper's own words for one file, not a new wording: the note on stderr and the report say the same thing.
- D3 classifies by when the difference first shows; a checkout git changed and the install changed further reads `git` (the first cause), with the first differing path.
- N1 does not bound one large file's byte copy (the review's "byte read already in progress"); it stops between files.
