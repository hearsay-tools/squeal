# Row 023-36 notes: what a `--run` run leaves running (T3)

## Design after the repair

- **Which runs.** A run is flagged when it holds a file that an accepted `status --at --run` request put in the queue itself (`NarrowRunRequest.newlyQueued`; never a selected file that was current, queued by another or running; review wave-20 third look), by project and path (`AtRunRequests`, `src/core/daemon/run-groups-watch.ts`). `at` travels with the `run-group-paths` request to the daemon's main thread, in `NarrowRunOptions` beside `owner`. The daemon flags files only after the scheduler accepted the request as a narrow run (`flagAccepted`). The key is the call's `owner` (row 023-34's per-call id) or, without one, the request's covered-files id. A refused or unknown request flags nothing, nor a request whose owner was taken back before the scheduler answered (taken-back ids are kept for the hour, at most 1,024). A take-back of that key, the run of the files, or one hour ends the flag. A mixed batch that holds a flagged file is that request's run: its processes share one env.
- **The mark.** Each flagged run gets a random token in its workers' env, `SQUEAL_RUN_GROUP` (`RUN_GROUP_VARIABLE`, `src/core/daemon/run-groups.ts`). The recorders put it into every child's env, the caller's own `env: {}` included. For Vitest that is `src/runners/observe/spawn.cjs`. For node:test it is `src/runners/node-test/runtime/recorder.cjs`, which patches `ChildProcess#spawn` (every async form) and the own `env` of `spawnSync`, `execFileSync` and `execSync`. So a detached child stays marked after its starter exits (B7).
- **The record.** Before the run starts, the daemon writes `{token, runId, groups}` to `<store dir>/run-groups/<hash of root>.json` (version 2; version 1 files are ignored). A daemon killed mid-run leaves it for `squeal stop`.
- **The stop** (`stopRuns`, `src/core/daemon/run-groups-stop.ts`), at the run's end, at the daemon's exit, and in `squeal stop` once no daemon serves:
  - stopped: a process whose env carries the run's token; a member of a group whose leader is alive and carries the token (the kernel gives no other process the group id while the leader lives);
  - never: the run's own workers (a carrier whose parent is the daemon, or a process of the daemon's tree without the same token), a process with no token, a process with another run's token;
  - spared and named: an unmarked member of a recorded group whose leader is gone or no longer carries the token. A group id plus a start bound proves nothing after the leader exits (B6).
- Nothing is matched by path or command line.

## Limits (also in the note text, `NOT_COVERED`)

The mark reaches what a test starts through Node while Squeal's recorder runs in that process. Not covered:

- a program that clears its env before it starts a child (for example a shell running `env -i setsid server`): that child carries no token; if its group's marked leader is alive, it is still stopped as a group member, otherwise it is spared and named;
- pytest tests (no recorder of this kind);
- runs without the recorder (a Vitest run where the observe recorder is not loaded);
- Worker threads need nothing: they are threads of the marked process.
