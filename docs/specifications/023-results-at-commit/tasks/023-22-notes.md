# 023-22 notes: the red evidence rule in `squeal proof` (issue #244)

Wave 14b, brief `wave-14b.md`; spec 023 D5.5 as amended 2026-11-19 (the human, "A: evidence rule"), D5.6.

## What changed

The classifier still reads only the runners' structured records, never English message text, except the texts `--red-error` names. Two additive fields on `CheckError` (`src/core/types/check.ts`) carry what it needs:

| Field | Values | Set by |
|---|---|---|
| `stage` | `body`, `hook`, `timeout`, `other`; absent when the runner says nothing and in failure texts stored before 023-22 | Vitest: `testStage` and `withStage` in `src/runners/vitest/results.ts`. node:test: `failureType` in `src/runners/node-test/run/errors.ts`. pytest: the phase (`call` is `body`, `setup` and `teardown` are `hook`) in `src/runners/pytest/run/report.ts` |
| `assertionEvidence` | `true` or absent | Vitest: the serialized error has `expected` and `actual`, or a `matcherResult` object. node:test: the thrown value has `actual` and `expected` |

The daemon's keep protocol (`src/core/daemon/keep-protocol.ts`) validates both fields; it refuses unknown fields, so without this a gate write would fail.

`src/core/proof/verdict.ts`, `recordedKind` then `errorKind(error, redErrors)`, in this order:

1. `phase` `load`: `import`; `setup`: `setup`; `after-tests`: `hook` (as before).
2. A recorded load average or `stage: "timeout"`: `timeout`.
3. `stage: "hook"`: `hook`. An assertion in a hook is a `hook` now; before, Vitest's read as an assertion.
4. Assertion evidence: name `AssertionError`, code `ERR_ASSERTION`, `assertionEvidence`, or a non-null `diff`: `assertion`, wherever it was thrown.
5. `stage: "body"` and a deliberate class: `thrown` (new kind).
6. Else `error`.

`--red-error` texts: an error of any kind but `import` and `setup` whose message holds one of them reads `thrown`.

A failed test is `assertion` when every error is one; `thrown` when every error is an assertion or thrown and one is thrown; else the first other kind. `redCounts` (was `redOnAssertion`) is true when every failed test is `assertion` or `thrown`. `verdictOf` gives `proven` with the reason `red on a thrown error, not an assertion: <name>: <first message line>` (200 characters at most) when one is thrown. `withControl` keeps that label in front of P9's `red without the conditions too` reason. `redEvidence` gives the file's `evidence`: `assertion`, `thrown` or `null`.

Report: `ProofFile.evidence`, `ProofReport.redErrors`. JSON per file `evidence`, top-level `redErrors`; failure `kind` can be `thrown`. The rerun line repeats `--red-error`. No version raise: every field is added.

## Decisions the spec did not settle

- **Engine errors.** The spec names `TypeError`, `ReferenceError`, `SyntaxError` and pytest's `NameError`, `AttributeError`, `ImportError`, `SyntaxError`, `TypeError`. I added their subclasses and siblings the engine throws: `RangeError` (stack overflow), `EvalError`, `URIError`, `UnboundLocalError`, `ModuleNotFoundError`, `IndentationError`, `TabError`. A dotted Python name is read by its last part (`builtins.TypeError`). `KeyError`, `IndexError` and `ZeroDivisionError` are outside the spec's list and count as thrown.
- **System codes.** An error with a Node code (`ERR_*`) or a system code (`E` and capitals, `ECONNREFUSED`) is not deliberate, whatever its class: the missing dynamic import above, a refused connection. Only the error's own code is read, not its causes'.
- **node:test codes.** node:test errors now record the thrown value's `code`, except on an `AssertionError`, so a node:test assertion summary does not gain `(ERR_ASSERTION)`. A node:test summary of a coded error now names the code, as Vitest's already did (task 001-361's `withCode`).
- **Several errors in one Vitest test.** A hook in `run` state marks every error of the test `hook`, so a body throw followed by a failing `afterEach` reads `hook`. Conservative.
- **Unknown stage.** Records without `stage` (older stored results, `squeal ci record`, any runner path that does not set it) keep a plain `Error` as `error`. A stored red side recorded before this row must run again to count as thrown.
- **`--red-error`** matches the error's own message (not its causes, not its stack), case-sensitive substring; an empty text is a usage error, since it would accept every failure. It accepts hooks, timeouts, engine errors and file teardown (`after-tests`), not `import` and `setup`. It applies to the red side and the control run, not the green side.
- **Reason text.** `KIND_TEXT.error` reads `a test threw an engine error, or an error outside its body`; P7's `notRunWhy` for a red side that does not count reads `red failed for another reason: nothing to prove` (was `red did not fail on an assertion`).
- **pytest `pytest.fail()`** raises `Failed`: counted as thrown (deliberate). Not probed: pytest-timeout fails a test through `pytest.fail`, I expect, so its timeout would count as thrown; Squeal records no pytest timeout marker.
