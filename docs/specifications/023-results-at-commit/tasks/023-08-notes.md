## Flow

1. Locate the worktree, `--base` and committed `HEAD`; named paths relative to the root.
2. Current side of the named files (`nowSide`, paths = the named files): daemon, else the gate keyer in the worktree. When the daemon has no trusted closure for a named file, the keyer is used (`keyed: true`).
3. Dirty: paths a named test loads (and the test itself) that `git diff HEAD` or the untracked list holds. When any: one line says the proof is of `HEAD`, and the green side is not read from the current side.
4. Case: `--case`, or `defaultCase` per file over the diff `base..HEAD` and the closure now; files that need different cases, or no case, are a usage error (exit 2).
5. Red side (`runSide`): `sideKeys` at the code version with the named files and `testSideCopies` (test-side paths the test version holds otherwise) copied in. The install, then the whole-checkout check against the side's expected tree. In `beforeRemove`, per keyed file: `missingImport` → `not comparable (imports <path>, absent at <code>)`; D4.9 `needsOf` → `not comparable (needs <path>)`; a stored result at the key (checkout unchanged) → read; else run. Runs go through `runInChild` with `store: changed === null`, read back by `outcomesOf`. The failure records come from the gate's answer (`GateFileRun.failed`) or the stored records (`endOfRecords`).
6. Green side, only for files whose red side failed on assertions alone: read from the current side (pass or fail) when nothing is dirty; else, or with no result now, `runSide` at `HEAD` over `HEAD`.
7. Verdict per file, report, exit (`proofExit`).

One budget (`--timeout`, 600 s) over the whole call: each side's run gets what is left; each install gets `min(300 s, left)`.

## Decisions the spec did not settle

- **Test side.** Runners do not give their include globs, so a path is test-side when it is a named test, lies in a folder named `test`, `tests`, `__tests__`, `spec`, `specs`, `__mocks__`, `fixtures`, `__fixtures__`, `__snapshots__` or `testdata`, or has a test file's name (`*.test.*`, `*.spec.*`, `*_test.*`, `test_*.py`). A helper in another folder (for example `src/test-utils.ts`) counts as code.
- **Copy set.** Every test-side path the test version holds otherwise than the code version, not only those the test loads: the closure at the test version is only known after keying in the checkout, and a file the test does not load changes neither its key nor its run. Test-side paths the test version lacks are not deleted from the checkout.
- **Missing source import.** A code-side path in the closure in the side's checkout that the code version lacks and the test version holds. Resolution candidates both versions lack are no import.
- **Assertion.** An error whose class name is `AssertionError` or whose code is `ERR_ASSERTION`, with no `phase` and no recorded `loadAverage`. A failed test is an assertion only when every error it recorded is one; a failure with no recorded error is not. A missing named export fails inside the test as a `TypeError` in Vitest (probed: `(0, __vite_ssr_import_1__.b) is not a function`), so it reads `red for another reason`; so does a fix for a crash (the old code throws `TypeError`). Kinds: `import` (phase `load`), `setup`, `hook` (`after-tests`), `timeout` (a recorded load average; absent on Windows, where a timeout reads `error`), `error`.
- **Red side not finished** (budget stopped it): `red for another reason`. **Not started** for want of budget: `not comparable (not run (budget))`. A failed node:test `prepare`: `red for another reason`.
- **Green side** is read or run only after a red side that failed on assertions alone; for every other red verdict it is `null` (`green: not read`), and the second call of a proven file reads both sides with no run.
- **Exit.** 3 outweighs 1 when files have both (an unknown answer, as D1).
- **Default case per file**; files that need different cases are refused with a usage error asking for `--case` or separate calls.
- **Dirty tree** (decided in the brief): the dirty check covers the named tests and their closures now; when dirty, the green side runs in a checkout at `HEAD` (its stored result there is read first).
- **A named test not committed at `HEAD`** reads `not comparable` (absent at `HEAD`) in the source case, with the dirty line: commit it first.
- The run count is the files that ran, summed over both sides.
