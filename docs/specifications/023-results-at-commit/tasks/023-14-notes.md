## Why the shadow half is held

`squeal ci export` keys a file only when the shard's evidence holds every closure path (018 D9). Vite 8 resolves relative imports in rolldown's native resolver (`viteResolvePlugin`, `vite/dist/node/chunks/node.js` 28952), so `evidence.cjs` never sees the probe of `src/registry.js` and the export leaves the file out ("its shard recorded other content, or none, for src/registry, src/registry.js ..."). The manifests are evidenced, because Vite reads each module's nearest `package.json` in JavaScript for its module type. `test/ci/resolution-import.test.ts` in the shadow commit pins the gap. Option A (coordinator, to the human): a row that records evidence for the shadow paths in the shard, or a certifier rule for them.

## Decisions the brief did not settle

1. Specifiers come from the module's source, parsed once per transform; the import targets come from the walk's edges. A module the parser cannot read adds nothing (its imports key as before).
2. A manifest that does not parse never reaches `manifestName`: Vite 8's resolver rejects it (`JSONError`), so no module below it has a transform. A manifest edited between Vite's read and ours throws, and the closure call fails as a state until the re-resolve. No `catch` (no case could run it).
3. Self-reference is matched by name only (Vite also needs `exports`): an over-run at worst.
4. Not modelled: tsconfig `paths` and aliases (declared incomplete, D3); the target of a `#` entry (a shadow of it); a relative `require`; setup and `globalSetup` closures (the environment hash), which get no resolution inputs.
5. Closure lists stored by an earlier release lack the new paths until the file is walked again (a miss or an edit). No adapter-version raise, as the brief says; the gap closes file by file.
