## Flow

1. The budget clock starts before `commitSide` (D4.6); the install's timeout is `min(300 s, --timeout)`.
2. `withCheckout`: sweep, checkout, install; then `git status --porcelain --untracked-files=no` in the tree. A tracked change fails the checkout as `install: <command> changed files git holds at <sha>: <paths>`: no keys, no run, nothing stored (B5).
3. Keying; then `whileOpen` selects among files with no result (B4): a test file the diff `<commit>..HEAD` changes, the adapters' `affected(changed)` (direct and transitive: a changed config or setup file selects its project's files), and a declared input (`createDeclaredInputs(policy.inputs, changed)`). `--all-missing`: every file with no result.
4. D4.9 (B6): a `loads` path git does not hold at the commit refuses the file when it exists in the checkout, or in the user's worktree while untracked at `HEAD` (a generated input the checkout lacks). Absent in both (resolution candidates, a snapshot not written yet) is no reason. The gate runs a path under every project that lists it, so when one project of a path is refused, the other projects of that path are refused too (`it runs with <project>'s <path>, which needs <x>`).
5. `beforeRemove`: estimate (with `--all-missing`), then `runInChild`. The child is the CLI (`io.relaunch`) with the mark and `SQUEAL_CODE_GATE_PARENT`, `detached` (its own group), its group recorded in the marker (`recordGroup`). It runs `runGateFiles` under the command's environment as it started (B1: Vitest's `NODE_ENV` in the CLI process does not reach it) and writes its answer to `<checkout>/at-run-answer.json`. It watches its parent (`watchParent` → `endGroup`, as the gate's `--json` child does). Removal and the sweep stop the recorded group (`stopRecordedGroup`), with any process a test started in it (B3). The parent stops the group if the child outlives its budget by 60 s. Without `io.relaunch` the files read `not determined (run: no command to start the run's process with)`.
6. Outcomes (B2, B7): each run file, and each not-selected file with no result that shares a path with one, is read from the store at its own key, filtered by project and path. Found: `pass`/`fail`, origin `run`, `stored: true`. Not found: a run file takes the gate's outcome for its path only when every project's run of that path agrees (`stored: false`); else `not determined (its N projects ended differently, ...)`. A sibling not found keeps `no result`.
7. Text: `--run: X of N ... ran in its checkout, S stored at its keys`, and `K not stored: the gate keeps a result only with coverage on at <sha>` when S < X. JSON `run.stored`.

## Decisions the spec did not settle

- `run` origin text: `run by this command, stored` / `run by this command, not stored`.
- A file started and stopped by the budget reads `not run (budget)`, like one never started.
- The rerun's `--timeout`: spent before the gate plus twice the left files' estimate, rounded up to a minute, at least 60 s; with no stored duration, twice the given `--timeout`.
- The estimate line goes to stderr in both modes and into JSON `run.estimate`; the child's output goes to stderr in text mode only.
- `--all-missing` and `--timeout` without `--run` are usage errors. A failed checkout prints no `--run:` line.
- The child exits 0 with its answer in a file; the parent's report carries any error as `not determined (run: ...)`.
