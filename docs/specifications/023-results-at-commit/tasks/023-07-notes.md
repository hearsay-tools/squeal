## Flow

1. The budget clock starts before `commitSide` (D4.6); the install's timeout is `min(300 s, --timeout)`.
2. `withCheckout`: sweep, checkout, install; then the whole-checkout check: every path the commit tracks (`copied` aside) compared with the commit's own tree. Its first differing path is `changed` on `Checked` and `KeysAt`, and `beforeRemove`'s third argument. It never fails the checkout: the keys are made, and the CLI shows every key-based state as `not comparable (install changed the checkout: <path>)`. `sideKeys` turns each such key into reason `changed`. Measured on this repository (13,105 tracked files, 264 MB, load average about 44 on 24 CPUs): 1.06 to 1.17 s, of a 10.7 to 12.3 s one-file checkout.
3. Keying.
4. `whileOpen` selects among files with no result (B4): a test file the diff `<commit>..HEAD` changes, the adapters' `affected(changed)` (direct and transitive: a changed config or setup file selects its project's files), and a declared input (`createDeclaredInputs(policy.inputs, changed)`). `--all-missing`: every file with no result.
5. D4.9 (B6): a `loads` path git does not hold at the commit refuses the file when it exists in the checkout, or in the user's worktree while untracked at `HEAD` (a generated input the checkout lacks). Absent in both (resolution candidates, a snapshot not written yet) is no reason. The gate runs a path under every project that lists it, so when one project of a path is refused, the other projects of that path are refused too (`it runs with <project>'s <path>, which needs <x>`).
6. `beforeRemove`: estimate (with `--all-missing`), then `runInChild`, with `store: false` when the checkout changed (the gate neither reads nor keeps results then). The child is the CLI (`io.relaunch`) with the mark and `SQUEAL_CODE_GATE_PARENT`, `detached` (its own group), its group recorded in the marker (`recordGroup`). It runs `runGateFiles` under the command's environment as it started (B1) and writes its answer to `<checkout>/at-run-answer.json`. It watches its parent (`watchParent` → `endGroup`). Removal and the sweep stop the recorded group (B3). The parent stops the group if the child outlives its budget by 60 s. Without `io.relaunch` the files read `not determined (run: no command to start the run's process with)`.
7. Outcomes (B2, B7): each run file, and each not-selected file with no result that shares a path with one, is read from the store at its own key, filtered by project and path. Found: `pass`/`fail`, origin `run`, `stored: true`. Not found: a run file takes the gate's outcome for its path only when every project's run of that path agrees (`stored: false`). After a changed checkout no store is read: each run file's outcome is shown as `not comparable` with `ran: pass|fail` (text `pass when run, not stored (install changed the checkout: <path>)`), and `run.notComparable` counts it.
8. Text: `--run: X of N ... ran in its checkout, S stored at its keys`; `K not stored (install changed the checkout: <path>)` after a changed checkout, else `K not stored: the gate keeps a result only with coverage on at <sha>`; the header line `The install changed the checkout (<path> differs from <sha>) ...`. JSON: top-level `changed` and `inputCheckMs`, `run.stored`, `run.changed`, `run.notComparable` (D4.9 refusals and changed-checkout runs).

## Decisions the spec did not settle

- `run` origin text: `run by this command, stored` / `run by this command, not stored`.
- A file started and stopped by the budget reads `not run (budget)`, like one never started.
- The rerun's `--timeout`: spent before the gate plus twice the left files' estimate, rounded up to a minute, at least 60 s; with no stored duration, twice the given `--timeout`.
- The estimate line goes to stderr in both modes and into JSON `run.estimate`; the child's output goes to stderr in text mode only.
- `--all-missing` and `--timeout` without `--run` are usage errors. A failed checkout prints no `--run:` line.
- The child exits 0 with its answer in a file; the parent's report carries any error as `not determined (run: ...)`.

## Left over


- The estimate counts every file as Vitest at `availableParallelism() - 1` (review nonblocking note); node:test entries and host-load scaling are not in it.
