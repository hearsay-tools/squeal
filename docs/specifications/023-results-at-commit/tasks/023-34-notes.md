## What each item does

- **T5.** `status --at … --wait` prints one line and exits 2: `squeal status: --at takes no --wait; --run waits up to --timeout (300 s)`. `parseAt` returns `AT_NO_WAIT`; `main.ts` prints it without the help.
- **T4.** The commit side runs first, so before the working tree's turn the call knows which selected files the gate ran and did not keep (`unkept`, `status-at-run-unkept.ts`). The working tree runs those files through the gate in a child, never through the daemon: the daemon's answer gives no outcome for a file it does not keep. The gate's answer gives the outcome (`unkeptNow`), and the working tree's side reads it when the store has no result (`withUnkept`). Both sides then read `pass -> pass (this run, not stored)`. Nothing is stored. Files the daemon ran and did not keep go through the gate once in the last pass. The gate path moved to `status-at-run-now-gate.ts`.
- **T1, no refusal.** Every `--run` call runs to its budget; none is refused before or while it runs (the human, 2026-11-21, after the wave-20 re-review: both guesses at the fit, 20 s per round and the first batch's rate, refused selections that fit). What did not start is taken back from the daemon, and the report gives R4's estimate and how to narrow. `test/cli/status-at-run-cold.test.ts` holds the review's two witnesses.
- **T1, take-back.** Each `--at --run` call makes its own identity (`owner`) before its first daemon request. It sends the owner on every `run-group-paths` request, with `lead` when the call named paths. A narrow run claims the queue entries it queued or shares (`RunQueue.claim`). An entry that anything else queues again (an edit, catch-up, a demoted reader, a forced or ordinary request) becomes nobody's, and no take-back removes it (review wave-20 B1). At the call's end, its daemon files first get the rest of the budget (`giveBack`). Then `take-back {owners}` always goes out. `Scheduler.takeBack` first cancels the owners, so a request the scheduler has not taken yet queues nothing when it is taken (B3). Then it removes every entry that no request and nothing else needs, if it has not started. A running file goes on; one another promotion holds stays. The report gives three counts: taken back, still running, and kept queued. An older daemon answers "unknown request type"; the report then keeps today's line "their runs go on in the daemon".
- **T1, named files lead (B2).** A narrow run with `lead` forms a batch that takes its files out of earlier batches and ranks ahead of every other batch, the later leading batch first (`Promotions.add`, `rank`). The tier in flight is not cut.
