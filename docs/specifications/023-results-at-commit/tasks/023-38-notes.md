# Row 023-38 notes: the commit worktree (D7.1, D7.4, D7.7)

What rows 023-39 and 023-40 need to know.

## Seam (agreed with the coordinator, 2026-11-21)

`src/core/checkout/commit-worktree.ts`:

- `ensureCommitWorktree({ root, commit, environment?, limit?, dir?, cacheRoot?, note?, placeWaitMs? })` returns `{ tree, folder, commit, fingerprint, commonDir }`. It finds or makes the worktree and installs it once. It starts no daemon. Row 023-40 calls it, then starts the daemon in `tree`.
- `readCommitWorktree(root)` returns the `CommitWorktreeMarker` (`commit`, `fingerprint`, `commonDir`, `createdAt`, `daemon?`) when `root` is a commit worktree, else `null`. Row 023-39 uses it to detect commit mode.
- `claimCommitWorktree(tree)`: the commit daemon calls it once at start, after it holds its daemon lock. It writes the daemon's lease into the marker.
- `removeCommitWorktree(tree, { note?, lockWaitMs? })`: the daemon calls it at exit. It never throws. It removes nothing when the tree is not a commit worktree or is gone. It keeps the worktree when another live process owns it now.

## Layout and ownership

- Folder: `<checkouts dir>/commit-<commit>-<fingerprint>/` with `marker.json`, `tree/`, `run/` and `install.lock`. The checkouts dir is D4.2's (`locateCheckouts`). The name is fixed by the commit and the fingerprint, so every caller finds the same folder under the checkout lock.
- Fingerprint: sha256 of the Node version, platform, arch and the allow-listed variables the caller passes (`environment`), first 16 hex digits. The commit fixes every file git holds.
- Marker: the plain checkout marker plus `fingerprint` (present only on a commit worktree), `daemon` (after the claim) and `installed`. The owner is `daemon ?? owner` (`ownerOf`). The sweep and `ps` use it.
- Takeover: a caller that finds the worktree with its owner gone writes itself as the owner and drops `daemon`. A dying daemon's later `removeCommitWorktree` then keeps the worktree.
- Gap for 023-40: before the claim, the creator is the owner. The creator must stay alive until the daemon has claimed the worktree. If it does not, a sweep in that window removes the worktree.

## Ceiling (D7.4)

- `commitWorktreeCeiling({ configured?, freeBytes?, perDaemonBytes? })` in `commit-places.ts`: free memory divided by 1 GB, at least 1. A configured whole number of at least 1 is used instead. The default estimate is the coordinator's (2026-11-21). Row 023-40 measures commit mode and may lower it.
- The count is machine-wide: the live commit worktrees under the cache root, plus this repository's git-folder dir. A lock at `<cache root>/commit-places.lock` covers the count and the creation.
- When the ceiling is full, the creator says once `squeal: waiting for a place: N of M commit worktrees live (...)`, then polls every second. It gives up after `placeWaitMs` (default 10 minutes). The worktree the caller asks for never waits.
- Config: row 023-40 reads the `squeal.config.json` key and passes `limit`. This row adds no schema change.

## Visibility

- `squeal ps` labels a commit worktree `commit worktree` and shows `daemon pid N` once a daemon claimed it (`PsCheckout.kind`, `PsCheckout.daemon`; an additive change in `src/core/ps`, coordinator-approved). A worktree whose owner is dead gets the existing `dead-checkout` flag.
- `squeal stop --at <commit>` (`src/cli/stop-at.ts`) works on the commit worktrees of this repository at that commit. It sends `stop` to the daemon socket and waits for the socket to close and for the claimed daemon's process to end. Then it calls `removeCommitWorktree`. Plain `squeal stop` does not touch commit worktrees.

## Repair after review wave-22 (B1, B3, N1)

- **Identity (B1).** `commitIdentity(tree)` in `src/core/checkout/commit-identity.ts` is the one check that read, claim, removal, `ensureCommitWorktree`'s reuse and the sweep use. A tree is a commit worktree only when: its folder is `commit-<commit>-<fingerprint>` from its marker; the folder's parent is `gitCheckoutsDir(commonDir)` or a cache dir named `worktreeIdOfRealPath(commonDir)` (any cache root, since a daemon's environment may name another one than its creator's); its `.git` is a file naming `<commonDir>/worktrees/<id>`, whose `gitdir` names the tree back; and git holds it locked with the reason `squeal`. Removal checks it again under the checkout lock.
- **Removal deletes only what Squeal made.** `removeCommitFolder` ends the install group and the processes left under the folder, removes the tree through `git worktree remove --force`, then removes only `marker.json` (and its temp files), `run/` and `install.lock*`. Anything else stays, and `note` names it. When git leaves the tree, the folder stays and the sweep tries again later.
- **`dir` must be a checkout location.** `ensureCommitWorktree` throws when `dir` is not one of the two locations. The wired daemon test no longer passes `dir` (agreed with the coordinator).
- **Machine-wide ceiling (B3).** Each new commit worktree is registered under the places lock at `<cache root>/commit-places/<sha256(folder)[:16]>.json` (`{ v, folder }`). The count is the commit worktrees under the cache root, plus the caller's dirs, plus the registrations, each folder once, with dead owners left out. A count removes a registration whose folder is gone or fails the identity check. It keeps the registration of a dead owner's worktree: a caller can take that worktree over, and it does not wait for a place to do so. Reuse registers again, so a lost registration is restored, and it never waits for a place.
- **Note for `ps`.** `cacheRepositoryDirs` now also lists `commit-places/`. It holds only files, so `listCheckouts` finds no checkouts there.

## Repair after re-review wave-22 (N2, N3; row 023-40b)

- **Kept folder stays Squeal's (N2).** When removal keeps a file Squeal did not make, the marker stays in the folder, without `group` and `installed`. The folder is then a *treeless commit folder*: its marker has a fingerprint, its name and location pass the identity rules, and its tree is gone (`treelessCommitFolder` in `commit-identity.ts`). The sweep and `ensureCommitWorktree` clear such a folder with `removeCommitFolder`, not with the recursive `removeTree`: Squeal's files go, other files stay, and `note` names them on every sweep. When only Squeal's files are left, the folder goes. A new worktree at the same commit is made in the same folder, beside the kept files. A create that stopped before `git worktree add` leaves the same shape and is cleared the same way.
- **Unreadable is not removed (N3).** `pathState(path)` reads `lstat` error codes: missing (ENOENT, ENOTDIR) is `removed`, present is `kept`, any other error (EACCES) is `unknown`. `removeCommitWorktree` now returns that outcome (`CommitRemoval`, an additive type change; it was `void`) and notes `could not read <tree>` when it cannot read the tree. `removeCommitFolder` never throws now; it returns the outcome too. `foundPlace` uses `lstatOrNull`, so an unreadable folder fails the call instead of counting as missing.
- **Daemon exit text (coordinator-approved, separate commit).** `CommitWorktrees.remove` returns the outcome; `removalText` takes it and has a third text, `the commit worktree may still be there (<root>): Squeal could not read it`. A test stub that returns nothing falls back to `pathState(root)`, not `existsSync`.
- **Tests.** `test/checkout/commit-kept.test.ts`: in both D4.2 locations, a kept file survives the later sweep and a new create at the same commit, and the folder goes once the file is gone; an unreadable tree is `unknown` (skipped where permissions do not bind: root or a capability that bypasses them). `test/daemon/commit-removal.test.ts`: the `unknown` outcome gives the new text. Red controls: the old sweep fails the two sweep tests; `foundPlace` without the treeless branch fails the two create tests.
- **Not changed.** A folder whose tree is still there but fails the identity check (for example after git refused the removal and the lock was gone) still goes through `removeTree`, as before.

## Repair after review wave-23 (N1)

- **An identity-failed folder stays whole.** A folder with a commit worktree's marker (it has a fingerprint) whose tree is there but fails `commitIdentity` is never removed recursively. Examples: git no longer holds the tree locked, or a removal left the tree without its `.git`. The sweep keeps the whole folder: tree, Squeal's own files and every other file. Each sweep notes `squeal: kept <folder>: its tree is not a commit worktree Squeal made; check it and remove it by hand` (`identityFailedNote` in `commit-identity.ts`). The kept folder is not in the sweep's result. `foundPlace` (`commit-worktree.ts`) no longer sends such a folder to `removeTree` either: a missing `.git` or another repository's `commonDir` in a fingerprint marker now fails the call with `<tree> is in the way`, as an unlocked whole tree already did.
- **Why Squeal's own files stay too.** Removing the marker would make the folder markerless, and the next sweep removes a markerless folder recursively (D6). `run` and the install lock are small; keeping them is safe.
- **Other paths reviewed.** `removeTree` is still reached by: a folder with no marker (D6's half-made create) and a plain checkout's marker (no fingerprint) in the sweep and in `foundPlace`; `addCheckout`'s failure cleanup of the folder it just made; `removeCheckout` in `at-keys-walk.ts` for its own plain checkout. None of these follows a failed identity check. `removeCommitWorktree` and the daemon exit path return early when identity fails. Outside this row's files, `squeal ps` (`src/core/ps/checkouts.ts`) still prints `rm -rf <folder>` as the `dead-checkout` command for a dead commit folder, also when its tree fails identity; a person runs it, Squeal does not. That is left for the coordinator.
- **Tests.** `test/checkout/commit-identity-failed.test.ts`, in both D4.2 locations: the reviewer's probe (made through `ensureCommitWorktree`, claimed, `user-file.txt` beside the tree, `git worktree unlock`, dead daemon lease) survives two sweeps with the tree, its files and `.git`, and each sweep gives the note; a tree without `.git` survives the sweep and stops a new create; an unlocked tree and a tree without `.git` each stop a new create without a sweep and keep every file. Red control: before the fix, 6 of the 8 failed (the sweep returned no note and deleted the folder; the create over a tree without `.git` resolved after a recursive removal). The 2 that passed are the unlocked-tree create cases, which review wave-22 B1 already covered.
