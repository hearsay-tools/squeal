## Result

**Cause found: the `.git` entry.** `packages/cezar/src/home/runtime-cli.test.ts` reads the repository's `.git` at run time, so `.git` is in its observed set. Squeal hashes that entry by its kind, not its bytes (`gitEntryByKind`, `src/core/keys/observed.ts`). In round 4's clone, a main checkout, `.git` is a directory. In Squeal's temporary checkout, made with `git worktree add`, `.git` is a file. Every other input of the key is equal, so the two keys differ. The commit side has no result at its key, and the working tree passes at its own key: `no result -> pass`.

**No code change** (the coordinator chose option A, 2026-11-20). The checkout is a different kind of tree from a main checkout, and the key says so on purpose: a test that reads `.git` can behave differently in a linked worktree. `--run --all-missing` runs the file in the checkout and stores its result at the checkout's key, and the comparison then reads it `unchanged` (shown below). Options B and C are recorded below for a later row.

## Why row 023-25 did not reproduce it

023-25 ran Squeal built from source with `tsrs` alone (runs 1 to 7: "built from source", "built from its tag"). That build has no `recorder.cjs`: `dist/runners/observe/` of 0.1.577 built the same way holds none. So `observeRecorder()` finds no recorder, and no run records what it reads. This matches 023-25's own finding that the store held no `observed.*` meta after a full run. Without the observed set, `.git` enters no key, and both sides were equal. The released plugin carries the recorder (`dist/observe/`), so round 3 and round 4 recorded it.

**Lesson for later probes**: run Squeal from the release, or from a full `pnpm run build`'s plugin bundle. A `tsrs`-only `dist/` silently drops runtime observation, and a probe built that way cannot see an observed input.

## The browser files (not round 4's evidence)

These were seen only here, because Chrome started. 6 browser files also read `no result -> pass` or `-> fail`. The probe on `packages/web/e2e/settings-agents.e2e.ts` names a different input: `.ai/qa/served/s7-01/.git/cezar-moved-projects/<hash>.json` is present in the clone and absent in the checkout. squawk's e2e harness writes it under the ignored `.ai/qa/` during a run, and the path holds the clone's folder name. This is a real difference in what the run sees, not a keying fault. In the `--all-missing` run, Squeal did not keep 4 of these files' results, because they "read paths first seen during the run"; it did not keep 1 because "what its key names changed during the run" (`.ai/qa/cez-home/config/install.json`). Both are the store rule working as intended.

## Options not taken

- **B, checkout setup.** When the user's tree has a `.git` directory, make the temporary checkout a shared clone (`git clone --shared --no-checkout`, then `checkout --detach <commit>`) instead of `git worktree add`, so both sides are "directory".
  - Cost: it amends D4.1 and D4.2 (a detached, locked worktree), and changes create, remove and the sweep in `src/core/checkout/`.
  - Risk: tests in the checkout would then see a separate repository, with their own refs and `origin` set to the user's repository. That can change other tests that read Git state.
- **C, keyer.** In a checkout, hash `.git` by the kind of the user's tree.
  - Cost: it touches the gate keyer.
  - Risk: it breaks "never store what the checkout does not match". A `--run` result from the checkout would claim a `.git` directory the run did not see.
- **A report line** (row 023-29's files) could name the cause where a file reads `no result` at the commit only because of the `.git` kind. For example: "reads `.git`, a directory here and a file in Squeal's checkout: `--run --all-missing` runs it there".
