Outcome: `squeal proof <test file>... --base <commit> [--case source|dependency|test] [--timeout <seconds>] [--json]` gives a verdict per named test file for the `source` and `test` cases, reading each side from the store first and running only the sides with no usable result. `dependency`, `--env`, `--without` and `--repeat` belong to 023-11: this row parses them and refuses them as usage errors (exit 2) with one line naming row 023-11's behaviour as not built yet; `--case dependency` is refused the same way.

- **Sides (D5 table).** `source`: red = the test at `HEAD` over the code at `--base`; green = the test and code at `HEAD`. `test`: red = the test at `--base` over the code at `HEAD`; green = `HEAD`. Default case as D5's table says, from the diff `<base>..HEAD` and the named test's closure; when neither default applies, a usage error asks for `--case`. Sides use committed `HEAD`. When the working tree differs from `HEAD` on a path a named test loads, print one line that the proof is of `HEAD`, not the uncommitted change (decided here; not in the spec).
- **Store first (D5.1).** The green side is read the way `status --at`'s current side is (daemon, else the gate keyer). The red side is keyed by the gate keyer in D4's checkout at the side's code version with the side's test version copied in, then looked up; a stored result there is read, not run. Normally one side of one file runs.
- **Test-file copy (D5.2).** Copy the named test and the test-side files it imports that the code version lacks or holds differently (helpers, fixtures, files under the project's test include globs) from the test version into the checkout before keying; pass them as `copied` to the whole-checkout check. A source file the test imports that the code version lacks: the file reads `not comparable (imports <path>, absent at <commit>)` and does not run (human, 2026-11-16).
- **Storing a side's run.** Store a side's result only when the whole-checkout check passes against the side's expected tree (the code version's tree with the copied paths at their test-version blobs); otherwise show it as 023-07 does (`not stored (install changed the checkout: <path>)`). The verdict uses the run's outcome either way.
- **Verdicts (D5.5)** and **exit codes (D5.6)** as the spec says. Tell an assertion failure apart from an import, setup, collection or timeout failure from the runner's own failure records (as `squeal why` reads them); no text matching on messages in English. The report carries the red side's failed tests with their failure text, both commits, the case and the run count; the JSON is versioned like `status --at`'s.
