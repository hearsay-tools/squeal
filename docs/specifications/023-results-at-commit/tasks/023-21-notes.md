## Decisions the brief did not settle

- **Which changed files stop (spec D5.2 as amended 2026-11-19, last by the human after `reviews/wave-14-sixth.md`, "A: every changed file").** When a named test is unchanged, the set is every file changed between the commits, not the files Squeal saw the test use: no record of what a test used is complete (folder listings, files a config imports, declared inputs read in a child, coverage off, child processes). A file that did not change is the same on both sides and cannot change the verdict, so the rule is complete by construction. The fifth look's after-run input check (`core/proof/inputs.ts`, the second check in `prove`) and the closure-based detection are removed; the stop is decided before any run. History: names (review B1), test-API imports (re-review), non-test importers (third look), parser-checked imports (fourth look), the keyed closure plus recorded reads (fifth look); each review found a changed input that the rule missed and that gave a false `proven`.
- **Read marks.** The stop marks the files Squeal saw the test read: its keyed closure in the green checkout (`at.loads`) and the repository's shared observed rows (reads, module loads, direct marks; a listed folder such as `support/` marks the changed files under it). Help only: an unmarked file stops the same way, and a mark settles nothing. The rows are read from the main store before the runs (`src/cli/proof-inputs.ts`).
- **The case.** The default case is D5's from the keyed closure, `--source` beating the test-side name rule; when the closure of an unchanged test holds no changed file (a file read, a listing, a config's setting), the flags decide: `source` when a `--source` path changed, else `test` (`proof-case.ts` `flagCase`).
- **`--source` warning.** A `--source` path that is not a changed file between the commits reads `Warning: --source <path>: not a changed file between <base> and HEAD; it settles nothing.`
- **No name rule.** `--source` beats the test-side name rule in copies, the default case and the absent-import refusal (`sides.ts`); `proof-side.ts` only passes the set to `missingImport`. A changed named test keeps the earlier rules: test-side files copied from the test version, the rest at each side's code version.
- **The stop needs no source change.** Any changed file neither flag names stops the file; with `--with` the default case becomes `test` (only test-side paths changed), so a helper-only fix proves as a test case.
- **The two reruns** are the call's own command (conditions, `--repeat`, `--red-error`, quoting kept, in the D1 synopsis order `--repeat`, `--with`, `--source`, `--red-error`) plus every changed import neither flag named, from the cwd, all as `--source` in one and all as `--with` in the other; flags already given are kept first; `--timeout` only when it is not the default. Files from every stopped file go in one line. The third line says the agent may name each file with either flag.
- **The warning** uses the closures at `HEAD` from the green checkout; with no named file keyed there, no warning is given (nothing is known).
- **JSON sides** always carry `with` and `source` (empty lists without the flags). Added fields only; `squeal-proof/1` stays.
- **`--with` of a named file** is dropped (it is named already); a path given twice counts once.
