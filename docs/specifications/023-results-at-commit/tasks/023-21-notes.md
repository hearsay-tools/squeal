## Decisions the brief did not settle

- **Which changed imports stop (spec D5.2 as amended 2026-11-19, last by the human after `reviews/wave-14-fourth.md`, "A: stop guessing").** Squeal does not decide whether a changed import is test or product code. Every changed file in an unchanged named test's closure (directly or through other files, added ones included) stops the file unless `--with` or `--source` names it. Paths on the test side (`isTestSide`: test folders, test file names, the named files, the `--with` paths) are not stops: D5.2's test-side copy rule already copies them from the test version, and that detection is kept as it was. History: the first build read a helper by its name (review B1); the second read test code from a file's own test-API import (barrel and data-only cases, re-review); the third required a non-test importer (aliases and a commented import, third look); the fourth checked every import with Squeal's parsers (a declared package re-exporting vitest and `require /* c */ ("node:test")`, fourth look). Each found test code that read as product code and gave a false `proven`. The classifier (`import-graph.ts`, the importer search, the declared-package and parser-reuse code in `proof-imports.ts`) is removed; core proof no longer imports runner-graph parsers.
- **No name rule (fifth look 1, the coordinator's choice of the simpler option).** For an unchanged named test, a changed file under `test/`, `fixtures/` or with a test name stops like any other; `isTestSide` no longer exempts it in `imports.ts`. The copy-when-absent-at-base rule is not kept as an exception either: a test-side file that is new at HEAD is a changed file too, so it stops until a flag names it. `--source` beats the name rule wherever it applies (`sides.ts`: `isTestSide`, `testSideCopies`, `defaultCase`, `missingImport` take the `--source` set; `proof-side.ts` only passes it to `missingImport`), so `--source test/value.ts` keeps base's `test/value.ts` on the red side. Where the named test itself changed, the test-side copy rule stays as it was.
- **Inputs the runs read (fifth look 2).** The stop before the runs reads the keyed closure (`at.loads`). After the red side, and again after every run before any verdict, each unchanged named test's inputs are read as Squeal keeps them for keys: the keyed closure and the repository's shared observed rows (`observed`, `observedModules`, `observedDirect` for the file, `observedStartup` for its project; `src/cli/proof-inputs.ts`). Every kept run merges its reads there (`gate/keep-seen.ts` `mergeSeen`), so a computed `import()` and a `readFileSync` appear once a side ran or was read from the store; the store's rows are shared and never pruned, so the set can only be wider than this run's, which stops more, never less. Every changed runner config file counts as an input too, read or not (`core/proof/inputs.ts` `isRunnerConfig`: Vitest and Vite configs and workspaces, `squeal.config.json`, `pytest.ini`, `pyproject.toml`, `setup.cfg`, `tox.ini`, `conftest.py`): a Vitest `test.env` is in no read. A changed input the call did not name makes the file `not comparable (changed input <path> was not named)`, exit 3, with the two reruns, whatever its sides ended as; a file caught after the red side gets no green run. Results the runs stored stay stored. No gate or `proof-side.ts` change was needed: the observed rows are read from the main store.
- **A side that records no reads.** A forced side (a condition or `--repeat` above 1) stores and merges nothing, so its reads are unknown: an unchanged named test then counts every changed path of `base..HEAD` the call did not name, with `; a side under a condition records no reads, so no changed file may be left unnamed` (or the `--repeat` wording) in the reason. Naming every changed file lets it prove. A missing main store reads the same way.
- **Only unchanged named tests are checked.** D5.2's rule is for a named test unchanged between the sides; a changed named test keeps the earlier behavior (test-side files copied, the rest at each side's code version), so the common "new test plus fix" proof needs no flag.
- **Pytest.** A changed Python helper (`support/rows.py`) stops like any other changed import; no Python case needs a parser now (`test/proof/imports.test.ts`).
- **Detection is the recorded closure.** The changed files come from each named file's closure as keyed in the green checkout at `HEAD` (`f.at.loads`) and the diff `base..HEAD`; nothing else is read.
- **The stop needs no source change.** Any changed import neither flag names stops the file; with `--with` the default case becomes `test` (only test-side paths changed), so a helper-only fix proves as a test case.
- **The two reruns** are the call's own command (conditions, `--repeat`, `--red-error`, quoting kept, in the D1 synopsis order `--repeat`, `--with`, `--source`, `--red-error`) plus every changed import neither flag named, from the cwd, all as `--source` in one and all as `--with` in the other; flags already given are kept first; `--timeout` only when it is not the default. Files from every stopped file go in one line. The third line says the agent may name each file with either flag.
- **The warning** uses the closures at `HEAD` from the green checkout; with no named file keyed there, no warning is given (nothing is known).
- **JSON sides** always carry `with` and `source` (empty lists without the flags). Added fields only; `squeal-proof/1` stays.
- **`--with` of a named file** is dropped (it is named already); a path given twice counts once.
