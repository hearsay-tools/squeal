## Decisions the brief did not settle

- **Test code or source (repaired after `reviews/wave-14.md` B1, the coordinator's rule of 2026-11-19).** The first build took a changed code-side import for a helper only by its folder or name (`isHelperPath`) and every other one for source, so `support/rows.ts`, a helper that imports vitest, read `proven` from the old helper's failure (B1). Now each changed code-side import (direct or transitive, added ones included) is read from git at `HEAD` and at `base` and is **test code** when:
  1. its text at either commit imports a test API: the frameworks of Squeal's runners and the libraries commonly run under them (JavaScript and TypeScript: `vitest` and its subpaths, `@vitest/*`, `node:test`, `@playwright/test`, `@jest/globals`, `chai`, `sinon`, `@testing-library/*`; Python: `pytest`, `_pytest`, `unittest`). Import forms read: `from "x"`, `import "x"`, `import("x")`, `require("x")`; Python `import x` and `from x import` at a line's start. The runner adapters hold no such list (`src/runners/*/describe.ts`), so it lives in `testApiOf`;
  2. or it is pytest's `conftest.py`;
  3. or it has a known helper name or folder (`isHelperPath`), kept as an extra signal only.

  Test code stops the file as above. Every other changed import is **source**: compared as before, and named in the report. A runner config (`isConfigPath`) is never test code: it imports `vitest/config` and is compared as source. The runner's own test include is not available to the proof (runners do not give their include globs, `023-08-notes.md`); paths that look like tests by name or folder (`isTestSide`) are already copied from the test version, so they need no stop. No config is read: a project needs no declaration for the common case of an unchanged test over changed `src/value.ts` (still proven, with the note line).
- **Known blind spot.** A test helper that imports no test API, is not a conftest and has an ordinary name, for example `support/rows.ts` holding only data rows the test iterates, counts as source. A changed row there is compared at the base on the red side, as before this row. The report still names it under `source changes the proof compares`, with `if one is test code, rerun with --with <path>`, so the reading is visible, not silent. The coordinator puts this limit before the reviewer and the human.
- **Only source changed.** An unchanged test whose closure changed only in source files still runs: this is the ordinary "commit the failing test, then the fix" proof, a source file only tests import included. Stopping it would loop, since its rerun would add no `--with`.
- **The stop needs no source change.** Changed test code alone stops the file; with `--with` the default case becomes `test` (only test-side paths changed), so a helper-only fix proves as a test case.
- **The rerun line** is the call's own command plus the helpers as paths from the cwd, `--with` paths already given kept first; `--timeout` only when it is not the default. Helpers from every stopped file go in one line.
- **The warning** uses the closures at `HEAD` from the green checkout; with no named file keyed there, no warning is given (nothing is known).
- **JSON sides** always carry `with` (an empty list without `--with`). Added fields only; `squeal-proof/1` stays.
- **`--with` of a named file** is dropped (it is named already); a path given twice counts once.
