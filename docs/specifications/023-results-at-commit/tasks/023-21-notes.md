## Decisions the brief did not settle

- **Which changed imports stop (spec D5.2 as amended 2026-11-19, the human after the second review, "A: stop when unsure"; `reviews/wave-14-rereview.md` B1; evidence repaired after `reviews/wave-14-third.md`).** History: the first build settled a code-side import as source unless its name looked like a helper (review B1); the first repair took it for test code only when its own text imported a test API, and the re-review showed a helper that takes `it` and `expect` through an unchanged local barrel, and a data-only helper, still reading `proven`. Now, for each changed code-side import of an unchanged named test (direct or transitive, added ones included; `src/core/proof/imports.ts` `settle`):
  1. A `--source` path is product code.
  2. **Test code** stops it, named as test code: a test-side path (`isTestSide`, which stands for the runner's test include: runners do not give their globs), a named file or `--with` path, a `conftest.py`, or a file that reaches a test API directly or through local imports at `HEAD` or at `base` (`src/core/proof/import-graph.ts` `reachesTestApi`: a breadth-first walk over local specifiers, at most 5,000 files; past that the answer is unknown and the file is not settled). Test APIs: the frameworks of Squeal's runners and those commonly run under them (`vitest` and subpaths, `@vitest/*`, `node:test`, `@playwright/test`, `@jest/globals`, `chai`, `sinon`, `@testing-library/*`; Python `pytest`, `_pytest`, `unittest`). The runner adapters keep no such list.
  3. **Product code** when at least one project file that is not test code (rule 2, read at `HEAD` only) imports it. Importers are found with `git grep` for the file's name (its folder's for `index` or `__init__`) at `HEAD`, then each candidate's local imports are resolved to the path, so a mere mention does not count.
  4. Everything else stops, named as not known to be test or product code (a data-only helper, a file only tests import).

  Evidence (third look, `reviews/wave-14-third.md` 1 and 2): an importer settles a changed file only when `reachesTestApi` answers `none` for it at `HEAD`: every import it reaches is accounted for and none is a test API. The changed file itself must answer `none` at `HEAD` and `base` too. An import is accounted for when it is a local file the resolver finds (then followed), a builtin, a test API, or a bare package that the nearest `package.json` above the file or the root one declares in `dependencies`, `devDependencies`, `peerDependencies` or `optionalDependencies` (never the package's own name). In Python: a local module found from the file's package or folders, the standard library (the pytest graph's `stdlibNames`), or a top-level name that is no local module anywhere in the tree (an installed package). Anything else (a package `#imports` alias, a tsconfig `paths` alias, an undeclared bare name, a relative path that finds no file, a computed import, a source that does not parse) makes the answer unknown, and the why reads `could not resolve <specifier> in <file>`. A file with no settling importer stops with both reruns; the first unknown importer's why is shown. Aliases are refused, not resolved: full alias support is not needed to refuse safely (the review's words).
- **Which parser and resolver (third look).** Imports are read with Squeal's own parsers, never with text: JavaScript and TypeScript by the node:test graph's `parseModule` (`src/runners/node-test/graph/parse.ts`, es-module-lexer; type-only imports dropped; a computed `import()` or `require` makes the file unknown), its literal `require` calls kept only where `codeAt` (`src/runners/node-test/graph/code-ranges.ts`) says they are code; Python by the pytest graph's `parsePython` (tree-sitter-python). `git grep` only picks importer candidates by name; the parser decides. Squeal's existing resolver (`src/runners/node-test/graph/resolver.ts`, enhanced-resolve) reads the filesystem of a worktree, while proof reads both commits from git, so the relative-path rules are kept here (extension, `.js` as `.ts`, `index`; Python package paths) and every alias is refused instead of resolved. Reusing the runner's closure would need the green checkout's path from `proof-side.ts`, which another row owns this wave; a later row can switch to it.
- **Base or HEAD.** Test-API reach is read at `HEAD` and at `base`: a helper that imported vitest at base and no longer does is still test code. Importers are read at `HEAD` only: whether product code uses a file is a fact of the code the proof certifies; the red side's base code is the version under test, not the evidence. A file only base's product code imported stops, which is the safe side.
- **No name lists.** No file name settles anything (spec D5.2). `isHelperPath` and the runner-config exception of the first repair are gone: a changed `vitest.config.ts` in a closure reaches `vitest/config` and stops as test code.
- **Only product code changed.** An unchanged test whose closure changed only in settled product code still runs (the ordinary "commit the failing test, then the fix" proof). A source file only tests import now stops: `--source <path>` proves it.
- **The stop needs no source change.** An unsettled import alone stops the file; with `--with` the default case becomes `test` (only test-side paths changed), so a helper-only fix proves as a test case.
- **The two reruns** are the call's own command (conditions, `--repeat`, `--red-error`, quoting kept, in the D1 synopsis order `--repeat`, `--with`, `--source`, `--red-error`) plus the unsettled paths from the cwd, flags already given kept first; `--timeout` only when it is not the default. Paths from every stopped file go in one line. The `--source` rerun keeps the paths shown to be test code under `--with` and is absent when every unsettled path is test code.
- **The warning** uses the closures at `HEAD` from the green checkout; with no named file keyed there, no warning is given (nothing is known).
- **JSON sides** always carry `with` and `source` (empty lists without the flags). Added fields only; `squeal-proof/1` stays.
- **`--with` of a named file** is dropped (it is named already); a path given twice counts once.
