## Flow, beside 023-08's

1. `parseProof` collects the raw conditions; `locate` places each `--without` from the cwd: a path in the repository (not the root, not `.git`) is hidden in the checkout; else a path under the command's `HOME` is hidden through the run's own `HOME`; else exit 2 with one line.
2. Both sides take the same `conditions` and `repeat` (`Common`).
3. A side is *forced* when it has a condition or `repeat > 1` (`forcedReason`): no store-first read, runs with `store: false`, `outcomesOf` with `stored: false`, no store read of failure evidence. Its `notStored` says why.
4. `runFiles` runs the pending files up to `repeat` times, one `runInChild` per round, and stops a file at its first run that does not pass. The red side so stops at its first failure; a green side that fails is `not green` at once. Each round gets the budget left; with under 1 s left, the files still due read `not run (budget)` with the runs made so far.
5. The run's environment (`runEnv`): the command's, `--env` applied, and with a `HOME` path hidden, `HOME` set to `<checkout folder>/home`, made by `ownHome` once per side: empty but for the `--home-keep` copies (review wave-9 B1). The checkout's removal, or the next sweep after a kill, removes it (`proof-killed.test.ts` checks the real files after the sweep).
6. Keying and the install use the command's environment, not the conditioned one. Only the run sees the conditions.

## Review wave-9 repairs

- **B2 (no removal through a link).** `proof-locate.ts` `linkedWithout`: a repository `--without` path that is a link, or lies under one, in the base or `HEAD` tree (`linkOnPath`) is a usage error (exit 2, one line naming the link). Both checkouts hold those trees before their install, and copies refuse link parents (`copyIntoCheckout`). Backstop in the checkout: `at-keys-side.ts` `removeHidden` walks each parent with `lstat` and throws `CheckoutFailed` on a link or a file; the path itself, a link included, is removed by `rmSync`, which never follows it. Audit of every other write and delete in the proof and checkout code: `copyIntoCheckout` (link parents refused, exclusive copy); the link swap after it in `sideKeys` `prepare` (same call, parents already checked); `testSource` (a fresh `mkdtemp` folder); `removeTree` (`git worktree remove`, then `rmSync`, which removes links without following them); the run's request and answer files and the marker in the Squeal-owned checkout folder (written after the install, which runs the repository's own code and could already do anything, so out of this class).
- **B3 (a changed conditioned checkout).** `proof-side.ts`: when the whole-checkout check reports a change on a side with a condition, every file of that side reads `not comparable (install changed the checkout: <path>; the condition is not known to hold)` and nothing runs there. A side only repeated keeps 023-08's handling (runs, not stored); its not-stored reason now names the install change before the forced reason (`proof-run.ts`).
- **B1 (the run's own HOME), the human's "B", 2026-11-18.** Keying records no read under `HOME` (the recorder keeps only paths under the worktree root, `src/runners/observe/recorder.cjs`; the closure drops paths leaving it, `src/core/keys/closure.ts`), so the own `HOME` cannot be built from recorded reads. It now starts empty; `--home-keep <path under HOME>` (repeatable) copies a file or folder in (`src/core/proof/own-home.ts`: `placeKeep` at the command, `ownHome` per side). Byte copies with `lstat`, never through a link: a link in a kept path, or in a folder above it, is exit 2 with one line (`--home-keep X: ~/<path> is a link; a kept path must hold none`); so are a path outside `HOME`, a missing one, one inside a hidden path, and `--home-keep` with no `--without` path under `HOME`. The hidden path is never copied, even from a kept folder that holds it. A link that appears between the check and the copy fails that side's files as `not comparable (own HOME: ...)`. Nothing in the own `HOME` is a link, so `..`, aliases, writes and deletes there never reach the real `HOME`; its removal with the checkout removes only copies. A test that needs a `HOME` file nobody kept fails openly. The report's conditions name each kept path (`--home-keep X (copied into own HOME)`; JSON `conditions.homeKeep`), and the rerun line repeats them.

## Candidate CI of 0.1.562 (run 44299153586)

Three tests failed on both CI Node versions and passed here: `proof-repeat` (a flaky red side read `not red`; a green side that fails once read `proven`) and, on Node 22, `proof-review9` B1 (exit 3). Cause: the gate's load retry (row 020-54, `src/core/code/gate/retry.ts`). When a file fails while the one-minute load is over the CPU count, the gate runs it once more and keeps the rerun's result. CI's shared 4-vCPU shards run over that load; this host does not. A proof's run is one observation: the retry consumed a counter value and turned the red failure on round 2, and the green failure, into passes; the B1 probe's retry ran after its first attempt deleted its kept copies and threw `ENOENT` (red for another reason). The `squeal code` stderr line that names a load rerun is printed by the gate's verdict, not by `runGateFiles`, so the CI stderr showed none.

Fix: `status-at-run-child.ts` `RunRequest.retry` / `ChildRun.retry`; with `false` the child gives the gate `noLoadRetry` (`hostLoad` with the load unknown), so no failed file runs again. Every proof run passes `retry: false` (`proof-run.ts`). 023-07's `--run` keeps the retry. `test/cli/proof-load-retry.test.ts` reproduces the CI condition through the gate's own `hostLoad` option (no load made): an overloaded host turns a first failure into `passed`; the proof's reading keeps `failed`. The proof tests' failure messages now carry the command's stderr and its report (`proof-kit.ts` `why`).

## Decisions the spec did not settle

- **Forced means stored nowhere, for repeat too.** With `--repeat` above 1, every side (not only a `test` red side) runs and stores nothing. A stored pass cannot stand for n passes, and a store-on run of a key that already holds a result reads the store instead of running (`runGateFiles` with `store: true`).
- **Stop at the first run that does not pass, on both sides.** D5.4 stops red at its first failure; green must pass every time, so it stops at its first failure too: the verdict is the same and the budget is saved. The verdict uses that run's evidence.
- **Conditions are allowed in every case**, not only `dependency` (D5's table says `none` for `source`). The brief applies them "to both sides" without a case limit; refusing them in `source` would only lose information.
- **A repository path is hidden before the install**, in `prepare`. The install does not see it either; the check after the install fails (`install changed the checkout: <path>`) when the install puts it back.
- **`--env HOME=...` with a `--without` path under `HOME`** is a usage error: the run's own `HOME` would override it.
- **Whole `HOME` hidden** (`--without $HOME`): the run's `HOME` is an empty folder, and no path can be kept.
- **`--home-keep` details (B1).** Overlapping kept paths copy once (the outer one). A kept path below a folder copies only that path, with the folders above it made empty. Sockets, FIFOs and devices are not copied.
- **The rerun line's `--timeout`** is twice the given one, rounded up to the minute, at least 60 s (020's factor; no per-run estimate is kept for proofs). It repeats every condition, `--case` and `--repeat`.
- **Run counts.** `runs` in the report sums every run of every file on both sides; each side's `runs` counts its own runs of the file. A run the gate did not start does not count.
