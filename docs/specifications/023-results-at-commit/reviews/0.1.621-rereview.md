## Blockers

### B1. Proven: refreshing a waiter mark can erase the handover identity

Locations: `src/core/slow/slot-files.ts:109`, `:163`; `src/core/scheduler/slow-tier.ts:523`.

The S1 repair promises to keep yielding while the partner's same wait is open. The wait's identity now includes its mark's complete contents. `markSlotWaiter` rewrites that file with `writeFileSync`, which truncates it before writing. A reader in another process can observe the empty file during an ordinary refresh. That changes the identity, clears `#yieldedTo`, and lets the yielding side take another turn.

The independent probe uses `pair(30000)` and `holdFirst(commit, A)` from `slot-pairs-fixture.ts`. The commit side runs A; the tree side queues A/B/C and waits. After A ends, the probe waits for the commit side to publish `slot: "turn"`. It obtains the tree's mark from `slotWaiters`, saves its contents, and opens the mark with `openSync(path, "w")`. This pauses the writer at the normal refresh's truncation boundary. While that descriptor stays open and empty, the probe nudges the commit side and waits for rest.

Observed log: **`commit:a, commit:b`**. Expected: only `commit:a` until the tree side takes its turn. The tree still wants the slot. The probe restores the contents and closes the descriptor in `finally`.

This is a deterministic filesystem interleaving, not a claim that a synchronous write yields within one process. The two daemons are separate processes and can pause between the open and write operations.

**One-worker repair:** publish a complete mark atomically. Treat incomplete or unreadable identity conservatively so a transient read cannot cancel a recorded handover. Add a paused-refresh test through the real schedulers. Preserve dead-process and expiry recovery.

### B2. Proven: a recreated older-format mark keeps the new side yielding after partner turns

Locations: `src/core/slow/slot-files.ts:109`, `:163`, `:171`; `src/core/scheduler/slow-tier.ts:523`.

An older daemon writes only `<worktree>\n`. Each of its waits has the same identity in the new reader. If the old daemon takes a turn, clears its mark, then starts another wait before the new side runs again, the new side sees the identical mark. It keeps yielding to a wait that already received a turn. Regular refreshes keep this state fresh. `waiterRuns` treats the older mark as running because it contains no PID.

The independent protocol probe starts the new commit scheduler on A, with B/C still queued. It writes an old-format partner mark through `markSlotWaiter(dir, oldId, "browser")`, without a wait token. After A ends and the new side yields, the probe repeats this sequence three times while the new side is not scheduled:

1. Clear the old mark.
2. Acquire the actual shared SQLite permit as the old worktree; assert acquisition succeeds; release it.
3. Recreate the old-format mark.
4. Nudge the new commit scheduler.

All three partner permit turns succeed. The new scheduler's log remains **`commit:a`**. B does not run. This is a protocol compatibility reproduction, not an end-to-end run of an installed old daemon. It uses the older mark representation and real shared permits. The same sequence can repeat while the old participant has more work.

This reopens S1 at the new handover boundary: the partner can take repeated turns while the new side keeps yielding. It also disproves the repair notes' assertion that every waiter that takes a slot has a new identity on its next wait when older participants share the slot.

**One-worker repair:** use a bounded legacy fallback or evidence of partner turns that works with older marks. Do not retain an indefinite handover debt from identical legacy text. Add this clear/take/recreate case while keeping new-token alternation and three-side progress.

### B3. Proven: an unreadable permit is reported as “in use” without a holder

Location: `src/core/state/slot-now.ts:41` to `:45`.

The B2 repair promises to say “in use” only from the permits read now. `heldPermits` includes conservative `record.kind: "unreadable"` entries. These include malformed database files that no process holds. Counting every entry as evidence of a held permit turns uncertainty into a current occupancy claim.

The independent probe acquires and releases a browser permit normally. It then writes `not a database` into `group.browser.0.lock`, with no holder left open. It calls:

```ts
slotNow({
  kind: "waiting", for: "slot", slot: "held",

```

Actual result: **`{ kind: "waiting", for: "slot", slot: "in use" }`**. The reader knows only that the permit is unreadable. `test/slow/slot-holders.test.ts` already documents this distinction with an unheld malformed file.

**One-worker repair:** retain uncertain or historical wording when unreadable entries prevent proving all permits held. The existing “taken at its last try” fallback is sufficient. Keep conservative slot enforcement; do not declare malformed capacity free. Add the malformed-unheld permit through the live read and a text formatter.
