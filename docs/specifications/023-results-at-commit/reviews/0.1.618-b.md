### B1. Proven: native realpath and watch reads leave a path falsely certified as absent

Locations: `src/runners/observe/fs.cjs:78`, `:249`; `src/runners/observe/inputs.ts:118`; `src/core/scheduler/observed.ts:109`.

Wave 39 requires that every read found the path absent, with no read that found it present. The brief also requires conservative refusal when the recorder cannot determine a wrapper's outcome. The new certification trusts a set that misses successful reads through `fs.realpathSync.native`, `fs.realpath.native` and `fs.watch`.

`replace` preserves the original function's properties. Thus wrapping `realpathSync` and `realpath` copies their original, unwrapped `.native` functions. No watch wrapper records a present or unknown outcome. An earlier `existsSync` false remains the only outcome for the same path. This was a recorder coverage gap before the candidate; the new first-seen exemption turns it into a stored wrong result on the first run.

Three cheap probes used this sequence for each API: probe `probe.json` while absent; make it present through an outside-root alias; successfully call the API on its normal in-root spelling; remove it through the alias. Each returned:

```json

```

The alias prevented a recorded write from masking the outcome defect. The scheduler proof then used a separate parent process for the mutations, with no alias or child read:

1. Start a real Vitest adapter and scheduler with runtime observation enabled. Add one test file with a previously unread `data/native.json` path.
2. The test sees `existsSync(path) === false`, signals readiness outside the worktree, and waits.
3. The parent creates `data/native.json` and opens the gate. No watcher revision names this transient path.
4. The test successfully calls `realpathSync.native(path)`, asserts that it returned the path, and signals that the read finished.
5. The parent removes the file and opens the final gate. The test completes with a pass.
6. The scheduler stores that pass at the grown key with the path absent. Apply an unrelated revision and settle again.

Actual output:

The run's reported `absent` contained `data/native.json`. A fresh execution at this key would throw ENOENT at the native realpath assertion. Instead, the original pass stays current with no rerun. The regression assertion failed with `expected [ 'pass/current' ] to not include 'pass/current'`.

### B2. Proven: recording promise outcomes consumes unhandled read rejections

Location: `src/runners/observe/absent.cjs:87`.

The new promise branch attaches a rejection handler to the original promise with `result.then(...)`, ignores the chained promise, and returns the original. This marks the original rejection handled. The recorder's handler returns normally, so the ignored chained promise also resolves. A rejection the application did not handle disappears from Node's unhandled-rejection reporting.

The independent probe ran this script without observation, with the base recorder from `5ecdb3c51`, and with the candidate recorder:

```js
import { readFile } from "node:fs/promises";
process.on("unhandledRejection", error => console.log(error.code));
readFile("missing.json");
await new Promise(resolve => setTimeout(resolve, 30));
```

Actual stdout:

```json
{"plain":"ENOENT\n","baseline":"ENOENT\n","recorded":""}
```

This changes execution, not only which run is stored. Code that relies on the rejection event behaves differently under observation. An unawaited read rejection that Node or a test runner would report can be hidden, allowing a faulty run to appear successful. The defect applies to the newly settled promise reads, including `readFile`, `stat`, `access`, `realpath` and directory reads. It does not depend on B1 or a filesystem race.

**One-worker repair:** return the promise chain that records the outcome and preserves the rejection, rather than returning an original promise whose rejection the recorder consumed. Preserve the original value or error for callers. Add uncaught and explicitly caught rejection controls, plus a successful read. The uncaught case must retain the base recorder's rejection event; the caught case must produce no extra event.
