## Blocker

### B1: the post-run directory filter loses a tracked file the run read and replaced

**Proven.** `src/runners/observe/inputs.ts:91`, `rewrittenOf`.

Row 023-47's done-when requires that a run whose inputs changed during the run never be stored at a key that omits what it read. Spec 023 D2 requires the same keying rule for every reader. The new function excludes a path when `isDirectory(abs)` is true after the run. That does not prove it was a directory when the test read it.

A test can read a tracked file, remove it, and create a directory at the same path:

```js
const got = readFileSync("data.txt", "utf8");
rmSync("data.txt");
mkdirSync("data.txt");
// The test's outcome depends on got.
```

The live-recorder probe confirmed that both raw `paths` and raw `written` contain `data.txt`. `observedInputs` then returns no observation for that read: the old `paths` filter drops written paths, and `rewrittenOf` drops this one because it is now a directory.

A second probe used `test/code/gate/keep-grown-kit.ts` without replacing product sources:

1. `worktree()` supplies tracked `READ` (`data/known.txt`) outside test `A`'s closure.
2. Save `keyOf(at.keys, A)` and call `keep` with an empty observation object for `A`.
3. In `started`, read `READ`, remove it and create a directory there. Build the observation with `observedInputs`, using a `RecordedFile` whose `paths` and `written` each contain the absolute `READ`; its other sets are empty. Assign the returned observation to the run's object when present.
4. The observer returns `[]`. After `keep`, `resultsAt(at.commonDir, ran)` is **1**, where the required result is **0**.

Thus the real keeper stores the run at the original key and merges no read. Two commits differing only in that input still share the blind key, so the same persistent cross-commit result path remains. The later directory's contents need not matter: the lost dependency is the file's original content.

**Worker-sized repair:** retain read-and-written candidates independently of their post-run filesystem type. Let the core's tracked-path check distinguish git-held file paths from directory-only probes. Keep the scratch-file exclusion. Add the live observer and keeper regressions above, including a later key that contains the removed file input. Add a validity case for the replacement and keep the alarm green. Rebuild the committed bundles. This needs no change to proof or status readers.
