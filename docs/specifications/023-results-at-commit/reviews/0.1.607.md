## Proven blockers

### B1. The named batch bypasses the sparse-duration rule and keeps a false headline time

**Proven.** `src/cli/status-at-estimate-named.ts:88` to `:94`; `src/cli/status-at-call-run.ts:239` to `:247`; batch wording at `src/cli/status-at-estimate-named.ts:112`.

Row 023-62 requires no time from too few stored durations. Row 023-60 requires the named file's estimate to include the batch it must wait for. The new helper sums only known durations. Any single duration makes the whole batch's time known. The call then retains the named file's own numeric estimate even when the batch's time is unknown: `batch.seconds ?? 0` treats uncertainty as zero.

Reproduction: use the existing named-call fixture with twelve files in one in-flight commit run. Store only the named file's 3 s duration. Leave the other eleven durations unknown. The run began 60 s ago. The command returned:

```json
{"files":1,"width":1,"basis":"durations","known":1,"seconds":3,"batch":{"files":12,"ran":60,"seconds":0}}
```

The probe expected `batch.seconds` and the headline `seconds` to be null. It failed with `expected +0 to be null`. Text converts the batch's zero to `any time now: it has run past its stored durations`, although eleven batch files have no stored duration. This can occur without a cut: the cut's unknown durations count as zero, so they provide no excess remainder that would trigger it. A previously cut tier can also remain in flight by design.

**One-worker fix:** apply the duration coverage rule and the main estimator's treatment of missing durations to all files in each holding batch. Preserve unknown batch time in the headline instead of falling back to the named file's own time. Distinguish no durations from too few in the batch text. Keep known, sufficiently covered batch estimates and lone-file estimates working. Do not change the scheduler's cut policy to hide this report defect.

**Required regression:** one named known duration among many unknown batch durations, through text and JSON, with no measured rate. The headline and batch must both stay unknown. Also test that an unknown holding-batch time cannot fall back to a numeric estimate of only the call's own files. The current tests cover all durations and zero durations in the helper, but omit this combined case.

### B2. The idle recovery line promises work its suggested wide call does not select

**Proven.** `src/cli/status-at-call-run.ts:148` to `:155`; text in `src/cli/status-at-report-join.ts:17`. Selection contract: `src/core/daemon/at-asks.ts:264`.

The vision requires truthful status and actionable evidence. W1's recovery instruction must actually ask the files it counts. `idleOf` counts every file known on one side and idle on the other. A working-tree no-result state has no commit selection marker. A known commit-side result also carries no such marker. Thus unchanged files can enter this count even though a wide `--run` excludes them from both `files` and `withResult`.

Reproduction: A imports changed `src/a.ts`; B imports untouched `src/b.ts`. Both pass at the commit. Neither has a working-tree result. A bare wide `--wait` prints:

```text
now: 2 test files with a result at <c> have none in the working tree, and none is queued or running there; `squeal status --at <c> --run` queues them
```

The probe used the real `choose()` selection rule. It returned `withResult: [A]`. The suggested wide `--run` then sent only `test/a.test.ts` to the worktree daemon. B stayed idle. The probe failed with `expected 2 to be 1` for the promised count, after confirming the actual queue contained only A.

**One-worker fix:** base the promise on the selection the suggested command will use, or give a command that explicitly names the counted idle files. Do not infer selection from a stored result or from the absence of a pending mark. Handle the commit-side recovery direction under the same rule.

**Required regression:** changed A plus unchanged B, with a known result on one side and no result on the other. Execute the printed recovery request through the selection path and compare its files with the promised files. Cover a join without a kept wide ask and the reverse side too. Keep the existing selected-file recovery test.
