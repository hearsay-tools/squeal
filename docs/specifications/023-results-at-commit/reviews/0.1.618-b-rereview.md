## Blockers

### B1 remains. Proven: a relative Dir loses its original location after chdir

Locations: new `src/runners/observe/reveal.cjs:27`, `:184`.

The original native-realpath and watch holes close, but the new Dir wrappers still violate the same rule: a path the run found present must not be certified absent. `Dirent.parentPath` can be relative to the working directory used when `opendir` opened the directory. `dirent` instead resolves it against `process.cwd()` when an entry is returned. If the caller changes directory between those operations, the recorder marks the wrong path present.

Independent sync, promise-read and async-iterator probes all used this order: probe `data/probe.json` while absent; make it through an outside-root alias; open `data` with a relative spelling; change cwd to `elsewhere`; read all entries; remove the file through the alias. Each printed the real entry but retained it in `ObservedInputs.absent`:

```json
{"stdout":"anchor.txt\nprobe.json\n","absent":["data/probe.json"],"paths":["data/probe.json","main.mjs"]}
```

The recorder resolves the present entry as `elsewhere/data/probe.json`. A path it never read is vetoed; the path it actually read keeps only its earlier absent outcome.

The real-adapter scheduler proof used one test and a separate parent for disk changes. The test first probed `data/dir-probe.json` absent, signalled readiness outside the worktree and waited. The parent made the file and opened the gate. A followed Node child opened relative `data`, changed cwd, read its entries, restored cwd and returned the names. The test asserted that `dir-probe.json` was among them. The parent then removed the file and opened the final gate. No revision named the transient file. After the pass was recorded, the parent applied one unrelated revision and settled the scheduler again.

Actual output:

```json
{"phase":2,"absentNow":true,"before":1,"after":1,"sameKey":true,"states":["pass/current"],"runs":["pass"]}
```

The run's observations named `data/dir-probe.json` absent and `data` as a listed directory. A fresh run at that key would not find the asserted name. Instead the pass stays current without a rerun. This child carries the recorder; the defect is its incorrect outcome path, not an accepted unfollowed-child read.

**One-worker repair:** retain each Dir's absolute directory location when it is opened, using the call's starting cwd. Resolve all of that handle's returned entries against that location, in sync, callback, promise and iterator forms. Do not infer the original location from cwd at read time. Add the chdir probes and retain the separate-parent scheduler ordering above. When a handle's origin is unknown, refuse certification conservatively rather than marking a guessed path.
