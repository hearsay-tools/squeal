## New should-fix note

### S3. Proven, nonblocking in this bounded re-review: a function named `async` loses its frame

**Location:** `src/core/status/test-frame.ts:17`, with `v8Position` at line 38.

JavaScript permits `function async() { ... }`. Native V8 prints its frame as
`at async (<position>)`. The added greedy optional prefix consumes `async `,
leaving `(<position>)`. `v8Position` finds no ` (` separator and cannot parse
the trailing `)`. A named helper frame no longer proves that the stack belongs
to the error's location; a named test frame is itself lost.

Reproduce on Node 26 with the candidate parser (the imports are types only):

```js
import { testFileFrame } from "./src/core/status/test-frame.ts";
const check = { kind: "test", project: "", testPath: "test/a.test.ts", fullName: "case" };
const errors = [{
  name: "Error", message: "boom", diff: null,
  location: { path: "src/helper.ts", line: 3, column: 9 },
  stack: "Error: boom\n    at async (src/helper.ts:3:9)\n    at test/a.test.ts:8:4",
}];
console.log(testFileFrame(check, errors));
// Candidate: null. Before the repair: { path: "test/a.test.ts", line: 8, column: 4 }.
```

The same regression occurs with a normal helper followed by
`at async (test/a.test.ts:8:4)`. A native `function async()` probe confirms the
frame spelling. This loses the optional called-from location; it does not
fabricate a failure or a pass.

**One-worker fix:** preserve named-frame parsing before stripping an async
prefix from a bare position, or otherwise distinguish `async (` from
`async <position>`. Add regressions with `async` as both helper and test
function name. Keep the new anonymous async cases, named async functions,
parenthesized route paths, and the provenance guards. Rebuild and version the
bundles for any product repair. This is a new note, not a reopened prior
blocker, under the explicit bounded re-review rule.
