## What fits

1. **Arguments and provenance.** At `src/runners/vitest/sources.ts:144`, binding
   preserves the plugin container's receiver. The wrapper awaits the existing
   stamp before forwarding the same ID and every trailing argument. It returns
   the original resolved value and propagates rejection. Thus the cast preserves
   both the Vite 8.3 one-argument nullable result and the Vite 8.4 metadata
   overload's non-null result. The broad internal `Load` type erases information
   locally; it does not fabricate a result. Typecheck includes the aliased 8.4
   declaration and its type assertion. The real two-version test checks both a
   transformed result and detection of a later disk edit.
2. **Other wrappers.** I searched method assignments, binding, proxies and
   property definitions in `src/`, then read the Vitest matches. The other
   plugin-container wrapper, `src/runners/vitest/ci-runtime/coverage-stamps.cjs:38`,
   already forwards `id, ...rest`. I found no second argument-dropping Vite or
   Vitest method wrapper.
3. **Cause bounds.** `src/core/runner-host/protocol.ts:253` follows at most three
   causes, rejects cycles by identity, keeps only the first line of each added
   message, and truncates each to 300 characters. The maximum added output is
   906 characters including separators. It does not serialize cause objects,
   their extra fields, stacks or environment. A throwaway probe checked a
   100,000-character cause, a secret sentinel on its second line, an object with
   a secret field and throwing `toString`, and a fourth nested cause: all bounds
   and exclusions held. The current tests cover cycles and duplicate text too.
   `messageOf` uses the same formatter and strips terminal controls. Its direct
   and runner-host paths both retain the underlying Vite reason.
4. **Repository dependencies.** `package.json` and both lockfile importer edges
   keep root Vite and Vitest's Vite peer on `8.3.2`. The `vite-8.4` alias resolves
   exactly `vite@8.4.0` and appears only in the regression test, not product
   imports. `minimumReleaseAgeExclude: [vite@8.4.0]` names the real package and
   exact version behind the alias. The fresh frozen sandbox install accepted it;
   the successful Node 24 and 26 CI jobs independently exercised CI installation.
   This retains an installed older Squeal's ability to validate the repository
   while testing the newly incompatible upstream path.
5. **Benchmark provenance.** `BENCH_DEPS` pins all three packages exactly,
   including Vite `8.4.0`. The generated project's installed versions matched
   those pins in the shipped proof. `bench/run-all.mjs:225` records actual
