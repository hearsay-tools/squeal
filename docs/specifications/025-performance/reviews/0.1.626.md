## Should-fix notes

### S1: The benchmark bypasses the new hook startup block

**Proven; nonblocking measurement gap.**
Changed boundary: `plugins/claude-code/hooks/run:42`; caller:
`bench/session.mjs:67`. The new block tests `[ "$1" = node ]`. The benchmark
passes `process.execPath`, an absolute path, so its hooks get neither the new
compile-cache variables nor the proxy carry preload. Shipped hooks use the
literal `node` command and the startup tests cover that path successfully.

A disposable probe ran the same hook runner twice with a fresh temporary HOME,
`NODE_USE_ENV_PROXY=1`, and no cache variable. It printed these fields:

```text
command       cache                         own   proxy   preload
node          <temporary HOME>/.cache/...    1     1       true
absolute Node null                          null  1       false
```

The probe exited 0 and removed its temporary files. Thus the current paired
`@hooks` run can measure D6 and D9, but cannot establish D7's startup gains.
This does not invalidate the separate shell/adapter correctness tests.

One benchmark worker can make session hook calls use the shipped invocation
with the intended Node on PATH, then assert that the startup block ran before
collecting D7 timings. Use the CLI launcher for CLI startup measurements too:
`bench/session.mjs:59` and `bench/run-cell.mjs:90` currently invoke bundles
directly. Keep the old-version comparison on the same invocation path.

### S2: Log collection excludes the shutdown write-wait summary

**Proven; nonblocking measurement gap.**
Changed boundary: `bench/run-cell.mjs:400`. Logs are read and copied at line
379, then parsed into `cell.hookWriteWait`, before `squeal stop` at line 405.
D9 flushes the partial reporting interval during shutdown at
`src/core/daemon/daemon.ts:1612`. That summary cannot reach the saved cell or
its copied logs.

For example, a write of 200 ms after the last minute summary contributes no
individual long-wait line and its shutdown summary is omitted. The reported
maximum and p95 can then miss that final interval. With no earlier summaries,
the cell can report n/a despite having taken writes.

One benchmark worker can capture resource/store measurements at the current
boundary, stop the daemons, then collect the final logs and parse write waits.
Add a focused test with a summary emitted only at shutdown. D9's producer and
the parser agree on the line format; the remaining gap is collection order.
