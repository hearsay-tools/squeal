# 024-01 notes: source-path `status --wait` promotion and catch-up wake

## What changed

- `src/cli/wait/named.ts`: `SOURCE_PROMOTE_CAP = 50` and `promotedWaitFiles(root, cwd, paths, selection)`. The named wait now promotes its result, not `ownNamedFiles`. `ownNamedFiles` is unchanged. It still drives `--check` focus, `checkUsage` and `askNamedRuns`.
- `src/cli/status-wait-promote.ts`: `PromoteNamed` takes an optional 4th parameter `{ wakeCatchUp?: boolean }`. `promoteNamed` sends when it has files or a wake. The request carries `wakeCatchUp: true` only when asked.
- Daemon chain: `PromoteRequest.wakeCatchUp?: true` (`types/daemon.ts`). `protocol.ts` parses it in a new `parsePromote`, which keeps `parseRequest` from growing. A non-boolean is refused. `false` is dropped. The flag passes through `desk-messages.ts`, `desk.ts`, `front-desk.ts`, `handlers.ts`, `daemon.ts`, `Scheduler.promote` and `promoteRequest`.
- `src/core/scheduler/quiet.ts`: `BacklogQuiet.endCatchUp(now)` clears `#catchUp` and publishes only when it was not empty. `#until` stays. `promoteRequest` calls it when `wakeCatchUp === true`.
- `src/core/types/scheduler.ts` (outside this row's list; the coordinator agreed, own commit): `Scheduler.promote` takes an optional `wakeCatchUp?: true`.

## Decisions the spec did not settle

- **How to tell which files a source path selected.** `NamedSelection` has no per-path file list, and `named-selection.ts` is not this row's file. `promotedWaitFiles` therefore treats these files as source-selected: the selection's files minus the own files minus every file under a named folder (`folderPath` with the same `selects` rule that `selectNamedFiles` uses). It does this only when at least one path has `kind === "source"`. Two effects follow:
  - A file that a folder and a source path both select is not promoted. This is the safe side of row 011-406.
  - The readers of a `not-run` path, when it is named beside a source path, count as source-selected. This case is rare. Exact attribution needs a per-path file list in `NamedSelection`.
- **More than 50 own files and no source path:** all own files are still promoted and no wake is sent. The cap applies only when source-selected files push the total past it, as requirement 2 says.
- **Past the cap with no own file:** the request has `testFiles: []` and `wakeCatchUp: true`. An older daemon parses it as a promotion of nothing and ignores the unknown field.

## Tests

- New `test/cli/status-wait-source-promote.test.ts` covers: 15 files from a source path are all promoted; an own file beside a source path is sent once; exactly 50 files are promoted; past the cap only own files go, with the wake; past the cap with no own file the wake goes alone; a folder beside a source path leaves the folder's files out; a folder alone promotes nothing; `--check` on a source path is still a usage error.
- New `test/scheduler/quiet-wake.test.ts` covers `endCatchUp` unit cases and three scheduler cases on the catch-up fixture: promoted catch-up files run at once; `wakeCatchUp` starts the held catch-up; without it, catch-up keeps waiting. The wake case fails when the `endCatchUp` call is removed (checked by hand).
- `test/daemon/promote.test.ts`: parse, handler and front-desk forwarding of `wakeCatchUp`.
- `test/cli/status-wait-promote.test.ts`: the old "promotes nothing for a source path" test now expects `[A, B]`, which is the new behaviour. A new case covers a wake sent with no files.
