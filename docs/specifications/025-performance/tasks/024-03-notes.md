# Row 024-03 notes: coverage wire deduplication and `CoverageWriter` batching

## Changes

- **D3.1, `src/runners/vitest/coverage.ts`:** `coveredFiles` reads each kept payload's script URLs (`scriptPath`, as `buildRecord` reads them). It builds each environment's sources only from those files. The old code copied every transformed module. The filter is **per environment per run**, the union of that run's kept payloads, not per file. Reason: the mapping worker caches sources by map identity (`workerMapper` `idOf`, `map-worker.ts` `KEEP = 2` runs). One map per file would make the worker ask for every source again for each file. The spec allows this level ("that run's V8 coverage `result`"). A payload that does not read adds no paths; its record fails to map in any case.
- **D3.2, `src/core/runner-host/coverage-wire.ts`:** the wire has a new `tables` field. It holds each distinct sources map (by identity) once per run, and each file names its `table`. The decoder makes one `Map` per table, and every file that names the table gets that same `Map`. A legacy wire, where each file has its own `sources` entries, still decodes. A missing table throws. The wire size now grows with the number of modules, not with files times modules.
- **D3.3, `src/core/code/coverage/writer.ts`, `src/core/code/store/coverage.ts`, `src/core/code/store/types.ts`:**
  - Mapped records with their keys wait in `ready`. A batch is written when `MAX_BATCH_FILES` (25) records wait, or when `BATCH_WINDOW_MS` (200 ms) has passed since the first record of the batch.
  - `putPartsBatch` writes all parts of a batch in one transaction, then all manifests in the next.
  - `onStored` runs once per stored batch. The batch write is measured by `Pace` and waits for `pace.due()`, as the per-job steps do.
  - A busy store stalls each record of the batch for the existing retry. Any other error writes each record alone, so one bad record drops only itself.
  - `close()` writes the records in `ready` before it drops queued and stalled jobs.
  - `busy()` and `idle()` count records in `ready`.

## Type changes

- `CodeCoverageRepo.putPartsBatch(items: readonly CoverageRecordPut[]): Promise<void>` and the type `CoverageRecordPut` were added to `src/core/code/store/types.ts` (approved by coordinator 201d84ee). `putParts` now calls `putPartsBatch([one])`.
- `WireCoveredFile.sources` is now optional. `WireCoveredFile.table?` and `WireCoverageRun.tables?` are new.
- New exports from the writer: `MAX_BATCH_FILES` and `BATCH_WINDOW_MS`.

## Behaviour changes that tests saw

- `writer-stored.test.ts`: two files of one run now give one `onStored` call. The log of a throw names "a.test.js and 1 more".
- `writer-busy.test.ts`: three records that retry after a busy store give one `onStored` call, not three.
- One file is now stored about 200 ms later (the batch window). Tests that wait for `idle()` still pass.
