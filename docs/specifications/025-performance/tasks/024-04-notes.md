# Row 024-04 notes: idle daemon CPU and the recorder's `realpath` cache

## What changed

1. `src/core/daemon/lifecycle.ts`: the default `presenceMs` is 1 s (was 250 ms). `timings.presenceMs` still overrides it. Departure grace stays 3 s, so a consumer that leaves is now seen 1 s later at most.
2. `src/core/watcher/change-feed.ts`: an idle feed backs off its full passes. The design is coordinator 201d84ee's answer to the conflict below:
   - The idle timer still fires every `reconcileIntervalMs` (30 s). A tick before the next full pass is due reads only `HEAD` (`gitHead`, a file read). When `HEAD` is unchanged, it calls `onDelivered` and returns: no `git status`, no tracked-path scan.
   - A full pass is due `gap` after the last one (half a tick early counts, for timer jitter). After each idle full pass, the gap doubles when the pass found what the one before it found (same `HEAD`, same candidate paths and stats), up to `MAX_IDLE_POLL_MS` (300 s); otherwise it goes back to 30 s. The start pass has no `HEAD` before it, so the ladder is: full passes at 30, 60, 120, 240, 480, 780 s, then every 300 s.
   - Reset to 30 s: any watcher hint, a drop or backend error (`onLost`), any public `reconcile()` (the daemon's `pass()`, status sync, `start`). A moved `HEAD` runs a full pass on that tick.
   - No backoff when the watch is at the system's limit (`atWatchLimit`) or not started, and none when the caller set `timings.reconcileIntervalMs` (tests, commit mode's `COMMIT_FEED_TIMINGS`).
3. `src/core/store-process/server.ts`: `fileSchemaReader(path)` keeps the last `user_version` and reads the file again only when `stat` of the file or its `-wal` changed (`dev:ino:mtimeMs:size`). The WAL is part of the key: in WAL mode a `PRAGMA user_version` lands in `-wal` before a checkpoint copies it into the file. A missing file reads 0 and is not cached. The `existsSync` "removed" check is unchanged.
4. `src/runners/observe/recorder.cjs`: `realpathCache(realpath, limit = 16_384)` keeps successful answers in a `Map`; a throw keeps nothing; a full map is cleared before the next insert. It is exported (`module.exports = { realpathCache }`) for its unit test. `RECORDER_VERSION` and `KEY_FORMAT_VERSION` are unchanged; `test/keys/key-format.test.ts` passes (12 of 12).

## The conflict the backoff met

`src/core/status/feed-late.ts` sets `FEED_LATE_MS = 2 * reconcileIntervalMs` (60 s). `presence/findings.ts` `lateOf` and `delivery/late.ts` call a feed late when it delivered no batch for 60 s. A plain 30 s -> 300 s timer would make every idle daemon read "late". The light tick keeps `onDelivered` at 30 s, so the late rule is unchanged; a hung queue still stops the heartbeat.

## Known limits

- Between full passes, an edit that the watcher missed and that does not move `HEAD` waits for the next full pass (up to 300 s while idle). The watcher is healthy in this state by definition; a drop or error resets the gap.
- An idle tick that only reads `HEAD` is not a scheduler batch, so the scheduler's install check (it runs on `interval` batches) runs on full passes only.
- The `realpath` cache keeps a symlink's old target if the link is retargeted inside one process. The recorder asks once per path, test file and kind anyway (`add` returns false for a path seen), so this only matters across kinds or test files of one worker.

## Tests

- `test/watcher/change-feed-backoff.test.ts`: fake `setTimeout`, a fake clock, a quiet backend; git runs for real. The ladder, the fixed interval, resets after a hint, a drop, an asked pass, a moved `HEAD`, and no backoff at the watch limit.
- `test/store-process/file-schema.test.ts`: one open while unchanged; a schema change still in the WAL is seen; a missing file is read again.
- `test/runners/observe/realpath-cache.test.ts`: one ask per path, no cached failure, the limit, and a module loaded through a link still records link and target.
