# 024-02 notes: hook delivery and `squeal status` read path (spec 024 D2)

## What changed

1. **Narrow state read for a marked consumer.** `relevantStates(store, consumer, mark)` in
   `src/core/store/view-seed.ts` reads the states that are not `pass`, the states the consumer's
   view holds, and the states born after the mark, in `knownStates.list` order. `trustedMark` is
   now exported from `view-mark.ts`. In `delivery.ts`, `deliveryStates` picks the narrow read when
   the consumer has a trusted mark and the delivery is not the waiter's (`idle`). The full list
   (`all`, lazy through `once`) is read only for `readLiveHeader` and `annotate`, so a silent
   boundary or peek never reads it. `currentFailures` and `ownNotes` use the narrow states.
2. **`tellUncovered` reads first.** `uncoveredNow` finds the paths read-only (changed, code, not
   told, read by no test, on disk). The transaction is entered only when that finds paths, and
   `uncoveredNow` runs again inside it before `recordUncoveredTold`. `unreadByTests` stops the
   closure scan once every candidate path is covered. A listed file with no trusted closure,
   reached before every path is covered, still gives `[]`.
3. **Single-batch write and release.** `SendingConnection.unit` runs its work through `#run`.
   A plain batch (not held, no `post` sender) that ends during the synchronous run of the work is
   deferred. It is sent when the run ends: when the work returns, or at its first `await`. If the
   work returned a value, not a promise, and no other unit's work is around it, nothing can write
   after that batch, so it is sent with `release: true`. `delivery.ts`'s `unit` now runs its
   work synchronously when no hold of its thread is waited for, so delivery units benefit too.
4. **Read-only `squeal status`.** `withStatusStore` opens a store at `SCHEMA_VERSION` with
   `new DatabaseSync(path, { readOnly: true })` (`openReadOnly` in `src/core/status/open.ts`).
   Missing, newer and corrupt stores are reported as before. A store at an older schema falls back
   to `openStore`, which migrates it, as before.

## Decisions the spec did not settle

- **`readOwn` keeps its `states` argument.** The brief asked `readOwn` to query only the rekeyed
  files' states when narrow states are passed. `readOwn` uses `states` only to count rekeyed
  files that have an `unknown` state. `relevantStates` holds every state that is not `pass`, so
  the count is exact on the narrow list and no extra query is needed. The contract is now in its
  doc comment. `test/delivery/narrow-delivery.test.ts` covers this through the delivery.
- **No change to `src/harness/shared/deliver.ts`.** `context.write` is `SendingConnection.unit`,
  which takes the lease only when a transaction or hold throws `NeedsLease`. Once `tellUncovered`
  reads first, a covered edit opens no transaction, so it takes no lease and sends no release.
  `test/delivery/uncovered-read-first.test.ts` proves it through a `SendingConnection`.
- **No change to `daemon-writer.ts`.** `DaemonWriter.send(batch, true)` already exists for a
  hold's commit, and the daemon's `WriteDesk` ends the lease when the write settles, written or
  rolled back. One error path differs from a separate release: if the combined write request gets
  no answer at all, the client has already dropped its token and sends no release. The daemon
  then ends the lease when the hook's process is gone (row 011-393). A hold's commit already
  behaves this way.
- **Deferring at the first `await`.** A deferred batch is sent when the work first yields, before
  any other code runs. So async work sends its first batch at the same point as before.
- **A status read that writes is refused.** With a read-only connection, a callback that writes
  gets `store-unreadable` ("attempt to write a readonly database"), not a busy retry. Before, the
  011-113 defect (a status read that wrote) showed as a busy store beside a writer. Now it fails
  every time, which finds it sooner.

## Tests

- New: `test/delivery/narrow-delivery.test.ts`: a random model (40 seeds × 40 steps of writes,
  unknowns, retirements, re-births, registrations, boundaries and peeks) that compares
  `planDelta` on `relevantStates` with `planDelta` on `knownStates.list`. It made more than 500
  comparisons, more than 100 of them on a narrower read. Removing any one of the three query
  clauses fails it. It also checks that a silent boundary or peek never calls `knownStates.list`,
  that `lastSeenAt` is still touched, that news reads the full list, and that an unmarked
  consumer reads the full list.
- New: `test/delivery/uncovered-read-first.test.ts`: no lease for a covered edit; one lease for
  an uncovered edit; nothing on the next boundary; trust rule kept; one closure read when the
  first file covers the edit; every file read for an uncovered path. Five of its seven tests fail
  on the old `uncovered.ts`.
- New: `test/delivery/single-batch-release.test.ts` (fixture `test/delivery/sent-fixture.ts`):
  write+release for synchronous work; write then release for awaiting work and for work that
  throws; no request for read-only work; a hold sends nothing before its commit and nothing on
  its rollback (row 011-288); Stop's `endTurn` and `unregister` send one write+release through
  `createDelivery`. The `SendingConnection` cases fail on the old code; the `endTurn` and
  `unregister` cases fail on the old `delivery.ts` `unit`.
- New: `test/status/open-readonly.test.ts`: a write is refused; a read beside a killed writer's
  WAL leaves both the store file and the WAL byte for byte as they were (a read-write open
  checkpointed them); an older-schema store migrates. Two of its three tests fail on the old open.
- Updated: `test/status/frame-beside-writer.test.ts`: its two tests that wrote inside a status
  read now check that such a write is refused. The busy retry and the timeout are now shown with
  the exclusive-lock holder. `test/status/torn-read.test.ts` now mocks `createStore`, which both
  `openStore` and the read-only open call, where it mocked `openStore`.
