# Row 025-08 notes: benchmark accuracy and visibility (D8)

Worker notes for the coordinator and the next worker. Nothing here has run on boat.dev yet.

## What changed

- `bench/run-cell.mjs`, step 5: after `squeal start` in the other worktrees, the cell polls each of them with `squeal status --json` once a second until `baselineSettled` (below), with one 5 minute bound for all of them. Each `phases.startOthers[i]` gets `settle: { ms, settled, polls }`. Only then do `idle0` / `idleStore0` and the idle minute start. Single-worktree cells skip the wait (`roots.length > 1`), so they are unchanged.
- `bench/lib.mjs`:
  - `baselineSettled(status)`: false while `testFilesListed === false`, `counts.pending`, `testFilesWithoutChecks.pending` or `code.pending` (when `code` is present) is not 0. A field the status does not print does not hold the wait, so older releases settle on what they print.
  - `waitForBaselines(roots, read, { timeoutMs, pollMs, now, wait })`: the poll loop, with the clock and sleep injectable for tests.
  - `hookWriteWaitLog(text)`: parses D9's `long write wait: hook write waited N ms` and `hook writes: N taken, queue wait p95 P ms max M ms`. Returns `{ seen, taken, p95MaxMs, maxMs, longWaitsMs }`.
  - `longWriteCount(text)`: the old `/long write/gi` count without `long write wait` lines. Without this, every D9 line would have counted as a store long write once 025-09 lands.
- `run-cell.mjs` saves `cell.hookWriteWait = hookWriteWaitLog(<daemon logs, not store-*.log>)`.
- `bench/summarize.mjs`:
  - New report metrics (Hooks): `hook.preToolUse.p99`, `.max`, `hook.postToolBatch.p99`, `.max`, `hook.writeWait.p95`, `hook.writeWait.max`, `hook.longWriteWaits`. Write-wait values are null (n/a) when no D9 line exists; for a cell saved before this row, they are read from its copied `logs/` (daemon logs only).
  - New scored metric (Resources): `res.treeRss.max` = `daemonRss.maxTreeBytes / worktrees / 2**20`, healthy ≤ 1200 MiB, warn ≤ 2400 MiB.
  - The p99s, `hook.writeWait.max`, `hook.longWriteWaits` and `res.treeRss.max` are in the paired comparison's raw table (`RAW`).
  - The script no longer runs on import: `summarize(dir)` writes `scores.json` and returns `{ scorecard, overall, scores, areaScores, gateFails, values }`; the CLI prints the scorecard as before. The former 26-complexity top level is split into `scoreRun`, `areaScore`, `headerLines`, `unhealthyLines`, `metricLines` and the comparison helpers, which now take the run object instead of closing over module state.
- `bench/gen-project.mjs`: `--cases N` (default 6) and `--functions M` (default 0). With M > 0 each module gets `src/h<i>.ts` with M one-line exported functions; the test file imports `h<i>_0` and case 0 checks it. Default output is byte-for-byte the same as before.
- `bench/run-all.mjs`: new cell `scale-real` (2,000 files, 10 cases, 30 functions: 20,000 checks, 62,001 functions), opt-in through `OPT_IN`: not in a plain run or `@all`, selected by name or `@scale` (`size-l`, `scale-real`). Templates are keyed by `templateKey(c)` (`p2000`, `p2000-c10-f30`). The run body moved into `main()`, called only when the file is the entry point, so tests can import `CELLS`, `GROUPS`, `selectCells`, `templateKey`.
- `bench/README.md`: the settle wait in phase 5, the new metrics and limits, `@scale`, the `scale-real` cell and the generator options.
- `test/bench/summarize.test.ts` (new, 13 tests).

## Decisions the spec did not settle

1. **Tree RSS limits: healthy ≤ 1200, warn ≤ 2400 MiB per worktree**, not the brief's example 750 / 1500. Measured per-worktree tree RSS in the 2026-11-22 and 2026-11-24 runs: ref 1028–1168, load-50 1054–1142, size-l 1557–1925, wt-3 709–752, store-7g-wt3 673–748 MiB. With 750 every ref cell would sit in warn; the test runners dominate the number. 1200 sits just above ref, so a growth there shows. Change the two numbers in `METRICS` if the coordinator wants stricter limits.
2. **Per worktree, not whole machine.** `res.daemonRss.max` is per daemon, so `res.treeRss.max` divides the whole-cell peak by the worktree count to compare wt-3 with ref. It is the peak of the mean, not the peak of the largest tree; `samples.json` keeps only the sum, so the largest single tree is not available without a sampler change.
3. **Scoring `res.treeRss.max` moves old Resources scores.** Re-summarizing the 0.1.615 vs 0.1.616 run: overall 80 → 82, Resources 59 → 69 (ref, wt-3, load-50 gain a healthy metric; size-l a warn). Every stored raw value is unchanged (the backward-compatibility test checks each one). Compare scores across this change only by re-summarizing old runs.
4. **Write-wait metrics are report-only**, so releases without D9 do not get a different area score from n/a values.
5. **`hook.writeWait.p95` is the highest per-minute p95** in the cell: the daemon logs a p95 per minute, not the samples.
6. **Settle wait and fields an older release does not print**: absent `testFilesListed` or `code` counts as settled. The brief said `testFilesListed === true`; that would hold the wait for 5 minutes on every release that does not print the field.
7. **Helper functions live in `src/h<i>.ts`**, not in `src/m<i>.ts`: `session.mjs` (not owned) rewrites the whole `src/m<i>.ts` on each edit, which would delete 30 functions per edit and add code-store churn that a real edit does not make.

## Risks and checks for the first boat.dev run

- **Settle wait on lookup-only daemons is unverified.** If a lookup-only worktree keeps `counts.pending` above 0 with no edit, wt-3 and wt-6 wait the full 5 minutes before the idle minute. `phases.startOthers[i].settle.settled === false` shows it. Read it in the first `@quick` run's `cell.json`.
- `scale-real` cost is estimated, not measured: 20,000 cases of 15 ms is about 300 CPU-seconds per full run, plus a fresh template install.
- `wt-3` / `wt-6` idle CPU before and after this row do not compare (the README says so).

## Squeal coverage of the new test

`test/bench/summarize.test.ts` loads the bench scripts through a variable path (TypeScript types a literal `.mjs` import without declarations as an error), so Squeal's closure does not see `bench/*.mjs`: `squeal status --wait` says "no test file's closure holds bench/lib.mjs". Only `bench/gen-project.mjs` (spawned by path) selects the test. An `inputs` entry in `squeal.config.json` (not owned by this row) would fix it: `"test/bench/**/*.test.ts": ["bench/*.mjs", "bench/results/2026-11-24-*/**"]`.
