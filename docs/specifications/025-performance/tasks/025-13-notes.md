# Row 025-13 notes: review 0.1.626 S1 and S2, settle before idle, Codex fixture teardown

Worker `9b9ff68b`, 2026-11-24. Base: `main` at `957897ae3` (0.1.628).

## What changed

1. **S1, hook runners** (`plugins/{claude-code,antigravity}/hooks/run`): the D7 block runs for
   `case $1 in node | */node)`. The proxy carry keeps the caller's Node (`node_cmd=$1`).
   `test/cli/startup-env.test.ts` adds, per hook runner and shell, an absolute `process.execPath`
   case (with and without `--if-squeal`), and a non-Node command left alone. Without the fix the
   four absolute-path cases fail for `claude-code/hooks/run` (checked by restoring the old file).
2. **S1, benchmark CLI path** (`bench/session.mjs`, `bench/run-cell.mjs`): the CLI runs through
   the plugin's `bin/squeal` when it exists, else the bundle, as before. `PATH` starts with
   `dirname(process.execPath)`, so `bin/squeal`'s `node` is the benchmark's Node. `cell.cli`
   records `"bin/squeal"` or `"bundle"`. Hooks still get the absolute Node through `hooks/run`.
   Old tags (`0.1.623`) also ship `bin/squeal`. Both sides of a paired run use the same path.
   Before 0.1.629 an absolute Node in `hooks/run` gets no D7 block. A paired hook comparison
   against an older tag therefore still measures D7 on one side only.
3. **S2, logs after stop** (`bench/run-cell.mjs`, `bench/lib.mjs` `readDaemonLogs`): the run
   records the store process CPU, RSS and seen count at the old boundary. It then stops every
   daemon and waits up to 20 s for them to exit. After that it reads and copies the logs and
   parses the store long writes, the store-process log, the relay and D9's hook write waits.
4. **Settle before idle** (`bench/lib.mjs`, `bench/run-cell.mjs`, `bench/summarize.mjs`):
   - **Cause** (`results/2026-11-24-0.1.623-vs-0.1.626-…/cells/wt-3@0.1.626`): the run log says
     `idle` at 20:30:36. The wt1 and wt2 daemons logged `serving` at 20:30:42 and 20:30:43.
     wt1 committed 11501 rows of baseline adoption first. `status --json` read the store alone:
     zero counts, and `code` `{files: 0, pending: 0}` (the code store's "missing" branch in
     `src/core/status/code-status.ts`). The old check took that as settled on the first poll.
   - `baselineWaitingFor(status)` names what is still pending, or null. The values: `status`,
     `daemon` (present and not `alive`), `listing`, `checks`, `testFiles`, `code` (pending, or
     `files` 0 while `testFileCounts` has files) and `lint` (pending, less `awaitingPause` and
     `awaitingRun[].checks`). A field an older version does not print does not hold the wait.
     `baselineSettled` wraps it.
   - Each `settle` now has `{ ms, settled, polls, waitingFor, code: { files, pending } | null }`.
   - Then, while a store process exists, `waitForQuiet(storeMeter.cpuS)` runs: under 2% of one
     core over a 2 s window, at most 60 s. The result goes in `cell.phases.storeQuiet`
     (`{ ms, settled, polls, lastPct }`).
   - The scorecard has a new section, "Before the idle minute" (`idleSettleIssues`). It lists
     unsettled secondary baselines and what they waited for, a store process that was not quiet,
     and cells that ran the CLI from the bundle.
5. **Codex fixture teardown** (`test/harness/codex/cache-fixture.ts`): `CodexMachine.end(pids)`
   sends SIGKILL to the given pids. It also kills every process of the machine, found in /proc
   by working directory or a command-line argument under `dir/`, or by `HOME=<home>` in
   environ. It does not kill the test process or its parent. It waits up to 5 s, polling every
   20 ms, and counts zombies as ended. Then it calls `cleanup()`, which now uses `rmSync` with
   `maxRetries: 10, retryDelay: 50`. The four `version-copies-*.test.ts` files call
   `await m.end(...)`. `version-copies.test.ts` (not owned) keeps its synchronous `cleanup()`.
   A new test in `version-copies-start.test.ts` starts a detached writer under HOME, passes no
   pid, and checks that the writer gets SIGKILL and the directory is removed.
