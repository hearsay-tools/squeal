# Row 025-09 notes: hook write-wait instrumentation (D9)

## What changed

- `src/core/daemon/desk-messages.ts`: the `FromDesk` `"write"` message has `queuedAt: EpochMs`.
- `src/core/daemon/front-desk.ts`: `requestWrite` posts `queuedAt: Date.now()`.
- `src/core/daemon/desk.ts`: `DeskEvents.onWriteWait?(waitMs)` (additive). The worker desk's `case "write"` calls it with `max(0, Date.now() - queuedAt)` before `requestWrite`. `guarded()` wraps it with `safe`, so a throw goes to `onError`. The in-thread desk (TypeScript sources, no worker) never calls it: there is no queue.
- `src/core/daemon/write-wait.ts` (new): `WriteWaitStats`, `LONG_WRITE_WAIT_MS = 250`, `WRITE_WAIT_SAMPLE_CAP = 1024`.
- `src/core/daemon/daemon.ts`: `#openDesk` starts a fresh `WriteWaitStats` and a 60 s unref'd interval (`WRITE_WAIT_REPORT_MS`) that logs `take()`. `#shutdown` clears it right after the `socket close` step and logs the remaining line, if any. A second `#openDesk` restarts both.

## Log lines (parsed by `bench/lib.mjs`, row 025-08)

- `long write wait: hook write waited <int> ms for the daemon main thread` when a wait is above 250 ms (250 itself is not logged).
- `hook writes: <int> taken, queue wait p95 <int> ms max <int> ms` each minute and at shutdown, only when at least one write was taken since the last line.

## Choices the spec did not settle

- p95 is nearest-rank over the kept samples (`sorted[ceil(0.95 n) - 1]`), rounded to an integer.
- Sample cap: a ring of the newest 1024 waits per report. Count and max are exact over all waits; only the p95 reads the ring.
- A negative or non-finite wait (clock step) counts as 0.
- The shutdown line is logged after the socket closes, so no write can arrive after it.
- The 60 s cadence is a local constant, not shared with `relay.ts`'s timer, which is outside this row.

## Tests

- `test/daemon/write-wait.test.ts`: the threshold, the summary format and its reset, the sample cap, bad waits, and a real worker front desk: a second thread sends a write over the socket while the main thread is blocked (`Atomics.wait`) until the answer and 400 ms more; `onWriteWait` must see at least 380 ms. With `queuedAt` skewed by +10 s the test fails (wait 0), so it discriminates.
- No daemon-level test reads the minute or shutdown line; the daemon wiring is small and the bench parser (025-08) reads the real log.
