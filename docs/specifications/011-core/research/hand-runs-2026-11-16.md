## 2. A named wait gives no verdict for a pause-group file (row 011-383)

- The cezar `squeal.config.json` puts `*parity*.test.ts` and `worker-*.test.ts` in the group `run-loop` at `"pause"` (trial hearsay-tools/squawk#3551).
- `squeal status --wait 60000 <parity file>` returns exit 3 at once and names `squeal run run-loop <file> --wait 60000` (`leftGroupText`, `src/cli/status-wait-groups.ts`). No agent ran that command in the period; 57 hand runs were these files.
- A test file named by its own path that is stale with nothing queued already gets one run asked (`status-wait-ask.ts`).
- The owner's order of 2026-11-16 15:42Z tells agents to use `squeal status --wait <path>` for every result.

## 3. Focused results and `why` (row 011-384)

- `squeal status --wait <file> --check '<name>'` returns exit 3 (`focused`) when the selected checks pass (`selectionResult`, `src/cli/verdict.ts`). The cezar session's reviewer flagged that agents read exit 3 as "no answer".
- `squeal why '<check>' --include-logs` gives the diff, stack, history and console log path, but needs the full check name; agents copy it from `squeal failures <file>`. Agents ran `why` 3 times and `failures` 10 times; 32 hand runs were for that detail (`-t` reruns, assertion greps, added `console.error`).

## 4. Red proofs (spec 023)
