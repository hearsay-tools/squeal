## Problem

What the scheduler does next is decided inside one async loop, the pump (`src/core/scheduler/scheduler.ts` `#pump`, about line 1053; the file has 1,578 lines and the class about 77 methods). Many owners wake it, and its decisions are mixed with store writes, runner calls and timers. Read in source code at `524c63be3`:

**What makes it hard for agents.** The human asked on 2026-11-15 what would make the scheduler easy for agents to understand and follow. The answer this card builds: one place to read "what happens next, and why"; time as an input; decisions as data from closed lists, so adding an event or a decision makes the compiler name every place to handle it; each rule in one module, composed in one written order; glossary terms that match modules.

## Decisions (the human, 2026-11-15)

1. **Scope: one clock and one wake first, then the step** ("Card 7 size: C: B first, then the step", after the human asked "What would make the architecture easy to understand and follow by agents?"). The first rows make time an input and give the loop the only timer; the later rows make the loop's body one step.
   - Rejected: stop the card; one clock and one wake only, the step later (time becomes visible, the decisions stay spread out); the fully pure step in which every lookup is a question the step returns (more rows, reworks card 6's lookup interface, which card 6 rejected for its cost).
2. **Wake shape: the loop keeps its shape; parts state wake times; closed lists; the decide/act splits are the step's first rows** ("Wake shape: 1 + lists, splits first in step", after the human asked "Why not 3?"). Three interfaces were designed in parallel (design-it-twice, 2026-11-15): the smallest (the pump becomes a function that returns its next wake), one ready for the step (registered wake sources, typed events, decide/act splits now), one built around the tests (owners get wake slots, the pump's waits become one wait, a rest signal). All three agreed on one clock port with a host and a virtual adapter, one timer at the earliest wake, due owners run in one written order, a rest signal that counts the scheduler's own async work and sets a runner's run aside, and a check against untracked background promises.
   - The chosen shape: the test-first design, with the step-ready design's closed lists of events and wake reasons. The model test moves onto the virtual clock before any decide/act split, so it guards the riskiest split (the yield check: 4 past blockers on wrong evidence, 1 on an event that never reached it), and the splits take their shape from the step.
   - Rejected: the smallest design (the loop's rewrite lands with no table test to check it); the step-ready design as drawn (5 rows before the step; the model test moves last; the "decide" halves shaped before the step's interface).
3. **Step shape: one step, its rules in written order** ("Step shape: 1: one step, rules in order"). Three interfaces were designed in parallel (design-it-twice, 2026-11-15): one entry point; one built for the agent who reads it and the test that pins it; separate stages put together by a small framework. The first two converged and were merged:
   - one synchronous entry point, `step`, that takes the events since the last step, one clock reading, the due wakes, the reads it asked for, and its ports; it returns decisions from a closed list and the next wake;
   - its body is the rules in written order, one line each, each a module that exists or comes from a split;
   - code that already holds a lock turn (a revision's pass, applied runner work, a promotion or focus request) calls the same step with no reads, so it decides the yield check there and never starts a tier.
   - Rejected: the stage framework (a generic stage type, a walk and a carrier for agents to learn first; it adds little: both give a later remote lane one place).
4. **Slow lanes: decided in one piece, inside the step** ("Slow lanes: A: one piece, inside the step"). The load read and the slot files are synchronous file reads (`loadPerCpu`, `acquireSlowSlot`; read in source code), so listing, the load guard, the slot and the pick run in the step's one lock turn, with the disk facts read just before. The re-check after a wait, the interruption count and the "selecting" flag go; "close idle slow lanes on a hold" is written once. The lock turn's length is measured before the row lands, and a bad measurement goes to the human first.
   - Rejected: the lanes stay as they are, asked through one async decision (the waits, their re-checks and the 3 copies of the close rule stay; an agent reads a separate async path).

## Coordinator's calls (repo-local; the human may overturn)

- **Locations.** Flat under `src/core/scheduler/`, one entry file each, no barrel (row 015-110): `clock.ts` (the clock port and the host adapter), `wakes.ts` (the wake loop and the rest signal), `step.ts` (the step and its rules' order), `step-events.ts` (the closed lists), and the split decide halves beside their owners (`yields.ts`, `command-hold.ts`, `slow-release.ts`). The virtual clock lives in `test/helpers/virtual-clock.ts` and replaces `test/scheduler/model-clock.ts`.
- **The clock port** (011-351). `now()` and one arm/disarm of the only timer. The host adapter reads `Date.now` or the given `now`, looks `setTimeout` up per call (so `vi.useFakeTimers` still works), clamps the delay to 2^31-1 ms and unrefs the timer. `SchedulerOptions.clock` is added; `SchedulerOptions.now` stays as shorthand for the host adapter over that `now`, and its 273 test call sites change in a later quality row. A time difference that was measured on the steady clock (the slow lane's load budget, the claims window) is clamped to at least 0.
- **The wake loop** (011-352), from the test-first design:
  - each owner gets a wake slot and states its next time (`at`, `atMost`); the loop arms one timer at the earliest;
  - one service pass takes one reading and runs every due owner in this written order: command hold, merge hold, yield bound, slow release, each slow lane in the configured order (the default `slow` last), slot gather, claims, runner-part bound, then the pump;
  - the pump's five waits (`#nextEvent`, `#claimWake`, `#quietWake`, `#capacityWake`, `#eventOrAfter`) become one wait for an event or a time;
  - `#notify` call sites post a typed event from a closed list (`SchedulerEvent`); wake reasons are a closed list (`WakeReason`); the pump still reads only "an event came" until 011-356;
  - `rest()` resolves when no pass runs, no tracked work is open, the lock has nothing queued or running (a count hook passed to `Mutex`, not a wrapper), no wake is due, and this still holds after one `setImmediate`; a runner's `run` is set aside, so a held run counts as rest and its end does not; it reports the next wake and each owner's;
  - a test fails on a bare `void` promise or a detached `.catch(` in `src/core/scheduler` outside the loop's tracking (today `void this.#releaseLane`, `scheduler.ts:1330`, and `void this.commandHold()`, `scheduler.ts:259`).
- **Timing differences the move rows accept, each named in the row's notes:** two owners due in the same millisecond run in the written order, not Node's timer order; the merge-hold check repeats a fixed delay after the previous check ends (today a fixed 1 s rate that skips a tick while a check runs); three owners move from the steady clock to the scheduler's clock; on the virtual clock a slot gather's measured commit time is 0, so its gather is always 25 ms there; the quiet wait stays relative to the plan's reading (`idle.wakeAt - idle.at`) until 011-356, which may use the absolute wake, a difference of milliseconds named in its notes; a command hold's end waits for the loop's turn behind a pass already running.
- **The step's interface** (011-356): `step(turn): Step`, synchronous, one lock turn, never throws.
  - `turn`: `at` (the one reading), `events` (since the last step, in arrival order), `due` (the wake reasons due at `at`), `reads` (the install stamp and the probe asked for by the last step, or none), and the ports: card 5's `admit(facts)` stamped with the turn, card 6's `QueueView`, `PlanAsks` and act step, the slow lanes' synchronous core (after 011-357), the yield state, the command hold and slow release state, the tiers in flight. The live adapter is the scheduler's memory and store; the table adapter is a builder in tests. Two adapters: a real seam.
  - `Step`: `decisions` (a closed list: start a tier, stop a tier, write the yield row, cancel the quiet wait, drain runner work, read the install stamp, read the probe, refresh the install, reinstall, reconcile released paths, queue a re-walk chunk, cancel held tiers, close lanes, end a load deferral, tell a note), the next wake with its reason, and an error when a port threw: the decisions made before it stand and the loop stalls after carrying them out, so a stop decided before a failing plan is not lost.
  - A table places each decision kind "in the lock turn" or "after it"; adding a kind does not compile until it is placed, and the loop's carry-out switch ends in an exhaustive check.
  - The rules, in order: hold ends; the yield check; a stall holds; drain runner work; the install wait; nothing may start; read the install stamp; probe the disk facts (runtime folder, merge hold, released paths); start a fast tier (admission, then `planTiers` and `startNext`); ask the slow lanes in order; close slow lanes that are due or idle on a hold; the idle answer (claims, quiet, pool, re-walk, or wait).
  - No tier starts without reads from the current iteration: card 5's "read again after a wait" becomes one invariant.
  - The lock watcher's operation text (`squeal run <group>` prints "the scheduler, which has been selecting the next tier for 3 s") stays as today for each kind of work. Where one turn now does what several did (011-357), the turn relabels its operation to the lane it is in; the worker reports before changing any text.
- **The yield split** (011-354). `decideYields(at, trigger, view)` is today's `#decide`, `waitedFor`, `boundOf` and `rankToBeat` over one reading, folding the cut marks tier by tier (a later tier reads the marks an earlier one set, `yields.ts:154-170`). It returns per-tier decisions, marks, bounds, history entries and the row. `TierYields` keeps its state and the apply. Which events reach the check is one exhaustive switch over `SchedulerEvent` in `yields.ts`: today's filter (`file-ended` only when inputs changed or the tier stands `named`), `held` reaches nothing, `yield-bound` and claims adopt stored results first. The five call sites pass their event and stop filtering. Dropping the filter is a later rule change for the human.
- **In-turn triggers** (011-356). The revision pass (`scheduler.ts:483`), applied runner work (`:123`) and a promote or focus request (`:188`) keep the yield check inside their own lock turn: `applied()` runs inside the runner work's turn (`refine-apply.ts:72`) and the next drain task takes the lock again (`runner-work.ts:282`), so a check queued behind it could lag a whole tier (lessons defect 1). Each calls `step` with no reads.
- **011-357 drops** `#mayStart`, the preemption counter (`slow-tier.ts:296`), `SlowRelease.selecting`, the temporary "ask the lanes" decision and `SlowHost`; a preemption that arrived between a lane's listing and its pick is seen at the next step. The measurement: a fake runner with 1, 3 and 6 configured groups, the step's lock-turn length before and after, on a scratch `HOME`, when the host is calm; the notes give the numbers.
