## Blockers

### B1. Proven: the optional heartbeat read can replace no verdict with a crash and exceed the wait

Locations: `src/cli/group-pending.ts:26`, `src/cli/group-pending.ts:85`, `src/cli/run-lint-group.ts:100`; the test-group deadline path also calls this helper at `src/cli/run-group.ts:139`.

Contract: 019 D6 requires the pending command's no-verdict line and **exit 3**. R1 explicitly requires that the deadline heartbeat read cannot make the CLI fail or hang when the store is busy or absent. The existing wait contract also bounds discovery, sockets and sleeps by one deadline.

`heartbeatSilence` calls `inStore`, which opens the shared SQLite store with a fixed 1,000 ms busy timeout. `inStore` handles missing/newer/corrupt-store return values but does not catch `SQLITE_BUSY` from opening or reading. Thus a diagnostic that should be optional can throw instead of rendering the already recorded socket evidence. The lint path additionally builds `deadlineText` before every pending poll, so it reads the heartbeat repeatedly, even before the deadline. The worker notes describe this as one read at the deadline.

**Observed with a private WAL store and a stand-in socket:** the socket returned a valid pending response, with the scheduler's holder. Immediately before sending that response it took an exclusive SQLite connection lock. The diagnostic read then failed:

```text
source runLintGroupCommand, waitMs=300, unlocked:
  306 ms, return 3, no stderr, correct no-verdict/holder/next-action line
source runLintGroupCommand, waitMs=300, busy:
  1008 ms, throws "database is locked", errcode 5, no stdout

committed 0.1.409 CLI, run lint --wait 300, unlocked:
  490 ms including process startup, exit 3, no stderr
committed 0.1.409 CLI, run lint --wait 300, busy:
  1294 ms including process startup, exit 1, no stdout
  Error: database is locked
  at userVersion (.../plugins/claude-code/dist/cli/squeal.mjs:5054:51)
```

This probe does not claim that ordinary WAL writers block heartbeat reads. It exercises an unreadable busy store, the failure mode R1 names. With no store, `heartbeatSilence` returned `null` correctly. The exact 0.1.408 CLI read the same new payload without error: exit 3, 479 ms including process startup, no stderr.

**One-worker fix:** make this optional observation fail closed to no heartbeat detail when the store cannot be read. Keep the socket's holder and next action, and preserve exit 3. Give the read a small budget within the command's deadline; catching an exception after a fixed one-second wait alone does not restore the deadline. In the lint loop, render/read only when returning the deadline response, including its unanswered-final-poll branch. Add private-store regression coverage for busy and absent stores in both lint and test-group commands. Check bounded elapsed time, exit 3, empty stderr, and retention of the recorded holder. Rebuild bundles through the coordinator's normal gate.
