## What fits

- **Honest state and retirement.** R1 tests 1 to 7 run through a real daemon and pass. A removed project's key and states disappear. Its told failure becomes one `fail-retired` delivery, then silence. A later edit runs nothing; retry refuses it. The kept project's key, states and run count do not move. The held removed run stops, reports no stored result, and does not erase the kept part of its tier. A changed run finishes and its file runs at the new key. The pending retry disappears with the removed file. Invalid JSON preserves the projects until the next valid save.
- **The reconciliation seam.** The generic set has one implementation for node:test and pytest, keyed by name and a canonical stamp of every entry field. A field-order change leaves the runner alone. Every `invalidate` reconciles before fan-out. Owners of all leavers go before a new listing claims their names, so a name swap or a move between sets has no conflict. Added and recreated names force the existing environment/listing refinement; the existing ledger removes keys, queue entries, retry claims and states in its commit. No scheduler rewrite is hidden in this range.
- **Runs during a reload.** The composite snapshots its run groups synchronously when owners are known. A removed member gets its own stop signal, joined to the outer signal. Its report is withheld, including diagnostics and observed inputs. This avoids an `unknown` replacing a told failure before the listing retires it. A replaced member already running finishes. A removed or replaced member whose part has not started is withheld and never called after close. Unit tests cover each case, kept parts and close ordering.
- **History in the right worktree.** Each listed failure gets one lookup by its provenance worktree, project and path. Stored and replaced entries both use it after the merge's limit. A row with a null key remains active. The tests cover deleted, removed, renamed and kept projects, removed worktrees, reads from either worktree, JSON and text, replaced history, the 20-row cap, unchanged totals and exactly 20 lookups for 20 listed rows.
- **Registration before printing.** Both handoff and spawn use `served`, which matches the answering ping's start time to the recorded daemon. Handoff still requires a nonstopping successor at least as new as the CLI. At the bound an answering successor is printed; with none answering, the old exit-1 path remains. The new stand-ins detect both missing waits. The existing handoff, warmup and lifecycle checks pass without weakened assertions.
- **Spec and scope.** C6 records inactive history, including listed-but-unkeyed files in the amendment log. C9 records registration before printing, the handoff bound and the 10 s spawn bound. C10 records withholding an unstarted part and ignoring object-field order. The three new status lines name the actual implementation choices, including reconciliation on every invalidation and the accepted close-error policy. The board rows are still `running` while the candidate awaits review; this is not a false completed-work claim.
