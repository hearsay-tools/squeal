## B1: resolved

The original failure was a real SessionStart that found no stop, spawned, then read an `untilStart` mark left during its settle. `asTold` removed `stopped` but kept `untilStart`, and the new header branch printed stopped instead of starting.

The repair now removes both projected stop flags in `asTold` through `withoutStop`. `asStopped` checks the same start marks as 011-251 through `marksOf`, with the reader's clock. A live start mark wins with either record; a recent spawn mark wins only with the record cleared. `stopOf` prevents every changed renderer from reading `untilStart` alone or naming a stop beside `startingSince`. All three `asStopped` callers pass their existing clock.

The new `test/harness/until-start-spawn.test.ts` reproduces the original sequence through the real `runHook`. It writes the mark inside the injected ensure call before returning `spawned`. The registration, status, JSON, full status, header and wait read starting. The first heartbeat reads alive without duplicate news. After the record clears, those readers show stopped until start again. The test asserts exactly one spawn across the sequence, including a later boundary past the start grace. Its current affected result passes.

`test/cli/until-start-readers.test.ts` exercises the first review's table through the actual CLI formats, a real header and the wait's first judgment. All twelve combinations pass, six for each stop:

| Record | Other mark | Status, full status, JSON and header | Wait's first judgment |
| --- | --- | --- | --- |
| Cleared | None | Stopped, in the stored mode | Down, stopped |
| Cleared | Recent spawn | Starting, `startMark: "spawn"`, no stop flags | Lapsed, locked |
| Cleared | Live locked start | Starting, `startMark: "start"`, no stop flags | Lapsed, locked |
| Stale | None | Stopped, in the stored mode | Lapsed, socket check pending |
| Stale | Recent spawn only | Stopped, in the stored mode | Lapsed, socket check pending |
| Stale | Live locked start | Starting, `startMark: "start"`, no stop flags | Lapsed, locked |

The last two socket-check readings remain intentionally distinct from a confirmed live start. In particular, a spawn mark alone with a stale record remains no proof of a start, as required by the 0.1.355 repair. The wait code, `died.ts`, `stopping.ts` and shared ensure code are unchanged from the new base.

The repair does not modify `markStopped`, `heldStop` or `stopHolds`. The durable mark still suppresses ensure calls and returns before the tree print. The affected Git, worktree, heartbeat, plain-stop, start and no-store controls pass. Updating the fixture to answer `alive` for an already-recorded live daemon removes a false spawn mark from setup; it does not remove those assertions.
