**Contract:** 011 C14 says the adapter “reports how many checks the runner collected and how many held a text.” The accepted design section 2.2 requires `collected` and `matched` in the focused meta entry; C15 needs the zero-match case to say `No check ... (the run collected M checks)`. R2 is the producer of that entry. Its consumer cannot recover these counts from an empty list of selected results.

The probe above proves that a runner's valid `collected: 4, matched: 0` is lost while the file remains completed. The recorder stores no zero-match count. This is a newly enabled report boundary in this wave, even though the lossy merge body predates it. The wrappers' new test checks capability forwarding only. The real-Vitest scheduler test bypasses the daemon's composite, so its `matched: 2` assertion cannot detect this.

**One-worker fix:** merge the parts' `focused` arrays in `composite-runner.ts`, retaining the project/file identity and the distinction between no field and a zero match. Add a regression that executes a focused run through the daemon's wrapper stack and checks the persisted `collected`/`matched` for both a match and no match. Keep the whole-file report unchanged. Rebuild the shipped bundles through the coordinator.

### B2. A backlog turn that cannot run lets whole files overtake their focused entries

**Proven, blocking.** `src/core/scheduler/focused.ts:83` to 87, used at line 107. `turnFirst` asks the raw `queue.hasFast` whether a second-group file exists in a free lane. It does not apply the drain filter used by `Ledger.ordered`/`fastQueued`, or the claim check that tier selection applies. When the four-tier fairness turn is due, such a file suppresses *all* focused selection. Ordinary selection then skips the paused or claimed backlog and takes the promoted files whole. Their results make their remaining focused entries disappear.

**Contract:** 011 C4's focused tier goes before every other class of its lane, promoted files included, subject to the backlog's actual turn after four first-group tiers. R2's done-when says “the focused tier leads its lane” and “the file's own run leads the next tier.” C9/011-93 leaves the backlog paused during a departure drain; it cannot take that turn. The worker's accepted decision in `status.md` says the backlog goes first only when it can start in a free lane and quiet does not hold it.

**Reproduction:** adapt `test/scheduler/focused-turn.test.ts` case 5, with `tierSize: 1`: one held short tier `S`, five edited files `f1` to `f5`, and a re-keyed environment-only backlog file `B`.
