## What fits

- **The cause holds in the installed source.** A newly ignored directory reaches `onDebounced` through `ignoredDirs`. `buildWatchSpec` adds an exclusion. `chokidarBackend.update` opens W2, waits for ready and then closes W1 whenever exclusions grow. In chokidar 5.0.0's `handler.js`, `_handleFile` awaits `stat(file)` for an `fs.watch` notification and returns without emitting if `this.fsw.closed` is then true. W2 attaches its per-path listener only when its scan reaches that file; `ignoreInitial` suppresses an initial add. An edit before W2 attaches, whose W1 stat completes after close, can therefore disappear from both watches. The old feed returned false when exclusions only grew. The worker's forced trace is consistent with this path; the original CI failure alone did not prove this exact ordering.
- **The fix reaches the correct boundary.** `rebuildSpec` returns true only after a different spec has successfully updated the subscription. `onDebounced` then calls `reconcileNow("watch")` once, after delivering any kept hinted paths. That pass reads Git status and re-stats the cache and extra files, so a tracked file omitted from hints is examined again. The scheduler still decides whether bytes changed and whether a revision is needed. No new result acceptance, status provenance or hold bypass is introduced.
- **Other backends receive the same feed recovery.** Parcel also replaces subscriptions. Its native `UnsubscribeRunner` calls `Watcher::unwatch` before backend removal; `unwatch` erases the callback without flushing pending events, and `triggerCallbacks` delivers only while callbacks remain. A scratch probe on installed @parcel/watcher 2.6.0, Linux, primed its debounce, wrote the target, subscribed with a new exclusion and unsubscribed the old subscription in about 1 ms. The pending target edit never arrived in 200 ms; a later target edit arrived through the new subscription. This proves an analogous pending-event gap in the shared subscription mechanism on Linux; the FSEvents source also starts its replacement stream from “since now”, but macOS was not run here. The added feed pass applies after exclusion changes for either backend. There is no separate polling backend in Squeal. `CHOKIDAR_USEPOLLING` can switch chokidar to `fs.watchFile`; its ordinary nonzero-stat callback supplies the stats and does not take the awaited-stat branch that caused the reported native-watch race. Polling swaps or newly included paths still get the same follow-up pass. No claim of exhaustive polling or macOS verification is made.
- **No self-sustaining loop appears.** `reconcileNow` can itself update the spec, then gathers candidates and emits one batch; it never recursively calls itself. `sameWatchSpec` compares the sorted exclusions and extras and skips an unchanged update. The feed queue serializes work. Scheduler extra-file notifications enqueue their update without awaiting the current batch; a stable set does not update the backend again. A new excluded directory triggers one pass. Further writes inside it produce no root-watch hints. Ignored directories Git does not list are remembered in `UnlistedDirs`, and an unchanged spec returns false. A second real filesystem change can require another pass; that is new work, not a loop.

It is not paid per edit, per cache result, or per unchanged spec rebuild. An existing `node_modules` excludes Vitest's cache before it appears. The watcher replacement already scans the tree. This is an acceptable cost for recovering an edit immediately instead of waiting 30 s.
