### The repaired wait

**Proven, source and controlled regression:** claims `FakeRunner.runs` records starts. Its `run()` can still be sleeping after `release()` opens its held gate. Counting starts or opening that gate does not establish a result. The claims builder passes `countCalls(runner, calls)` to the scheduler, and its `quiet()` waits for `calls.runs` even without a runner-part bound. It then rests again so scheduler result processing finishes. The existing `ran(F1) === 0` and `passing() === 2` assertions keep their meaning.

To separate this behavior from host speed, a private archive of the repair pin added a promise gate through `b.runner.during`, only in the `records` case. At the changed wait it captured whether the wait returned, let 50 ms pass, and required it still to be pending, with one active run and only one passing file. It then opened the gate, awaited the wait and kept both original assertions. Test cleanup also opened the gate. This suspended a runner; it created no CPU load.
