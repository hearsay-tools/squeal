### N2. Proven: one clock reading is an observable timing exception

Locations: `src/core/scheduler/tier-live.ts:40`, `src/core/scheduler/scheduler.ts:1130` and `src/core/scheduler/scheduler.ts:1384`.

The design explicitly says "One clock reading" and permits the quiet wake to use it instead of the later reading. This implementation follows that choice. It does not preserve every boundary-time decision literally: a claim bound, focused deadline, quiet deadline or promotion rank that expires between two former readings is now judged at the plan's earlier instant. Start order can consequently differ at that boundary. This is the approved clock change, not an extra order rule introduced by the generator.

The pump also sleeps `wakeAt - at` after awaiting `#groupLanesNext`. For example, with 200 ms of quiet remaining when the plan reads the clock, and a 100 ms intervening group-lane check returning false without a wake, the new pump sleeps another 200 ms; the old pump would read 100 ms remaining. The extra 100 ms is observable. A notify still ends the wait immediately. The source imposes no millisecond-size bound on the intervening async work; the worker notes' "milliseconds" is an expectation, not a proved upper bound.

No fix is required for this row because the design names this difference. Coordinator action: record the timing qualification when accepting the worker's calls. Any later change to sleep against a fresh absolute deadline should be a small behavior row with a controlled-clock regression case.
