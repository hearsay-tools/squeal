## What fits

### Lease safety

- `src/core/daemon/write-desk.ts:186`: only an explicit `false` liveness
  result ends an idle lease early. A missing process identity or `null`
  liveness keeps the lease until its existing time bound. The unchanged
  process check compares PID namespace and start time, rejects a reused
  PID, treats a stopped process as live, and treats an unreadable identity
  as unknown. The real-process tests cover exit, SIGSTOP, PID reuse and a
  different namespace.
- A pending write returns before any liveness check. The new test keeps a
  dead client's lease until its write settles, then allows the next lease.
  The real hook test kills a holder and delivers the still-owed transition
  within the original lease time, without the former five-second sleep.
- A live holder paused past its time still keeps the lease and renews its
  time bound. Thus the early dead-holder branch does not reopen review
  0.1.442 B3's duplicate-report window for a live paused hook.
- The stopping path uses the same current-lease decision. It refuses a
  second client while a live or pending-write holder owns the lease. Once
  no lease remains, it returns `daemon is stopping`, as before. It grants
  no new lease or socket write during stopping.

### Store reads and delivery

- `src/core/code/store/schema.ts:141`: both indexes use the existing
  additive open path. No migration, existing column or `user_version`
  changes. Creation still rechecks under the write lock. Reader opens
  make neither index.
- `src/core/code/store/states.ts:62`: readers detect which indexes exist.
  They omit `INDEXED BY` on an older store. Tests drop both indexes, read
  through `create: false`, verify identical answers and continued absence
  of the indexes, then verify that a creating open restores them. Failing,
  edited, other-outcome, measure, worktree and path filters keep their
  answers and order. `EXPLAIN QUERY PLAN` names `states_failing` and
  `states_edited` for the intended reads. Path-limited reads keep their
  primary-key lookup.
- `src/core/delivery/code-reads.ts:24`: the maps belong to one call inside
  one transaction, with separate entries per measure. They preserve the
  previous measure order and each query's row order. Empty results are
  cached too. The candidate test confirms one failing and edited read per
  measure per transaction, including the quiet boundary.
- `src/core/delivery/code-deliver.ts:441`: the initial read and the later
  write each create their own cache. The summary-only write does not
  receive the initial cache. `codeStep` writes views and told marks, not
  states. `withToldOver` reads the updated view after the step while sharing
  the same transaction's failing states. The optional argument to
  `code-told.ts` preserves callers that do not supply cached states.
- The temporary differential proof loaded `code-deliver.ts` and
  `code-told.ts` from `325b21404`, with their other dependencies pointing
  at unchanged candidate modules. It compared complete registration
  values, views and delivery payloads against the candidate for all three
  measures: registration seeds, a quiet boundary, first failure,
  told-over counts, repeated silence, first edit after failure, recovery,
  complexity/CRAP recounts and reseeding. All values matched. It also
  asserted the three told-over counts and both recount counts directly.
- Two turnover probes committed a recovery on a separate writer after
  the initial read transaction ended and before the write began. Both the
  ordinary write and `HoldingConnection` path returned no stale failure
  and left no failing view entry after commit. Existing delivery tests
  cover standing failures, summaries told once, recount timing, and CRAP
  and untested news through the public delivery path.
