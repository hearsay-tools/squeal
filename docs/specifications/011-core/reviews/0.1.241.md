## Verdict

**FAIL**: one proven blocker in the new test, one plausible portability note and one proven documentation nit. No proven fault in the runtime GC implementation. A local pass does not clear the CI failure or the test setup error below.

## Blockers

### B1. Proven: the daemon test holds the wrong slow-slot permit

Location: `test/daemon/idle-gc-daemon.test.ts:41`, with the failing assertion at line 100.

The row's done-when requires proof that queued work waiting for a slot counts as idle. The test takes `slowSlotDir(repo.env)`, whose runtime directory belongs to the fixture. It passes that environment to `startDaemon`, but does not change the test process's `XDG_RUNTIME_DIR`.

The daemon passes the fixture directory to its capacity pool (`src/core/daemon/daemon.ts:557`). It does not pass a `slow.slotDir` override. The slow lane therefore takes `this.options.slotDir ?? slowSlotDir()` (`src/core/scheduler/slow-tier.ts:184`), which reads the test process's environment. The held permit and the slow lane's permit are in different directories. Holding the first cannot keep the slow file queued.

CI proves the consequence: the slow file stored `pass` before line 100, although the test still held its permit. The GC assertions before that line passed. Locally the full run and the separate Node 22 run pass, so a passing result here depends on whether the unblocked slow lane starts before the assertion. The added two-second quiet check does not fix the permit mismatch.

Repair scope: this test only. Point the process's slow-slot lookup at the fixture runtime directory for the test, restore it at teardown, and assert that the slow lane has actually entered its slot wait before advancing the GC clock. Keep the assertions that the slow file has no result. Verify the repaired test on Node 22 and Node 24, including CI. Do not change product scheduling to satisfy the test.

## Should-fix

### S1. Plausible: the memory test does not skip Linux without `/proc`

Location: `test/daemon/idle-gc-memory.test.ts:29`.

The review brief asks for a skip where `/proc` is absent. The guard checks only `process.platform === "linux"`. On Linux without a readable `/proc/self/status`, production `readMemory()` falls back to RSS, while the test still requires `kind === "private"`. That environment was not exercised here. This is a portability note, not a demonstrated break on the tested hosts. Gate the test on the private-memory reading being available.

## What fits

- `idleGcDue` enforces the 60-second boundary, no active tier and one collection per quiet interval. `ended()` resets the interval only after a tracked run ends. Concurrent tracked runs keep the counter nonzero until all finish.
- The daemon wraps the composite runner outside `afterEachRun`. Fast Vitest, slow Vitest, node:test and pytest runs all reach `executeTier` and that same wrapper, including backlog slots. Slow slot and load waits occur before `executeTier`, so queued work alone does not prevent collection.
- The daemon owns the GC state across timer restarts. Its callback checks the stopping phase. Shutdown sets that phase and stops the timers before awaiting runner closure. The lifecycle's `attempt` contains unexpected errors from the callback.
- Missing, throwing lookup and throwing GC cases disable collection and persist one note. The unit cases check that subsequent tiers do not restart lookup or GC retries. A successful collection logs memory before and after, plus pause duration.
- The temporary expose flag is cleared in `finally` after context lookup. There is no asynchronous gap while it is enabled. The child probe checks the resulting global and worker-thread state. An existing global GC uses the early return and is left intact.
- The memory regression compares a plain major GC with the real idle last-resort call in a fresh child process. The Node 24 suite and the separate Node 22 probe support its intended distinction.
- All eight version files carry 0.1.241; the lockfile's root package agrees. All four committed CLI bundles have SHA-256 `022d5b7ebfd02ad25ad7d6cf62ed8f4395470355ecbcb9f8fc8e8869b1156421`. The existing bundle comparisons passed. No key-format or recorder version change is needed for this resource-only behavior.
