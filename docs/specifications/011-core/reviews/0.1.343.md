## Blockers

### B1. Proven: daemon mode disables the macOS descendant reader

**Location:** `src/core/daemon/outlived.ts:102` and `:298`; the hook is installed at `src/core/daemon/escaped.ts:435`.

**Contract:** 011-245 requires reading a worker's descendants before forced cancellation and naming those still alive after it. Its scope explicitly includes how the descendants are read on Linux and macOS. The amended 011 C13 says the daemon reads "the workers' descendants" and describes macOS as having "no env tie and no session id". The worker notes promise that a macOS holder still below a worker, or in a group a worker or descendant leads, is found.

**Failure:** the daemon always gives Vitest workers `SQUEAL_DAEMON_CHILD`. `tiesOf` therefore supplies `worker`. `heldByRun` accepts a child as a worker only when `table.variable(pid, worker.variable) === worker.value`. The macOS table always returns null. Thus `workers`, `below` and `ids` are empty. Its recorder-variable reads also return null. Every branch of the final selection is false, even for a live holder whose parent is the run's live worker. A forced cancel then kills the worker and leaves that holder without the promised note. The fake-table probe above reproduces this with the real daemon ties. No timing race or unreadable real host is needed.

The current macOS test only parses `ps` rows. The descendant/group test calls `heldByRun({})`, which removes the production marker requirement and cannot catch this seam failure.

**One-worker fix:** give macOS worker selection a positive, run-specific identity source that works without environment reads, then use it to seed the descendant/group walk. Preserve exclusion of another daemon, another lane's overlapping run and the daemon itself; do not replace the marker check with "all daemon children". Add a table-driven test through `cutReading` or `afterEachRun` with the daemon marker present and macOS's null-variable table, asserting the own descendant is named and the other lane is excluded. Keep the 500 ms forced-cancel bound, bounded `ps` calls and the unchanged sweep. If the safe identity requires a hook-contract change, the coordinator must amend that contract with the repair.
