## Should-fix

### S1, proven: the side finding understates how long the missed full check can wait

`tasks/011-373/notes.md:38` says the next full check is "up to 24 hours later".
The underlying observation is real, but this upper bound is not.
`claimFullCheck` (`src/core/daemon/full-check.ts:116`) records the start time
and refuses a new claim for 24 hours. It has no owner identity. SIGKILL
prevents the parent's `finally` at line 224 from returning that claim. Only
the parent consumes the child's JSON and writes a fault mark. An orphan's
fault therefore does not mark the store. `daemon.ts:984` starts a full check
once on reaching ready; there is no daily retry timer. Another check becomes
eligible after 24 hours and runs at a subsequent daemon start. With no later
start, the delay has no fixed upper bound.

**One-worker fix:** correct the row notes to name eligibility and the need for
a later start. No product change is required to land these two rows. A change
to claim recovery needs a separate approved row, not an expansion of this one.

**How often it matters:** the parent must die after claiming and before consuming
the answer. The notes measured an orphan living roughly four seconds on the
large fixture. No production interruption rate or corruption rate was measured.
Loss of fault reporting additionally requires a fault found by the full check
that the replacement's quick check does not detect, such as index inconsistency.
Kills during startup can correlate with that window, so a probability based on
uniform random kills would be misleading. This is a real pre-existing recovery
gap, not a new product regression or a blocker against these test-only changes.

## Notes

### N1, plausible: protect the frozen check independently of the suite callback queue

`test/daemon/sigkill-children.test.ts:138` registers the frozen check's kill in
`suite.cleanup`. The existing `daemonSuite` hook first awaits `stopStrays`, then
runs these callbacks (`test/daemon/helpers.ts:444`). If runner-host shutdown
fails, that await throws before the callbacks. The stopped-host probe reached
this error, but no surviving check was observed, so a leak remains unproven.

**One-worker improvement:** put the frozen check under a test-local `try/finally`
that kills it and waits for its exit before suite teardown. Keep the existing
suite cleanup as a fallback. Verify both the happy path and failed host exit.
No shared-helper rewrite is necessary for this row.

### N2, plausible: freezing removes the replacement race, but not the capture race

`test/daemon/sigkill-children.test.ts:121` waits for ready before discovering the
short-lived check, then inspects its descriptors and runner hosts before SIGSTOP
at line 137. Descheduling the test worker while the check runs can lose that
capture window; a later 30-second poll cannot find a check that has already
finished. This did not occur in the normal run. No host-load failure is proven.

**One-worker improvement:** synchronize check entry and pause with a test hook
or controlled child handshake if this becomes a flake. Do not enlarge the store
or choose a longer host-specific sleep. The existing SIGSTOP proof after capture
is sound.
