## Blockers

### B1. Proven: the new stop text hides a daemon that SessionStart just spawned

Changed boundary: `src/core/delivery/header.ts:201`; introduced field: `src/core/delivery/stopped.ts:108`. The existing `asTold` boundary at `src/core/delivery/liveness.ts:211` removes `stopped` when a consumer is told a daemon is starting, but now leaves `untilStart`. The new header branch reads `untilStart` before `startingSince` and prints a stopped daemon.

Contract: vision principle 2 says “An old result never gets to pose as the current truth.” C9's 011-251 amendment says “the headers say a daemon is starting”. The 011-254 amendment explicitly allows a daemon spawned in the stop window to validate until it exits. That accepted race does not authorize reporting it as stopped.

Failure sequence:

1. SessionStart finds no daemon and no stop mark, then starts its spawn.
2. `squeal stop --until-start` leaves its mark before that hook finishes registering, as in the documented row 011-20 window.
3. The hook reports `spawned`. No heartbeat arrives within its 750 ms settle budget. It registers with `startingSince`.
4. `asTold` produces a down liveness value with `startingSince` and `untilStart: true`, but no `stopped` flag. The header prints “The daemon is stopped until `squeal start`” instead of “A daemon is starting”. The process can register and validate next without any explicit start.

I reproduced this through the real exported `runHook("session-start", ...)`, with a private store and runtime directory. The injected `ensureDaemon` writes `markStopped(store, id, now + 1, null, untilStart)` inside a transaction, then returns `"spawned"`. I ran identical cases with `untilStart` false and true. This models the mark landing after the hook checked it, rather than assuming a race occurred.

An active start must remain visible in registration, status, full status and delivery; a starting projection must not leave `untilStart` to masquerade as a stopped daemon. Keep the stored `untilStart` mark, so no later boundary spawns after the racing daemon exits. Add the true-mode version of the existing stop-during-SessionStart test, plus cleared/stale record cases with start/spawn marks. Check the same state through JSON, status and a real formatted header. Do not merely change the string or clear the durable mark.
