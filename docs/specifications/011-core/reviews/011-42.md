## Blockers

### B1. Proven: a named wait on a running slow file still reads every known state on each open poll

**Boundary:** `src/cli/status-wait-paths.ts:247–268`, especially its `pauseOnlyIds` call at line 262; `src/cli/named-files.ts:136`. **Missing regression:** `test/cli/wait-reads.test.ts:78` covers a fast named file only.

C6 says: “Each poll reads only what decides whether the wait ends, never every known state of the worktree”; the brief requires that a status wait poll with nothing changed for its files make no unfiltered `knownStates.list` call.

Reproduction, using the existing counting-store helper:

1. Seed revision 4 with one slow test file pending and one unrelated current test file. Declare the slow path under `slow.include`, with `slow.trigger: "idle"`.
2. Leave the slow file's key row `pending: "running"`. Supply a live daemon record and a sync answer at revision 4. Nothing changes during the wait.
3. Call `waitForNamed(root, [slowPath], { timeoutMs: 2500, pollMs: 1000, settleMs: 0, ... })`.
4. Discard the first and final store sessions. Both intermediate sessions log `["file-states", "states"]`. The wait returns `timeout`.

`readClasses` filters its read correctly. However, each ready poll also calls `pauseOnlyIds`, which filters the selected refs to slow files and then reads **all** known states before checking whether the slow file is running. A running file stays held, so every subsequent open poll repeats the full read. Its unrelated worktree states cannot change this file's pause eligibility or end the wait. A queued slow file held by a claim or lane work can also keep reaching the same read.

This is a proven failure of this row's stated outcome and done-when, not a new false pass. The helper's unfiltered read predates the candidate, but it is directly on the polling path this row promises to narrow. The worker's handoff explicitly lists it as left outside ownership; the candidate has no C6 amendment accepting that exception. It needs a small integration repair.

**Repair sized for one worker:** grant ownership of `src/cli/named-files.ts` for this seam and change the read inside `pauseOnlyIds` to `store.knownStates.list(worktreeId, slow)`, or provide the same filtered data from its caller. It uses only those files' checks. Add the running slow-file counting regression alongside the fast named-file case. Keep the idle-pause, running, claim, continuous-trigger and mixed fast/slow verdict tests passing. Rebuild the committed bundles and review the repair at its exact candidate SHA.
