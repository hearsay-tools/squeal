## Blockers

### B1. Proven: registration samples its heartbeat before the operations it used to follow

Locations: `src/core/daemon/daemon.ts:454`, especially `heartbeatAt: this.#now()` at line 462; `src/core/presence/events.ts:58` and its upsert at line 69. Base comparison: `daemon.ts` lines 453–475 at `1483c7619`.

Contract: the board row says **"Behaviour preserved; stored formats unchanged"**. The review brief also requires that the `daemon.ts` move change no ordering or clock read. The two calls to the clock remain, but their positions relative to I/O do not.

The old registration does this inside its transaction:

```text
exit mark -> handoff clock -> endHandoff -> linkedWorktreeDir
-> worktrees.upsert -> heartbeat clock -> worktrees.setDaemon
```

The candidate evaluates the complete event argument before entering `recordRegistration`:

```text
linkedWorktreeDir -> handoff clock -> heartbeat clock
-> exit mark -> endHandoff -> worktrees.upsert -> worktrees.setDaemon
```

The external comparison executed both method bodies with the same store double. Its clock starts at 1000 ms. `worktrees.upsert` advances it by 11000 ms to model an I/O pause or descheduling inside that operation. The heartbeat interval is 5000 ms. The test asserts these results using the unchanged `daemonLiveness` rule immediately after registration:

| Value | Base | Candidate |
| --- | --- | --- |
| Clock after registration | 12000 | 12000 |
| Stored `heartbeatAt` | 12000 | 1000 |
| Heartbeat reading | `alive` | `down` |

This proves the changed sampling boundary and its effect under that timing. It does not claim that an 11-second pause occurred in a real daemon during review. Even a shorter pause changes the stored timestamp. A real pause beyond grace can make a newly registered daemon read down until its next beat. The moved layout read also precedes the handoff clock and exit mark now; preserve its old position in the repair.

Fix, one worker: keep the presence event as the writer, but defer worktree metadata and heartbeat evaluation until their old points within registration. A clock callback or lazy event inputs can preserve this order. Keep the two distinct clock reads, the same transaction, release of predecessor runs before registration, and start/spawn mark clearing after commit. Add one ordered registration test that advances the clock during a store operation. A test that only counts two clock calls cannot catch this break. The event-byte tests pass because their times are already values when they call the event.
