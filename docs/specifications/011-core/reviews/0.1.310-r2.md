### N1. Proven: a sentinel snapshot hides a genuine later touch

**Location:** `src/core/scheduler/stability.ts:70`; the snapshot is taken at `src/core/scheduler/tiers.ts:466` and checked by `unstableInputs` at line 587.

**Contract:** C2 says, "Before a tier is recorded, the inputs its keys name are re-stat'ed against the stat cache as the tier was selected: a touch found there, whose batch has not arrived, withholds the files whose keys name it." Its examples include "a revert and its restore inside one batch". This is a new finding in the repair delta, so the bounded re-review files it as a note. It does not reopen B1's lost write across reload.

`unknownStat` correctly forces a hash read, but `touchedUnchanged` skips every cached sentinel. This also skips a write made after tier selection. A concrete sequence is:

1. A racy cached file is written between a pass's candidate stat and its hash read. The pass stores the new content and a sentinel, then starts the content change's tier. `newTier` copies that sentinel into the tier snapshot; it does not first replace it with a real-stat baseline.
2. While the tier runs, the file is changed to other bytes and restored to the keyed bytes. The tier can execute those other bytes. No watcher batch has arrived yet. The completion stat differs; the probe also advances mtime to remove timestamp-tick dependence.
3. `changedSince` reads the restored bytes. There is no content change. Line 70 drops the touch because the snapshot is a sentinel, so it returns both `changed` and `touched` empty. The completion barrier has no touch to withhold. A later stable reconciliation cannot repair the already captured sentinel snapshot.

A real-filesystem probe of exactly that reconciliation/snapshot/restore sequence fails its expected-touch assertion here. The same probe passes on the first candidate's archived source. This establishes the missing touch. The source path from `newTier` to `unstableInputs` establishes where a live tier can use that snapshot; this review did not run a second full scheduler proof of the final result store.

**Bounded follow-up for one worker:** retain persistent distrust of a moved hash/stat pair, while giving a tier a real stat baseline against which later same-bytes writes can be detected. Distinguish the pre-read write whose own batch must not emit a false touch from a write made after the tier starts. Add the sentinel-snapshot revert/restore case and a tier completion case.
