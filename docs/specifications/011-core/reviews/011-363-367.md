## Should-fix

### S1. Catch-up `settle` can fire an earlier non-gather wake

**Proven helper limitation; plausible impact on future callers; non-blocking for this wave.** `test/scheduler/tier-yields-fixture.ts:81-87`. R1 asks that helpers “cannot pass a bound or recheck a test means to stay before.” The helper selects every `slot-gather` from `rest.wakes`, without checking `rest.next`, then advances to the gather. `VirtualClock.advance` fires every earlier timer too.

The throwaway probe supplied a side with a stable empty run list, a virtual clock at 0, a `yield-bound` at 10 and a `slot-gather` at 25. Its `rest` returned the pending wakes in order. After `await settle(side)`, the clock was 25 and the fired list was `['yield-bound', 'slot-gather']`. The same pending-wake setup through `drive-fixture.until(..., { steps: 1 })` left time at 0 and fired nothing.

The current moved tests do not establish this overlap: their before-bound checks hold the relevant run, and their required record gathers finish in setup or after the intended release. I found no assertion made vacuous by this path, so it does not prove a break of either row's done-when. It does refute the helper's comment that no other wake fires unless the test moves time.

**One-worker fix:** before advancing a gather, reject or expose any earlier or simultaneous non-gather wake so the caller chooses whether to advance it. Add a focused test with an earlier yield bound and a later gather. Preserve the existing eleven-file results. Do this before reusing the helper for overlapping slots and deadline checks.

## Nits

### N1. The drive helper's comment excludes a pool recheck that its default permits

**Proven, non-blocking.** `test/scheduler/drive-fixture.ts:34`, also the helper description in `tasks/011-367/notes.md:8`. The default `DRIVEN` includes `pump`. A pool refusal produces a timed pump wake (`src/core/scheduler/step.ts:372-373`, then `scheduler.ts`'s timed wait). Therefore the default does advance pool rechecks. This is needed by `idleOn` and agrees with the worker's reported repeated-pump failure; it is not a new product defect.

**Fix:** say that the default drives gathers and pump waits, including capacity rechecks. Callers that must remain before a capacity recheck must use explicit `advance`/`rest`, as `capacity-pool` case 2 already does, or exclude `pump` through `driven`. No behavior change is needed.
