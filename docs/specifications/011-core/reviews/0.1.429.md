## Blockers

### B1. Proven: a stop mark suppresses an existing failure hold beside an open check

Location: `src/harness/shared/stop-required.ts:142`, in `requiredStep`.
Consumers: the 2 s entry's `heldReason` in `stop-decide.ts` and the
waiting entry's `decide` in `stop-slow.ts`.

011 C8's new amendment requires: "Holds for required failures already
found, and every rule for a daemon that died, are unchanged." R1 also
explicitly requires that "the stopped-on-purpose rule never hides a
failure already found". The new branch returns `null` whenever **any**
required check is open and the daemon is stopped by request. It never
reaches `failingLines`, even for a different check whose failure is
current and already known. `lintStopReasons` excludes the required lint
tools, so it cannot supply the missing hold elsewhere.

Reproduce with the existing wiring and hook fixtures, separately for
Claude Code and Codex:

1. Use `hookedRepo({ "src/a.js": "ok\n" }, { enabled: true, blocking: true },
   { checks: [{ name: "lint", lint: true, at: "stop" }],
   stop: { slowWaitMs: 400 } })`.
2. Start the main agent's turn and mark the waiting entry known.
3. Edit `src/a.js` to `bad no-undef\n`. Release the lint group using
   `releaseLintGroup` and the fixture tree's current hashes. Settle the
   lint pass. This records a current own failure after registration.
4. Add a pending check for `untouched.js` with `pendingLint(r)`.
5. Clear the daemon record and call
   `markStopped(store, worktreeId, Date.now() + 1, null, true)`.
6. Run `stopBoth` twice and read the consumer's stop-hold count.

Actual observations, from the focused probe:

| Harness | Untouched check pending | Required holds after both Stops | Second quick entry | Second waiting entry |
| --- | --- | --- | --- | --- |
| Claude Code | no (control) | 1 | silent | silent |
| Codex | no (control) | 1 | silent | silent |
| Claude Code | yes | **0** | silent | silent |
| Codex | yes | **0** | silent | silent |

In the failing cases the first quick entry delivers `FAIL lint: src/a.js:
1 finding, +1 no-undef (no-undef found)` as news, alongside the new
stopped-daemon information line for `untouched.js`. It never gives the
`lint.blocking` hold that the control gives. The next Stop is silent and
the turn ends with that required failure still present. Codex encodes the
initial news as a harness `block`, but it is not a counted required hold;
the same missing policy hold occurs in both harnesses.

One-worker fix: keep open checks nonblocking while stopped, but continue
to the existing failure decision instead of returning `null` for the
whole required step. Keep the live/crashed-daemon open-first order,
no-edit exemption and per-turn hold budget. Add regression cases with
one current required failure and another open check under a stop mark;
exercise both entries and both harnesses. Keep the no-pending controls.

## What fits

- `unchangedSinceRegistration(context)` remains the single decision owner.
  Both entries call it; any revision after registration defeats it,
  including another session's revision.
- The registration records `HEAD` through the shared delivery, with the
  root supplied by the hook context. This covers a linked worktree before
  its daemon has registered a root. Older values without `head` still
  read, and a returning registration keeps its original head.
- Git runs outside the deciding transactions, only when no revision and
  no scanned-daemon proof leave the second proof able to decide. The
  per-context cache avoids repeated reads. Git errors and a bounded
  timeout leave the proof false. The 2 s entry limits Git to its remaining
  budget; the waiting entry caps its Git read at 1 s.
- The selected current tests cover a fresh registration before the scan,
  an unobserved tracked edit, a commit, an untracked new file, both
  subagent exemptions, and an edit after subagent registration. The
  Codex no-edit case starts after a main-agent revision, so that earlier
  revision does not incorrectly count as the subagent's edit.
- Stop marks with and without `--until-start` release open lint checks;
  the information line rides on existing news and names `squeal start`.
  A later Stop stays silent, and the waiting entry does not wait out its
  policy bound. The crash case retains its old hold. B1 concerns their
  missing combination with an existing failure.
- 011 C8, 019 D4 and 004 D9 describe the two proofs and the subagent rule.
  The ignored-file and pre-existing-dirty-tree revert limits are explicit
  in C8 and the worker notes. No new optimistic test-status claim was
  found. Exact-candidate CI verified build and bundle consistency.
