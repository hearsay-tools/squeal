   tests pass on the candidate and fail on the base. The shipped-process
   comparison also covers all three sync request stages and the watch's

   within about 300 ms of the outcome with unchanged lines and exit codes.
2. **Proven: cancellation follows the decision.**
   `src/cli/wait/wait.ts:299` stops the sync and watch in the existing
   loop's `finally`, after the read has built its outcome, or on error.
   The new callbacks in `named.ts` and `status.ts` stop only the watch.
   No read, readiness rule, sync reply interpretation, deadline, or
   liveness decision was moved. Before stop, each new signal is un-aborted.
   The outcome stores its sync value before cleanup. Presence code is unchanged.

   `src/core/daemon/client.ts:95` rejects an already aborted signal before
   connecting. The abort handler calls the same guarded settlement as
   response, error, close, and timeout (`client.ts:102`): it clears the timer,
   removes the listener, destroys the socket, and settles once.
   Optional argument order is preserved through `askDaemon`,
   `daemonSocket`, and both lookup ping branches. Sync lookup, initial sync,
   and sync-status all receive the same controller's signal.
   Callers without a signal retain their timeout and endpoint checks.
4. **Proven: scope holds.** The source diff is exactly the eight granted
   files. Tests add only the two new regression files. Other changes are
   the worker notes and version/bundle output, including install.sh and
   runtime manifest hashes. Presence, `src/cli/code*.ts`, keys, and the
   row 011-49 snapshot test are unchanged. Key-format and version-sensitive
   results are current. Earlier review 0.1.487's notes are already reflected
