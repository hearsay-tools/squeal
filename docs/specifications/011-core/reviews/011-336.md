## Blockers

### B1. Proven: a path mentioned in an unrelated command causes its process group to be killed

Locations: `test/harness/opencode/real.ts:165-168`; `test/helpers/process-groups.ts:44-47,76`.

R1 requires: "`test/helpers/process-groups.ts` cannot kill or wait on a process the test did not start."

`awaitBridges` matches any occurrence of `<dist>/hooks/` in the flattened command line. `groupsRunning` then accepts that process's PGID without checking its executable, script argument, or group leadership. `awaitGroups` waits for and eventually kills every live member of that group.

The independent probe created a private dummy `dist/hooks/end.mjs` and launched a detached `tail -f` as a stand-in for an unrelated observer. It started no bridge and no OpenCode process. It then called the candidate's actual `awaitBridges(dist, 100)` through an external Vitest test. The test asserted that the error named `tail -f` and that the observer exited by SIGKILL. Both assertions passed twice. Only the probe's own disposable process was signalled.

Captured second result:

Minimal reproduction inside Vitest, with the candidate `awaitBridges` imported:

```ts
const dist = mkdtempSync("/tmp/review-bridge-owner-");
mkdirSync(join(dist, "hooks"));
const file = join(dist, "hooks", "end.mjs");
writeFileSync(file, "// no bridge is started\n");
const observer = spawn("tail", ["-f", file], {
  detached: true, stdio: "ignore",

await expect(awaitBridges(dist, 100)).rejects.toThrow("tail -f");
```

A real observer need not lead its group. The current code would then kill its shell and other processes in that group too. Merely having a unique build directory does not prove that every process mentioning it was started by OpenCode.

Repair, one worker: establish bridge identity before taking a PGID. Match the actual Node hook entrypoint, not an arbitrary argument substring, and require the expected detached group leader. Keep accepted groups tied to this run's ownership; do not admit a pre-existing observer or unrelated group. Add a negative test with a disposable unrelated process mentioning the hook path, plus a positive test that still waits for an owned bridge and its surviving child. The unrelated process must remain alive and must not consume the bridge grace. Keep the repair in test helpers; no product change is needed for this demonstrated failure.
