## Blocker

C4 step 5 exempts a promoted-only tier from yielding **for work an edit caused**. It does not exempt it from a promoted file's eligible yield. C15 Rank still requires that yield when its conditions hold. The worker's notes, sections 1 and 4, also say the yield to a later wait stays unchanged. `TierYield.named` in `src/core/types/standing.ts:34` describes a file selected by the same or an earlier **open** wait. An old `Tier.promoted` flag proves neither condition.

### S3. Plausible: repeated waits without edits can hold unrelated backlog indefinitely

Seams: `src/core/scheduler/tiers.ts:383`; C15 Rank; status amendment 2026-10-28 011-265.

The selection test already proves that five successive promoted-only tiers do not advance the turn counter. Filtering to promoted files then excludes unrelated backlog even when a turn was already due. A sustained sequence of named waits can repeat this without edits. Each wait's deadline bounds that wait, not the full sequence, so it is not a backlog-progress bound.

This behavior is **explicitly accepted in the amended rule**, and no real workload starvation is proven. It is a nonblocking fairness risk. Add a test and a clear conditional progress statement for a sustained stream. A fairness bound would change the accepted no-count/no-turn rule and needs a separate decision; do not restore the counter as a review repair.
