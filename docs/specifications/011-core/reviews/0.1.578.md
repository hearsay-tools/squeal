## B3: the named wait reuses holds measured at the wrong time

**Proven, blocking, P2.** Changed boundary: `src/cli/wait/named.ts:196` builds the reads at the current time and line 210 passes them to `readNamedFiles` at `standingAt`. Consumers: `src/core/status/standing.ts:156` and `src/core/status/holds.ts:90`.

C6's row 011-421 amendment says **"Output is unchanged."** The existing named-wait contract at `named.ts:198` also says a deadline read names what held each file at the deadline's last millisecond. `WorktreeReads` is not only stored rows: its `holds` already include a derived `expired` flag. Passing `standingAt` does not recompute that flag when `reads.holds` is supplied.

Independent reproduction through the exported `namedPoll`:

1. Use `repoWith([A])` from `test/cli/status-wait-fixture.ts`: one queued named file, live daemon, revision 4.
2. Add a command hold with `addCommandHold`, start `NOW - 1000`, `until = NOW + 5000`, command `sleep 60`, null wrapper/child. These are valid recorded hold values.
3. Create `namedPoll(repo.main, [A], ...)` at `NOW`, timeout 5000, settle 0, poll 20, synced revision 4, no-op promotion.
4. Move the injected clock to `NOW + 5000`. Call its final `read({store, root: repo.main, commonDir: repo.commonDir}, true, () => 5000)`.
5. Compare `step.end.files` with `readNamedFiles(store, repo.mainId, repo.main, [ref(A)], step.end.result.daemon, NOW + 4999)`, the old call's time and inputs.

Actual probe output:

```text

old files[0].pending.hold:  { cause: command, ..., until: deadline }
new files[0].pending.hold:  { cause: command, ..., until: deadline, expired: true }
```

This final read can occur when a hold appears between the previous poll and the deadline. It needs no store mutation inside the read transaction. The snapshot may correctly report an expired hold at its own time; the named files must still use their earlier standing time. The new result changes their JSON and violates the row's explicit unchanged-output goal. The worker notes' claim that the reads are "rows, not a time" is false for `holds`.

One-worker repair: retain reuse of states, keys, header and runs, but recompute time-derived named standing facts at `standingAt` when their read time differs. A narrow option is to omit cached `holds` and `slowSlot` from the reads passed to `readNamedFiles`; this still avoids the extra whole-worktree state reads. `slowSlot` also contains `heldMs` computed from its read time (`slot-holders.ts:114`); that second manifestation is **plausible**, not independently probed.
