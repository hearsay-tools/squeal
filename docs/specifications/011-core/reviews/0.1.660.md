## Blockers

### B1. Proven: several groups still read and parse the same activity row several times per header

**Location:** `src/core/state/lane-reads.ts:45`, through `readGroupActivity` at `src/core/slow/state.ts:86`.

**Contract:** wave 130's outcome says: "One header read reads the published requests and lane activity once". The board's done-when says: "One fresh request/activity read per header read, shared by both readers, fresh per poll". The review brief explicitly asks to check the worker's open point on several groups.

`LaneReads.activity` caches by group name. Each first lookup calls `readGroupActivity`, which reads and parses the whole configured-groups activity row, then selects that group's entry. Two different configured groups therefore read the same row twice. The new context avoids repeat lookups of one name but does not make the shared activity row a single read per header.

The probe used the existing temporary SQLite store and policy fixtures:

1. Configure manual `browser` and `api` groups with disjoint test globs.
2. Seed one queued, pending file in each group.
3. Spy on `store.meta.get`, then call `readHeader` once.
4. Count calls whose key equals `groupTiersMetaKey(worktreeId)`.

Actual result:

```text

```

The row need not exist for the duplicate reads to occur. With N configured test groups, the reader reaches the same row N times. Publishing activity does not change that call path. The worker notes correctly disclose this limitation; they do not amend the row's outcome. The new single-group regression test passes and proves its stated single-group done-when. It does not cover the broader per-header outcome or the multiple-group case named in the review brief.

This is an incomplete read-count outcome, not a newly introduced wrong status or a measured latency regression. The base also used one activity lookup per group. It blocks here because this row expressly requires one request/activity read per header and asks for this case to be reviewed. The missing timing comparison is unrelated to the proof.
