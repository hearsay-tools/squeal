## Should-fix

### S1. Proven: the clock test proves forwarding at two boundaries, not one total reading per turn

Location: `test/scheduler/step-reading.test.ts:65`, `:70`, `:103`; `src/core/scheduler/step-live.ts:219`.

R1 asks both whether the step's reading reaches the yield check, yield row and fast plan, and whether “no other clock read remains in a step's turn.” The first is proven. The stronger second statement is false as a literal description of the live call graph.

The new test records the argument passed to `TierYields.check` and `Ledger.ordered`; it compares those arguments with the step's first reading. It does not count clock reads. For example, the plan's `beside` callback at `step-live.ts:223` still calls `besideFiles(context, ...)`, which reads `context.now()` at `beside.ts:36` and calls `ledger.orderedBatches()` without the supplied reading at `beside.ts:51`. Other existing paths include adoption, slow-release wake bookkeeping, and tier-start timestamps. Some are action timestamps rather than decision inputs and should remain distinct in any claim.

This is **nonblocking**. The extra helper reads predate this range. S7 names the two sites `yields.ts:119` and `tier-live.ts:40`; both now receive the step's reading. I found no new wrong scheduling decision caused by these remaining reads. The reviewer scope excludes treating unchanged helpers as new wave defects.

One-worker follow-up: state that the current proof covers the yield decision/row and fast queue view. If a later row promises every decision uses one reading, extend the virtual-clock test to cover beside selection and claim/deadline reads, pass `at` through those decision helpers, and keep actual start/write timestamps and wake-loop bookkeeping explicit. Do not claim that the current test proves a total clock-call count of one.

2. **Proven, placement:** `DecisionAt` derives its union from `DECISION_PLACE`. `TurnDecision` has five kinds and `AfterDecision` eight. Each switch lists only its own kinds and ends in `unplaced(never)`. Adding an unplaced kind breaks the `satisfies Record<StepDecisionKind, DecisionPlace>` check. The existing `@ts-expect-error` rows remain effective under typecheck. The eleven cross-place cases are gone.
3. **Proven, 011-366:** the four moved sites each have a table row. `holdBegan` decides cancel-held and then pump; `closeSlowLanes` handles both an ended slow lane and idle lanes on hold; `reinstallMissing` handles a pass's event and the pump's missing-install admission; `closeBesideLane` decides the second instance's close. Their old decision bodies are gone from the scheduler.
4. **Proven, ignored return values:** the pass's `install-missing` event reaches `reinstallMissing`, which immediately carries out the turn-placed reinstall and returns `turn`. A `revision` event reaches only `yieldCheck`, which immediately carries out turn-placed check-yields; the remaining outside rules emit nothing for that event. The same argument holds for the existing request/applied-work events and queued yield events. No after-turn decision is discarded at those call sites. The hold and flight-end callers, which can emit after decisions, call `StepLive.after`.
5. **Proven, S7's named boundaries:** `Out.decide` forwards `Turn.at` to carry; the adapter passes it as `TierYields.check`'s sixth argument; the check passes it to the yield-row write. `startNext` and `idleNow` pass it into `liveView`, including both normal and batch queue order. The adjusted 0-read expectation inside the yield check is consistent with the reading now taken before entry. See S1 for the broader claim.
