## 011-398: named verdicts during an unlisted revision

**B1 — proven, blocking, P1: an old passing result can exit 0 after import resolution changes.**

Location: `src/cli/verdict.ts:164`, with `fixedSelection` at line 50 and its callers in `src/cli/wait/snapshot.ts:113` and `src/cli/wait/named.ts:107`.

The bypass proves that the named selection holds the same test file. It does not prove that the file's closure is still valid. The content pass re-keys known closure paths. Structural changes can alter import resolution without changing any of those paths. Only the held runner phase discovers the new closure (`closuresToReresolve`, then `fetchRunnerPart`). Clearing `runnerPartPending` before that phase exposes the old pass as current.

Real-Vitest reproduction, using the existing `barrel` harness with `RUN_MISSING` and `tierSize: 1`:

1. Before starting, make `test/math.test.ts` import `add` from extensionless `../src/choice`. Put `export const add = (a, b) => a + b` in `src/choice/index.ts`. Run the baseline; the test passes.
2. Hold `runner.invalidate` on a promise. Add `src/choice.ts`, which imports `wrong` from `./wrong.ts` and exports `add = (a, b) => a + b + wrong`. Add `src/wrong.ts` exporting `wrong = 1`. Submit both paths with `h.batch`.
3. The content pass stores the revision. The test's key is unchanged; `runnerPartPending` is true. Read `namedSnapshot` for `test/math.test.ts`, with sync reporting that stored revision and the harness incarnation.
4. Release `invalidate` and await the harness's quiet point. Vitest resolves the added file, the test's key changes, and its `adds` check fails.

Observed before refinement:

```text
code: 0
keyUnchanged: true
runnerPartPending: true
Named test files at revision 1: no known failures; 1 test file, each with a current result.
```

Observed after refinement, without another edit:

```text
test/math.test.ts > adds: fail, current, observedAt 1
expected 4 to be 3
```

This breaks `docs/vision.md`, “An old result never gets to pose as the current truth,” and 011 goal 3, “Everything the agent is told is true at the moment it is told.” The worker notes identify the general risk, but the brief's safe-current-file outcome does not authorize a false pass. A worktree-wide unlisted suffix does not qualify away exit 0 or the named claim of a current result.

One-worker repair: retain the listing hold for a named file whose closure may still change, or record that uncertainty in the content pass and clear it only after its runner refinement. Do not use path kind alone as proof. Keep the safe unrelated-edit exit-0 case. Add the structural import-resolution regression above for snapshot and wait. The no-run wording and listing-holder tests otherwise fit the brief.

Verdict 011-398: **FAIL** (B1).
