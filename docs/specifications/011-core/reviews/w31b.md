## Blockers

### B1: Proven, file teardown can remove a live driver's directory after a test timeout

`test/keys/validity/self-test.ts:94` awaits only `removals`, then removes the whole work directory at line 96. A comparison adds its removal only in `finally` at lines 115 to 119, after `compareTrees` settles. A timed-out Vitest test stops waiting for its test function; it does not settle the comparison. Thus an in-flight comparison is absent from the array when teardown snapshots it.

The new asynchronous run or decision drivers can still be running at that point. `allEnded` correctly waits for their promises inside `compareTrees`, but the file hook never waits for that pending call. It removes both sides, their runtimes, stores and the release tree while drivers can still read or write them. A driver that creates later scratch can recreate a deleted path. Its later `finally` removes only `run-N`, leaving the recreated parent. The 120 s hook timeout does not help: with no registered removal, the hook can complete immediately.

**Contract:** row 011-179 says, "The work directory's removal ends inside its hook at load 99, or runs off the hook; the file leaves nothing behind." The review brief also requires no driver to write into a directory being removed. The scaled timeout probe above proves the changed driver path violates that contract. The ordinary driver-rejection path covered by `sides.test.ts` does not exercise Vitest timing out its caller.

**One-worker fix:** track each complete comparison-and-removal task from the moment `compare()` starts, before it can yield, and make `afterAll` wait for every in-flight task before removing the shared parent. Preserve the bounded hook and expose a driver that never ends as a teardown failure. If bounded cancellation is added, stop and reap the affected driver processes before deleting their paths. Do not solve this by raising the test or hook timeout again. Add a scaled Vitest timeout regression that holds a driver past the test deadline, proves its directory remains until it ends or is reaped, and proves the shared parent is gone after teardown. Keep the existing rejection-order test.
