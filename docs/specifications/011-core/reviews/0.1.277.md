## Blockers

### B1. A hook can step down the short successor when it still holds the predecessor's record

**Proven.** `src/harness/shared/ensure.ts:136`, with the record read at `:100` and the unqualified request at `:140`. C9's 2026-10-23 amendment says: "No hook asks that incarnation to step down again." Row 011-140's done-when also requires that a successor older than its claim gets no second step-down.

The guard compares the short mark with the record read earlier by `ensureIfStale` or `ensure`. That record can be the predecessor. A successor registers in another process between those reads. It atomically ends the live claim, writes its own short mark, and replaces the daemon record. Its socket has the same path as the predecessor's. The hook then compares the new mark with the old incarnation, finds no match, finds the claim gone, and sends the older record's socket a version-only `step-down`. The request reaches the short successor. `requestStepDown` also sends `stop` after acceptance, and the hook claims another handoff and requests another successor.

A deterministic probe called the real `ensureIfStale` with a real store and socket endpoint. The injected clock performed the successor's registering transaction just after the hook read the predecessor's record. Both daemons were version `0.1.272`, with distinct starts and tokens, and the hook was `0.1.277`. The live claim was to `0.1.277`. The probe asserted that the current short mark named the new incarnation, that the socket received `step-down`, and that one successor spawn was requested. It passed. This fixes the interleaving in place; no stress timing or probability claim is needed. The endpoint accepted the request as the real handler does: `src/core/daemon/handlers.ts:295` compares only versions, and `daemon.ts:676` cancels tiers and schedules shutdown on acceptance. The probe proves the forbidden request; the real handler's response to it is read in source.

**One-worker fix:** make the hook's handoff decision reject a stale daemon record when the currently registered incarnation has changed, and read the current record with its short/claim marks consistently before deciding to ask. Preserve `squeal start` as the explicit replacement path. Add a deterministic regression that registers a short successor between the initial record read and the handoff decision, then asserts no `step-down`, no `stop` and no successor spawn. Retain the existing unmarked older-daemon handoff behavior and the once-per-consumer notice checks.

### B3. An accepted short-daemon step-down can fall back to an `alive` success

### A short handoff is reported at the version that serves

`endHandoff` runs inside the daemon's registering transaction. It removes the claim, compares the registering version with the live claim, and writes one incarnation mark and one note when the successor is older. The note names both versions and the executable. An equal or newer successor, an expired claim, or a registration with no claim clears the mark instead.

The interfaces agree on the incarnation: registration uses the daemon's version, start and token; `handOver`, status and `squeal start` compare the mark with `handoffFrom(record)`. A mark matching the record the hook read suppresses another step-down in the stable case. B1 covers a registration between that read and the guard. It does not make a dead daemon alive. Status and delivered headers name the actual serving version, the claimed version and `squeal start`. The liveness told slot stores the marked incarnation for each consumer, and registration seeds it from the header already delivered. Repeated boundaries therefore give no second notice for the same mark.

A newer `squeal start` sends the marked daemon a step-down and intends to use the existing handoff finisher; B3 shows its entry race. The finisher cancels the old daemon, claims or joins the handoff, waits for a successor of at least the CLI's version to serve, and waits for its registration before printing status. The real-daemon regression checks replacement, the changed PID, the old daemon's exit and removal of the short mark. It failed at the replacement output check in this run, as recorded in B3.

The executable field is additive. It lives beside the token in `meta`, is read only when the token's start and version match the daemon registration, and is absent for an older writer. ### A busy record changes withhold history only after its write lands

`#prepare` keeps environment re-keying and observed inputs once. Each `#write` attempt rereads the hold and runs `#barrier` over the files it leaves free. The barrier uses `Withholds.peek`, which changes no history. Only after the outer store transaction returns does `barrier.count()` record the barred files and clear the free unbarred files. A thrown transaction changes neither set of counts. `#written` prevents a slot whose write already landed from counting again when its later ledger commit retries. Slot result writes are in the completed store transaction; the later ledger commit publishes their buffered state.

The new scheduler cases test both directions of the old error: a held touched run must not consume the first withhold, and a held untouched run must not clear an earlier withhold. A mixed tier checks that only free files and their touched paths appear in the note, each count moves once, and environment re-keying and observations run once per report despite retry.
