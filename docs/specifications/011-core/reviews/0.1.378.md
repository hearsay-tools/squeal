## Blockers

### B1. Proven: edits consume the backlog turn after a batch

Locations: `src/core/scheduler/tiers.ts:265`, `src/core/scheduler/tiers.ts:268`, `src/core/scheduler/queue.ts:386`.

The board row, wave 59 W1 and research Recommendation 4 require: **"with backlog queued, one backlog tier after each batch tier."** The review brief asks for this check explicitly. The purpose is to bound backlog delay by one batch rather than a stream of batches.

`rest` excludes promoted files only. The recursive selection retains ordinary first-group ordering and the old four-edit-tier counter. An edit tier then clears `#batchTurn` in `tierSelected`, even when it took no backlog file. Thus an edit consumes the turn that should move the backlog.

Reproduction: use the `Ledger`/`selectTier` setup from `test/scheduler/batch-select.test.ts`, with `runner.tierSize: 1` and `runner.backlogTierSize: 4`. Queue one nonrecent backlog file, ten recent edit files and five separate one-file waits. Give every file its own key, no stored result and a known duration of 1,000 ms. Promote the waits in order at one fixed clock reading. Select tiers with a free lane, clearing each selected file's running state and committing the ledger between selections. Actual output:

```text
batch wait0
edit edit0
batch wait1
edit edit1
batch wait2
edit edit2
batch wait3
edit edit3
batch wait4
turn backlog
```

The backlog waits through five batches. After each of the first four batches, the next tier contains no backlog work. Work beside a batch does not repair the selection rule when edit work remains once the lane is free.

The existing seven-wait test passes because its only non-batch files are backlog files. It does not test edits competing for that turn. The worker notes explicitly choose any non-batch tier, an edit's included. C4 step 5 and C15 Rank were amended to match that weaker rule in `94c05d16a`. This is not an unexplained code/spec mismatch: it is a proven failure of the stronger row and review requirement. The four-tier counter still provides eventual progress in this fixture; the claim here is the lost one-batch bound, not indefinite starvation.

**One repair row:** make the post-batch turn select second-group work when eligible backlog work is queued. Do not discharge that obligation merely because an edit tier ran. Keep claims, catch-up quiet rules, lane eligibility and beside tiers' exemption from both counters. Extend the selection fixture with edits plus multiple batches and require a backlog tier between consecutive batch tiers. Also check that a new wait cannot immediately yield away the tier that serves this turn. The coordinator must align the weakened C4/C15 sentences with the repaired bound, or obtain an explicit decision to weaken the row's requirement.
