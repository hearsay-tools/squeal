## B1: quiet does not observe abandonment after it starts waiting

**Proven.** `test/helpers/quiet-point.ts:147-149` waits only for `side.calls.nextEnd()` when a counted call is open and a `runner-part-bound` wake remains. A bound can abandon a call without ending the underlying promise. No counter event then releases this wait, so `quiet()` does not read the new rest where the bound is gone. It waits until its host-clock guard throws, 120 seconds by default.

This breaks R1's contract, "it cannot hang where `idle()` returned", and the worker's own abandonment decision. The exemption in `waitedCalls` at line 173 works only if the call was already abandoned before the most recent rest. The existing helper test at `test/helpers/quiet-point.test.ts:113` covers that earlier abandonment, not the transition while quiet waits.

The reproduction uses the real catch-up scheduler and the host clock, with one file importing `src/a.ts`:

1. Build `catchUpSide` with `policy: RUN_MISSING`, `hostSlots: 2`, `runnerPartMs: 400`. Start and quiet the baseline.
2. Replace `side.runner.invalidate` with a promise held until test cleanup. Edit `src/a.ts` and assert that `side.rest()` names `runner-part-bound`.
3. Start `side.quiet({ limitMs: 1_500 })`, capturing its result or error. Let 600 ms pass without releasing the call.
4. Await `side.scheduler.idle()`. It resolves. A fresh rest has no `runner-part-bound`, and `side.calls.describe()` is still `invalidate ×1`.
5. The quiet point fails instead of returning:

```text
Scheduler.idle resolved after abandonment; quiet outcome:
no quiet point in 1500 ms: a runner call stayed open; open calls: invalidate ×1
AssertionError: expected <that error> to be 'quiet'
```

No run is held or hidden in this reproduction. The scheduler has finished handling the abandoned refinement. `RunnerPartBound.call` deliberately keeps the runner's original promise open and drops late answers (`src/core/scheduler/runner-work-bound.ts:63`). Waiting for that promise to settle cannot detect abandonment.

**Fix for one worker:** make the runner-call wait also observe scheduler progress or periodically obtain a fresh rest, within the existing guard. Re-evaluate which calls still matter after a bound is dropped. Do not advance virtual time to a bound or stop waiting for live runs. Add a regression that enters quiet while a bound is armed, lets the scheduler abandon the still-open call, and requires quiet to return. Cover the virtual-clock case with an explicit external clock move too. Avoid accumulating unused `nextEnd` subscriptions if polling is used.
