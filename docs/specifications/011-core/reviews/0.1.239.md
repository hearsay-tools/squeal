## Blockers

### B1. Every valid slow-slot holder reads as unreadable on Node 22.13

**Proven.** `src/core/slow/slot.ts:180`, called by `src/core/status/slot-holders.ts:55`. Spec 011 C6 requires the slow-slot line to name each occupied permit's holder and to read its record without a lock. Node 22.13 is a supported runtime (`package.json`'s engines floor). The worker notes and the wave 8 status line explicitly leave this version unchecked.

`permitRecord` passes a URL object to `DatabaseSync`. Node 22.13 accepts only a string and throws `ERR_INVALID_ARG_TYPE: The "path" argument must be a string.` The catch returns `unreadable`. Thus every valid held permit loses its worktree, pid, age and work, even though its committed record can be read on newer supported Node versions. This is new code in the range.

A probe imported the real built `acquireSlowSlot` and `heldPermits`. It created a private scratch directory, acquired one permit with its own live pid and worktree id `review-holder`, read it before releasing it, then removed the scratch directory. The same script ran on both versions:

```text
$ npx --yes --package=node@22.13.0 node /tmp/review-239-floor.mjs "$PWD"
{"node":"v22.13.0","held":[{"file":"slow.lock","record":{"kind":"unreadable"}}]}
$ node /tmp/review-239-floor.mjs "$PWD"
{"node":"v24.21.0","held":[{"file":"slow.lock","record":{"kind":"holder","pid":635752,"worktreeId":"review-holder","since":1792598358885}}]}
```

**One-worker fix:** implement a holder read that works without a lock on Node 22.13. Preserve the existing floor, the holder's permit, the private-directory checks, multiple permits and explicit missing/unreadable states. Run the held-permit tests on 22.13 as well as 24. A string replacement alone is insufficient: a probe passing `file:///.../held.db?immutable=1` as a string on 22.13 returned `unable to open database file`; a plain path returned `database is locked` while its owner held it.

### B2. A signal already aborted at execution omits the cancel note

**Proven.** `src/runners/vitest/run.ts:74`. Spec 011 C4 step 5: "The cancel names its cause in the run's failure, its log's header and a note". The 011-56 done-when also requires the cause in the log line and note.

The early return uses `cancelled(signal.reason)` for the failure but never calls `collector.note`. The normal abort branch writes the note at line 91. A stop or step-down can arrive while the adapter is waiting for its gate or instance preparation, so the signal can already be aborted when `execute` begins. Its report and header then name the cause, but the required note is absent. The new test aborts only after a worker starts and cannot cover this path.

A probe called the real built `execute`, `buildReport` and `writeRunLog` with an already-aborted `stop` signal. Its runner function would throw if called; it was not called. The entire resulting log was:

```text
squeal vitest run pre-abort
end: completed (run cancelled: squeal stop), 0 ms

```

`collector.log` was `[]`.

**One-worker fix:** write the same cause note in the already-aborted branch. Add a regression for an abort before execution, checking the failure, header and note and that no runner starts. Cover the named causes and the neutral unknown-cause fallback. Keep incomplete files uncompleted and queued again.
