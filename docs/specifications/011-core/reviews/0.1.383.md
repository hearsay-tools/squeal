## Blockers

### B1. Proven: removed-root stop ignores the saved socket and falsely reports no daemon

Location: `src/cli/stop-removed.ts:96`, reached from lines 46–47; false completion at line 129. `rowKept` at line 139 reads only a Boolean from the saved row and discards its daemon socket.

Row 011-277 requires stopping a removed worktree's daemon from its saved identity, with an honest stopped, remaining or unknown result. Spec 011 C1 says: “Hooks and the CLI pick the socket by one rule: the one recorded in the store first when its heartbeat is fresh and a daemon answers there, else the computed one.” The vision requires trustworthy state and stated uncertainty.

The new path instead always pings `socketPathFor(id)` from the caller's current environment. If that socket is absent, it opens the repository store only to establish that the worktree existed. It then prints `No daemon running` and returns 0. A saved row can hold a fresh daemon record with a different, responsive `socketPath`, for example when the daemon and this CLI have different `XDG_RUNTIME_DIR` values. The normal existing-root CLI supports this through `daemonSocket` and `locateDaemon`; the new missing-root path bypasses it.

**Reproduced on this exact candidate, including its committed bundle:**

1. Create a private Git checkout and linked worktree A. Compute A's ID while A exists.
2. Bind a stand-in daemon socket under a private `old` runtime directory. It answers ping with A's root, ID, fresh start time and pid. Save that socket and fresh heartbeat in A's real repository store row.
3. Remove A's root. Change the caller's `XDG_RUNTIME_DIR` to a private `new` directory. Run from the main checkout, so the saved row is available.
4. Call `stopCommand([A.root], io)`; then run `node plugins/claude-code/dist/cli/squeal.mjs stop A.root` in the same environment and checkout.
5. Both return exit 0, empty stderr and the following stdout. Neither sends a stop to the saved socket. A direct ping afterward still succeeds.

`tasks/011-277/notes.md` already names the different-environment limitation. That admission does not make `No daemon running` true when the recorded socket answers. The existing new tests always record and bind `socketPathFor(id)` under the same runtime directory, so they cannot catch this case.

**Bounded fix:** resolve the saved row through the existing ancestor/current-checkout search before choosing the socket. Apply C1's recorded-socket-first rule, keeping the root/ID checks and incarnation checks needed to reject a stale or reused socket. Keep the computed socket as the supported fallback. Never infer that no daemon runs solely from absence at the computed socket while an unexamined recorded socket exists; use an unknown result and exit 1 when identity or liveness cannot be established. Preserve the exit-1 refusal for a path never recorded as a worktree and the ban on stopping the enclosing checkout. Add a fresh recorded-socket/different-runtime regression with worktree B still running. Keep the existing child-process, exited-daemon, wrong-root and missing-path cases. No process scan or scheduling change is needed.
