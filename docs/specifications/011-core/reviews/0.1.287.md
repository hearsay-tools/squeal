This breaks the vision's “trustworthy state over optimistic claims” and row 011-137's whole-module safety rule. The candidate can return a pass for unchanged test code whose ordinary run fails.

**Reproduction:** use a real Vitest adapter and this file. `started` is a fresh marker path in the scratch fixture; the harness waits for it before cancelling with `step-down`.

```ts
import { writeFileSync } from "node:fs";
import { afterEach, it } from "vitest";

it.fails("should fail naturally", async () => {
  writeFileSync(started, "");
  await new Promise((resolve) => setTimeout(resolve, 600));
});
afterEach((ctx) => {
  if (ctx.signal.aborted) throw new Error("cleanup aborted");
});
```

Run the file with an abort signal, wait for `started`, then abort with `step-down`. Vitest interrupts the body. Its abort handling first marks the test skipped. The cleanup error changes that to failed, then the expected-failure handling changes it to passed. `TestCase.result()` exposes `passed` with no error. The module also reports passed. The candidate therefore sets `cut: false` and completes it. The previous report gate withholds this after-cancel module; this range admits it. Run the identical file without cancellation: the body passes and cleanup does not throw, so `it.fails` fails with `Expect test to fail`.
