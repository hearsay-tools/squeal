```ts
  store.revisions.get(worktreeId, listed)?.createdAt,
```

```ts

  store.revisions.get(worktreeId, listed)?.createdAt,
```

(`src/cli/retry.ts:93`, `:115`). `openCommandStore` does not put reads in a

a daemon's completed start scan between these two reads.

store. Seed revision 1 and an old scan marker, both before the new file's
ctime, plus one previously keyed file. Capture the key list, as retry does.
Call each commit's exported `notKeyed` with that list. Wrap only
`store.revisions.get`: after its real read returns, let the second
connection commit a key for the new file and a completed scan marker whose
daemon started after that file was created. Then return the actual revision
row. Both runs execute the same statements and the same intervening commit.
The marker read is the only changed observation.
