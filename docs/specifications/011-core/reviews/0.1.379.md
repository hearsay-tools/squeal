## Blocker

### B1. Proven: extra-file membership does not prove Git still ignores a changed path

Location: `src/core/scheduler/keying.ts:233` and `:857`; the other writer is `src/core/scheduler/batch.ts:62`.

C5 promises: “a path git ignores, which the daemon watched as an extra file when it recorded the change, reads `git-ignored <path>`”. The task notes also say: “A tracked file that matches `.gitignore` is not ignored by git and is not marked.” Vision principle 2 requires honest revision facts.

Both revision writers now use `keys.isExtra(path)` as that fact. `#extra` retains a named path after `git add -f`, a commit, or an ignore-rule change that makes it visible to Git. `track` only checks previously unhashed/dropped paths (`keying.ts:814`); `#release` removes unnamed inherited paths, not paths that became tracked. `isExtra` simply reads the retained set. A daemon restart can correct it, but ordinary revisions in the same daemon cannot.

Reproduction used the descriptor fixture's setup and public calls from `test/delivery/ignored-paths.test.ts`:

1. Create and commit `.gitignore` containing `.ai/qa/` and a reader test. Write the ignored descriptor `.ai/qa/test-env.json`.
2. Bootstrap one `WorktreeKeys`, set its environment and reader closure naming the descriptor, then call `trackUntracked`. The descriptor enters `extraFiles()`.
3. Rewrite the descriptor and reconcile. Revision 1 correctly carries `ignored: true`.
4. With that same keys instance, run `git add -f .ai/qa/test-env.json`, then commit it. Rewrite its contents again.
5. Reconcile the cache and extra paths with `statCandidates` and `keys.reconcile({ trigger: "interval", paths }, head)`. Read `readLiveHeader` and `headerLines` for both forms.

Actual output (hashes omitted):

```text
tracked by Git .ai/qa/test-env.json
git status M .ai/qa/test-env.json
extra set before revision [".ai/qa/test-env.json"]
tracked revision [{"path":".ai/qa/test-env.json",...,"ignored":true}]
news Revision 2 · 9d98c8db + 0, dirty (changed git-ignored .ai/qa/test-env.json): no check pending, stale or unknown. ...
full Revision 2 · 9d98c8db + 0, dirty (changed git-ignored .ai/qa/test-env.json): 0 current, 0 pending, 0 stale, 0 unknown. ...
```

The pass uses the real interval reconciliation interface. The watch/batch writer reads the identical stale set. This is a new false statement in the candidate's header, even though the set's lifetime predates the candidate. Existing tests cover a path that starts tracked beside an ignored path, not this transition.

One-worker fix: refresh the ignored classification used by revision writers when Git tracking or ignore rules change, or supply a fresh batched classification before committing changes. Keep the fact on each revision, preserve old-row compatibility and key semantics, and do no Git work at delivery. Do not merely inspect today's Git state in `readLiveHeader`, which would rewrite the meaning of an earlier revision. Cover the same-daemon ignored-to-tracked transition and an ignore-rule removal. Assert that revision 1 keeps its mark, revision 2 has none, and a header spanning both uses revision 2's unmarked change. Check both writers.

### S2. Proven, nonblocking: a closing parenthesis in a path defeats the new news parsers

Location: `evals/lib/squeal-text.mjs:311`, `test/e2e/agree.ts:16` and `:29`.

The new changed-path group ends at the first `)`. A normal route path such as `src/app/(auth)/page.tsx` contains one before the clause ends. The e2e parser then rejects the header. The eval parser cannot read its counts when no commit clause is present; its older greedy commit group happens to absorb this case when a commit is present.

A cheap probe passed real `formatDelta` output to `squealEvidence(text, "push", 0)` with the existing `settled` fixture and only `changedPaths` changed:

```text

=> pending: 0, stale: 0, unknown: 0, verdict: pass
Revision 3 (changed src/app/(auth)/page.tsx): no check pending, stale or unknown.
=> pending: null, stale: null, unknown: null, verdict: unknown
```

The e2e full-header grammar already had this restriction before the range. The candidate extends it to news; the eval outcome stays conservative rather than claiming a false pass. Treat this as a bounded parser follow-up, not another blocker on the path-display done-when. Fix both consumers to identify the clause's final boundary without treating a path's first `)` as that boundary. Add a formatter round-trip with a route-group path, with and without a commit. Preserve the e2e parser's capture indexes.
