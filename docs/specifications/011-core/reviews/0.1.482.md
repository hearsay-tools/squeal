## Decisions and limits

- **Proven, fits:** unavailable also covers a store that does not open. W1 explicitly permits changes in the “busy and unread cases.” Replacing silent omission with an unavailable reason preserves uncertainty. The missing-store branch is established by source inspection, not a separate command experiment.
- **Proven, fits:** joined progress and current count remain separate reads (`run.ts:116`, `:118`). Each gets its own bound, up to 1 s without `--wait`; a blocked join can therefore add two unread parts and spend about 2 s before printing. With a finite deadline, a read begun after expiry takes the existing full final-read timeout. This is the two-read decision R1 asks to judge (numbered 3 in the worker notes). It adds no false progress or successful verdict. Combining the reads is optional, not required for this row.
- **Proven, fits:** heartbeat keeps 100 ms rather than taking a fresh 1 s after the group deadline. Both command tests retain their timing assertions and exit 3.
- **Proven test limit, accepted:** `owedText` is tested through the production verdict formatter rather than a whole command. With the lock already held, the wait produces `unopened` before it can reach `stopped`. The formatter row directly covers its lock handling and remaining-time bound. No command-level stopped-under-lock claim is made.
- **Unverified:** full-suite CI, local build and bundle parity. The review skill explicitly permits recording unavailable or pending checks without making them findings. The host forbids local substitutes for these checks here.
