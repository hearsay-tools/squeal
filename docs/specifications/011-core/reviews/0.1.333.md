- **011-232, accepted cost and hole:** a cut batch whose handler exits with a code or survives until SIGKILL loses all its completed files, including those completed before the signal. Such a batch must run again; a project that repeatedly reaches the deadline can make progress only in batches that exit before it. A handler that first permits pytest events and later restores SIGTERM's default action and re-kills can still admit those post-signal events. The code comment and 007 status amendment state that hole. This is the approved rule B, not an exact event-prefix guarantee.
- **Common Python setups, source inspection:** ordinary coverage.py does not install this handler unless its `sigterm` option is enabled. With that option, [`Coverage._on_sigterm`](https://github.com/nedbat/coveragepy/blob/master/coverage/control.py) synchronously saves coverage, restores the prior handler and re-sends SIGTERM before pytest resumes. With the normal prior default handler, this writes no pytest teardown and does not hit the stated hole or lose the completed prefix. Saving for longer than Squeal's two-second grace can instead end in SIGKILL and lose that batch's completed prefix under the accepted rule. [`pytest-timeout`](https://github.com/pytest-dev/pytest-timeout/blob/master/pytest_timeout.py) uses SIGALRM for its signal method or `os._exit(1)` from its timer thread; it installs no SIGTERM handler. It does not itself create this hole. Its thread method can already leave incomplete reports. A conftest's `signal.signal(SIGTERM, handler)` that returns, ignores the signal or raises `SystemExit` can lose the batch's earlier completed files, as the new tests model. It hits the re-kill hole only if it allows pytest to emit events and then kills with default SIGTERM. Composed or custom coverage handlers need the same qualification. These common-tool conclusions are source-based, not live coverage.py/pytest-timeout integration tests.
