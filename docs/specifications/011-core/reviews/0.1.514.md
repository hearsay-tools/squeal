**Where:** `src/core/scheduler/decide-yields.ts:151` and `:159`; newly extracted `src/core/scheduler/yield-waits.ts:96` and `:102`. The first path calls `peekClaim`, then `Claims.holds` (`claims.ts:53-64`), which writes `#seen` and `#waiting` and can delete a remembered claim. The second calls `focusedWaiting`, then `FocusedEntries.waiting` (`focused-entries.ts:53-55`), which removes expired entries from the live queue.

**Contract:** row 011-354 and wave 100 W1 require “`decideYields(at, trigger, view)` is a pure function over one reading” and “`TierYields` only applies it.” The design's done-when repeats that requirement. The new function's own comment says it “writes nothing.” These mutations were valid in the old decide-and-apply check. Moving them behind the new exported pure interface breaks this row's goal; this finding does not ask to repair unrelated pre-existing claim rules.
