## Drop candidates

None. Each feature of the stretch answers a human decision, a review or a measured cost, and passes the decision filter. Five were weighed and kept:

- The named wait's asked run (011-207, about 360 lines in `status-wait-ask.ts`, three review rounds) is the one exception to "a named wait does not change which files run". The human chose it in triage round 10 for gh-82: a wait that ends `timeout` on a stale file that nothing queues is blocking with no news (filter 2). Its one-run fact keeps it bounded (filter 5).
- The `retries-asked` row (`kept.ts`, up to 4,096 entries). It is what makes "one run per key" hold past the 1,024 requests (review 0.1.322 B2), and the human accepted its known limit (decision card c63f05ef). Without it a named wait could ask again at every trim (filter 2).
- Rule C, the restart note (011-209). It shows only in a named wait, on a daemon's first several-file tier in a fast lane. It says what is not known, no yield kept from before the start, in place of silence that reads as "none happened" (filter 3).
- `SlowRelease` (011-211, 106 lines). It frees a slow lane's `globalSetup` environment (a test environment, a lease, a port) during a hold and after 60 s with no slow run, and changes no file's result or order (gh-78). The 60 s is a constant with no policy key: `slow.releaseMs` is a scheduler option that only tests set (`src/core/scheduler/options.ts:181-185`). It passes filter 2: a hold no longer keeps the agent's test environment busy. Filter 5 would want a policy key only if a project asks for another bound.
- The `load` retry's 600 s bound (011-213). Without it a load retry on a host that stays above its CPU count never runs, and its FAIL stands with no news (filters 1 and 2).
