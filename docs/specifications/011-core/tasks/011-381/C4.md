## Exception: `backlog-slots` stays on the host clock

It runs real node:test processes and checks real-time bounds: the slots' refill against list scheduling, `REACT_MS`, the waiter's share within one slot's file. The scheduler learns each file's duration from its clock; on a virtual clock that stands still they would be 0 ms, and case 1's wall-budget setup (`timeoutMs: 20_000`, "the baseline taught the durations") would lose its meaning. So only the wait changes.

`through: ["pump"]` at the end of cases 1 and 4: both end after a backlog through the pool, where a slot the pool refuses waits for its next look. A one-off probe at load 7.7 (the rest's wakes at case 4's end) found no wake left and all 16 runs done, so `through` was not needed here; the survey's probe saw one timed call in this file at load 15 to 30. `through` only waits for what `idle()` waited for. Case 2 has no wait of its own.
