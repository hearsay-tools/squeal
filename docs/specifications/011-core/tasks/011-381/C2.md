## Decisions

- **Turn and waiting cases use `idleOn`, not `idleSlow`.** With a consumer in a turn, `idleSlow` in `rekeyed-duration` case 2 moved the clock through the slow lane's looks until the slow tier ran (4 slow runs in place of 2). The same holds for `warm-up.test.ts`'s last case. On the host's clock `idle()` returned there with the looks still armed. `idleOn` stops at the first non-driven wake, which matches. I did not find which timed rule ends the turn's hold on the virtual clock; the next worker should not use `idleSlow` in a turn.
- **`slow-release` is not driven.** `idle()` did not wait for an idle slow instance's close; `SLOW_DRIVEN` leaves it out.
