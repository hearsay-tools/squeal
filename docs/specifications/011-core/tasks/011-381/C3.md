## Decisions the brief did not settle

1. **Host clock plus `through` in place of the virtual clock for four files.** The brief says class C moves to the virtual clock, but also that each case keeps its meaning. These cases assert real-time bounds (a cancel 1 s in, current within run plus 6 s, heartbeat expiry within two intervals plus 1 s). On a virtual clock the scheduler's wakes stop following real time, so these bounds would test something else. `through` waits for exactly the wake `idle()` waited for.
2. **`idleOn` from `drive-fixture.ts`, not a new helper.** `CatchUpSide` already matches its `Driven` interface. It moves the clock only to `pump` and `slot-gather` wakes, which are the wakes the probe and my log found.
