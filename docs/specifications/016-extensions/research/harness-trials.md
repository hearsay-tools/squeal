# Research: Cursor CLI and OMP, tried for real

Brief 016-35, 2026-10-26. Every install and session ran as `squeal-e2e` (`sudo -n -u squeal-e2e -H env -i HOME=/home/squeal-e2e PATH=…`, cwd `/`). The scratch repository is `~/ht035/repo`: Vitest 5.0.3, `squeal.config.json`, and a fast and a slow test. Squeal went in as `git archive squeal--v0.1.335 plugins/pi plugins/claude-code`; that is the latest release tag. Probes, scripts and logs are in `probes/harness-trials/` (its README lists them).

**Sessions.** The human logged `squeal-e2e` in to Cursor and to OMP's `openai-codex` provider on 2026-10-26, after the first version of this file (5f0f9e58). Login state was checked only as logged in or not: both were logged in. Sessions run:
- **Cursor:** 6 real sessions (c1 to c6) of the 10 allowed, all on Cursor's default model (`Auto`).
- **OMP:** 10 sessions against a local fake OpenAI-compatible model (omp1 to omp9, `fake-openai.mjs`). One of them hung on an open stdin before OMP started and is counted anyway. Then 3 real sessions (r1 to r3) on `openai-codex/gpt-6-luna`, the cap, all with the probe shim and the Node-routed probe copy.
- **No agent session:** the scripts also drove Squeal's Pi extension directly, with no model (`wake-direct.mjs`), under Node and under OMP's Bun.

After every session, `ps -u squeal-e2e` showed no `omp`, no Cursor process and no Squeal daemon of mine left over.

## Findings

**1. Set-up.** Cursor CLI's `install` script (SHA-256 `77d44de2…`) downloads `downloads.cursor.com/lab/2026.10.22-27dcf5f/linux/x64/agent-cli-package.tar.gz`. It installs to `~/.local/share/cursor-agent/versions/2026.10.22-27dcf5f/` with links `agent` and `cursor-agent` in `~/.local/bin`, and `--version` prints `2026.10.22-27dcf5f`. *Verified by experiment.* OMP's README names `curl -fsSL https://omp.sh/install | sh`. With `--binary --ref v18.8.0`, the script asks `build.stencil.so/api/products/omp/versions/18.8.0/linux-x86_64`, which answers 404. The GitHub release `v18.8.0` (2026-10-07) holds `omp-linux-x64`, 283,289,056 bytes: the same size as the `agent` user's `~/.local/bin/omp` (size read with `ls`; the file was not opened). It is checked against `SHA256SUMS.txt` (`6d0bd5d6…`), installed to `~/.local/bin/omp`, and `omp --version` prints `omp/18.8.0`. *Verified by experiment.* OMP's headless ChatGPT login is `omp login openai-codex-device`: it shows an `auth.openai.com/codex/device` link and a code, and stores the result as provider `openai-codex` (`packages/ai/src/registry/oauth/openai-codex.ts`, `docs/providers.md`). *Read in source code, v18.8.0.* With the login in place, `omp models` lists the `openai-codex` group, `gpt-6-luna` included. *Verified by experiment.*

To remove both logins: `sudo -u squeal-e2e -H env -i HOME=/home/squeal-e2e PATH=/home/squeal-e2e/.local/bin:/usr/bin:/bin cursor-agent logout` (listed in `cursor-agent --help`: "Sign out and clear stored authentication"), then `sudo -u squeal-e2e rm -rf /home/squeal-e2e/.cursor /home/squeal-e2e/.omp`. OMP has no `logout` command: logout is `/logout` inside a session (`docs/providers.md`), and `omp logout` would start a session with `logout` as its prompt. Its login is stored in `~/.omp/agent/agent.db`, so deleting `~/.omp` removes it, together with this trial's sessions and `models.yml`. *Read in `--help` and docs; not run.*

**2. Cursor CLI** (2026.10.22-27dcf5f; sessions in `probes/harness-trials/cursor-sessions.txt`; bundle excerpts in `cursor-source.txt`; docs `cursor.com/docs/hooks.md` and `docs/reference/third-party-hooks.md`, fetched 2026-10-26).

- *Hook sources* (c1, print mode). The same logging hook was registered in `.cursor/hooks.json` and in `.claude/settings.json`, and both ran for `sessionStart`, `preToolUse`, `postToolUse` and `sessionEnd`. Only the Cursor source got `beforeShellExecution`, `afterShellExecution`, `afterFileEdit` and `postToolUseFailure`. *Verified by experiment.* The docs also list enterprise, team and user files, and the CLI imports Claude Code plugins. The converter `g()` keeps only `type`, `command`, `timeout` and `matcher`, sets `loop_limit: null`, and drops `args`. *Read in source code.*
- *Squeal as shipped* (c3, `--plugin-dir` on `plugins/claude-code`). The skill loaded and the model read it, but no Squeal text reached the model. Every hook entry is `${CLAUDE_PLUGIN_ROOT}/hooks/run` with its work in `args`, and `hooks/run` exits 0 without args (012 CC1). The model then ran `squeal status --wait 60000` itself, which failed with exit code 127, because `squeal` is not on `PATH`. *Verified by experiment.*
- *Payloads.* Every event carries `conversation_id`, `session_id`, `generation_id`, `model`, `cursor_version`, `transcript_path`, `workspace_roots` and `user_email`. Tool events add `tool_name`, `tool_input`, `tool_use_id` and `cwd`, but `cwd` was always `""`, so the root comes from `workspace_roots[0]` or `CURSOR_PROJECT_DIR`. `stop` adds `status` and `loop_count`, plus token counts. Hooks get `CURSOR_PROJECT_DIR`, `CLAUDE_PROJECT_DIR` and `CURSOR_VERSION`. Tool names are Cursor's own, even for Claude-format hooks: `Shell`, `Read`, `Write`, `Grep`. A denied call and a read of a missing file fired `postToolUseFailure` and no `postToolUse` (c1); a shell command exiting 1 fired no `postToolUse` either (c5). *Verified by experiment.*
- *Output reaching the model.* The model echoed every nonce from `sessionStart` and `postToolUse` `additional_context`, in both formats; the Claude format was the nested `hookSpecificOutput.additionalContext` (c1). An exit 2 with stderr from a Claude-format `preToolUse` blocked the shell call, and the model saw the stderr. A Cursor-format deny showed the model `user_message` plus Cursor's "Agent note: Do not suggest workarounds to the blocked tool."; the model never saw `agent_message`, which the docs name as the model's text (c1, `modelVisibleError`). The model still retried once, as asked (c1, c6). *Verified by experiment.*
- *Stop.* `stop` and `beforeSubmitPrompt` fire only in interactive mode (c2 under a pseudo-terminal; never in print mode, c1). `followup_message` at `loop_count` 0 became the next user message, and the model answered it (c2: `CONTINUED`). *Verified by experiment.* The CLI calls them only when Cursor-format hooks exist for that step. *Read in source code.*
- *Process tree.* Every hook ran as `node ← bash ← cursor-agent` (`MainThread` comm), so Squeal's harness-process walk (R9) skips `bash` and finds `cursor-agent`. *Verified by experiment.* Print mode left a detached `worker-server` and a `typescript-language-server` running after the session ended; I stopped them by pid. *Verified by experiment.*
- *Squeal through a translator* (c4 to c6). `cursor-squeal.sh` maps Cursor's payload to Claude Code's hook input and runs Squeal's shipped bundle for the event. It maps `conversation_id` to the session, `workspace_roots[0]` to `cwd`, `Shell` to `Bash` and writers to `Edit`, `postToolUse` to `PostToolBatch` and `loop_count > 0` to `stop_hook_active`. It maps the answer back the other way. In c4 the translator was one Node process, the bundle's parent: Squeal took it for the session's process, saw it exit after each hook, sent the full registration again at every tool boundary, and let the daemon stop. With a shell as the parent (c5, c6), Squeal behaved as under Claude Code. *Verified by experiment.*
- *Idle wake.* No hook fires while the session is idle, and the CLI has no extension API. A `stop` hook that waits for pending checks, as Squeal's Claude Code `stop-slow` does, is the only lead. *Inferred.*

**3. OMP** (`can1357/oh-my-pi` @4ef97c88, tag `v18.8.0`; docs `extensions.md`, `extension-loading.md`, `hooks.md`, `rpc.md`, `models.md`).

- *What it is.* "Fork of Pi" (README). It is a Bun 1.4.2 single binary (`BUN_BE_BUN=1 omp -e …` prints `1.4.2`). Bun there has `node:sqlite` and `worker_threads`. *Verified by experiment.* Its loader rewrites `@earendil-works/*` and `@mariozechner/*` imports to the host copies, and accepts `pi.extensions` in `package.json`. *Read in source code.*
- *The package loads unchanged.* `omp -e <plugins/pi>` loaded Squeal's extension and skill. With a live daemon, the start header reached the model as a user message before the prompt (`omp-sessions.txt`, omp3 step 0: `SQUEAL · registered at revision 0 …`). *Verified by experiment.*
- *Events that differ from Pi's.* Seen in the event log (omp1): `session_start`, `before_agent_start`, `agent_start`, `context`, `turn_start`, `tool_call`, `tool_result`, `turn_end`, `session_stop`, `agent_end` and `session_shutdown` fire. `agent_before_settle` and `agent_settled` never fire, and OMP's types declare neither. *Verified by experiment.* `turn_end` has no result type, so Squeal's `{ entries }` is dropped. `before_agent_start` carries `systemPrompt: string[]`, not `systemPromptOptions`, so the primer is lost. *Read in source code; verified by experiment.* In omp3 the test failed at revision 1, and the next tool boundary sent nothing to the model. The worker had already delivered that change, so the next `write` was not denied either.
- *The stray agent.* Squeal's worker spawns the daemon as `spawn(process.execPath, [cli, "daemon", root])` (`ensure.ts:217`). Under OMP that is `omp <squeal.mjs> daemon <root>`. In omp2 this started a second OMP session in `.git/squeal`, which took each argument as a user message. Its first message was the text `/home/squeal-e2e/ht035/squeal/plugins/pi/dist/cli/squeal.mjs`. It then called the model 6 times and ran `read` and two `write`s, leaving `.git/squeal/sum.js` behind (`stray-session.txt`). No daemon started. Squeal's texts name the CLI the same way (`piCommand`): `/home/squeal-e2e/.local/bin/omp --disable-warning=ExperimentalWarning …/squeal.mjs run --all` (omp3, step 0). Running that command would start yet another agent. A main-thread assignment to `process.execPath` does not reach the worker thread (`execpath-worker.mjs`). *Verified by experiment.*
- *Idle push.* `pi.sendMessage(m, { triggerTurn: true, deliverAs: "followUp" })` started a turn in RPC mode with no prompt sent. In omp9: `session_settled` at 10:40:55.872, Squeal's `sendMessage` at 10:40:59.392, `agent_start` at 10:40:59.399. *Verified by experiment.* Squeal's idle wait answers under Bun as under Node (`wake-direct.mjs`: `woken true` at 12.7 s under Bun and 12.9 s under Node). It waits only for test files still pending when the turn ended. *Verified by experiment.*
- *Real model* (`omp-real-sessions.txt`). The routed copy's worker spawns with `process.env.HT_NODE || process.execPath` (`dist/worker.mjs` lines 11160 and 11944), checked before r1. Each run's `ps` samples showed one `omp` and the daemon under `/opt/squeal-e2e/node24/bin/node`. That daemon was the live one `reset-repo.sh start` began, so the real runs never took the spawn path; omp7 (fake model) is the evidence for it. On `openai-codex` the start header is stored as a `custom_message`, and `tool_result` `additionalContext` is stored and sent as a **`developer`-role message** after the tool result (r1 11:57:21.686, r2 11:59:24.378). The tool-call block arrives as the tool's result. In r2 the first write after the break (11:59:26.531) got `SQUEAL · 1 check changed … FAIL slow.test.js`, the model's reasoning summary read "Retrying creation", and the retry wrote the file. In r1 and r3 the turn ended with the slow test pending. Squeal's follow-up came 1.0 s and 0.8 s after the turn ended, and gpt-6-luna answered with the FAIL line, as asked. No run reached the end-of-turn check with news: in r3 the answer took 3.8 s and the result came 0.8 s after `session_stop`. In r2, OMP sent `prompt_result` but never `session_settled`, and the run hit its 300 s timeout. OMP holds that frame while its own async jobs run (`rpc-session-settle.ts`); which job held it is not determined. *Verified by experiment.*

## Recommendation for Squeal

1. **Fix the OMP spawn before any OMP user exists** (finding 3). A Pi package running under any non-Node host starts an unattended agent run. OpenCode already solves the same problem: `findNode` in `src/harness/opencode/host.ts` (lines 146 to 156) finds a Node on `PATH` because `process.execPath` is OpenCode's Bun there. An OMP adapter reuses that resolution, both for the daemon spawn and for the CLI command in Squeal's texts.
2. **OMP is the Pi adapter plus a thin event map, not a new class.** These are the four mappings the shim proved (`omp-shim.js`), the first three also on gpt-6-luna:
   - the boundary delta → `tool_result` `additionalContext`, per call, as Codex's PostToolUse; on `openai-codex` it becomes a `developer` message;
   - the primer → the `before_agent_start` result `systemPrompt`;
   - Pi's settle → `session_stop` `{ continue, additionalContext }`, which also accepts Claude Code's `decision: "block"`, capped at 8;
   - Pi's settled → `agent_end` with `willContinue` false.
   Delivering the boundary through a steer message was late and out of order, so it should not be used. OMP is class B with an idle push, alongside Pi, OpenCode, Amp and Cline (`harness-landscape.md`).
3. **Cursor: Cursor-format hooks that run Squeal's existing Claude Code handlers.** Ship a `.cursor-plugin/plugin.json` (or `.cursor/hooks.json` from `squeal setup`) whose `command` is complete, so nothing depends on dropped `args`. That is the "route through Cursor's own manifest" Later item of 012. The c5 and c6 runs show the mapping is small and is data:
   - `sessionStart` → R1, `postToolUse` → R2, `preToolUse` deny with the reason in `user_message` → R3, `stop` `followup_message` → R4;
   - `conversation_id` as the session, `workspace_roots[0]` as the root (`cwd` is empty), Cursor's tool names (`Shell`, `Write`, `Read`, `Grep` seen) mapped to Squeal's edit and shell sets;
   - the translation must run inside the hook process, or under a shell. A Node wrapper around the bundle breaks session liveness (c4);
   - `squeal` must be on `PATH` or named absolutely in the texts (c3).
   Accept R5 as missing and state it as a capability tier. R4 exists only in interactive mode.
4. **What the harness contract and its kit must state**, from what broke here:
   - the host runtime and the executable Squeal may spawn: never `process.execPath` unless it is Node;
   - the hook's parent chain up to the harness process, with only shells between (Cursor c4);
   - for each event, whether its result is used, when its text reaches the model (before the next request, or one step later) and in which role (`developer`, user, tool result);
   - which events a failed or denied tool fires;
   - which event ends a turn, whether a continuation is one turn or a new user turn, its cap, and in which modes it fires;
   - whether an idle push exists, and in which modes.
   The kit must run the real host with a scripted model, as `fake-openai.mjs` does, and assert on the request bodies. omp2's stray session and c4's per-hook re-registration are the cases such a kit catches and a unit test with a stub host does not. Each scenario must write content new to Squeal's store, and must end the turn only after the daemon has queued the run. A real-model run adds what a fake cannot show: a model that reads before every edit (Cursor) gets R2 at the read and rarely meets R3.

## Open questions

- OMP's end-of-turn check on a real model. On gpt-6-luna the final answer took 1 to 4 s, and a 4 s test always landed after `session_stop`, so the wake took it. A test that finishes during the final answer decides it.
- Why OMP sent no `session_settled` in r2. Its settle waits out the session's async jobs (`rpc-session-settle.ts`, `agent-session.ts` `#hasPendingAsyncWake`). Squeal's `agent_settled` handler awaits one worker call with a deadline and arms the wake without awaiting it (`src/harness/pi/extension.ts:226`). The job list at that moment decides it.
- Cursor: in c4, `stop` ran twice at `loop_count` 2 within one second, once with a follow-up and once without. The cause is not determined.
- Why the start header was missing when the session spawned the daemon itself (omp2). Likely the 2 s `session_start` deadline (inferred).
