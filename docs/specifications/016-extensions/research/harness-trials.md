# Research: Cursor CLI and OMP, tried for real

Brief 016-35, 2026-10-26. Every install and session ran as `squeal-e2e` (`sudo -n -u squeal-e2e -H env -i HOME=/home/squeal-e2e PATH=…`, cwd `/`). The scratch repository is `~/ht035/repo`: Vitest 5.0.3, `squeal.config.json`, and a fast and a slow test. Squeal went in as `git archive squeal--v0.1.335 plugins/pi plugins/claude-code`; that is the latest release tag. Probes, scripts and logs are in `probes/harness-trials/` (its README lists them).

**Limits.** No login was available as an environment variable. The parent decided to run OMP against a local fake OpenAI-compatible model (`fake-openai.mjs`) and to report Cursor from its shipped code and docs. So **every OMP finding comes from a real OMP 18.8.0 process with a scripted model, and every Cursor finding is "not run"**. The parent asked the human for logins on 2026-10-26. Real-model sessions (at most 3 for OMP, at most 10 for Cursor) wait for that. OMP used 10 fake-model sessions; one of them hung on an open stdin before OMP started and is counted anyway. The scripts also drove Squeal's Pi extension directly, with no agent session and no model (`wake-direct.mjs`), under Node and under OMP's Bun.

## Findings

**1. Set-up.** Cursor CLI's `install` script (SHA-256 `77d44de2…`) downloads `downloads.cursor.com/lab/2026.10.22-27dcf5f/linux/x64/agent-cli-package.tar.gz`. It installs to `~/.local/share/cursor-agent/versions/2026.10.22-27dcf5f/` with links `agent` and `cursor-agent` in `~/.local/bin`, and `--version` prints `2026.10.22-27dcf5f`. *Verified by experiment.* OMP's README names `curl -fsSL https://omp.sh/install | sh`. With `--binary --ref v18.8.0`, the script asks `build.stencil.so/api/products/omp/versions/18.8.0/linux-x86_64`, which answers 404. The GitHub release `v18.8.0` (2026-10-07) holds `omp-linux-x64`, 283,289,056 bytes: the same size as the `agent` user's `~/.local/bin/omp` (size read with `ls`; the file was not opened). It is checked against `SHA256SUMS.txt` (`6d0bd5d6…`), installed to `~/.local/bin/omp`, and `omp --version` prints `omp/18.8.0`. *Verified by experiment.* OMP's headless ChatGPT login is `omp login openai-codex-device`: it shows an `auth.openai.com/codex/device` link and a code, and stores the result as provider `openai-codex` (`packages/ai/src/registry/oauth/openai-codex.ts`, `docs/providers.md`). *Read in source code, v18.8.0.* To remove the logins later: `sudo -u squeal-e2e -H env -i HOME=/home/squeal-e2e PATH=/home/squeal-e2e/.local/bin:/usr/bin:/bin cursor-agent logout` (listed in `cursor-agent --help`: "Sign out and clear stored authentication"), then `sudo -u squeal-e2e rm -rf /home/squeal-e2e/.cursor /home/squeal-e2e/.omp`. OMP has no `logout` command: logout is `/logout` inside a session (`docs/providers.md`), and `omp logout` would start a session with `logout` as its prompt. Its login is stored in `~/.omp/agent/agent.db`, so deleting `~/.omp` removes it, together with this trial's sessions and `models.yml`. *Read in `--help` and docs; not run.*

**2. Cursor CLI** (shipped bundle 2026.10.22-27dcf5f, read 2026-10-26; excerpts in `probes/harness-trials/cursor-source.txt`; docs `cursor.com/docs/hooks.md` and `docs/reference/third-party-hooks.md`, fetched 2026-10-26). *Not run.*

- *Hook sources.* The docs list enterprise, team, `.cursor/hooks.json`, `~/.cursor/hooks.json`, `.claude/settings.local.json`, `.claude/settings.json` and `~/.claude/settings.json`. All matching hooks run, and the Claude Code sources depend on "Include Third-Party Plugins, Skills, and Other Configs", which is on by default. The CLI also loads Claude Code plugins (`source: "claude-plugin"`), unless `importThirdPartyPlugins` is off. It reads `.cursor-plugin/plugin.json` and `.claude-plugin/plugin.json` manifests, and has a `--plugin-dir` flag.
- *Claude Code mapping.* The converter `g()` keeps only `type`, `command`, `timeout` and `matcher`, and sets `loop_limit: null`. So `args` is still dropped, as in 2026.10.16 (`012-…/research/cursor-dropped-args.md`). Squeal 0.1.335's every entry is `${CLAUDE_PLUGIN_ROOT}/hooks/run` with its work in `args`, and `hooks/run` exits 0 without args (012 CC1). So **Squeal is installed but silent under Cursor**: all five behaviours are missing. The mapped events are `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `SessionStart`, `SessionEnd` and `PreCompact`. `PostToolBatch`, `SubagentStart` and `asyncRewake` have no mapping.
- *Native events.* `sessionStart` → `additional_context` goes into "the conversation's initial system context". The CLI awaits this hook and passes the context on (`7000.index.js`). `postToolUse` → `additional_context` is "injected into the conversation after the tool result"; the CLI returns it on the agent loop's `postToolUse` request. `preToolUse` → `permission: "deny"` with `agent_message` (or exit 2 with stderr), and Cursor appends "Agent note: Do not suggest workarounds to the blocked tool." `stop` (`status`, `loop_count`) → `followup_message` "will automatically submit it as the next user message"; the default cap is 5, and `null` for Claude Code hooks. Every payload has `conversation_id`, `generation_id` and `workspace_roots`; tool events add `cwd`. Hooks also get `CURSOR_PROJECT_DIR`, `CLAUDE_PROJECT_DIR`, and `CURSOR_PLUGIN_ROOT` for plugin hooks.
- *Idle wake.* No hook fires while the session is idle, and the CLI has no extension API. The only lead is a `stop` hook that waits for pending results inside its timeout, then answers with `followup_message`, as Squeal's Claude Code `stop-slow` does. That holds the session busy (inferred).
- *Child of the CLI?* The executor runs `command` through its shell executor, with the payload on stdin or as `<command> <<'CURSOR_HOOK_EOF'`. Whether that process descends from the `cursor-agent` process that Squeal's harness-process walk would find (R9) is **not determined**: `cursor-agent-worker-sea` sits beside the CLI, and only a `ps` during a hook decides it.

**3. OMP** (`can1357/oh-my-pi` @4ef97c88, tag `v18.8.0`; docs `extensions.md`, `extension-loading.md`, `hooks.md`, `rpc.md`, `models.md`).

- *What it is.* "Fork of Pi" (README). It is a Bun 1.4.2 single binary (`BUN_BE_BUN=1 omp -e …` prints `1.4.2`). Bun there has `node:sqlite` and `worker_threads`. *Verified by experiment.* Its loader rewrites `@earendil-works/*` and `@mariozechner/*` imports to the host copies, and accepts `pi.extensions` in `package.json`. *Read in source code.*
- *The package loads unchanged.* `omp -e <plugins/pi>` loaded Squeal's extension and skill. With a live daemon, the start header reached the model as a user message before the prompt (`omp-sessions.txt`, omp3 step 0: `SQUEAL · registered at revision 0 …`). *Verified by experiment.*
- *Events that differ from Pi's.* Seen in the event log (omp1): `session_start`, `before_agent_start`, `agent_start`, `context`, `turn_start`, `tool_call`, `tool_result`, `turn_end`, `session_stop`, `agent_end` and `session_shutdown` fire. `agent_before_settle` and `agent_settled` never fire, and OMP's types declare neither. *Verified by experiment.* `turn_end` has no result type, so Squeal's `{ entries }` is dropped. `before_agent_start` carries `systemPrompt: string[]`, not `systemPromptOptions`, so the primer is lost. *Read in source code; verified by experiment.* In omp3 the test failed at revision 1, and the next tool boundary sent nothing to the model. The worker had already delivered that change, so the next `write` was not denied either.
- *The stray agent.* Squeal's worker spawns the daemon as `spawn(process.execPath, [cli, "daemon", root])` (`ensure.ts:217`). Under OMP that is `omp <squeal.mjs> daemon <root>`. In omp2 this started a second OMP session in `.git/squeal`, which took each argument as a user message. Its first message was the text `/home/squeal-e2e/ht035/squeal/plugins/pi/dist/cli/squeal.mjs`. It then called the model 6 times and ran `read` and two `write`s, leaving `.git/squeal/sum.js` behind (`stray-session.txt`). No daemon started. Squeal's texts name the CLI the same way (`piCommand`): `/home/squeal-e2e/.local/bin/omp --disable-warning=ExperimentalWarning …/squeal.mjs run --all` (omp3, step 0). Running that command would start yet another agent. A main-thread assignment to `process.execPath` does not reach the worker thread (`execpath-worker.mjs`). *Verified by experiment.*
- *Idle push.* `pi.sendMessage(m, { triggerTurn: true, deliverAs: "followUp" })` started a turn in RPC mode with no prompt sent. In omp9: `session_settled` at 10:40:55.872, Squeal's `sendMessage` at 10:40:59.392, `agent_start` at 10:40:59.399. The model received `SQUEAL · 1 check changed … FAIL slow.test.js …`. *Verified by experiment.* Squeal's idle wait answers under Bun as under Node (`wake-direct.mjs`: `woken true` at 12.7 s under Bun and 12.9 s under Node). It waits only for test files still pending when the turn ended. Two of my runs ended the turn before the daemon queued the run, and one rewrote content Squeal already had a result for. Those three runs showed no wake for that reason. *Verified by experiment.*

The spawn routed to Node is a probe copy only (`node-copy.sh`: `process.env.HT_NODE || process.execPath` at the spawn and in `piCommand`). With it, `ps` showed one `omp` process and the daemon as `/opt/squeal-e2e/node24/bin/node …/squeal.mjs daemon` (`ps-omp7.txt`), and no new stray session appeared. *Verified by experiment.* After every run, `ps -u squeal-e2e` showed no `omp` and no daemon left over.

## Recommendation for Squeal

1. **Fix the OMP spawn before any OMP user exists** (finding 3). A Pi package running under any non-Node host starts an unattended agent run. OpenCode already solves the same problem: `findNode` in `src/harness/opencode/host.ts` (lines 146 to 156) finds a Node on `PATH` because `process.execPath` is OpenCode's Bun there. An OMP adapter reuses that resolution, both for the daemon spawn and for the CLI command in Squeal's texts.
2. **OMP is the Pi adapter plus a thin event map, not a new class.** These are the four mappings the shim proved (`omp-shim.js`):
   - the boundary delta → `tool_result` `additionalContext`, per call, as Codex's PostToolUse;
   - the primer → the `before_agent_start` result `systemPrompt`;
   - Pi's settle → `session_stop` `{ continue, additionalContext }`, which also accepts Claude Code's `decision: "block"`, capped at 8;
   - Pi's settled → `agent_end` with `willContinue` false.
   Delivering the boundary through a steer message was late and out of order, so it should not be used. OMP is class B with an idle push, alongside Pi, OpenCode, Amp and Cline (`harness-landscape.md`).
3. **Cursor: Cursor's own hook manifest.** Ship a `.cursor-plugin/plugin.json` with Cursor-format hooks whose `command` is complete, so nothing depends on dropped `args`. That is the "route through Cursor's own manifest" Later item of 012. Use `postToolUse` as the push, as in `harness-landscape.md` recommendation 1, `preToolUse` deny for R3, `stop` `followup_message` for R4, and `sessionStart` for R1. Accept R5 as missing, and state it as a capability tier. The shared mapping is data: event names, `conversation_id` as the session, `cwd` or `workspace_roots[0]` as the root, the output fields and the loop cap.
4. **What the harness contract and its kit must state**, from what broke here:
   - the host runtime and the executable Squeal may spawn: never `process.execPath` unless it is Node;
   - for each event, whether its result is used and when its text is sent to the model: before the next request, or one step later;
   - which event ends a turn, whether a continuation is one turn or a new user turn, and its cap;
   - whether an idle push exists, and in which modes.
   The kit must run the real host with a scripted model, as `fake-openai.mjs` does, and assert on the request bodies. omp2's stray session is the case such a kit catches and a unit test with a stub host does not. Each scenario must write content new to Squeal's store, and must end the turn only after the daemon has queued the run.

## Open questions

- Every Cursor cell, until a logged-in run: whether `sessionStart`, `postToolUse` and `stop` fire in the CLI with the documented fields; whether `additional_context` reaches the model; and whether hooks are children of `cursor-agent`.
- With a real model on `openai-codex` (Responses API), where does `tool_result` `additionalContext` land? OMP says "developer/system priority where the selected transport supports it". The fake used chat completions, where it arrived as a user message.
- Why the start header was missing when the session spawned the daemon itself (omp2). Likely the 2 s `session_start` deadline (inferred). The routed runs started with a daemon "stopped by request", and there the header arrived.
