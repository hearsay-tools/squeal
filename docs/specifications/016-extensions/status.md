## Decisions so far

- 2026-10-24, the human, a big idea to research: could Squeal be reorganized as a core plus extensions? Harness adapters connect other harnesses through a clear contract they must satisfy. pytest, node:test, Vitest, complexity and CRAP become plugins or extensions. The aim is to let people extend Squeal themselves, for adoption and for an ecosystem of every kind of live feedback an agent should get: tests, quality metrics, linters. "No way I can support every language / testing framework there is on my own." Research thoroughly first, then report.
- 2026-10-24, the coordinator's assumptions, for the research to confirm or change:
  - The core keeps the promise: revision provenance, transitions, keys, the shared store and status. An extension must not be able to break it silently; a third-party check that gives a false pass costs Squeal's trust, not the extension's.
  - Extension has tiers: no code (a command and an output format), a declarative manifest, and code with the full contract (affected selection, a warm process, focus).
  - A third-party runner may be written in another language, so a process boundary is likely for at least one tier.
  - The harness contract is the smallest (vision principle 6: three operations) and the closest to ready; the runner contract is the largest.
  - Our own runners would move behind the public contract, so it is tested by real use.
- 2026-10-24, the human: a fan-out of two researchers on different models plus a judge for the central question, the check protocol (016-07 on GPT-6-Astra beside 016-03 on Opus; judge 016-08 on GPT-6.1-Sol).
- 2026-10-24, research 016-01 to 016-08 done (`research/seams.md`, `plugin-mechanisms.md`, `check-protocol.md`, `check-protocol-astra.md`, `check-protocol-judgment.md`, `harness-landscape.md`, `ecosystem-adoption.md`, `third-party-trust.md`). What they settle, as inputs, not decisions:
  - Seams (016-01): the daemon imports each runner by path, so no outside runner can load. The daemon also hands runners an interface outside `RunnerAdapter`: node:test and pytest get a store that writes every worktree's stored closures directly, and the daemon sets their scheduling hints. 14 imports and about 430 code lines in core and CLI name a runner; 011's "Known seams" misses 9 groups (complexity loads tree-sitter through the pytest runner, policy has one member per runner, `harness/shared` parses `vitest`, `node --test` and `pytest` commands, status payload values such as `not-vitest`). Ten seams; the files they touch hold about 6,600 product lines. Highest risk: runner wiring and the injected observed store.
  - Harness side (016-01, 016-04): C8's rules are already shared by four adapters, but the CLI has no register, tool-boundary, peek or end-turn command, so an adapter outside the repository gets status only: no per-session silence, no deny-once, no idle wake. Cursor, Copilot CLI, Gemini CLI and Factory Droid have hook scripts close to Claude Code's (Cursor and Copilot read `.claude/settings.json`), so each is a mapping; none has an idle wake. Amp and Cline are in-process plugins with an idle push. MCP is pull only: no client puts pushed server text into the model's context. Claude Code's hook format is the de facto standard and diverges at `PostToolBatch` and wake. Contract shape: C8 behind one entry point plus per-harness data, with a kit modelled on the ACP TCK.
  - Mechanisms (016-02): two tiers, not three. A manifest (command, inputs, output format, the exit code decides) and a process protocol. trunk's and MegaLinter's manifest tier covers 56 to 57% of their linters with no code; a drifting regex is its typical silent fault. Third-party JavaScript in the daemon's thread blocked every timer and, by patching `Array.prototype.includes`, changed the host's answers with no error; a worker thread or a child process contained all four cases (verified by experiment, Node 24.21.0). Select by project config and pin; never auto-load what is installed.
  - Protocol (016-03, 016-07, judgment 016-08): adopt no protocol whole; none carries C3's inputs or C4's acceptance rule. Own a versioned Squeal check-provider contract with three bindings and one set of acceptance rules: a command and its report, JSON-RPC with `Content-Length` framing over stdio, and an in-process JavaScript binding for our runners. Reuse MTP's split of discovery, execution and updates, never its UIDs as identity. Unproven completion (a signal, truncated output, a lost provider) stays unknown; a missing end alone never makes a file failure or retires a check. Scheduling hints stay local, never one RPC per call under the scheduler lock. Two open experiments with the 016 coordinator as owner: the diagnostic check unit (a scope or a finding; a line-free content anchor survives an inserted line but changes with the message), and the per-edit cost of the three bindings.
  - Adoption (016-05): no case shows plugins driving adoption by themselves; Ruff overtook flake8 and pylint with none, and its maintainer names bundling as the feature and a public API as a freeze on refactors. A broad code API is expensive (ESLint's flat config took five years). Use concentrates in the official tier (Terraform: 0.5% of providers, 83% of top-100 downloads). No ecosystem gates whether a plugin's results are true. Agents pass a good kit and cheat a weak one; Squeal's own agent-written runners failed 22 of 34 reviews, some on stale passes. An ecosystem can form around a closed core when the API, the SDK and the registry are open; the repository today grants nothing (`private`, `UNLICENSED`, no LICENSE file).
  - Trust (016-06): the core computes an extension's key from its name, exact version and resolved config digest; the extension gives inputs only. Store the provider and its version beside each result: Squeal cannot name or drop one provider's results today, and no system studied can. The recorder saw 3 of 6 reads across languages, `strace -f` all 6, an `LD_PRELOAD` shim missed a static binary; tracer cost unmeasured. A SessionStart hook starts the daemon in any repository with `squeal.config.json`, so a committed config that names a fetched provider would run code the repository does not hold: run a provider only when the user's own config pins it. Landlock read allow lists work unprivileged on this host; user namespaces do not.
- 2026-10-24, the human, asked before deciding: would the change improve Squeal's quality, cut the number of issues and make the work more consistent even if nobody ever adds a plugin? The coordinator's judgment, not a measurement: yes for the internal half (one contract inside the core for our own runners, complexity and harnesses; one write path to the shared store; the provider recorded per result; a correctness kit run against every runner), no for the public half (protocol, SDK, license, registry), which pays only if outsiders come. It would not touch defects that need one runner's internals, harness quirks or load, and its first step changes the riskiest code.

## Open questions

1. In-process JavaScript modules, an out-of-process protocol, or both, and for which tier?
2. What is the minimum a check provider must give for transitions, keys and the shared store to stay trustworthy?
3. Which existing standard (Build Server Protocol, LSP diagnostics, TAP, JUnit XML, SARIF, Microsoft.Testing.Platform, `go test -json`) to adopt, and what Squeal must add to it?
4. What moves out of the core today, at what cost, and with what risk to the shipped runners and harnesses?
5. Distribution, discovery and trust of third-party extensions; whether an ecosystem can form while `package.json` says `"private": true` and `"license": "UNLICENSED"`.
6. Does extensibility drive adoption for a tool like Squeal, and what does a public API cost to keep?
