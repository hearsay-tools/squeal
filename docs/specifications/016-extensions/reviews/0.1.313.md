## Blockers

### B1. The first edit in a live second worktree uses stale direct marks (proven)

Locations: `src/core/scheduler/refinement.ts:192`, `:251`, `:274`, `:284`; `src/core/scheduler/edit-cut.ts:183`.

Goal 6 requires an edit of a child process's imported path to put its test file in `direct` in a second worktree. D4 assigns the stored marks to the core. C4 step 4 counts these marks among the K shortest direct importers, before transitive readers.

`fetchRunnerPart` computes `observedDirectOf` from the worktree's cached marks. Only later does `applyRunnerPart` call `regrowObserved`, which reads another worktree's new marks. Settlement and the edit cut still use the set computed before that read. This loses a mark on the first edit after the other worktree stores it. A later timer refinement can hide the failure.

A probe over the real scheduler and store used the existing catch-up fixture. Product sources in the scratch archive matched this candidate exactly. No timer or sleep decides the result:

1. X (500 ms) and Z (100 ms) both reach `src/child.ts` through `src/a.ts`. Neither is a one-hop graph importer. K is 1.
2. Start B with module-load observations enabled and no observations to report. Let its baseline finish.
3. Start A over the same store. Its X run reports `paths: [child]` and `direct: [child]`. Edit X in A to make it run and store that mark. Assert `observedDirect.` holds `{ "test/x.test.ts": ["src/child.ts"] }`.
4. Call `editAndRun(b, "src/child.ts")` without a prior runner-only refresh.

```text
Expected: editPaths=[test/x.test.ts], catchUpPaths=[test/z.test.ts]
Actual:   editPaths=[test/z.test.ts], catchUpPaths=[test/x.test.ts]
AssertionError: expected [ 'test/z.test.ts' ] to deeply equal [ 'test/x.test.ts' ]
```

A control that calls `b.scheduler.refreshObserved()` and waits for idle before step 4 passes with X as edit work and Z as catch-up. Thus the mark exists and the cut uses it when the view is fresh. The candidate's restart and second-worktree tests start B after A stored its mark, so they do not cover this order.

Fix sized for one worker: derive the direct-mark set from the refreshed core view when applying the refinement, after shared observations and closures are current. Use that same set for settlement and the edit cut. Keep the runner's fallback separate and preserve the K bound. Add this live-worktree sequence, including a mark on a path already in the static closure; also check a newly observed path whose reverse-index entry must first be assembled.

### B2. The pytest e2e inheritance gate still expects the old observation behavior (proven CI failure)

Location: `test/e2e/pytest.test.ts:293` on the candidate. Evidence: exact-head CI output above, all four harness/Python variants.

A synced second worktree can inherit them without running the two files that used to grow their observations locally. The unchanged assertion requires both files to run, so the suite fails.
