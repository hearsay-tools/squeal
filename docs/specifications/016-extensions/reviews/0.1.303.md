## Blockers

### B1. Another worktree can change the runner attributed to an existing failure (proven)

Locations: `src/core/store/repos/results.ts:149`, `src/core/store/repos/test-files.ts:204`, `src/core/delivery/attribution.ts:279`.

Goal 4: "The `.js` doctest case of 007 `reviews/wave-5.875.md` gets no 'No dependencies are installed' sentence." D3: "The runner that produced a check is stored" and attribution reads that record.

`checks` is shared across worktrees. Its identity is project, test path, kind and full name. A file-level check has no test name, so a pytest doctest and a Vitest file check can have exactly the same identity in two worktrees. Project names are unique within one composite runner, not across worktrees.

Each `putMany` now overwrites the one `checks.runner` value. Delivery reads that value without the displayed result's key or worktree. The write can describe another result while this worktree still holds its original failure under another key.

The preserved probe uses the real store, state sink and delivery. It adds two cases to the candidate's delivery fixture:

1. Worktree A stores a pytest file-level failure at `[py] docs/example.js`, key `k1`.
2. Worktree B stores a Vitest pass for the same check, key `other-runner-key`.
3. Worktree A delivers its pytest failure, once at the tool boundary and once at registration in a separate case.

Both cases fail the assertion that the sentence is absent:

```text

dependenciesInstalled: false

No dependencies are installed in this worktree; failures that cannot find a package are expected until an install.

```

The same two cases pass when only the delivery import is changed to the delivery code from the fetched main. The candidate store and probe writes stay the same: `2 passed | 25 skipped`, exit 0. This isolates the regression to the new attribution path. This is a store/delivery probe, not a claim to have started two live daemons.

Fix for one worker: bind the recorded producer to the result being displayed, at least check plus key for result-backed failures. Preserve the right producer for setup failures, which have no result key. Attribution must select the producer for this worktree's failing state. Another key's write must not change it. Keep the old-record fallback and C7 compatibility. Add the two-worktree file-check collision in both directions and through both callers. Do not restore inference from the live policy or file suffix. A global last-writer value on `checks` cannot represent both retained results.

### B2. K8 passes when no run was cut (proven)

Location: `test/kit/steps.ts:97`.

D1 determinism: "K8 cuts the run at a marker." K8's scenario says a check passes, the next check writes the marker and holds, and the driver cuts that run. Its purpose is to prove that the interrupted file contributes no result.

The driver records the absence of a cut as a note. It still checks only the expected `unknown` outcome. A crash before any test starts also has no completed file and therefore reads `unknown`. If recovery succeeds, K8 reports PASS without exercising interruption.

The preserved `cut-probe.txt` uses the real node:test pack and K8. It wraps only the first `run` call to return a valid `crashed` report before starting any test. The second call uses the real adapter. Output:

```text
PASS K8 × node-test
note step 0 cut for stop: not cut: no started file before the run ended
note step 0 failure: review probe: process failed before any test started
ok   step 0 run (crashed): cut is unknown, expected unknown
ok   step 1 edit test/cut.test.mjs: reaches cut by affected=direct, closure=true, ...
ok   step 2 run (completed): cut is pass, expected pass

AssertionError: K8 must reject a run that never reached its marker or was cut
'PASS' !== 'FAIL'
exit 1
```

This is a failure of the scenario's precondition. It also lets the 60-second marker-wait deadline expire without failing the precondition. The probe proves the early-crash path; it does not rely on host load or a sleep.

Fix for one worker: make reaching the marker and sending the requested abort an assertion of every cut step. A run that ends first, or exhausts the marker wait, must fail that assertion even when its result is unknown. Keep the outcome and recovery assertions. Add driver cases for an early crash and a successful marker-triggered cut. No adapter change is needed.
