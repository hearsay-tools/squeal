# 018-53 notes: repair of review 0.1.579

Worker notes for the repair of B1 to B4 and S1 (`reviews/0.1.579.md`). What changed and why, for whoever continues.

## Seam map

- **B3, the reporter** (`src/runners/node-test/ci-runtime/node-test-reporter.mjs`): every failure of its own (the encoder's import, open, a short or failed write, close) is caught inside the reporter. It stops writing, drains the rest of the events, writes `<graph>/<pid>.reporter-failed` and yields one line to its destination. An error of Node's own event stream (`SourceError`) is rethrown: it is the test run's. `ci-runs.ts` `readFailed` reads the marks: that process's part holds no file, `end: "crashed"`, and the note names why, never the D23.5 "no reporter" line. A missing events directory no longer throws in `readNodeTestRuns`.
- **B1, `NODE_OPTIONS`**: the reporter's header holds the process's raw `NODE_OPTIONS` and the settings' `hooks` (all hooks `ci record` put there, Vitest's too in a mixed command). `ci-flags.ts` `projectNodeOptions` removes those hooks and Squeal's recorders. `ci-runs.ts` refuses a D25 flag found there (note: "`<flag>` from NODE_OPTIONS"), and takes shard and preloads from `NODE_OPTIONS` then `execArgv`, in Node's order. The part holds them as `nodeTest.nodeOptions` (new optional field of format 5). At export (`export-node-test.ts` `recordedFlags`, `entryFlags`) a process matches an entry when `entryArgv([...nodeOptions, ...execArgv])` equals `[...entryArgv(entry's NODE_OPTIONS here), ...entry.argv]`. The entry's options come from this job's env as the adapter reads them (`projectEnv`, `tokenizeNodeOptions`, in `export-node-test-here.ts`). A part without `nodeOptions` gives no evidence.
- **B2, `env.allowlist`**: `ci record` passes the policy's allowlist to the node:test recording, and the reporter records those variables beside the entries' `env` names. `NodeTestEntryHere.allowlisted` holds this job's hash of each allow-listed name the entry's `env` does not set. `export-node-test-refusals.ts` `allowlistRefusal`: a name the part does not hold leaves the entry out ("do not say"), and another value leaves it out too. A name the entry sets is compared with the entry's value only (D26.3), because the test process sees that value.
- **B4, ownership** (`export-node-test.ts` `owning`): a process with files is the run of each entry of its shape that lists one of them. A process without files joins only a sharded entry of its shape (count above 1) that has another process with files of the same count. An unsharded empty process joins no entry. Node, env and shard refusals read `owners`, never the shape match.
- **S1, manifests** (`src/runners/ci-runtime/evidence-hooks.cjs` `manifest`): the resolve hook reads the `package.json` that `module.findPackageJSON` finds for the resolved module and for its importer, and the entry file's. This is Node's own reader, called while the module resolves. A Node without `findPackageJSON` (before 22.14) takes none, so those files are left out. The hook is shared, so Vitest's recording now has this evidence too.

## Decisions the review did not settle

1. **`NODE_OPTIONS` is matched, not only refused.** The recorded options must equal what the entry's processes get from this export job's `NODE_OPTIONS`. A CI step that sets `NODE_OPTIONS=--max-old-space-size=4096` only for the recorded step loses its node:test files until the export job sets the same. This is safe and strict. The key does not hold `NODE_OPTIONS` except through preloads, so a looser rule ("other options may differ") would also be sound for flags that do not change behaviour. Squeal cannot tell those apart.
2. **An empty unsharded process belongs to no entry.** It can make no shard set incomplete and gives no file, so the "two parts of shard 1/1" refusal does not fire for it. An empty process in a sharded run is still ambiguous between entries of one shape and count, so it joins each of them (conservative).
3. **Reporter failure output.** On its own failure the reporter yields one line to its destination (stderr in the documented pair). That is the one case where it prints.
