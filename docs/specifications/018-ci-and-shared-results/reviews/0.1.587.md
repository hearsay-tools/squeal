## Blocker

### B1. Proven: query stripping happens after alias matching, so an exact alias loses its target

Locations: `src/runners/node-test/graph/resolver.ts:288` to `:294`, and `src/runners/node-test/graph/tsconfig.ts:108`. Row 018-66's done-when says: "The differential never finds a module Node loads that the closure lacks." The row explicitly owns query handling. The review brief also names queries on bare specifiers.

The new alias mapper receives the full `@dep?q=1` specifier. Its exact lookup cannot match `@dep`. No alias candidate is passed to enhanced-resolve. Taking `request.path` without its query only helps when resolution already succeeded. Real tsx resolves the bare name without its query and loads `dep.ts`.

Minimal ESM project with tsx available:

```json
// tsconfig.json
{"compilerOptions":{"paths":{"@dep":["./dep.ts"]}}}
```

```ts
// dep.ts
console.log("LOADED_DEP");
export const Value = 2;

// a.test.ts
import { test } from "node:test";
import assert from "node:assert/strict";
import { Value } from "@dep?q=1";
test("v", () => assert.equal(Value, 2));
```

Build `createNodeTestGraph({ root, cwd: root, argv: ["--import", "tsx"], testFiles: ["a.test.ts"] })` and compare with `node --import tsx --test a.test.ts` from that root. Actual results:

```text
Node: exit 0; LOADED_DEP printed
closure.paths: ["a.test.ts", "package.json", "tsconfig.json"]
closure.complete: true; incomplete: []
affected(["dep.ts"]): { direct: [], transitive: [] }
dep.ts changed to export const Value = 4: Node exits 1
```

The independent resolve-hook differential also finds `dep.ts` reachable from `a.test.ts`. This is a static closure and selection failure; no end-to-end stale imported pass is claimed.

Base comparison is explicit: the graph at `d0bc61703` held the bogus path `dep.ts?q=1` and also selected no test for `dep.ts`. Thus this is an incomplete query repair at the changed boundary, not a claim that the base handled this fixture safely. It blocks because the approved row's query repair and differential containment condition remain unmet. In contrast, the separate package-extends limit below is unchanged code outside this repair.

Repair for one worker: apply tsx's query handling before matching aliases, while keeping Node-only resolution semantics intact. Add this exact-alias case to the differential guard. Retain wildcard-query and relative query/fragment cases. Do not strip arbitrary fragments from every bare specifier: the independent `@dep#frag` control is rejected by real tsx. Require the loaded plain path in the closure and selection after its change. Re-run the key-format alarm after repair.

## Should-fix

### S1. Proven, non-blocking: timeout kills the endpoint process but leaves its git child alive

Locations: `src/core/ci/endpoints-child.ts:44` and `:66` to `:68`; the new child calls `committedInputs` through `src/core/ci/endpoints-hash.ts:59`. `committedInputs` starts `git ls-tree` with a 30 s timer owned by that endpoint process. The review brief asks whether a killed child leaves anything behind.

A real bundled-CLI probe put a `git` wrapper first on PATH. It delegates every command to the real git except `ls-tree`, for which it execs a Node process that records its pid and waits on an interval. This models a git blocked while reading the checkout. The fixture is an ordinary committed node:test project and names the reporter pair.

At the 10 s hashing limit, `ci record` kills only its immediate endpoint child. It then runs the real test, writes one completed part without endpoint hashes, and exits 0. Immediately afterward `ps -o pid,ppid,stat,args -p <recorded-pid>` shows the substitute git still running with state `Sl` and adopted by the host's reaper. It is not a zombie. The probe killed it and removed the fixture. A second run reproduced this result.

The endpoint child's 30 s git timer died with that child. It cannot later terminate git. This newly introduced process boundary therefore leaves abandoned work behind. It does not invalidate the demonstrated CLI exit bound or prove a wrong part, so it is a should-fix rather than a blocker against 018-67's stated done-when.

Worker-sized repair: give each endpoint round ownership of its whole process tree, with platform-appropriate termination that does not wait for a stuck read to finish. Test both timeout and parent disappearance with a live git descendant. Preserve the command's exit code and the parent's prompt exit.
