## What fits

- **D2 path safety:** both exporters call `absolutePathOfFile` before adding a file and its results. They use the same platform-independent predicate as the final `absolutePathIn` guard. The final guard still runs before either CLI writes a file. Shared start-up and environment descriptor paths for retained projects still throw `AbsolutePathError`.
- **D2 whole-file exclusion:** all results of an omitted file leave with it. The exporter keeps the retained files' paths, closure lists, observed entries, keys and result rows intact. It does not trim a bad path out of a key's evidence and keep the pass.
- **D9 certification:** file eligibility, read-time evidence checks, inspector exclusions and key computation still precede bundle creation. The change does not bypass these checks to recover more exports.
- **Count partition:** let `F`, `P`, `N`, `K`, `T`, `C`, `I`, `U`, `A` denote all files, passing files, named files, kept files, exported files, uncertified files, closure-inspector exclusions, unwatched files and absolute exclusions. The returned counts sum to `T + (F-P) + (K-T-C-I-A) + C + (P-N) + (N-K-U+I) + U + A = F`. The new `- absolute.length` in `unkeyed` prevents double counting. Store export likewise partitions its key rows into `noKey`, `noResult`, `failed`, `absolute` and exported files; `keyed` is a subtotal.
- **Import keys:** observed unions merge entries for the same project and test path, not all files of a project (`ObservedSets.of`, `SharedPaths.of`). `exportedFile` and `observedOf` read that entry only. Shared start-up inputs and the project environment remain in the bundle for retained projects. Import and re-key code are unchanged: `rekeyFiles` proves each retained file's own exported key and requires every exported closure input before re-keying. If a retained closure names the dropped test's source file, that source path stays in the retained closure. Omitting a test's result does not remove its source bytes from another test's key.
- **CLI diagnostics:** both commands name up to three excluded files and their first bad paths on stderr, include the project name when set, and count remaining files. A successful export includes the absolute exclusion count under `Left out`. The new end-to-end test checks the written bundle and visible diagnostic, not just a helper return value.
- **Bundle/version seam:** rebuilding all four harness bundles leaves the tree clean. Version changes are consistently 0.1.521 to 0.1.522; the helper and CLI changes are present in the built CLI bundles.
