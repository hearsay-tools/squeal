## Should-fix

### S1. Proven, non-blocking: an inherited file marker can suppress a fresh top-level recording

Locations: `src/runners/vitest/ci-runtime/vitest-ci.cjs:305` and `src/runners/node-test/ci-runtime/node-test-reporter.mjs:38`. The recording environment in `src/runners/vitest/ci-record.ts:150` inherits the caller's variables without binding `SQUEAL_CI_NODE_TEST_FILE` to this recording. The node:test hook's existing file detection at `src/runners/node-test/ci-runtime/node-test-ci.cjs:78` also trusts that variable.

Reproduction: set `SQUEAL_CI_NODE_TEST_FILE` to any nonempty stale path in the CI job's own environment, then run a fresh `ci record` around the two top-level commands above. The result is zero parts, despite four passing files. No valid owner pid or matching recording is required. The worker notes explicitly acknowledge the inherited-variable choice. This candidate extends that suppression to Vitest; the node:test file-attribution limitation already existed.

This loses recording and reuse. It does not manufacture a pass: the two independently failing top-level runs retained exit 1 and produced no parts. Suppressed files supply no checks for export. This reserved-variable contamination does not block the row's ordinary-environment repair, but a claim that top-level runs cannot be misclassified would be incorrect.

A small follow-up can scope the file/owner marker to the active recording, or reset the inherited attribution at a fresh recording boundary. Its tests must cover a stale top-level marker, a genuine nested child with its own environment, and a test that starts another `ci record`. Preserve the existing rule that another recording withholds the outer command's evidence; do not solve attribution by weakening that rule.
