## Blockers

### B1. Proven: a tracked `__proto__` input loses its non-commit hash and exports a wrong pass

Location: `src/core/ci/endpoints.ts:66`, assignment at line 71; consumed by `src/core/ci/reuse-endpoints.ts:53`.

D32 requires `stable` to hold each stable path whose content differs from the commit. D33.4 requires the endpoint hashes to equal the content here. The implementation constructs `stable` with `{}` and writes `stable[path] = hash`. For the valid root filename `__proto__`, that invokes the inherited setter instead of creating an own entry. A string hash disappears. A `null` absence hash also creates no own entry. Export then treats the omitted entry as the commit's content.

I reproduced the wrong pass with the committed candidate CLI, not a fabricated part:

1. Commit a small Vitest repository with `__proto__` containing `BAD\n`. Declare it in `squeal.config.json`: `{"inputs":{"test/*.test.ts":["__proto__"]}}`.
2. The test runs `execSync("cat __proto__")` and expects `GOOD`. The shell string supplies no read-time evidence for this file.
3. Clone this commit for export. In the recording checkout only, change `__proto__` to `GOOD\n` **before** `ci record`. Leave it unchanged throughout the command and afterwards.
4. Run `node <candidate-cli> ci record --out <parts> -- node <vitest> run` in the recording checkout. Run `node <candidate-cli> ci export --parts <parts> --out <bundle>` in the fresh clone.
5. Run plain Vitest in the fresh clone. As a control, export the same part with its format set to `squeal-ci-part/5`.

Actual evidence:

```text

recording content: GOOD
export content: BAD
part.format: squeal-ci-part/6
part.header.dirty: true
part.stable: {}
part.unstable: ["./"]
```

This is outside D34: no program changes or restores an input during the command. Both endpoints contain `GOOD`, while export contains `BAD`. The dirty recording is allowed and is exactly why D32 stores non-commit endpoint hashes.

One-worker repair: build `stable` with a null prototype, `Object.fromEntries`, or another own-property-safe insertion. Add a recorder regression for a tracked root `__proto__` with non-commit content at both ends, and an absent-at-both-ends case. Preserve the JSON entry and show that export refuses it in a fresh checkout of the commit. Keep the read-time rule and key versions unchanged.

## Should-fix

### S1. Plausible: endpoint hashing has no deadline before the user's command

Location: `src/cli/ci.ts:119` and `src/core/ci/endpoints.ts:76`.

Thrown errors are safely converted to a note, as the injected-error check proved. A slow read is awaited without a deadline. It runs before `runCommand`, which owns signal forwarding. I injected a five-second delay into `fs.promises.open` for one tracked input, then gave the bundled recording process a two-second outer timeout. Result: `SIGTERM`, `ETIMEDOUT`, and no marker from the command `sh -c 'echo command-ran > marker; exit 7'`.

The fault injection proves the wait is unbounded; it does not prove an ordinary CI filesystem will stall or a real workflow will hit its timeout. This is therefore non-blocking. D20.2's promise would be stronger with a bounded, cancellable endpoint pass that abandons certification and still runs the command. A timeout must also prevent abandoned hashing from continuing to compete with the command. Add a deterministic stalled-read check when this is addressed.
