## Blocker B1: the first importing environment fetches the same export twice

**Proven.** `src/core/shared/served.ts:55` recognises a completed attempt with no re-keyed files only by `ownId(fileHash, environments)`. However, `importIdHere` at lines 78-81 gives the first import the file-only id. That first attempt leaves no environment-specific marker.

When D10 accepts the environment but D11 cannot prove any file's key, all `import_files.environment` values remain CI's. On restart, the file-only id fails the marker check, no file has the local hash, and the descriptor comparison says re-keying is possible. `servesHere` returns false. The reader fetches the same export again in the unchanged environment, then records the environment-specific id. This violates this review brief's requirement to fetch an export at most once per environment. It is a redundant fetch on the first restart, not an unbounded loop; the second import stops later repeats.

The existing second case in `import-each-worktree.test.ts` does not catch this. Its first importer differs from CI under D10. The matching importer always comes second and gets the environment-specific id immediately.
