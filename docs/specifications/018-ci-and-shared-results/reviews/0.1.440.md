## Blockers

### B1. Proven: a compatible import in the shared store leaves a false format warning

Location: `src/core/shared/reader.ts:253` (the new clear runs only on the import
path), interacting with its existing early return at line 164;
`src/core/status/squeal-mismatch.ts:24` (a record is shown without checking
whether it still describes the selected export).

D21 requires silence when formats match and a per-worktree record "cleared
when an export of the same format arrives". Vision principle 2 requires
current facts. The new record survives an ordinary shared-store import path:

1. Worktree A reads C0, whose export has key format 22; local format is 21.
   It stores a refusal for C0.
2. CI publishes compatible C1, and worktree B imports it into the same store.
3. A advances to C1 and nudges its reader. `nearestHeld === 0` returns before
   `writeSquealMismatch(..., null)`.
4. The compatible C1 import is present, but A still holds the refusal for C0.
   The status renderer still says `CI results not used: CI ran Squeal 99.0.0,
   which records results in a different format than this Squeal (0.1.440).`

An independent second probe reproduces the same fault without another
worktree: import compatible C0, visit incompatible C1, then check out C0.
The old C1 refusal remains, even though C0's compatible import is already held.
Restarting the reader alone does not fix the early return.

Reproduction below uses this repository's scratch-remote helpers and a real
linked worktree. Save it outside the repository as `probe.test.ts`, replacing
`<repo>` with this checkout's absolute path. Use an external Vitest config
whose `root` is the checkout and `test.include` is the probe's absolute path.
Run with temporary HOME/XDG_CONFIG_HOME, `GIT_CONFIG_GLOBAL=/dev/null` and
`GIT_CONFIG_NOSYSTEM=1`. No real remote or HOME is changed.

```ts
import { it, expect } from "<repo>/node_modules/vitest/dist/index.js";
import { scratch, publish, readerOf } from "<repo>/test/shared/reader-kit.ts";
import { cloneWith, cloneOf, git, exportOf } from "<repo>/test/shared/remote.ts";
import { KEY_FORMAT_VERSION } from "<repo>/src/core/keys/key-format.ts";
import { decodeBundle } from "<repo>/src/core/store/transfer-bundle.ts";
import { readSquealMismatch } from "<repo>/src/core/shared/refused.ts";
import { worktreeIdFor } from "<repo>/src/core/fs/git-layout.ts";
it("clears a refusal after another worktree imports a compatible export", async () => {
  const s = scratch();
  const ci = cloneWith(s, "ci", 1);
  const [c0] = ci.commits;
  const bundle = decodeBundle(exportOf(c0));
  if (typeof bundle === "string") throw Error(bundle);
  await publish(ci.root, c0, exportOf(c0, {
    header: {
      ...bundle.header,
      squealVersion: "99.0.0",
      keyFormat: KEY_FORMAT_VERSION + 1,
    },
  }));
  const dev = cloneOf(s, "dev");
  const { run, store, commits } = readerOf(dev);
  await run();
  const id = worktreeIdFor(dev);
  expect(readSquealMismatch(store, id)?.commit).toBe(c0);

  git(ci.root, ["commit", "-q", "--allow-empty", "-m", "compatible"]);
  git(ci.root, ["push", "-q", "origin", "main"]);
  const c1 = git(ci.root, ["rev-parse", "HEAD"]);
  await publish(ci.root, c1);
  git(dev, ["pull", "-q", "--ff-only"]);
  const dev2 = s.dir + "/other-worktree";
  git(dev, ["worktree", "add", "--detach", dev2, c1]);
  const other = readerOf(dev2, { store });
  await other.run();
  expect(commits()).toEqual([c1]);
  await run();
  expect(readSquealMismatch(store, id)).toBeNull();
});

```

Actual result: `AssertionError: expected { ... } to be null`. The printed
`imported` list contains compatible C1, while `record.commit` is incompatible
C0 and `record.ci.keyFormat` is 22. The other probe also calls the real
`squealMismatchOf` and `squealMismatchLines`; the false line is present.

Repair size: one worker, reader/refusal validity and focused shared/status

export is already held, including imports from another worktree and a return

start-point rule and the fast path's lack of redundant fetches. Add both
