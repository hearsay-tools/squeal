## Blocker

### B1. Proven, narrowed but unresolved: the grace period changes the retry-window bound

Locations: `src/core/shared/look-again.ts:45` and `:76`; `test/shared/reader-look-again.test.ts:195`.

The repair puts the expiry decision in the correct two places: after the local start-point decision and immediately before the remote listing. The new tests prove that a 60-second callback and local steps that end at 60 seconds do not list for a 45-second window. They also prove one give-up note and no later timer. Those parts of B1 are repaired.

However, `expired` compares `now` with `until + 1000`, rather than the configured deadline. The passing test at line 195 expressly requires an extra listing at 45.5 seconds for a 45-second window:

```ts
await fire(30_000);
await fire(15_500);
expect(listings()).toBe(before + 2);
```

The built candidate's window object independently answers:

```text
window: everySeconds 30, forSeconds 45, first miss at 0
now 45000: expired false
now 45001: expired false
now 45500: expired false
now 46000: expired false
now 46001: expired true
```

D14 says "for up to `forSeconds`". The brief and prior B1 require no listing after the window. No amendment in this repair authorizes an extra second. The allowance also applies to an earlier timer delivered late and to time consumed by local git, not only the final timer. With a one-second configured window it can double the period in which a listing may start.

Judgment on the margin: a timer can fire late, so the final look must be best effort under a strict deadline. That does not require extending the deadline. A bounded one-second grace period is a possible policy choice, but it changes the requirement under review. This review cannot treat it as an implementation detail and close B1.

Repair for one worker: keep both pre-list checks and remove the positive late allowance. Preserve a look that reaches the boundary in time; skip one that reaches it late, with the one give-up note. Change the 45.5-second test to require no extra listing and cover a local step crossing the deadline by less than one second. If a grace period is wanted instead, its changed time bound needs an explicit spec decision before re-review.
