### B4. Proven: the process tsconfig's mappings do not reach importers outside its directory

Location: `src/runners/node-test/graph/resolver.ts:176` to `:180`, passed into enhanced-resolve at lines 183 to 197. This is within the retained-b1 scope: the graph must use the config tsx loads for every importer and must not omit a module Node loads.

The graph now selects the process's config, but passes it to enhanced-resolve's directory-scoped tsconfig plugin. That plugin applies the map only when the importer's directory is within the config's context. In the installed `enhanced-resolve/lib/TsconfigPathsPlugin.js`, `_selectPathsDataForContext` returns null when no configured context contains `request.path`. tsx applies its selected config to the importer even when it is elsewhere in the worktree.

Minimal ESM fixture, with tsx installed or linked at its root:


