## Blocker

### B1. A permanent host hang becomes a passing test run

**Proven.** `test/daemon/helpers.ts:357–364`, especially the unconditional `killProcesses` at line 364.

The helper waits 30 seconds, terminates the remaining hosts and children, then returns success. Nothing reports that natural exit failed. This removes evidence before `test/global-teardown.ts` can enforce its rule that a process from the test build which outlives the run fails the run. The review brief specifically requires that the bound and kill cannot hide a real hang and that daemonSuite coverage is retained.

Reproduction, in a temporary copy of the candidate, with the repository's normal global setup:

```ts
import { spawn } from "node:child_process";
import { once } from "node:events";
import { it } from "vitest";
import { daemonSuite, delay } from "./helpers.js";

const suite = daemonSuite();
it("a permanently stopped runner host is a leaked process", async () => {
  const repo = suite.fixture();
  const host = spawn(process.execPath,
    [suite.cli, "runner-host", repo.root, "--runner", "vitest"],
    { cwd: repo.root, env: repo.env, stdio: ["pipe", "ignore", "ignore"] });
  await once(host, "spawn");
  await delay(300);
  host.kill("SIGSTOP");
});
```

Run `pnpm exec vitest run test/daemon/review-hang.test.ts --maxWorkers=1`. This launches the real built runner-host command, rather than a command-name stand-in. It stays stopped forever. Candidate: **exit 0**, one test passed, 37.008 s wall time. The 30-second wait plus the five-second SIGTERM grace ends in SIGKILL and success. With only `helpers.ts` replaced by its parent version: **exit 1**, 7.141 s, with `error during close Error: 1 process(es) from the test build outlived the run; killed (lessons, defect 29)`, naming this test and host PID.

Fix scope: retain bounded cleanup, but capture survivors at the natural-exit deadline and fail with their PIDs/root after ensuring they are killed. Ensure remaining fixture cleanups still run on this failure. Add a regression for the timeout failure path, using an injectable short grace or clock so it does not cost 35 seconds. Keep the current delayed-but-eventually-exiting regression green. No product change is needed for this repair.

## Should-fix

### S1. Child tracking starts after the parent can already have exited

**Proven helper limitation; no real-fixture teardown failure demonstrated.** `test/daemon/helpers.ts:358–362`.

`left` initially contains hosts only. The first descendant snapshot runs after a 100 ms sleep. If a host exits in that interval, a surviving child is reparented and cannot be found by the PPID walk. An intermediate child can lose its descendants in the same way between later snapshots.

The temporary probe started a stand-in host from `testBuildDir` with the exact runner-host root arguments. That host started a long-lived Node child. After the child's PID was recorded, the probe called `awaitRunnerHosts(root, 500)` and immediately instructed the parent to exit. The helper returned with `runnerHosts(root) === []` while `isAlive(child) === true`. The probe explicitly killed the child afterwards. Recorded result: `{"orphanAlive":true,"hosts":[]}`.

Track descendants before the first sleep and retain their identities. If the intended contract includes descendants created just before a parent's exit, use a stable ownership mark rather than PPID snapshots alone, or narrow the comment and report that limitation. Do not widen process matching to all host or worktree processes. This is not another blocker: the writer proved responsible for this row's ENOTEMPTY is the runner host itself, whose exit is tracked.
