## Blockers

### B1. Proven: a late timer callback lists the remote after the retry window ends

Locations: `src/core/shared/look-again.ts:55`, `src/core/shared/reader.ts:198` and `src/core/shared/reader.ts:228`. Expiry is checked only at `look-again.ts:73`, after the remote listing has completed and only when it missed.

D14 says the reader lists again "for up to `forSeconds`". The row's done-when and this review's brief require no listing after the window. `takeDue` tests only the key and the due flag. It does not test the deadline. A delayed callback therefore authorizes a listing after the configured window. A busy event loop, suspended host or the reader's own wait for refinement can delay it.

Reproduction using the existing `movedBeforePublish` helper in `test/shared/reader-look-again.test.ts`:

```ts
const { listings, fire, r } = await movedBeforePublish({
  everySeconds: 30,
  forSeconds: 45,
});
const before = listings();
await fire(60_000); // Deliver the first 30 s callback late.
expect(listings()).toBe(before); // Fails: before + 1.
expect(r.notes).toHaveLength(1);
```

The independent scratch-remote probe printed:

```text
before: "x\n"
after:  "x\nx\n"
notes: ["CI results: origin had no refs/squeal/<sha> after 45 s; tests run here as before"]
FAIL: expected 'x\nx\n' to be 'x\n'
```

The late listing happens before the give-up note. If the export appears in the late listing, the reader can fetch and import it and never reaches the expiry check. The current window test fires exactly at 30 s and 45 s, so it misses this case.

Repair for one worker: make the timer/window owner expose an expired decision before remote I/O. A late callback must stop the window and emit its one note without listing. Check again at the boundary that starts the remote listing, since local git work can also consume time. Keep the existing allowed final look at the deadline, normal repeated misses, zero-window behavior, start-point replacement and close cancellation. Add a delayed-callback regression and a delayed local-step case. Do not change import or queue policy.

## Should-fix

### S1. Proven, nonblocking: accepted long timer values overflow Node's timer limit

Locations: `src/core/daemon/policy-shared.ts:35` and `src/core/shared/look-again.ts:78`, through `unrefTimer` at line 33.

Both fields accept `2147484` seconds with no policy problems. Their next timer delay is `2147484000` ms. Node accepts at most `2147483647` ms and replaces a larger delay with 1 ms. A source probe through the built candidate's `loadPolicy`, `LookAgain` and `unrefTimer` printed:

```text
TimeoutOverflowWarning: 2147484000 does not fit into a 32-bit signed integer.
Timeout duration was set to 1.
{"policy":{"everySeconds":2147484,"forSeconds":2147484},"problems":[],"firedWithin25ms":1}
```

This needs an unusually long custom policy; defaults are unaffected. It can turn a request for sparse remote access into a listing after every completed pass for days. Repair in one worker: reject unsupported delays with the normal one-problem/default behavior, or split long waits into bounded timer chunks. Cover the largest supported value and the first unsupported value. Do not silently pass an overflowing delay to Node.

### S2. Proven, nonblocking: the README promises reuse for every waiting file

Location: `README.md:224`: "When the results arrive, every file still waiting takes its CI result and does not run."

Reuse still requires a matching key and compatible environment. The passing `import-each-worktree.test.ts` explicitly proves that an incompatible environment imports no current passes. The dirty-content probe above also leaves the changed file without a current imported pass. A closure that gains a path may still race the second import, even when publish preceded the pull; that is the accepted option-C limitation in the row notes.

The paragraph correctly states that the reader does not hold queued runs and that a running file finishes. Qualify its reuse sentence with matching keys and say that publishing before main moves avoids the publish-delay race. It does not guarantee reuse for changed content, different environments or the closure-refinement race. This is a small wording repair; it does not ask for a queue hold or a D11 change.
