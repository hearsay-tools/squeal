## Blockers

### B1. Proven, P1: `NODE_OPTIONS` bypasses run-shape refusals and exports a whole-file false pass

Locations: `src/runners/node-test/ci-runs.ts:113`, `src/runners/node-test/ci-runtime/node-test-reporter.mjs:35`, `src/core/ci/export-node-test.ts:177`.

D25 refuses `--test-name-pattern` because it runs only part of a file. D26 permits reuse only for the entry's run shape. The refusal and assignment inspect only `process.execArgv`. Node does not put options supplied through `NODE_OPTIONS` there. `context.nodeOptions` is available to the part builder, but used only to find preloads.

Reproduction, with `nodeTest: [{name: "unit", include: ["*.test.mjs"]}]` and no entry flags:

```js
import { test } from "node:test";
import assert from "node:assert/strict";
test("passing", () => {});
test("failing", () => assert.fail("must fail without filter"));
```

Record the documented reporter command with `NODE_OPTIONS=--test-name-pattern=passing`. Then unset `NODE_OPTIONS` and export its parts at the same fixture commit.

Actual: recording exits 0 and writes one passing check. Export exits 0: `Exported 1 test file, 2 results`. One result is the **file PASS**, keyed for `argv: []`. Import into an unfiltered clone makes the file current. The direct control, `node --test a.test.mjs` without `NODE_OPTIONS`, exits 1 at `failing`. This is a current false pass, not just a missing test name in output.

**Repair scope:** capture each recorded process's effective project Node options, excluding Squeal's hooks, and use them for refusal and run-shape validation. Reading only the wrapper's environment also misses a shell that sets `NODE_OPTIONS` inside the recorded command. At minimum, every refused option supplied through `NODE_OPTIONS` must give an empty part with a note and preserve the command's exit code. Check remaining semantic options against the entry's effective options so other environment-supplied Node flags cannot acquire an unrelated entry's key. Do not move keys or the adapter version.

**Repair proof:** the two-test fixture above must not export a file PASS under the unfiltered key. Exercise both inherited `NODE_OPTIONS` and an assignment inside `sh -c`, alongside a valid unaffected entry.

### B2. Proven, P1: global allow-listed variables are replaced with the export job's values

Locations: `src/runners/node-test/ci-record.ts:117`, `src/cli/ci.ts:169`, `src/core/ci/export-node-test.ts:210`.

D1 keys allow-listed variables, D9 requires the exported key to describe the CI run, and vision principle 2 forbids an old or different state posing as current. The node:test recording collects only names from `nodeTest[].env`. The global `policy.env.allowlist` never reaches it. Export compares only entry `env`, then computes keys with the export job's global environment.

Reproduction:

```json
{"env":{"allowlist":["MODE"]},"nodeTest":[{"name":"unit","include":["*.test.mjs"]}]}
```

```js

import assert from "node:assert/strict";

```

Record with `MODE=ci`, then export with `MODE=local`. Actual: the part has `nodeTest.env: {}`. Export succeeds with one file and two PASS results. Its descriptor names `MODE` and hashes **local**, which the recorded test never saw. In a clone started with `MODE=local`, the import is current. The direct control fails with `'local' !== 'ci'`.

**Repair scope:** carry the global allowlist into node:test recording, retain the run's hashes, and compare all key-relevant variable hashes with the environment used to key each entry. Preserve the separate override rule for entry `env` and never print values. Missing evidence must leave out that entry's files, including older parts lacking the new evidence.

**Repair proof:** the example must refuse reuse under `MODE=local` and keep a valid independent entry/Vitest export. Equal values and entry overrides must still export and import at equal keys.

### B3. Proven, P1: a reporter output failure fails the user's passing command

Location: `src/runners/node-test/ci-runtime/node-test-reporter.mjs:57`.

D28: "a crash of the recording is a note, never a failed step." D20.2 preserves a user's CI when Squeal fails. The reporter imports its encoder, opens its output, writes and closes without handling its own errors. An error escapes into Node's reporter stream. Catching errors after `runCommand` cannot recover the command's original result.

Fault injection after successful `ci record` setup: before launching `node --test`, remove only the private `nodeTest.events` directory. The shell's first command was:

```js
const fs = require("node:fs");
const settings = JSON.parse(process.env.SQUEAL_CI_RECORD || "{}");
if (settings.nodeTest) fs.rmSync(settings.nodeTest.events, { recursive: true });
```

The remaining command runs one passing test with the normal reporter pair. Without recording, the same command exits 0 and prints one pass. Under recording, it exits **7** with `ENOENT` at the reporter's `openSync`, before normal test completion. `ci record` prints `no part written` afterward but returns 7. This deliberately injects a recording I/O failure; it is not evidence of spontaneous directory loss on a healthy host.

**Repair scope:** contain Squeal's encoder/output initialization and write/close failures inside its reporter. Continue draining the event stream when recording is unavailable; diagnose and withhold incomplete parts without failing the test command. Keep errors from the project's actual test source distinct from errors of Squeal's recording.

**Repair proof:** injected open and write failures preserve the passing command's exit 0; a real failing test still exits 1. The missing or incomplete reporter data must not export a pass.

### B4. Proven, P2: entries with equal cwd/flags share shard refusals before file ownership is known

Locations: `src/core/ci/export-node-test.ts:98`, `src/core/ci/export-node-test.ts:178`.

D26 says: "A refusal leaves out that entry's files and keeps the rest of the export." D23.2 allows two `node --test` processes in one command. Valid entries can share `cwd` and `argv` while selecting disjoint test files.

Reproduction: two entries at the root, both `argv: []`; `alpha` includes only `nt/a.test.mjs`, `beta` only `nt/b.test.cjs`. One recorded shell command runs `node --test ... nt/a.test.mjs && node --test ... nt/b.test.cjs`. Both commands pass and recording writes two parts. Export reports:

```text
project "alpha" has two parts of shard 1/1: left out (1 test file)
project "beta" has two parts of shard 1/1: left out (1 test file)
no test file to export; left out: 2 test files of node:test that no nodeTest entry here takes as its own run; wrote nothing
```

Each part matches both entries by cwd/flags, so both enter each entry's shard set. The later `filesOf` ownership check cannot undo the refusals. The same grouping also lets another entry's Node/env mismatch affect its neighbor. Current unit tests avoid this case by giving the neighboring entry different flags.

**Repair scope:** establish which command/entry owns each part before Node/env/shard refusal, retaining conservative treatment of ambiguous files and empty shards. Do not count a process running only another entry's files as a duplicate shard for this one. Keep one command that runs files from both entries supported.

**Repair proof:** two equal-shape entries with disjoint files export from separate commands; a Node/env/incomplete-shard refusal for one keeps the other. Include an empty shard and a single command containing both entries' files.
