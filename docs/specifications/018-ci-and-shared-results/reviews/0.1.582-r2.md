### B2. Proven: another path assignment loses a hooked read and enables a wrong endpoint fallback

Locations: `src/runners/ci-runtime/evidence.cjs:269`, reset at line 289, assignment at line 315; the new fallback consumes its missing evidence at `src/core/ci/reuse-endpoints.ts:81`.

The requested assignment audit found `pending[rel] = value` in `outputOf`. Both its initial value and each flush reset use `{}`. For a root input named `__proto__`, assigning a string hash invokes the inherited setter and creates no own entry. `Object.hasOwn(pending, rel)` does not make that assignment safe. The NDJSON evidence loses the hooked read, and `readRecorded` has no value to retain or mark conflicting.

This writer predates the wave. The regression is the new endpoint fallback: a lost read previously left the test out, while format 6 can now certify it as unread. The format 5 control proves that difference. This is within the expressly requested audit of other path assignments, rather than an unrelated expansion of the review.
