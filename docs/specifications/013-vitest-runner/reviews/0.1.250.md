## Blocker

### B1. Proven: a separate project config leaves the root server, root project and root environments whole

Location: `src/runners/vitest/empty-closed.ts:17` and `:32`.

The task contract requires deleting the own properties of the closed instance's projects, root and project Vite servers, and their environments. `closeEmptied` first awaits `vitest.close()`, then gathers those objects from `vitest.vite` and `vitest.projects`.

With a project loaded from a separate config, the root project is not in `vitest.projects`, and no selected project shares its server. Vitest 5.0.3 closes that root project and sets `vitest.vite = undefined` before its close resolves (`node_modules/vitest/dist/chunks/index.DpLw24bj.js:21503`). Cleanup then has no path to the root server or its environments. It also never includes the root project itself. The root environments retain their module graphs through the native callback roots that this row exists to address.

Reproduction on the pinned candidate:

1. Make a fixture with `package.json` declaring ESM and access to this candidate's `node_modules`.
2. Use these configs and one passing `a.test.ts`:

   ```ts
   // vitest.config.ts
   export default { test: { projects: ["./a/vitest.config.ts"] } };
   // a/vitest.config.ts
   export default { test: { name: "a", include: ["a.test.ts"] } };
   ```

3. Wrap `loadVitest(root).createVitest` to retain the returned instance, its `vite`, `getRootProject()`, and that server's environments. Keep a `WeakRef` to every environment's `moduleGraph`.
4. Open a `VitestAdapter`, run `{ project: "a", path: "a.test.ts" }`, and await `adapter.close()`.
5. Count the saved objects' own properties. Release the saved strong references. Run three major, synchronous, last-resort GCs in separate timer turns, as the new regression tests do.

Observed output:

```text
before {"projects":["a"],"core":"","coreIncluded":false,"rootKeys":30,"environmentKeys":[21,20,17]}
run completed [ 'pass' ]
after {"instanceKeys":0,"rootKeys":31,"coreKeys":25,"environmentKeys":[21,20,17]}
root graphs alive after GC [ true, true, true ]
```

An inline-project control shares the root server and empties that server and its environments. This explains why the new tests, which use the basic fixture, do not detect the separate-server case.

**Fix scope for one worker:** capture the cleanup targets before awaiting close, including the root project when it is absent from `vitest.projects`, the root server, and every selected project server and environment. Vitest exposes the root through the typed `getRootProject()` method. Empty the captured objects only after close resolves. Keep the current behavior for a rejected close and for `abandon`. A target-gathering error must not prevent the close itself. Leave plugin objects intact.

Gathering before close is sufficient for this demonstrated gap **when it also includes the root project**. A throwaway probe wrapped the close with that target snapshot and emptied the snapshot after the original close resolved. The product tree stayed unchanged:

```text
after {"instanceKeys":0,"rootKeys":0,"coreKeys":0,"environmentKeys":[0,0,0]}
root graphs alive after GC [ false, false, false ]
```

**Required first failing test:** extend `test/runners/vitest/empty-closed.test.ts` with “frees the root server of a closed instance whose selected project has its own config.” Use the separate-config fixture above. Assert that the root project, root server and root environments have no own properties after close, and that every saved root and selected-project graph collects after forced GC. Exercise it through recreates and drained slow passes. Keep the existing shared-plugin control and rejected-close guard. The new test must fail on this candidate before the repair.
