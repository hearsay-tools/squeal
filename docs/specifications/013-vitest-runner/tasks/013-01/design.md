# 013-01 design: a touch withholds only what the Vitest instance could have read

Worker, 2026-10-20, board row 013-01 (triage round 8, gh-33, [#33](https://github.com/hearsay-tools/squeal/issues/33)), brief `brief.md`. A draft for the human: once accepted, it amends 013 V5 "Touched files" (task 001-159). Squeal source at `b7f20ee2` (no diff from tag `squeal--v0.1.224` under `src/runners/vitest/`, `src/runners/node-test/` and `src/core/scheduler/`). Probes: Vitest 5.0.3 on Vite 8.3.2, Node 24.21.0, `tsc` 7.0.2, under `/tmp` with `HOME` and `XDG_*` there, one-minute load 8.9 to 22.4 on 24 CPUs; stopped when it reached 41 (`probes/README.md`). No test suite, daemon or build ran in this worktree.

Evidence tags: **verified by experiment** (a probe here), **read in source code**, **read in the store** (a copy of cezar's), **read in spec**, **inferred**.

## Summary

- Every cache V5 names except the dependency optimizer, off since 001-176, registers its read in the module graph of the environment that cached it: a virtual module's declared input is an import of the virtual module, with a transform of its own or not, and a stylesheet's `@import`ed file is an import of the stylesheet (verified by experiment). The optimizer's bundle is in no graph, which is why the narrowing needs it to stay off.
- A touch counts for an instance only when the instance could have read the path: a module of one of its environments names it, or it is one of the inputs the instance reads once and keeps outside any graph (config files and their dependencies, the global setup's closure, its installed lockfiles, and `package.json`, `tsconfig*.json` and `.env*` files). A touch of any other path, such as cezarion's `dist`, does nothing: no run is withheld and the instance is kept.
- Of the run in flight, a counted module path withholds only the test files whose graph reaches it. When none does (a computed `import()`, a setup file), it withholds every file of the run in a project whose graph holds the module. A counted instance input withholds all files. A counted touch replaces the instance at the next call, as today. A touch that does not count is forgotten once every call in flight when it was heard has returned, so no transform that could have read it is still running.
- A same-bytes in-place write can hand a reader empty bytes: 14 to 25 of about 40,000 concurrent reads saw an empty file during three `tsc` rebuilds. When Vite reads in that window and the stamp read before it, the stamp misses it and only the touch catches it, so a touch of a loaded file must keep counting.
- The completion barrier withholds the whole tier for any touched input a key names, so a loaded, keyed file still withholds every file of its tier. Narrowing the barrier to the files whose keys name the path is recommended, as decision D2 for the human.
- Out of this row, for the coordinator: cezar's `.d.ts` and `.js.map` rows are left over from a removed declaration and stay watched forever (a keys row), and node:test and pytest treat a touch as structural, with no withholding (a 003 and 007 row).

## 1. Each cache and where its read lands

`probes/graph-probe.mjs` warms one instance on `probes/make-fixture.sh`'s repository, then walks importers from each path to the test files (verified by experiment, Vitest 5.0.3, Vite 8.3.2):

| Holder of a project file's bytes | How Vite records the read | Reached from the path | Stamp |
|---|---|---|---|
| A plain module, a query variant (`?raw`, `?inline`) | its own module, in the file index | its importers, `raw.txt` to `raw.test` | per module ID |
| A virtual module's declared input, no transform of its own | a module without a transform, imported by the virtual module | `only-input.txt` to `only.test` | at the first check after the load |
| The same input with a transform of its own (wave-13d B1) | the input's one module, imported by its static importer and by the virtual module | `mod.ts` to `plain.test` and `virtual.test` | the input's own; the virtual load's at the first check |
| Processed CSS and its `@import` (wave-13d B2) | the `@import`ed file a file-only module (no ID, `/@fs/` URL) imported by the stylesheet, `?inline` or plain | `base.css` to `style.css?inline` to `css.test`; `base2.css` to `plain.css` to `css-plain.test` | none: it is not loaded through the container's `load` (postcss reads it, inferred) |
| Optimizer bundle through an alias (wave-13d S1) | none: the source is bundled under `node_modules/.vite/vitest/<hash>/deps_ssr/` | optimizer on: no module; off: `aliased.js` to `aliased.test` | none when on; per module ID when off |
| A `\0` ID naming a project file (wave-13c) | a module whose `file` keeps the `\0`, so not in the file index | file index: nothing; an ID scan: `zero.ts` to `zero.test` | per module ID (`sourceOf`) |
| Setup file, `__mocks__` file, `vi.importActual` target, computed `import()` | a module with no importer | no test file, so all of the run | per module ID |
| Lazy `import.meta.glob` | an import of the globbing module | `glob/a.ts` to `glob.test` | per module ID |
| Global setup | a module of the `__vitest__` environment, no importer; its state lives in the instance | no test file | per module ID; a moved one leaves the instance unsure (V5) |
| Config files and their dependencies | none: Vite bundles them itself | none | `ConfigStamps`, before `createVitest` |

Read in source code beside the probe: a package Vitest inlines from `node_modules` is in the graph but is no project file, so it has no stamp and no touch names it, except its installed lockfile; V8 replaces the instance when that changes. Vite's resolver caches every `package.json` it reads (`packageCache`, V2, task 001-81) and its transform reads `tsconfig` compiler options by path (inferred): neither is a module. `.env` files are read once when the config resolves (inferred, Vite's `loadEnv`, not read this session). Worker module caches (`isolate: false`, the VM pools) and `fsModuleCache` (off, 001-157) need no rule of their own: replacing the instance closes its pool. A file a plugin reads without declaring it is invisible here as it is to Vite's own watcher (V5).

Two consequences for the walk (read in source code, `moved.ts:37-57`): `reaches` starts from `getModulesByFile` only, so for a `\0` ID it finds no module and falls back to every file of the run. That is conservative for 001-146's check, but taken as a test of whether the instance loaded a file, it would answer "never loaded". And the ID scan alone (`sourceOf` over `idToModuleMap`, as `cachedModules` does) misses an `@import`ed stylesheet, which has no ID. The start set must be both.

## 2. The narrowed rule

**Which touches count.** For one instance, a touched path is:

- an **instance input** when it is one of the instance's config files or their dependencies (`configFiles`), a file of a project's global setup closure or one of its missing candidates (`recreateTriggers`), an installed lockfile it started with (`#lockfiles`), or any `package.json`, `tsconfig*.json`, `jsconfig*.json` or `.env*` file under the root, matched by name;
- a **module path** when a module of some environment of some project server names it: in the file index (`getModulesByFile`), or by its ID with any `\0` and query set aside (`sourceOf`). A declared input of a virtual module is one, as the probe shows;
- otherwise **not counted**: no module of the instance names it, so no cache of it holds the path's bytes, and no rule here applies. gh-33's `dist` files no Vitest file loads are here.

An instance with a browser-mode project, whose client environment can still bundle (V5), counts every touch as an instance input, as before 013-01.

**Which test files the run in flight withholds.** At the run's end, its heard touches are sorted against its own instance. An instance input withholds every file of the run. A module path is judged per project of the run whose environments hold a module of it. Such a project's files are withheld when their importer walk reaches a module of the path from the start set above. When none of them reaches it (a computed `import()`, a setup file, `__mocks__`, `vi.importActual`), every file of the run in that project is withheld, as 001-146 does for all of the run. A project whose graphs hold no module of the path loses nothing, since its own containers never served those bytes (V5, review wave-13b B2). 001-146's `mayHaveRun` falls back to every file of the run instead, and starts from the file index only. It stays as it is, since stamps are out of scope; it could share this walk later. The reason names only the counted paths. The scheduler's handling stays as amended 2026-10-17 (011-06): withheld files are re-queued, counted toward the discard limit, then `unknown`. A run's sorting at its end is sound: the run awaited every transform it executed, so their edges are recorded when it ends (inferred).

**When the instance is replaced.** As today, `invalidate` records a touch at once (`adapter.ts:288-294`). Each later call sorts the pending touches against the current instance before using it. A touch that counts makes the call replace the instance in an exclusive section (`#instance`, `adapter.ts:234-252`), as any touch does today. A touch that does not count stays pending until every call that was in flight when it was heard has returned. Sorted again then, it is forgotten if it still does not count.

The wait matters. A stylesheet compiled from transient bytes records its `@import`ed file only when its transform completes, and a virtual module records its declared input only after its load returns (inferred). A touch sorted while such a transform runs would be forgotten, and the transform cached afterwards. Transforms run only inside the adapter's calls (runs and the runner part, V7), so once the calls in flight at the touch have returned, no transform that began before it is still running. A touch that does not count takes no exclusive section, so the runner part no longer waits for the run in flight on a build's touches, as it does today.

**What the rule leaves alone.** Stamps (001-146) and keys are unchanged. The refinement still re-fetches the closures that name a touched path. The slow instance still hears a touch at once. A touched path that no instance counts costs its batch's reconciliation and nothing in the Vitest adapter, against a recreate and a cold transform of every closure today (about 2 s on this repository, task 001-159 notes).

**The completion barrier (decision D2).** The barrier (task 001-168, `scheduler.ts:622-634`) re-stats each tier's key inputs and withholds the whole tier when one was touched, even when the adapter heard the touch during the run. For a module some test file imports statically, that file's key names it, so with the barrier unchanged a touch of it still withholds every file of the tier, and the adapter's narrowing shows only for touches no key of the tier names, gh-33's among them. Content changes are already judged per file (`tiers.ts:551`). Narrowing the barrier the same way, to the files whose stability inputs name the touched path, gives node:test and pytest an exact rule: they hold no cache across files. For Vitest it gives up one coincidence: a file that read the path only through a cache its key does not name (a virtual module's declared input, a stylesheet's `@import`; the closure walk follows neither, `graph.ts:117-163`, `:225-239`, read in source code) is withheld today only when a sibling in its tier keys the path and the batch arrives after the run, and V5 already accepts the same miss when no key in the tier names the path. Wave-13e B2's regression declares the input for both files (`touched-late.test.ts`, `inputs: ["src/mod.ts"]`) and still holds. Recommendation: narrow the barrier too, in its own commit of the code row.

## 3. A same-bytes write in place

`tsc` truncates and rewrites in place (verified by experiment, `probes/tsc-read.mjs`). Three same-bytes rebuilds of 1,200 outputs, each read in a loop meanwhile: 14, 19 and 25 of about 40,000 reads saw an empty file (`.js`, `.js.map` and `.d.ts` alike). Every file ended with its bytes, its inode and a new mtime. A tighter loop of 2,000 in-place rewrites of one 256 KiB file had 2,227 of 2,980 concurrent reads see other bytes, 1,289 of them empty and the rest partial (`probes/inplace-read.mjs`). Vite transforms an empty module without complaint, so its transform of nothing is cached (inferred).

What the stamp sees (read in source code, `stamp.ts:22-34`, `sources.ts:292-300`): it stats the file, hashes its bytes, then Vite reads.

| Reads in the empty window | Stamp holds | Check after the write | Caught by |
|---|---|---|---|
| Stamp and Vite | the empty bytes' hash | stat moved, re-hash differs | the stamp (001-146) |
| Vite only (the window falls between the stamp's read and Vite's) | the full bytes' hash | stat moved, re-hash equal: the stamp is refreshed | the touch alone |
| Neither | the full bytes' hash | equal | nothing to catch |

So a touch of a loaded module must keep counting. Under the narrowed rule it does: the module is in the graph, its test files are withheld and the instance is replaced. V5's open interval between the stamp's read and Vite's is this case. When the batch arrives after the run, the barrier catches it if a key names the path (unchanged, or per file under D2). If no key names it, only the replacement at the next call protects later runs, as today.

## 4. Why `.d.ts` and `.js.map` reach the adapter

Read in the store (a copy taken 09:38, `probes/store-dist-rows.cjs`): 6 cezar worktrees each hold 281 to 282 `.d.ts`, 253 to 254 `.js.map` and 254 to 255 `.js` rows under `packages/cezar/dist/`. Closures name only `.js` paths and resolution candidates there, all from node:test `test:package` files. Revisions with `.d.ts` content changes exist from 2026-10-14 (`probes/store-dist-revisions.cjs`), so the rows were hashed and watched.

The mechanism, read in source code and cezarion's history. Until 0.1.220, an ignored path a declaration selected for a slow file was a declared input (004-47's "ignored files only for a slow file's declared artifact"). Cezarion declared `packages/cezar/dist/**` for its slow `packages/cezar/test/e2e/*.test.ts` until `b9883c99e` (2026-10-19, "drop test:package project from squeal config"), so every `dist` file was hashed and watched. Since 004-81 (0.1.220), `Keys.bootstrap` drops a cached ignored path a declaration still selects and keeps every other one as an extra file (`keying.ts:167-170`). `#release` lets go of only the paths a closure revived (`keying.ts:425-441`). So once the declaration is gone, a worktree's leftover rows stay watched for the life of its store, though nothing names them, and each rewrite with the same bytes is a touch. Which of the two fed the 0.1.224 incident's touches is not determined (inferred: the leftovers, since the declaration was removed the day before).

Should they reach the adapter? The touch fans out to every adapter (`composite-runner.ts:71-72`) and costs a reconciliation of about 800 paths per build. Under the narrowed rule they count for no Vitest instance. That they stay watched at all is a keys defect: bootstrap, or the first `#release` after it, should drop a cached ignored path nothing names (closure, environment, lockfile, observed read). That is 011 C2 and out of this row's scope (keys); recommended as a triage item of its own.

## 5. node:test

No touch rule of its own, and none is needed for results: each node:test run spawns fresh processes that read the disk, so no cache carries a touched file's transient bytes past a run, and the barrier covers a run's own interval. But `graph.invalidate` treats every kind but `change` as structural (`graph/graph.ts:96-104`), a touch included. It clears the resolver, resets the touched paths' parses and rebuilds the graph over every test file, and the project relists its test files (`adapter-project.ts:97-103`). This code is from 2026-10-07; `touch` arrived on 2026-10-09 (001-159). pytest relists on every kind but `change` too (`pytest/adapter.ts:221-222`). The cost of an 800-path touch batch there was not measured. Recommendation, outside this row: a touch is a `change` to those graphs, which re-parses the file (a parse taken during the transient window is corrected) without a rebuild or a relisting. It is a row for 003 and 007.

## V5 draft text

To replace the **Touched files** bullet of 013 V5, from its first sentence through "the next call of either lane replaces the instance: every project's and environment's transforms and module graph and the global setup's state go", and the sentences about a path the run itself wrote:

> - **Touched files** (task 001-159; reviews wave-13 to wave-13d; narrowed by task 013-01, gh-33). Four reviews each found one more cache that can keep a project file's transient bytes when it changes and changes back within one batch: a virtual module's declared input with a transform of its own, processed CSS holding what it `@import`ed, and the dependency optimizer's bundle of a source reached through an alias. All have the same trigger: a touch no revision names (D2). Each but the optimizer, off since task 001-176, records its read in the module graph of the environment that cached it: the declared input as an import of the virtual module, the `@import`ed file as an import of the stylesheet (013-01, Vitest 5.0.3 on Vite 8.3.2). So a touch counts for an instance only when the instance could have read the path. It counts when a module of some environment names it, in Vite's file index or by its ID with any `\0` and query set aside. It counts too when it is an input the instance reads once and holds outside any module graph: a config file or one of its dependencies, a file of a global setup's closure, an installed lockfile the instance started with, or a `package.json`, `tsconfig*.json`, `jsconfig*.json` or `.env*` file under the root. A run under the instance when a counting touch is heard makes some of its files not completed, with a reason naming the counted paths. These are the files whose import graph in their own project reaches a module of a counted path. When none of a project's files reaches it (a computed `import()`, a setup file, `vi.importActual`, a `__mocks__` file), all of the run's files in that project, if its environments hold a module of the path. The rest of the bullet stands, except under decision D2, where its barrier sentence reads: "...and a path written since whose bytes hash as before withholds the test files whose keys name it, as a content change discards them, their files `unknown` with a reason naming the path...". 011 C2's "a touch found there, whose batch has not arrived, withholds the run" then reads "...withholds the files whose keys name it". Its cost sentence becomes: "Cost: a recreate and a cold transform of every closure, once per batch with a counting touch; none for a batch whose touches no instance could have read."

## Rejected options

- **Keep 001-159 as it is.** Every touch withholds every file of the run and replaces the instance. It is safe but makes gh-33: a build's output, which no Vitest file loads, withholds every edit's run, and a second build leaves the files `unknown`.
- **Withhold only the reaching files, but replace the instance on every touch.** This keeps a recreate (about 2 s plus cold transforms here, more on cezar) per build, and protects later runs from an undeclared plugin read while leaving the run in flight exposed. That is inconsistent, and an edit of the same file is not checked either (V5).
- **Sort by stamps instead of the graph.** An `@import`ed stylesheet and a virtual module's declared input have no stamp of their own until a check, and config files none at all (section 1).
- **Sort by path class: ignore gitignored paths, or paths no closure names.** Gitignored build output can be loaded through Vite (the probe's `dist/loaded.js`). Closures name neither a virtual module's declared input nor an `@import` (`graph.ts:117-163`, `:225-239`).
- **Sort when the touch is heard, in `invalidate`.** A transform in flight records its `@import`s and declared inputs only when it completes (inferred), so a touch heard meanwhile would be forgotten while the transform caches transient bytes. Instead, the run sorts at its end, and an uncounted touch is forgotten only once the calls in flight when it was heard have returned.
- **Sort inside an exclusive section at the next call.** This is sound, since no call is in flight inside one, but every build's touches would then make the runner part wait for the run in flight, as the recreate does today (V7).
- **Invalidate a counted module in place instead of replacing the instance.** 001-159 replaced because nothing else dropped the global setup's state and the optimizer's metadata. Both are now handled: the global setup is an instance input, and the optimizer is off. Vite propagates an invalidation to importers that do not import statically (Vite's `invalidateModule`, not read this session). It is deferred, not rejected: a cost row, if touches of loaded files turn out to be frequent.
- **Fix gh-33 in keys only, by releasing leftover extras.** That removes cezar's stray touches but not the blast radius of a touch of a loaded file. It is recommended as its own row (section 4).
- **Narrow the barrier through a runner query** (a new `RunnerAdapter` method asking which files may have read a path). It is exact for Vitest, but it changes 011 C14 for one coincidence (section 2).

## Decisions for the human

- **D1.** Accept the narrowed rule: a touch counts only when the instance could have read the path, it withholds the reaching files, and it replaces the instance only when it counts. Default: yes.
- **D2.** Narrow the completion barrier to the files whose keys name the touched path, in the same code row. Default: yes, as its own commit. With no, the adapter's narrowing shows only for touches no key of the tier names, gh-33's case included.
- **D3.** Count `tsconfig*.json`, `jsconfig*.json` and `.env*` as instance inputs by name, though their edit does not replace the instance today. This is conservative, and a touch of them is rare. Default: yes.

## Limits

One Vitest and Vite pair (5.0.3, 8.3.2), one project, the `ssr` and `__vitest__` environments. A Vite that stops recording `@import`s in the `ssr` environment would make the narrowing miss them, which regression 6 pins. Browser mode was not probed. The rule itself is not built or run: its cost is inferred from 001-159's measurement. The cezar store copy holds worktrees of several Squeal versions, and which rows fed the 0.1.224 incident is not determined. The in-flight race of section 2 is inferred from Vite's transform order, not reproduced.
