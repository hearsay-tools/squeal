## Remaining blocker

### B4. Restoring a deleted config dependency does not recover the live Jest adapter

**Proven on Jest 29.7.0 and 30.5.2.** `src/runners/jest/environment.ts:76` and `:85`; consumers `src/runners/jest/adapter.ts:130` and `:147`.

The first review's B4 fix requires: “Rebuild the project when they change, including recovery when a dependency caused config loading to fail.” Spec 028 D2.3 includes the config file chain in environment identity. Wave 3.5 also requires a failed config's imported dependencies to remain watched so their repair reopens the project.

The successful-read case now works. The failure path still discards a dependency after deletion. The child returns only dependency paths that currently pass `statSync(...).isFile()`. A failed reread replaces the adapter's watched set with that reduced set. Restoring the helper then matches no watched path, so `invalidate()` returns without reading the restored config. Tests stay unavailable until another watched file changes or the adapter restarts.

Reduced reproduction using `createJestAdapter` directly, with real installed Jest:

```js
// jest.config.cjs
module.exports = {
  testEnvironment: "node",
  testMatch: ["<rootDir>/*.test.js"],
  ...require("./options.cjs")
};
// options.cjs
module.exports = { testTimeout: 1000 };
// a.test.js
test("ok", () => {});
```

1. Open a live adapter. Its environment includes `options.cjs` and lists `a.test.js`.
2. Delete `options.cjs`; call `invalidate([{path: "options.cjs", kind: "delete"}])`.
3. Restore it with `module.exports = { testTimeout: 9000 };`.
4. Call `invalidate([{path: "options.cjs", kind: "add"}])`; compare the live adapter with a new adapter on the same files.

Actual probe output, with identical results on both majors:

```text
Jest 29.7.0 / 30.5.2:
before: watched(options.cjs) = true
delete: recreatedProjects = [app]
broken: runnerVersion = unavailable; watched(options.cjs) = false
restore: recreatedProjects = []
live: runnerVersion = unavailable; testFiles = []
fresh: runnerVersion = 29.7.0 / 30.5.2
fresh: testFiles = [{ project: app, path: a.test.js }]
```

This is the same B4 dependency lifecycle and recovery contract, not a separate architecture concern. The added regression repairs a helper that still exists and throws. It does not delete and restore the helper, so it passes while this failure remains.

**One-worker fix:** retain the last known config dependency paths while a config is unavailable, including missing paths whose recreation can repair it, or use a bounded failed-config retry rule that handles their recreation. Ensure recovery refreshes the resolved config, test listing and graph and reports project recreation. Add both-major delete/restore regressions comparing the recovered live adapter with a fresh adapter. Keep unrelated source edits from repeatedly reopening a healthy project. Rebuild the shipped bundles after the source repair.
