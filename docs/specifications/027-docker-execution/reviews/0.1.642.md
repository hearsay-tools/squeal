## Blockers

### B1. Proven, P1: the empty-editable exception is cached after it stops being safe

**Changed boundary:** `src/runners/pytest/environment/states.ts:121`, admitting an outside directory when `buildStageEmpty` returns true.
**Callers:** `src/runners/pytest/adapter.ts:245` and `src/runners/pytest/adapter-run.ts:32`.

Spec 027 D3.4 requires: "Any outside editable that actually resolves Python code outside the worktree ... continues to be refused". Vision principle 2 forbids old state from posing as current truth.

The new exception depends on the contents of directories outside the worktree. Those contents are absent from `EnvironmentFiles` and its fingerprint. Once an empty editable is admitted, `recheck()` takes its unchanged-fingerprint shortcut. The run's before/after checks use that same incomplete fingerprint. Adding outside source can therefore leave the project `ready`, with its old environment key. A later test run can import the new outside module without the required refusal.

**Reproduction through public interfaces:**

1. Create two sibling temporary directories outside any git checkout: a worktree and a build-stage directory. Give the worktree a synthetic `.venv`, an executable interpreter-query stub, and pytest's package marker. Give the build stage only `pyproject.toml`.
2. In the environment, write editable `direct_url.json` pointing at the build stage, a valid `RECORD` listing `_app.pth`, and `_app.pth` containing the stage path.
3. Open `createPytestAdapter`, read `environment()`, and confirm `ready`.
4. Add `external.py` to the stage without changing any environment metadata. A fresh `environmentState` correctly returns `editable-outside`.
5. Call the existing adapter's `recheck()` and `environment()`. It still reports `ready` and the same resolved configuration, hence the same environment key inputs.

The probe used a controlled admission clock and no real pytest execution. Output:

```text
editable-probe {"initial":"ready","freshState":"editable-outside","recheck":{"recreatedProjects":[]},"retainedState":"ready","sameKey":true}
```

**One-worker repair:** make the outside-editable admission condition part of revalidation at quiet rechecks and before/after execution. A directory or finder that ceases to meet D3 must invalidate admission, recreate the project, and withhold results. Keep empty-stage admission and existing worktree-independent keys. Cover source appearing after admission, source appearing during a run, and a formerly empty finder changing its targets. A one-shot `environmentState` test cannot cover this seam.

### B2. Proven, P2: slot templates do not expand in PATH or PYTHONPATH

**Changed boundary:** `src/core/runner-host/slots.ts:135`, called by `src/runners/pytest/run/run.ts:223`.
**Composition:** activation in `src/runners/pytest/environment/hash.ts:55`, and runtime-path addition in `src/runners/pytest/run/run.ts:113`.

Spec 027 D2.1 says: "Values in `project.env` may contain `{slot}` ... `{slot0}` ... and `{worktreeSlot}`". Row `027-02` promises expansion in `project.env` without a variable-name exception.

`expandedVariables` expands a variable only when its final value exactly equals the original project template. Squeal itself changes two values first: `runEnvironment` prefixes `PATH` with the environment's `bin`, and `runPytest` appends its runtime directory to `PYTHONPATH`. Equality then fails for both variables. This is Squeal's composition, not an override from a different source.

**Reproduction:** run one batch with an executable stub that captures its environment, using the real `runEnvironment` and `runPytest` interfaces and:

```json
{
  "PATH": "/usr/bin:/tmp/tools/{slot}",
  "PYTHONPATH": "/tmp/modules/{slot}"
}
```

The stub receives the literal `{slot}` in both values, alongside Squeal's normal prefix/suffix:

```text
template-probe {"pathStillLiteral":true,"pythonpathStillLiteral":true}
```

A test that starts a slot-local helper, or imports a module from a slot-local generated directory, cannot use the configured location.

**One-worker repair:** expand the effective project values before adding activation and recorder paths, while preserving explicit child-environment precedence. Build the final environment per acquired slot. Keep hashing the unexpanded templates. Add a subprocess assertion for `PATH` and `PYTHONPATH`, including the retained environment `bin` and pytest recorder directory, plus an override case. The current Redis/JSON assertions do not exercise this composition.
