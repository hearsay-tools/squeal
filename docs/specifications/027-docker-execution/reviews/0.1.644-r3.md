## Remaining blocker

### B4. Creating a missing directory-import dependency does not recover the live adapter

**Proven on Jest 29.7.0 and 30.5.2.** Cause: `src/runners/jest/environment.ts:91` (`missed`) and `:142` (failed CJS resolution). Consumer: `src/runners/jest/adapter.ts:154` (exact watched-path match).

Round 2 requires: “Rebuild the project when they change, including recovery when a dependency caused config loading to fail.” It also requires retaining “missing paths whose recreation can repair it” or a bounded failed-config retry rule. Spec 028 D2.3 includes the config file chain in environment identity. This case is the same missing imported-dependency recovery contract.

When a worktree config calls `require("./options")`, Node can resolve it as `options/index.js`. If that file is missing at startup, the new `missed()` records `options` and `options` plus filename extensions. It never records `options/index.js`. An existing `options/` directory is then excluded because it is not a file. With no successful prior read, the adapter has no earlier dependency set to retain. Adding the valid helper matches no watched path, so `invalidate()` returns before reopening the config. The live project stays unavailable with no tests even though a new adapter reads it.

Reduced reproduction, using the public adapter with either installed Jest version:

```js
// package.json
{ "name": "app", "private": true }

// jest.config.cjs
module.exports = { testEnvironment: "node", ...require("./options") };

// b.test.js
test("ok", () => {});
```

1. Create an empty `options/` directory. Leave `options/index.js` absent.
2. Open `createJestAdapter` with project `{ name: "app", config: "jest.config.cjs", include: [], exclude: [], args: [], env: {} }` and this disposable project as `root`.
3. Confirm `environment()[0].runnerVersion === "unavailable"` and `testFiles()` is empty.
4. Create `options/index.js` containing `module.exports = { testTimeout: 9000, testMatch: ["<rootDir>/b.test.js"] };`.
5. Call `invalidate([{ path: "options/index.js", kind: "add" }])`.
6. Compare the live adapter with a fresh adapter on the same files.

Actual independent output, identical except for Jest version:

```text
Jest 29.7.0 / 30.5.2:
watched paths under options:
  options.cjs, options.cts, options.js, options.json,
  options.mjs, options.mts, options.ts
add options/index.js: recreatedProjects = []
live:  runnerVersion = unavailable; testFiles = []
fresh: runnerVersion = 29.7.0 / 30.5.2
fresh: testFiles = [{ project: app, path: b.test.js }]
```

The first matrix also reproduced this when the directory itself was initially absent. The focused confirmation pre-created the empty directory, so recovery cannot depend on receiving a directory-add event. The adapter receives the concrete file-add event it must handle.

**One-worker fix:** make the failed-config dependency rule cover Node's directory resolution, or retry additions under an unresolved local import path while the config is unavailable. Keep unrelated edits from reopening a healthy project. Add both-major missing-at-start directory-import regressions that compare recovered config, listing and graph with a fresh adapter. Rebuild the shipped bundles after the repair.
