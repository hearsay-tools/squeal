# 020-27 worker notes

Facts found while fixing review 0.1.443-r2 S1 and S2. They are not in the code comments.

- **How the Vitest process tells its workers.** Vitest 5.0.3 builds each worker's environment from `process.env` when the pool runs files (`{...process.env, ...options.env, ...config.env, ...project.config.env}`), after the `start` wrap in `vitest-ci.cjs`. A variable set in the `start` wrap reaches forks, threads and VM pools. `children.cjs` keeps other variables when it adds the hook to a child's env. Vitest 4.1 was not checked: only 5.0.3 is installed, and the 4.1 fixture is a stub that has no `configOverride`.
- **Do not change `SQUEAL_CI_RECORD` after preload.** `children.cjs` reads it once at preload. A child whose value differs is "foreign", and that withholds every path, which leaves the whole part out of the export.
- **No variable for "no provider" (R1, review 0.1.444 B3).** The first fix used `SQUEAL_CI_NO_PROVIDER=1`. A project that allow-listed that name by its literal got it in the run file's `env`, so the part descriptor named it and `ci export` refused the part. Any variable the Vitest process sets has this risk, because the run file's `env` is read from `process.env` at `onTestRunEnd`. The fact now travels in a file: `watchWorkers(raw, providerRuns)` writes `<raw>/inspector/<pid>.no-provider`, and `installWatch` returns when the file of its owner exists (owner: `process.ppid` for a forked worker, `process.pid` for a thread). `readWatch` reads only `<pid>-*.ndjson`, so the file is never read as a log. Evidence skips the run's own directory, so the write is not evidence. With a provider, `watchWorkers` removes a file of its pid left by an earlier process (pid reuse in one command).
- **What the file does not reach.** A process that a test worker starts has the worker as its parent, so it finds no file and installs the watch. It has no `__vitest_worker__`, so it writes nothing. The variable reached such grandchildren; the file does not. Before 020-27 they installed the watch too.
- **Vitest replaces `process.getBuiltinModule` in its workers.** In a fixture test file it is not native, also with no Squeal watch installed. To see whether the watch is installed, read `globalThis.__squealCiInspector`. The identity check is done only in `test/runners/vitest/ci-inspector-watch.test.ts`, in a plain Node process.
- **"Provider runs" is read from Vitest's config.** It is true when `config.coverage.enabled` is true or `configOverride.coverage.enabled` is true (`providerRuns` in `vitest-ci.cjs`). A `failed` header from a provider that did not start now has no `inspector` field (`withWatch` skips it). The static closure check in `ci export` still applies to that part.
- **No watch in the Vitest CLI process (R1, review 0.1.444 S1).** Vitest sets `__vitest_worker__` only in its workers (`provideWorkerState` in `base` and `vm` chunks of 5.0.3), so the watch in the CLI process could never log. The preload skips it in any main thread whose main script's name starts with `vitest`, the cheap first check of `vitestPackage`. It reads no file for that: `installWatch` must run before `installEvidence`, and `vitestPackage`, which reads files, stays after it so its reads stay in the evidence as before. Vitest's worker entries are `workers/forks.js`, `threads.js`, `vmForks.js`, `vmThreads.js`, so no worker matches. A `globalSetup` runs in the CLI process with its globals (probed: a preload global is visible there), so the integration fixture's `controller.ts` fails the run if the CLI process watches.
- **`process.getBuiltinModule` is a JavaScript function in Node.** Its `toString()` has no `[native code]`, so an identity check needs the original captured in the same process. The preload test checks the hooks by what they log instead.
