## Blockers

### B1. Proven: cancelling the gate leaves its prepare command running past its timeout

**Location:** `src/core/code/gate/prepare.ts:187` and `:208`; the signal crosses the new boundary at `src/cli/code-gate-relaunch.ts:117`.

**Contract:** D15.3: the command runs "inside D3.4's one budget; `timeoutSeconds` caps it too." The vision's resource-boundary rule requires enforceable timeouts. The review brief also names process-group cleanup and relaunch signals.

`runCommand` starts a detached process group. Only the live collector's timer or the prepare child's `exit` event kills it. The JSON parent forwards SIGTERM to the collector alone. The collector exits by the default signal action, which removes the timer without killing the detached prepare group. SIGINT has the same ownership gap.

**Reproduction at the shipped bundle: create a scratch git repository** with one node:test entry named `node`, including `test/*.test.mjs`, and this declaration at its base:

```json
{"prepare":{"command":["/absolute/path/to/node","prepare.cjs"],"timeoutSeconds":0.5}}
```

Use this command body:

```js
const fs = require('fs');
fs.writeFileSync('prepare.pid', String(process.pid));
setTimeout(() => fs.writeFileSync('after-timeout', 'still running'), 1500);
setTimeout(() => {}, 30000);
```

Commit the config, command and a passing test at branch `base`. Edit the test callback's return value so it is selected. Start `node <candidate>/plugins/claude-code/dist/cli/squeal.mjs code --base base --json --timeout 2`. When `prepare.pid` exists, send SIGTERM to that CLI PID. Wait for the CLI to exit, then wait 1.7 s and inspect the recorded prepare PID and marker.

Actual output:

```text
gateExit: 3
stdout: ""
stderr:
squeal code: node:test: 1 test file to run (tests 1)
squeal code: node:test entry "node": prepare: /home/agent/.nvm/versions/node/v24.22.1/bin/node prepare.cjs
squeal code: the gate's process ended on SIGTERM without a whole report, so stdout stays empty
prepareAliveAfterOwnTimeout: true
prepareWroteAfterGateExited: true
```

The timeout no longer caps the command. An interrupted build can keep changing the tree after the gate has returned.

**One-worker fix:** give the active prepare group a cancellation owner in the collection process. On SIGINT/SIGTERM, terminate its group before allowing the collector to settle or exit. Remove lifecycle listeners when the command settles. Preserve the bounded close grace and the existing empty-stdout/exit-3 behavior when no complete report exists. Add a real CLI regression that cancels during prepare and checks both its PID and an ordinary descendant, plus a delayed write. Cover both JSON and text entry paths. Do not claim a SIGKILL guarantee.

### B2. Proven: the pre-run print claims global setups run when all files come from existing evidence

**Location:** `src/core/code/gate/collect.ts:188`, before the stored-evidence lookup at `:195`; `src/core/code/gate/prerun.ts:133` uses that unfiltered selection to name setups.

**Contract:** D14.4 requires the print to name "the projects whose global setup will run, the root's when it has one." The vision also requires status and evidence claims to match the known state. D11.7 and D13 permit selected files to come from stores or parts with no run.
