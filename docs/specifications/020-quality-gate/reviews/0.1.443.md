### B1. Proven: yielded project coverage exports runtime inspector users

Location: `src/core/ci/export.ts:140-142`, with the yield path in `src/runners/vitest/ci-runtime/coverage.cjs:40-44`.

D19.6: "`ci export` leaves out a test file whose closure imports `node:inspector` whenever the shard ran with any coverage provider, the project's or Squeal's." D13.4 gives the reason: an inspector test can see the provider, while imported passes may cross a coverage difference.

The new exclusion reads only `closure.packages.builtins`. That is the export runner's static import walk, before the part's observed paths are added. When collection yields, `offCoverage.end()` returns no per-file inspector marks. Thus a runtime inspector user with no static `inspector` package entry passes both exclusions. This is a proven break of the row's D19.6 done-when, including its yielded case. The probe proves the wrong inclusion; it does not claim that its harmless assertions themselves cause a false pass after import.
