## Blockers

### B1. Proven: restored inputs let a kept pass certify bytes the run did not test

Location: `src/core/code/gate/keep.ts:158`, especially the filter at line 169.

Contract: D17.3 says a daemon can read a kept result “because the key means the same run.” The vision says, “An old result never gets to pose as the current truth.” The daemon's completion barrier in `scheduler/stability.ts` withholds a file when a keyed input was written during its run and ended as it was.

`changedSince()` returns both `changed` and `touched`. The keeper rejects only `changed`. If an input changes temporarily, a test reads those temporary bytes, and the input is restored before the run ends, `changed` is empty and `touched` names the input. The keeper stores the pass at the original key. That result is then reusable as current even though a fresh run at those original bytes fails.

Reproduction used the committed `plugins/claude-code/dist/cli/squeal.mjs`, with no source instrumentation:

1. Make a small git repository under the ignored gate fixture scratch directory, so Vitest resolves from this checkout. At the base, enable complexity and coverage, set `coverage.exclude: ["test/**"]`, `observe.runtimeInputs: false`, and `inputs: ["data/input.txt"]`. The input contains `bad\n`. Vitest selects `test/**/*.test.ts` with `maxWorkers: 1`.
2. On the feature branch, change `double(x)` from `x * 2` to `x + x`. Add a test that calls `double(2)`, reads the declared input, and expects `good\n`. Its callback waits at two handshakes with a driver outside the repository: just before the read and just after the read. The handshakes use an external directory, not a keyed input.
3. Start `node <candidate-cli> code --base main --json --timeout 60`. After the test reaches the first handshake, the driver writes `good\n` and lets it read. At the second handshake, the driver restores `bad\n`, then lets the test finish.
4. Run the same gate again without changing the input. Finally remove only this probe repository's `.git/squeal` directory and run a fresh control, again without changing the input.

Actual output, reduced to the relevant report fields:

```text

same bytes again:   exit 0, verdict pass, from {test/input.test.ts: store}, failed []

```

The explicit declared input makes this independent of observed-set growth. Observation being off is a supported policy; the daemon still applies its stability barrier to declared inputs.

Worker-sized fix: give keeping the daemon's completion-barrier rule for both changed and touched keyed inputs. Reject the affected file when either set intersects its stability paths. Add a deterministic restored-input test with a steady sibling that remains keepable. Assert that neither the gate nor a later daemon can adopt the affected result. Keep the existing key format; do not solve this by assigning a new meaning to an old key.

### B2. Proven: several node:test projects overwrite one another's pending keep state

Location: `src/core/code/gate/keep.ts:93`, line 118 and lines 123–125. Caller: `collect.ts:457–463` resolves every runner's stored lookup before any runner runs.

Contract: D17.3 says, “The gate writes each test file it ran to completion,” and the row's done-when requires a second run to read the completed files and run only the missing files.

`GateRun.runner` identifies the kind, `vitest` or `node-test`, not one opened adapter or project. Every node:test entry calls `expect("node-test", ...)`. The last entry overwrites the earlier one in `#pending`. When the first entry ends, `ran()` takes and deletes that last entry's state. Its files do not match the first entry's completed files, so nothing is kept. Later entries find no pending state. With two missing entries, neither is kept.
