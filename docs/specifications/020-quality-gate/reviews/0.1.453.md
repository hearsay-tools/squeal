## What fits

- **Honest state and text.** The diff leaves the verdict, report, exit code,
  `KEEP_BUSY_BOUND_MS = 30_000`, and all keeper message templates unchanged.
  `describeHolders` still says the holder is not known when no holder is
  found. It never names a waiter as the holder.
- **Bounded retry.** `src/core/store/lock-holders.ts:73` sets four reads;
  lines 98 to 103 make one initial read and at most three more. Each retry
  requests a 25 ms synchronous pause: 75 ms total requested sleep per
  lookup. `namesNoHolder` treats both an empty list and a waiter-only list
  as no holder. A holder stops the loop immediately. An unreadable source
  returns `undefined` and stops without another pause, including after an
  earlier readable miss. Non-Linux returns before constructing the source.
  These are read and sleep bounds, not a hard wall-clock promise about OS
  scheduling or synchronous `/proc` I/O.
- **Transaction seam.** `keepFile` awaits the writer and the existing busy
  backoff before `StoreWait.giveUp` reaches `holderOf`. The local writer's
  synchronous transaction returns or rolls back before it returns `busy`.
  The daemon writer returns `busy` after its request reports refusal; its
  transaction has also ended. `StoreWait.spent` runs after `keepFile` returns
  `spent`. Neither lookup runs inside those transactions. The first lookup
  runs once per `StoreWait`, the terminal lookup at most once; a flush adds
  at most two sets of 75 ms requested sleep. `giveUp` checks the original
  busy clock again after the first lookup, so the pause does not restart
  the 30 s bound. The terminal note can add its 75 ms after exhaustion.
- **Descriptor seam.** The new entry point stays inside `lock-holders.ts`
  and delegates to `holdersFrom` with the existing `createProcSource`.
  `fileKey` uses `statSync` on `-shm`; `existsSync` handles an absent key.
  File reads are `/proc/locks` and `/proc/<pid>/cmdline`. No descriptor of
  `store.sqlite`, `-wal` or `-shm` is opened or closed by the lookup. The
  general `lockHolders` API keeps its single-read behavior for other callers.
- **Tests.** The new tests exercise a missed first read, waiter-only first
  read, immediate holder, exhaustion, unreadable source, non-Linux, and a
  real SQLite holder. Existing keeper tests check the holder-bearing note,
  successful saving after release, exhaustion, and changed-input exclusion.
  All three relevant files passed in the independent run above.
- **Scope and bundles.** Product source changes are confined to the helper
  and `holderOf`. The four CLI bundles carry the same retry and call change;
  their `ps` bundles add only the shared pause buffer initializer. The rest
  of the bundle commit raises version metadata to 0.1.453 and updates runtime
  hashes. Rebuild equivalence is left to CI, not claimed from diff inspection.
