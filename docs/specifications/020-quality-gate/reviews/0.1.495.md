## Blockers

### B1. An early pass drops completed files when the worktree lock is only temporarily unavailable

**Proven.** `src/core/code/gate/keep-pass.ts:121`, with `chooseWriter` in the same file and `writerFor` in `keep-here.ts`.

D17.5: "a busy store, or any failure, hands the files back, to be tried again after a pause". Row 020-59 requires the keeper to save completed files while the other runs go on. Only the files still queued after the report take the final bounded write path.

When another process holds the per-worktree singleton lock, and no fresh serving-daemon record exists, `writerFor` returns `null`. The early pass then returns `left: []`. It has already removed the run from the keeper's queue, so that completed file can never be retried, including at `flush`. Another gate's early write pass can hold this lock without publishing a daemon record. A daemon starting or stopping can also leave this window.

Reproduction, using `test/code/gate/keep-busy-kit.ts`:

1. `freeStore()` creates the fixture. Construct a `Keeper` with the kit's stable `inputs()`, complexity enabled, and a fixed `head` callback.
2. Take `acquireDaemonLock(lockFileFor(commonDir, worktreeIdFor(root)))`. There is no daemon record.
3. Expect `A` at `KEY_A`, then call `keeper.ran` with `files: [A]`, `report([A])`, and `RECORD` mapped by `testFileId(A)`.
4. Allow the early pass to run for 150 ms. Release the lock before `keeper.flush()`.
5. Expect `resultsAt(commonDir, KEY_A)` to be 1.

Actual output:

```text
results: 0
notes: [
  '1 completed test file was not kept in the stores: a daemon runs in this worktree, and it keeps its own'
]
AssertionError: expected +0 to be 1
```

The note also asserts a daemon exists when the fixture has none. The old keeper did no early write; with the lock released before its final flush, this file reached the write path.

**Worker-sized fix:** retain the entire unwritten run, including grown-key files and pending reads, when an early pass has no usable writer. Try it again through `EarlyWrites`; do not emit or retain a terminal daemon note for that early failure. Revalidate inputs and the merge hold on the later attempt. The final pass may use the existing compatibility/refusal behavior. Add a test with the lock released before the report and one with an input changed before the retry.

### B2. A stored-only rerun says no file will run and omits its global setup

**Proven.** `src/core/code/gate/stored.ts:133` and `src/core/code/gate/lanes.ts:153`. These new paths mark stored evidence for execution after the existing pre-run summary has treated every known file as unrun (`prerun.ts:180`, `:186`).

D14.4 requires, before the first run, "the projects whose global setup will run, only for files that will run, the root's when a Vitest run remains". The vision requires honest state and provenance. D3.4's accepted exception excludes stored reruns from the duration estimate; it does not waive setup disclosure or permit a false run count.

Reproduction with the real CLI fixture:

1. Start from `BASE` in `test/cli/code-gate-fixture.ts`. Add root `globalSetup: ["./setup.ts"]` to the Vitest config. Its exported setup appends `run\n` to `setup-runs.txt`.
2. Make `test/math.test.ts` import `double` and assert `double(2) === 5`, so it fails. Commit the fixture, then change `double` from `x * 2` to `x + x`.
3. Run `code(root, ["--base", "main", "--json"])` to store the failure. Remove only `setup-runs.txt`.
4. Run `code(root, ["--base", "main", "--json", "--rerun-stored-failures"])`.

The second run creates `setup-runs.txt` with `run\n`. Its final report has `storedRerun["test/math.test.ts"].outcome === "failed"` and a completed file. But its stderr starts with:

```text
squeal code: Vitest: 1 test file selected (tests 1): none to run, 1 read from the stores
```

No `global setup runs for:` line appears. The assertion that this line exists fails. A potentially costly setup therefore executes after the gate told the user there was no run and disclosed no setup.

**Worker-sized fix:** make the pre-run summary distinguish evidence known from stores from files scheduled for a stored rerun. Count marked failures as scheduled execution, and include their projects and the root in setup disclosure. Keep them outside the duration estimate and early stop as D3.4 specifies. Add this stored-only case and a case where one project is reused and another reruns. Keep the host-load pin.

### B3. The early pass lets an input-read failure escape the keeper

**Proven.** `src/core/code/gate/keep-pass.ts:107`. `openingCheck` is awaited before the function's `try`. `EarlyWrites` assumes that its pass never rejects; `stop` forwards a rejection to `Keeper.flush`.

D17.5: "a busy store, or any failure, hands the files back"; "The verdict, the report and the exit code do not change." The keeper's public `flush` contract also says a failure costs only the write and never throws. The old implementation enclosed the opening input check in its catch.

Reproduction uses the same stable keeper fixture as B1, with no lock contention. Wrap the kit's hasher so its first `stat` delegates normally and its second `stat` rejects with `Error("EACCES: cannot stat src/a.mjs after the chunk")`. The first read passes the completed chunk's keep decision. The second read is the early pass's opening check. This models a file access failure between the decision and write; the real `createFsHasher` also throws on non-missing stat errors.

After `expect(A)` and the completed `keeper.ran`, assert `await expect(keeper.flush()).resolves.toBeUndefined()`.

Actual output:

```text
AssertionError: promise rejected "Error: EACCES: cannot stat src/a.mjs afte…" instead of resolving
Caused by: Error: EACCES: cannot stat src/a.mjs after the chunk
  at stillAsRead (src/core/run-evidence/run-evidence.ts:120)
  at openingCheck (src/core/code/gate/keep-pass.ts:265)
```

This proves the public keeper rejection. In the CLI, the uncaught `collected.keep` runs from `codeGateCommand`'s `finally`, so this failure can replace the verdict's normal return. A background rejection before the final flush is also not contained by `EarlyWrites`.

**Worker-sized fix:** move opening validation inside the pass's failure boundary. Preserve the original queue if opening it fails, retry during collection, and issue the bounded final not-kept note if it still fails after the report. Ensure no early-pass promise escapes. Add an opening-check error test that recovers on retry, and one whose final attempt still fails; neither may reject `ran`/`flush` or change the gate verdict.

- Stable-input tests cover changes during a chunk, changes after a busy refusal, and a changed input in a later chunk. The latter keeps the earlier result at its old key, as the accepted D17.3 amendment permits.
