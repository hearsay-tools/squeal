### B1. Proven: the new advice splits a test path that contains spaces

Location: `src/cli/code-gate-text-left-out.ts:54`.

D14.3 requires the verdict to add “the `--test` command for it”. The brief
also requires that the printed command be valid and run the named file.
The new interpolation prints the path without `shellWord`.

Reproduction used `leftOutText`, the existing `gateReport`/`functionRow`
fixtures, Bash and the real `parseGateArgs`. A changed function in
`e2e/edited spec.test.ts` listed that path as its own left-out loader,
with a manual `browser` group whose `selected` count was 1. Actual output:

```text
To run only the edited test file of them, add --test e2e/edited spec.test.ts; the other selected test files in scope still run, with their setup.
```

Passing that exact flag fragment through Bash and into `parseGateArgs`
produced:

```json
{
  "argv": ["--test", "e2e/edited", "spec.test.ts"],
  "tests": ["e2e/edited", "spec.test.ts"],
  "expectedTests": ["e2e/edited spec.test.ts"]
}
```

This asks for two different files. The intended existing file is not named.
The shell probe used only this harmless space-containing path.

**Worker-sized fix:** render each path with the existing
`src/core/text.ts:shellWord`. Add a shell argument round-trip test covering
spaces and a quote in a path. Keep safe paths and the three-file limit as
before. Do not add another quoting rule.

### B2. Proven: editing test data without editing a function gives no advice

Location: `src/cli/code-gate-text-left-out.ts:45-47`.

D14.3 says “when a left-out group holds an edited test file that did not run,
the verdict line adds the `--test` command for it”. `editedLeftOut` instead
requires a changed function in that file. A file edit need not change a
function body. The worker notes acknowledge this limit, but the amended
spec does not narrow the edited-file rule to changed functions.

A real `codeGateCommand` reproduction used a temporary git repository with
this base policy:

```json
{
  "nodeTest": [{"name":"browser","include":["e2e/**/*.test.mjs"]}],
  "checks": [{"name":"browser","runner":"nodeTest","project":"browser","at":"manual"}]
}
```

The base source was `export function double(x) { return x * 2; }`.
The test was:

```js
import { test } from 'node:test';
import assert from 'node:assert/strict';
import { double } from '../src/math.mjs';
const expected = 4;
test('double', () => { assert.equal(double(2), expected); });
```

The working tree changed the source body to `return x + x` and the test data
to `const expected = 2 + 2`. The callback body stayed the same. Calls with
`--base main`, and then `--base main --json`, both returned exit 3. Actual
verdict line:

```text
Code gate: incomplete. 1 changed function against main (merge base 0d943e56): 1 incomplete. browser (manual) did not run: 1 test file loads changed code; add --group browser to run it.
```

The JSON listed `e2e/edited.test.mjs` in `head.paths`, and the changed source
function listed it in `loaders.leftOut`. `scope.leftOut` had `files: 1` and
`selected: 1`. No `--test` advice appeared. This is an edited, selected test
file that the manual group left out.

**Worker-sized fix:** derive edited-file identity from the changed paths,
then intersect with evidence of test files actually left out. For this
case, `head.paths` and the union of `loaders.leftOut` already give both
facts. Retain advice for changed callbacks, deduplication, path order and
the three-file limit. Add an integration test for a data-only test edit;
also keep an unchanged left-out test and an edited in-scope test out of
the advice. If a needed case has no loader row, carry its file identity
explicitly rather than inferring an edit from a function row.

### B3. Proven: the new field reports a file as run after prepare blocked it

Location: `src/core/code/gate/scope.ts:233-235` and `:253`.

D14.3 defines `scope.leftOut[].tests` as “the group's files that ran because
`--test` named them”; it is “absent when none did”. The type comment at
lines 65-66 and all three changed command references use that meaning.
The tally increments during selection, before any prepare or test run,
and the final report publishes that count unchanged.

A second real `codeGateCommand` probe used the same manual node:test
group, with a base prepare command:

```json
{"command":["node","-e","process.exit(1)"]}
```

The changed test callback was `() => { assert.equal(2, 2); }`. The command
was `--base main --test e2e/edited.test.mjs --json`. It returned exit 3.
Actual stderr included:

```text
squeal code: browser (manual) is left out: its 1 test file runs by --test
squeal code: node:test entry "browser": prepare exited 1 after 0.1 s: its 1 selected test file does not run
```

The final JSON contradicted its new field's contract:

```json
{
  "scope.leftOut": [{
    "name":"browser", "at":"manual", "files":1,
    "selected":0, "add":"--group browser", "tests":1
  }],
  "runs[0].completed": [],
  "runs[0].durationMs": null,
  "runs[0].prepare[0]": {
    "project":"browser", "command":["node","-e","process.exit(1)"],
    "outcome":"failed", "exit":1, "durationMs":99,
    "notRun":["e2e/edited.test.mjs"]
  }
}
```

These are selected fields, with dotted keys for readability. The test never
started, yet the new field says one file ran. This breaks the vision's rule
to record a result where it is known. The overall verdict correctly stays
incomplete; that does not make the new field accurate.

**Worker-sized fix:** separate scope admission from observed execution.
Keep the pre-run scope allocation useful, but derive a final field that
claims execution from final run evidence. A file blocked by prepare or
never started must not count as run. Define how stored and part evidence
count too, and test those boundaries. If the intended field instead counts
files admitted by `--test`, obtain and record that contract amendment and
use that meaning in the type, spec and all shipped references. Selection
alone must not be documented as proof that a test ran.
