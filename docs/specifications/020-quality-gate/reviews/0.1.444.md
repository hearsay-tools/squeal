## Blockers

### B1. Proven: signal termination after the JSON frame changes the exit code

Location: `src/cli/code-gate-relaunch.ts:155-157`; regression expectation in `test/cli/code-gate-relaunch.test.ts:103`.

D17.5 says: **“The verdict, the report and the exit code do not change.”** The task explicitly asks whether the new `128 + signal` behavior meets that rule. It does not. D1 also defines 0/1/3/2 as the gate's exit codes.

The probe loaded the base revision's `relaunchGate` from `git show 7436388a2:src/cli/code-gate-relaunch.ts` and the candidate's source. It gave each the same child: write a whole length-prefixed `{"verdict":"pass"}\n` to fd 3, then terminate itself with SIGTERM. Actual output:

```text
base:      code=3,   stdout=""
candidate: code=143, stdout="{\"verdict\":\"pass\"}\n"
candidate stderr: squeal code: the gate's process ended on SIGTERM after its report
```

Printing the report before persistence requires the earlier stdout delivery. It does not require a new exit code. The candidate deliberately tests 143, so the green test locks in the deviation rather than proving compatibility. No accepted amendment authorizes it; the worker notes only record the choice.

One-worker fix: keep early report delivery, retain exit 3 for a child that terminates on a signal, and distinguish the diagnostic after a report from the diagnostic before one. Cover whole-frame and incomplete-frame signals. A different signal-exit policy needs an explicit spec decision before this finding can be closed.

### B2. Proven: inputs can change during the wait and the deferred write still keeps the file

Locations: `src/core/code/gate/keep.ts:109-115`, `:225-231`; `src/core/code/gate/keep-write.ts:122-153`.

020-28's done-when says: **“a file whose keyed inputs changed before the deferred write is not kept.”** The board also calls for “a changed key at write time.” `steadyOf` checks once, before opening the stores. `slicedWrite` can then wait for 30 s, and neither transaction rechecks the file. 2. At the busy note, after the report and initial stability check, change that keyed source to `return 9`, then release the holder.

Actual output:

