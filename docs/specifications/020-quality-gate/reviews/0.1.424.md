## Blockers

### B1 — proven: a CC exception accepts incomplete head evidence

Locations: `src/core/code/gate/evaluate.ts:162`, `src/core/code/gate/evaluate.ts:183`, `src/core/code/gate/exceptions.ts:109`.

D8: **“An exception needs complete head evidence (D5).”** D5 defines complete evidence to include a whole record from each loading test file at the head bytes. D5 separately permits an ordinary pass proven by a subset bound. D8 does not extend that permission to accepting a violation through an exception.

A changed function has CC 22. Two selected, completed test files load its source. One supplies 100% own-line coverage, so its subset CRAP is 22. The other has no coverage record. An approved complexity exception with value 22 makes the candidate report this function as `accepted`, with `gap: null`, and the entire verdict as `pass`. The report itself has two expected loaders and only one measured loader.

`evidenceJudgement` turns this missing-record case into `PASS` because the subset CRAP is under 30. `judge` passes only that judgement to the exception layer. `stateOf` therefore cannot distinguish complete evidence from a subset pass, and accepts the CC exception. The same path is used for inherited CC exceptions.
