## Blockers

### B1. Proven: a changed test file can be skipped when its functions do not change

Location: `src/core/code/gate/collect.ts:106`, including the early return at line 107 and selection at line 122.

Spec D3.1 requires selection of "every changed test file". Goals 4 and 5 require the selected tests to run and failed tests to block.

The collector derives every changed path from `changed.functions`. That loses a test path when only its top-level code changes, or when all of its functions are classified as unchanged, moved or shifted. `changed.counted` still contains the changed test path, but the collector does not use it. With no other changed function, it returns before opening an adapter.

Failing case: commit this passing Vitest file as the base:

```ts
import { it, expect } from "vitest";
it("passes", () => expect(1).toBe(1));
```

Append `throw new Error("changed test fails at top level");` without changing the callback. Run the candidate's bundled CLI with `code --base main --json`:

```json
{"exit":0,"verdict":"pass","counts":{"pass":0,"violation":0,"incomplete":0,"skipped":0},"runs":[]}
```

The same tree with `--test test/a.test.ts` returns exit 3, verdict `incomplete`, and a completed run with `failed:[{"path":"test/a.test.ts","tests":["(file-level error)"]}]`. The explicit run proves this is a selection failure, not a runner setup problem.

Repair scope for one worker: retain changed test paths independently of changed function rows through inventory and collection. Include them before the no-work return and in `select()`. Preserve path narrowing. Add a real CLI regression for the top-level failure above and for a changed test whose function bodies only move or shift. Keep ordinary unchanged test files outside selection unless they load changed code or are named with `--test`.

### B2. Proven: a failed test in an unfinished file is erased, allowing a subset pass

Location: `src/core/code/gate/collect.ts:270`, at the new boundary to `RunReport`, and `src/core/code/gate/evaluate.ts:159`.

Spec D5.5 requires "No selected test failed". Its subset rule says, "It is still not a pass while a selected test failed." Goal 5 says a failed test makes the verdict incomplete.

The gate accepts a coverage bound from a completed loader while another loader is unfinished. But `evidenceOf()` forces `failed: []` for every unfinished file. The existing Vitest adapter also filters all unfinished-file results out of `RunReport` (`src/runners/vitest/run.ts:250`). That old adapter contract is insufficient for this new gate: it provides no channel for the failure already observed before cancellation. The evaluator therefore sees no failure and accepts the subset pass.

Failing case, reproduced with the bundled CLI and `--timeout 4`:

- Base source: `export function foo(x:number) { return x * 2; }`.
- First test file imports `foo` and passes `expect(foo(2)).toBe(4)`.
- Second test file imports `foo`. Its first test runs `expect(foo(2)).toBe(9)`. Its second test sleeps for 60 seconds. Project `testTimeout` is 120000 ms and `maxWorkers` is 2.
- Commit those files. Change only the source to `return x + x;`.
- A marker written immediately before the failing assertion confirmed that test executed. The value is 4, so the assertion fails before the sleeping test is cancelled.

Actual result:

```json
{"exit":0,"verdict":"pass","counts":{"pass":1,"violation":0,"incomplete":0,"skipped":0},"runs":[{"runner":"vitest","selected":["test/a.test.ts","test/b.test.ts"],"completed":["test/a.test.ts"],"notFinished":["test/b.test.ts"],"failed":[],"durationMs":3195}]}
```

Stderr: `squeal code: vitest run: run exceeded timeoutMs (3167 ms)`.

Repair scope for one worker: give the gate trustworthy observed failures from selected files even when the file does not finish. Extend the runner report or provide an explicit collection channel, then consume it independently of `completed`. Audit the node:test boundary for the same completed-file filtering. Keep unfinished coverage records unusable. Keep the D5 subset-pass rule when no test failed. Add this end-to-end regression and a no-failure timeout control; do not fix this by accepting partial records or disabling subset passes wholesale.
