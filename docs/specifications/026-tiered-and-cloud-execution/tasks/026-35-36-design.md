# 026-35 and 026-36: the project owns its remote machine's setup

Coordinator 2da658d7, 2026-11-27. The human chose these two rows (with 026-34) after hearsay-tools/squeal#289: a project's browser tests ran on the remote VM, whose image has no Chrome. The project, not Squeal and not the user's config, should own what its tests need on a remote machine. Draft for the human's approval; becomes a spec 026 decision once approved.

## 026-35 `remote.setup`: a project script that prepares each remote machine

- `squeal.config.json`: `"remote": { "setup": ".squeal/remote-setup.sh" }`, a repository-relative path to an executable script. Default: none.
- Squeal runs it on the remote, in the worktree's remote tree, as the remote login user, after the tree arrives and **before** the dependency install (an install script may need a tool it adds). A bounded time (15 min); its output goes to the daemon log.
- A mark on the machine (under the remote cache, per machine, since system tools are machine-wide) holds the SHA-256 of the script's content. At each connect: mark equal, ready; mark different or absent, run it again. An edit to the script thus sets every machine up again; no user step.
- A failing script refuses that remote with its exit code and last output lines in `squeal status`; its runs go as `whenLost` says. The next connect tries again only after the script changes or a backoff.
- **Never in result keys.** System tools are not in keys on either side today; the script changes tools, so it stays out. Keying it would re-key every remote result on each edit and stop reuse between remote, worktrees and CI.
- Works for every provider (ssh, agent37, boat). The agent37 `template` stays in the user's config as the fast path (a prebuilt image); the setup script also covers the gap between images.
- Question for the human: also a project `remote.template` hint (agent37 only)? Proposed: no; the script is provider-neutral.

## 026-36 per-file `requires.commands`

- `requires.commands` keeps its array form (every test needs these). New object form: `{ "<test-file glob>": ["google-chrome", ...], "*": ["git"] }`.
- At connect, Squeal looks for each command on the remote. A missing global command refuses the remote, as today. A missing per-file command keeps only the matching files here, and `squeal status` names it: `agent37 lacks google-chrome for packages/web/e2e/*.e2e.ts; these files run here; add it to remote.setup`.
- Optional version check: an entry `{ "command": "google-chrome", "version": "--version" }` runs the command with that argument on both sides; a different first line keeps the files here, named. Plain names do no version check.
- Missing here: named in status as today; the tests still run.
- Never stores a remote result for a file whose command is missing there.
