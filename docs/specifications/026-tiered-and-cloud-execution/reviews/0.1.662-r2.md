## Nonblocking notes

### N2 — proven: a leading-space intent path can prevent Git synchronization

Location: `src/core/runner-host/remote/providers/agent37/git-index.ts:148-157`, especially the whitespace test at line 152.

`git ls-files --debug` prints a simple leading-space filename without C quotes, even with `core.quotePath=true`. `intentToAdd` treats any line starting with whitespace as stat data. It can therefore lose that filename or assign its flag to the previous path.

After the original B2 case succeeds, add `" leading.txt"` with `git add -N` and sync again. The focused probe observes:


The transfer is wrong, but the new semantic hash detects it. Both sync and `keeper.current()` return false. Repository-reading remote work cannot claim current Git metadata. This is a nonblocking note under the bounded re-review rule, and it does not reopen the original false-current blocker.
