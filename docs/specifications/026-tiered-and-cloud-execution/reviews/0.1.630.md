## Blockers

### B1. Proven: the attributes precheck can accept converting index blobs

**Location:** `src/core/runner-host/remote/tree.ts:70`, `:130`.

The candidate promises the `git-index.ts` soundness guard for converting attributes. Spec 021 D10, retained by 026 D8, requires the worktree files on the remote. A tracked-attributes listing is insufficient: Git also applies an untracked `.gitattributes` file. When no tracked attributes, explicit `core.attributesFile`, or nonempty `info/attributes` exists, this precheck skips `check-attr` entirely.

**Reproduction:** initialize a SHA-1 repository and commit `a.txt` containing `line\n`. Create an untracked `.gitattributes` containing `*.txt text eol=crlf`. Write `line\r\n` to `a.txt`, then `git add a.txt` to refresh its clean index metadata without adding the attributes file. `git status --porcelain --untracked-files=no` is empty. `treeEntries` returns the LF index blob `a999a0c...`; `readEntry` returns the CRLF disk blob `0e7d2a2...`. The new `.git` materializer can now write the normalized bytes without requesting the actual file.

The later run proof can repair a differing content blob if the path enters its proof. That does not make the initial tree or remote planning correct. Implicit global attributes are another source the precheck does not inspect; the untracked-file case alone proves this finding.

**Repair scope:** one worker, `tree.ts` and `tree.test.ts`. Run the existing batched `check-attr` for every index candidate, or prove absence of every Git attributes source before omitting it. Add untracked/ignored attributes and implicit global-attributes fixtures. Require exact equality with disk reads under text/eol and filter conversion.

### B2. Proven: the shortcut substitutes index permissions and type for disk state

**Location:** `src/core/runner-host/remote/tree.ts:126`, `:169`.

The promised tree-mode preservation fails when Git is configured to ignore mode or symlink differences. Blob proof does not repair this, because the bytes can be equal.

**Reproduction:** commit a regular `a` and a symlink `link -> a`. Set `core.filemode=false` and `core.symlinks=false`. Make `a` executable, replace `link` with a regular file containing `a`, and leave the index untouched. Git reports a clean tree. `treeEntries` emits non-executable `a` and `mode: "link"` for the regular file. Copy only `.git` to a fresh remote root and pass the entries to `createTreeHost(...).tree`.

The materializer reports no missing files. The remote loses `a`'s executable bit and creates a symlink where the local tree has a regular file. Calling `host.differing` with blobs read from the actual local files returns `[]`. Thus a test of permissions, `lstat`, or symlink resolution can execute against a different tree while the candidate reports equal blob proof. This breaks the tree contract and vision principle 2.

**Repair scope:** the same tree worker. Read disk type and executable bits with `lstat` even when reusing the content oid. Refuse the shortcut when the on-disk type cannot be represented by that index entry. Include both configuration settings in a round-trip test with `.git` materialization and the proof check. Guard index reuse across concurrent file changes as required by `readCleanIndexHashes`' caller contract.

### B3. Proven: the installed fingerprint cache hides changed environment inputs

**Location:** `src/core/runner-host/remote/blob-cache.ts:124`, `:169`, `:187`; consumed at `lane-compare.ts:104`.

Spec 026 D10.1 preserves 021 D11.2: the environment must compare equal before a remote result is accepted. Keeping the remote calls live does not prove equality when the local fingerprint is stale.

**Reproduction A, even with explicit invalidation:** create `.pnp.cjs` and `.yarn/patches/a.patch`. Set the `.pnp.cjs` mtime to 60 seconds ago. Prime the cache, change the patch, call `onInvalidate([".yarn/patches/a.patch"])`, and read again. Neither the signature nor `touchesInstalled` covers `.yarn/patches`. The cached fingerprint stays `e18996f9...`, while direct `installedDependenciesFingerprint(root, root)` returns `c8c38d49...`.

A fake host with one valid runner descriptor and the original installed fingerprint demonstrates the seam: `compareRemoteEnvironment` with this cache returns `differences: []`; the same call without the cache returns `["installed dependencies differ"]`. Both calls read the remote core and runner environment. A 30-second TTL bounds the wrong answer; it does not make it current.

**Reproduction B, incomplete stat signature:** create `node_modules/@scope/a/package.json` and a hidden npm lockfile naming that package. Age the watched directory/lockfile mtimes, then prime the cache. Remove `node_modules/@scope/a`, leaving the watched root-directory and lockfile stats unchanged. The changed scope directory is not in the signature. The cache returns the old fingerprint while the direct reader detects the missing package and returns another fingerprint. This does not need a same-tick rewrite. The direct fingerprint also reads inputs such as Rush metadata and nested package folders that the twelve-path signature cannot prove unchanged.

**Repair scope:** one worker, `blob-cache.ts` and cache/comparison tests. Base caching on the dependency set actually consumed by the fingerprint reader. Cover patch descendants, Yarn patch paths, supported lockfile formats, links and package-folder validation/fallback. Until a complete signature exists, bypass this cache for layouts whose freshness it cannot establish. Preserve live remote checks. Add the comparison regression above, rather than only checking that a root hidden-lockfile edit changes a cache entry.

### B4. Proven: hard-link fallback returns a bundle that pruning can delete

**Location:** `src/core/runner-host/remote/providers/agent37/bundle-cache.ts:158`.

The stated cache contract pins a caller's bundle before unlocking and requires a clean fallback when hard links fail. Returning the shared cache filename provides neither guarantee.

**Reproduction:** place the repository/cache on `/tmp` and the caller directories on `/dev/shm`, causing real `EXDEV`. `sharedFullBundle` returns the shared `.git/squeal/remote-bundles/<key>.bundle` filename. Before reading it, create bundles for two later commits through separate calls. With the two-entry limit, pruning deletes the first returned file. The probe prints `EXDEV_AFTER_PRUNE false`.

The caller reads only after this function returns. Another daemon can prune during that interval. With the current `Readable.from`/`createReadStream` path this can fail the transfer; the shared path is not a lifetime guarantee.

**Repair scope:** one bundle-cache worker. On link failure, copy the cached bytes to the caller's private filename while holding the lock, or create a private bundle there. Return only a caller-owned path. Test cross-device fallback followed by pruning before consumption. Retain hard links for the normal path.

### B5. Proven: an existing unwritable cache fails instead of falling back

**Location:** `src/core/runner-host/remote/providers/agent37/bundle-cache.ts:128`.

Only `mkdir` errors invoke the promised unwritable-common-directory fallback. `mkdir(..., { recursive: true })` can succeed for an existing read-only cache directory. Opening/acquiring the SQLite lock, or publishing a new bundle, can then fail.

**Reproduction:** build a bundle normally, chmod the existing `remote-bundles` directory to `0555`, and call `sharedFullBundle` with a fresh writable caller directory. Under the ordinary non-root user, the call rejects with `attempt to write a readonly database`. A private `git bundle create` remains possible because the repository is readable and the caller directory is writable. The candidate instead fails bootstrap.

**Repair scope:** the bundle-cache worker. Treat cache-access failures as optional-cache misses and create the private bundle after releasing any acquired lock. Keep aborts and real bundle-creation failures visible. Test an existing non-writable cache, not only a failing initial mkdir, and cover publication/link errors without leaking the lock.

### B6. Proven: a moving HEAD can permanently poison another worktree's cache key

**Location:** `src/core/runner-host/remote/providers/agent37/bundle-cache.ts:140`, `:145`.

The key uses the captured `local` state, but bundle creation resolves live `HEAD` and `--tags` after the lock wait. They can identify different object sets. The previous per-call snapshot race is now persisted and shared with future callers.

**Reproduction:** save state A and keep a second worktree at A. Before the first cache creation, move the creating worktree to an unrelated orphan commit B. Call `sharedFullBundle` with saved state A. It stores a B bundle under A's key. Now call from the unchanged second worktree using its fresh, correct state A. It hits that cached file. Unbundle it into an empty repository and `git cat-file -e <A>` fails. The probe prints `BUNDLE_KEY_POISONED true`.

This interleaving is possible while `ensureGitTree` reads the remote or waits for the shared lock. Future A bootstraps repeatedly receive a bundle lacking A until eviction. `hasBundle` checks only that it is a nonempty regular file, so it cannot repair the poisoned entry. Spec 026 D7.3.3 requires bootstrap of the requested Git state.

**Repair scope:** the bundle-cache worker. Build from the captured object ids and ensure the resulting bundle contains that exact HEAD and tag object set. Alternatively, validate state before and after packing and never publish a mismatched bundle under the old key. Test an unrelated HEAD change and tag movement during the wait/build, then verify a fresh caller in another worktree can import every requested object.

### B7. Proven: cancellation after lock acquisition leaks the repository lock

**Location:** `src/core/runner-host/remote/providers/agent37/bundle-cache.ts:134`, `:139`.

`throwIfAborted()` runs after acquisition but before the `try/finally` that releases the lock. `awaitDaemonLock` tries to acquire before checking `giveUp`, so a waiter can acquire after its signal was aborted.

**Reproduction:** hold `bundle.lock.sqlite` with `acquireDaemonLock`. Start `sharedFullBundle` with an AbortController. While it waits, release the holder and abort the signal in the same timer callback. At its next poll, the waiter acquires the lock, returns, then throws `AbortError` at line 134. A subsequent `acquireDaemonLock` returns `null`. The probe prints `LOCK_AVAILABLE_AFTER_ABORT false`.

The daemon can stay alive after a cancelled connection attempt. It then holds this repository-wide exclusive lock indefinitely, forcing other worktrees through the timeout/fallback path. This defeats shared packing and the cancellation/resource boundary.

**Repair scope:** the bundle-cache worker. As soon as an actual lock is acquired, cover every exit, including the abort check, with `finally { release() }`. Test the release-and-abort interleaving and require immediate reacquisition afterward.

## What fits

- The diff stays within the named remote source/test areas, version/install metadata and generated plugin bundles. There is no provider branch added to the generic lane or tree protocol.
- Single-thread packing is applied to full and incremental bundle creation. The normal shared-worktree test verifies one pack and each branch's own refs. Normal hard-link pinning protects callers against later pruning.
- `treePathsFor` uses literal pathspecs, deduplicates paths, preserves tracked deletions, and falls back above 256 valid paths. Its bracket-path and ignored-file fixture passes.
- The index shortcut rejects non-SHA-1 repositories, status-listed paths, non-plain entries, unmerged stages and submodule modes. It disables index reuse for converting autocrlf settings. These guards do not resolve B1/B2.
- `.git` materialization restricts writes to requested entries, verifies SHA-1 bytes, uses the existing safe writer and records successful files in `files.json`. The test checks executable/link materialization and deletion of owned files. It does not recreate omitted committed paths.
- Blob caching checks mtime, ctime, size, inode and mode. It does not cache symlink reads or missing paths. It bounds read concurrency and entry count, and lane invalidation evicts named blobs. The targeted tests pass ordinary edits/deletions and the racy-window scenario. No additional stale BlobCache hit was proven.
- Remote core and adapter environment reads remain live, including under `planning: "remote"`. B3 concerns the new local cache, not removal of these remote checks.
