## Blockers

### B1. Proven: install repair deletes the package manager selected from PATH

**Changed location:** `src/core/runner-host/remote/tree-install.ts:86`, with deletion at line 96 and execution at line 99.

**Contract:** Row 026-25 must expose the package manager for remote installs and test runs. The retained Spec 021 D10 repair contract, documented at the top of `tree-install.ts`, also requires rebuilding an unchanged-lock install when its fingerprint changed or its old record has no fingerprint. The candidate must preserve that working repair path.

**Failure scenario:** The remote host has `root/node_modules/.bin` on PATH, and its only `pnpm` is in that directory. A previous install record has the same lock blob and `modules: true`, but needs repair. This can be an older record without `installed`, or an install whose fingerprint changed after a restore. No synced file lies under `node_modules`, so `keepModules` is false.

The candidate calls `managerEnv` first. It finds the existing `pnpm` and provisions nothing. The repair then removes all of `node_modules`, including that executable. The following install exits 127. The base removed the old install before resolving the manager, so it provisioned a stable copy outside the deleted directory and completed the repair.

**Clean-candidate reproduction:** A scratch TypeScript probe called `installTree` directly. It used temporary fixture directories, a fake npm that copies an executable pnpm script into the requested prefix, and a Node-only tools directory. No registry, live provider, or real user environment was needed. It ran the base's `tree-install.ts` with its relative imports redirected to the unchanged helper modules, then the candidate's actual module, with separate identical fixtures:

1. Write `package.json` with `packageManager: "pnpm@9.15.0"` and a pnpm lockfile.
2. Create executable `root/node_modules/.bin/pnpm`.
3. Write `installed.json` as `{locks: {"pnpm-lock.yaml": "same-lock"}, modules: true}`, without an `installed` fingerprint.
4. Call `installTree` with that same locks object, `keepModules: false`, and `env.PATH = root/node_modules/.bin + ":/usr/bin:/bin"`. Supply fake npm and a Node-only `tools.nodeDir`, so no second manager can hide the deletion.

Command: `pnpm exec tsx /tmp/squeal-wave10-install-probe.mts`. Exit 0 because the probe captured and printed both outcomes:

```json
{"label":"baseline","answer":{"ran":true,"command":"pnpm install --frozen-lockfile","again":true},"provisioned":true}
{"label":"candidate","error":"Error: pnpm install --frozen-lockfile failed on the remote (exit code 127): sh: 1: pnpm: not found"}
```

The first probe attempt accidentally allowed the tools directory to supply another pnpm; both versions passed. Giving it a Node-only tools directory produced the discriminating result above. The probe and its fixtures were removed before committing.

**One-worker repair:** In `tree-install.ts`, remove an install that needs repair before resolving `managerEnv`. Gate that removal with `!unchanged && same && !keepModules`. Then resolve the manager, publish PATH through `onPath`, and retain the unchanged early return. This keeps the new unchanged-install PATH behavior while preventing selection of an executable that is about to disappear. Add the fixture above to the install tests, with no fallback manager beside Node. Assert successful repair, stable provisioned PATH, and no manager selection from the deleted directory. Keep the existing fresh/unchanged and custom-env-isolation tests green.
