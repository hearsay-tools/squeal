## B1: abort while opening the Agent37 connection

**Closed, proven.** `src/core/runner-host/remote/providers/agent37/api.ts:181` passes the signal to `openEndpoint`. In `providers/agent37/net.ts:179`, CONNECT cancellation destroys the actual request and raw socket. Its error handler clears the deadline and detaches the abort listener. `ready` at `:223` handles direct TCP and TLS readiness: abort clears the deadline, detaches, destroys the socket and rejects. The TLS failure path at `:285` also destroys the tunnel. A signal already aborted at entry starts no connection. There is no new promise race in connection setup.

The new committed tests in `prune-abort.test.ts` have current passing Squeal results. They exercise a real proxy withholding CONNECT and a proxy answering CONNECT but withholding the TLS handshake. They assert zero open sockets, zero tracked timers and a retained machine record.

The independent probe ran the actual prune and built-in Agent37 provider with **two** tracked records. It aborted after reaching each pending phase. “proxy-TLS” means the TLS connection to an HTTPS proxy itself, before CONNECT; “direct-TLS” means TLS without a proxy. The probe tracked the 60-second connection deadlines, checked they existed before abort, then waited for their removal and socket closure. Actual output:

```text
B1_CONNECT {"aborted":true,"openSockets":0,"deadlines":0,"connections":1,"records":2}
B1_tunnel-TLS {"aborted":true,"openSockets":0,"deadlines":0,"connections":1,"records":2}
B1_proxy-TLS {"aborted":true,"openSockets":0,"deadlines":0,"connections":1,"records":2}
B1_direct-TLS {"aborted":true,"openSockets":0,"deadlines":0,"connections":1,"records":2}
```

Each case returned no release outcome, kept both uncertain records, and opened only the first connection. The queued second release did not start. This closes round 2's live CONNECT-socket leak and covers the requested pending TLS phase through the same cancellation path.
