## Blockers

### B1. Proven: version validation is not strict semver

**Location:** `src/core/runner-host/remote/package-manager.ts:43`, `:59`.

Wave 8 requirement 1: “validate strict `x.y.z[-pre]` (falling back to `<name>@latest` on invalid/injected values; Yarn 2+ uses `@yarnpkg/cli-dist`)”.

The numeric regex permits leading zeroes in major/minor/patch and numeric prerelease identifiers. `managerSpec("pnpm", { packageManager: "pnpm@01.2.3" }, false)` produces `pnpm@01.2.3`, not the required fallback. `pnpm@1.2.3-01` has the same defect. Conversely, a valid prerelease such as `pnpm@1.2.3-rc-1` selects latest because the prerelease character class excludes hyphens. A fresh remote can therefore request an invalid version or install a different version than the valid declared pin. The same parser controls Yarn.

**Repair scope:** one worker, `package-manager.ts` and its tests. Use strict semver rules after removing the hash suffix: no leading zeroes in numeric fields/identifiers, allow hyphens in prerelease identifiers, and consume the entire value. Retain fixed package names, argv spawning and the safe fallback. Add table cases for these three inputs and both managers. Invalid inputs must select latest; valid prereleases must retain the exact version and safe cache name.

### B2. Proven: an empty PATH entry loses an existing manager

**Location:** `src/core/runner-host/remote/package-manager.ts:67` and `:84`.

Wave 8 requirement 1: “Keep any `pnpm`/`yarn` already on `env.PATH` untouched (zero `npm` calls)”.

POSIX PATH uses an empty segment for the current directory. The existing install ran its shell in `place.root`, so a manager there is available through a PATH such as `/usr/bin:/bin:`. Both `onPath` and `withPathDir` discard empty segments; discovery also resolves relative entries against the host process's cwd instead of the install root.

The isolated probe created an executable `<root>/pnpm` that prints `existing-pnpm`. With `cwd: root` and `PATH=/usr/bin:/bin:`, `sh -c 'pnpm --version'` succeeds. Calling `managerEnv("pnpm install", sameEnv, { root, managers, tools: { nodeDir, npm: ["/does/not/exist"] }, output })` instead fails with `could not run npm install pnpm@latest: spawn /does/not/exist ENOENT`. This proves it attempts npm despite an existing manager. With a working npm it substitutes a newly downloaded manager. No injection or invalid manifest is needed.

**Repair scope:** one worker, the same helper and tests. Preserve PATH segment order and empty entries when appending the Node directory. Resolve manager discovery against the child command's actual cwd (`place.root`), including empty and relative segments. Test pnpm and yarn reached through a trailing/leading empty segment and a relative directory; assert zero npm calls and execution of the original wrapper.

## Should-fix

### S1. Plausible, nonblocking: broken-cache repair can remove a concurrent winner

**Location:** `src/core/runner-host/remote/package-manager.ts:143` through `:150`.

Normal first-time concurrent publication passed with real npm. The fallback for a pre-existing broken cache is different: after a failed rename and `made() === false`, each installer recursively removes the shared destination without checking ownership. Two repairers can both observe the broken destination; A removes it and publishes a good copy, then B's already-decided removal deletes A's copy before B publishes. A may have returned that path and started its tree install during the gap. No controlled race proof was run, so this is not blocking.

**Suggested scope:** serialize repair/publication for a cache key or otherwise prevent repair from deleting a newly published valid destination. Add a deterministic two-repairer test around the failed-rename/check/remove boundary. Keep the current unique temporary directories, whole-directory publication and loser cleanup.
