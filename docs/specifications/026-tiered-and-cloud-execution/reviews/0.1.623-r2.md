## Nonblocking note

### N1. Proven: cancellation still waits during API endpoint setup

Changed boundary: `src/core/runner-host/remote/providers/agent37/api.ts:172`.

The new signal is checked before and after `await openEndpoint(...)`, then attached to the HTTP request. `openEndpoint` has no signal argument. An inspect waiting on TCP, proxy CONNECT or TLS setup therefore cannot stop at the abort; it waits for that connection stage to finish or reach its existing 60000 ms deadline.

A read-only probe used `Agent37Api.inspect(id, signal)` against a local TCP server that accepted the TLS ClientHello and never answered. It aborted after receiving that ClientHello, waited 200 ms, and printed:

```json
{"phase":"TLS handshake held","aborted":true,"settledAfter200Ms":false,"elapsedMs":208}
```

The request settled only after the probe destroyed the held socket. The probe exited 0. The 60 s deadline is read from source; the probe did not wait 60 s.

This is a shutdown-latency remainder in B1's changed inspect path. It is nonblocking: it does not reproduce the fresh-instance leak, and both real daemon cleanup probes pass. **One-worker follow-up:** give endpoint setup an optional signal, destroy the connecting/tunnelling/TLS socket on abort, and add a held-handshake cancellation test. Keep the intentionally uncancelled create response and deletion path intact.
