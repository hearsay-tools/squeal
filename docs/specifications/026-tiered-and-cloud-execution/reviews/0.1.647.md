## What fits

- **Pool floor:** `pool.ts:313` clamps the requested minimum through `#most()` before sharing, gating, acquisition and publishing the waiter's `least`. The helper matches the brief's formula. The host cap, project cap and wanted cap apply together. Independent probes granted 1, 2, 2 and 4 for project slots 1, 2, 2.9 and 8 on an eight-slot pool; wanted 1 with project slots 2 granted 1. Existing tests cover the three-slot host and remote admission of least 4.
- **Project edge cases:** absent project uses the host cap; project slots at or above the host cap cannot enlarge it. A fractional cap at least 1 is floored. Invalid slots below 1 do not lower `#most()`. The existing sharing/target code still refuses a zero-cap project, but user configuration rejects non-positive and non-integer project slots. That existing invalid-input behavior is outside this change.
- **Refusal reporting and floor:** the clamped minimum reaches `#logRefusal`. The added remote admission test observes the exact ceiling-refusal line at 4 busy CPUs with another background tier marked, then grants 3 after that mark clears. This covers the old silent-refusal failure. Current ceiling tests also pass. Checkpoints retain permit/fair-share limits while avoiding the host's background ceiling; backlog asks retain the ceiling and oldest-waiter floor.
- **Runner caps:** both adapters cap non-group concurrency by the grant and retain their configured cap. Workers without a configured cap are honored, with a minimum of 1. Group and slow lanes retain the existing all-files behavior; pytest also retains one file per group batch. The downstream node:test file queue and pytest batch queue use this concurrency bound.
- **Scheduler seams:** both traits now report `min(tierSize, grant)`, with `declareTraits` supplying the default and minimum. Both report fewest 1 and widest 4 for an eight-file, tier-size-4 probe. `grantFit` detects a named batch at grant 1 as narrower than its edit tier; a grant of 4 is not narrower. With an offer of 4 and a budget of 10 seconds per worker, a grant of 1 trims 10-second files to one. Existing batch and wall tests pass. Node-test and pytest backlog slots retain their one-process sizing.
- **Remote wire and ownership:** `AdmitAsk.kind` is optional. Omitted or non-checkpoint values use backlog admission. `admitRun` supplies checkpoint only when `background !== true`. The unchanged lane already calls this helper and sends its returned grant as `workers`; no lane edit is needed. The existing RPC forwards the ask object without dropping the new field. Tokens, grant claims, returns and cancellation still use their existing paths. An older sender's omitted kind retains the old behavior.
- **Validity and versions:** the harnesses pass `workers` into both adapters. The node:test case sets concurrency 2 and workers 1. The pytest case runs on Python 3.13 with workers 1; its two light files fit one default batch, so it checks stored-result compatibility, not actual multi-batch concurrency. The focused comparison stores equal results. No key/schema/adapter version changed. Generated CLI changes contain the reviewed source changes and the version raise; other changed hook bundles contain the version substitution. Runtime hashes match, and exact-candidate Node 24 CI confirms build cleanliness.
