## Blockers

### B1. Proven: remote error text can print the API key

Locations: `src/core/runner-host/remote/providers/agent37/api.ts:115`, `websocket.ts:71`, and `tunnel.ts:131` in that same directory.

D7.3 says Squeal never stores the key in logs or command-line arguments. The wave brief also requires that API keys and proxy credentials never appear in error messages. The API client copies arbitrary `error.code` and `error.message` from a failed response into `Agent37Error`. The tunnel copies the arbitrary HTTP status reason into its stderr. Neither boundary removes credentials.

A local mock returned HTTP 401 with `error.message` containing the request's synthetic Bearer key. `Agent37Api.inspect()` rejected with that key in its message. A local TLS WebSocket mock returned `401 Invalid-<synthetic key>`; `runTunnel()` sent the key to its `fail` callback, which the CLI prints to stderr. Provider/lane error logging can then persist that text. The existing tests only use constant, credential-free error text.

Fix in one transport worker: keep arbitrary remote response text out of public errors, or apply one safe error policy before any callback/log/exception. Use status and allowlisted error codes. Account for injecting proxies, where the process does not know the credential that could be reflected. Do not expose a raw credential in the exception's `code` property either. Add API and tunnel error-reflection tests with synthetic credentials, including proxy error text.

### B2. Proven: bundle bootstrap leaves locally deleted files in the remote tree

Location: `src/core/runner-host/remote/providers/agent37/bootstrap.ts:92`; seam with `src/core/runner-host/remote/tree-host.ts:139` and `connect.ts:278`.

D7.3's bundle bootstrap and D8 remote planning must operate on the current worktree. Vision principle 2 says an old state cannot pose as current. A fresh bootstrap executes `git reset --hard FETCH_HEAD`, populating every committed file. Those files are absent from the tree host's `files.json`. The first normal sync removes only files that its manifest already owns, so it cannot remove a bootstrapped file that the local worktree deleted before connect.

Probe: commit `keep.ts` and `deleted.test.ts`; delete the latter locally without committing; run the real `ensureGitTree()` over fake SSH; then run `createTreeHost().tree(treeEntries(local))` and all `writesFor()` writes, as `remoteHostOver()` does. Output:

```text
Deleted tracked test exists: local= false remote= true
```

Remote discovery can list the deleted test. Other tests can also read the old file or find it in a directory scan. This is a new mismatch introduced by seeding the worktree outside the existing tree owner.

Fix in one bootstrap/sync worker: transfer ownership of all bootstrapped files to the sync manifest before exposing the tree, or initialize Git history/index without populating an unmanaged working tree. Preserve `.git` and existing install/cache state. Test first connect with a deleted tracked test and a deleted tracked data file, followed by remote planning and reads.

### B3. Proven: instance reuse preserves an obsolete Git HEAD and index

Location: `src/core/runner-host/remote/providers/agent37/bootstrap.ts:113`; capability exposed at `providers/agent37/index.ts:168` and used by `lane-repository.ts:71`.

D8.4 now sends repository-reading tests to this machine because `hasGitRepository` is true. `ensureGitTree()` checks only whether `.git` is a directory and returns `present`. It never compares or refreshes the remote HEAD, index or history. Regular file sync excludes `.git`.

Probe: bootstrap commit A, make commit B locally, then call `ensureGitTree()` again against the same remote tree. Output:

```text
Reuse kind: present HEAD equal: false
```

This occurs across normal daemon sessions that reuse the stored instance. A test that compares the current `package.json` with `git show HEAD:package.json`, or reads a tag introduced by B, sees B's synced files with A's Git metadata. D19's guard cannot catch this: Git succeeds, so there is no `not a git repository` diagnostic. The new routing can therefore produce and keep a false test result. Local commits while a daemon remains attached have the same missing metadata-sync boundary.

Fix in one repository-sync worker: make the Git capability conditional on current metadata, refresh HEAD/index/required refs without overwriting synced dirty files, and detect later local HEAD changes. Until refreshed, keep repository readers local or leave them unknown according to policy. Keep vendor logic behind the provider seam. Test reuse after a new commit/tag and a HEAD change during an attached session. The existing reuse test asserts that no second bundle is sent but never advances the local commit; it does not establish freshness.

### B4. Proven: direct local runs do not enable local invalidation

Location: `src/core/runner-host/remote/lane.ts:558`, `lane.ts:616`, and `lane.ts:619`.

The 026-12 brief requires forwarding invalidations once the local runner was used. Under remote planning, `opened` starts false. `runHere()` and planning fallback set it true, but the direct local branches call `here.run()` without setting it. These branches cover a tier outside the configured remote tiers and a tier whose files all route locally through `needsRepository` or the D19 memory.

Probe: create a lazy lane with `planning: "remote"`, remote tiers `["background"]`, and a recording local adapter. Run an edit tier locally, then invalidate a source path. The local adapter records only:

```text
Local nonremote-tier run, then invalidation calls: ["run"]
```

The required `invalidate` call is missing. Subsequent edits and touch events never reach that live local instance unless another path happens to set `opened`. This breaks the adapter's invalidation/provenance contract. Some adapters independently check stale source files at run time; that does not replace delivery of all invalidation events, including touches.

Fix in one lane worker: mark local use before every route into a local run, including both direct branches, and preserve the existing permit/log semantics. Test an excluded tier and an all-local repository split. Assert that later change and touch invalidations reach the local instance, while a remote-only lane still makes zero local calls.

## Should-fix

### S1. Proven, nonblocking: WebSocket upgrade has no deadline

Location: `src/core/runner-host/remote/providers/agent37/tunnel.ts:66` and `tunnel.ts:77`.

`connectMs` bounds TCP/CONNECT/TLS setup. After TLS succeeds, `bridge()` has no timer while it waits for HTTP 101. A peer can keep the socket open without replying. Stdin end/close during this stage does not finish the bridge either; the end handler is installed only after the upgrade.

A local TLS server accepted the upgrade request and stayed silent. With `connectMs: 30`, the promise was still pending after 200 ms and settled only when the probe destroyed the server socket. Production's 30-second connect limit likewise does not bound this phase. Outer SSH operations have deadlines, so this is a transport cleanup/responsiveness note rather than an additional proven result-correctness blocker.

Fix: carry a deadline through the HTTP upgrade, handle input end/error/close before upgrade, clear timers and listeners on every terminal path, and bound close-handshake waiting. Add silent-upgrade and early-stdin-close tests. Keep using only local TLS/proxy fixtures.
