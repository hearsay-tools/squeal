# #308: ignored build inputs and the loss policy

Keep the existing refusal under `whenLost: "not-run"`; treating local file
existence as permission to fall back would change policy. The reported refusal
is reproduced synthetically on 0.1.665. The original application incident and
its scheduler/status UNKNOWN state were not replayed.

Examined 2026-11-28: source **0.1.665**, commit
`018267eeae8a99e1cd7fb90a5cdb33e737eecf04`. `lane.ts`, `lane-proof.ts` and the
shared fixture have no diff from release tag `squeal--v0.1.665`. The installed
launcher also reported 0.1.665. No product or configuration change, cloud
provisioning, real build or full-suite run was needed.

| Question | Finding and evidence |
| --- | --- |
| Does local existence make an ignored input syncable? | **read in source code, 0.1.665**: no. Spec 021 D10 excludes ignored files from transfer. `classify()` in `lane-proof.ts` marks a differing, locally present input outside that tree as unsyncable. The proof partitions affected files and avoids futile resends. |
| Does the reported refusal occur now? | **verified by experiment, 0.1.665**: yes, synthetically. A closure containing `packages/cezar/dist/hsq.js`, and a runtime observation of `packages/cezar/web/dist/index.html`, each produce the named ignored-input refusal under `not-run`. Both files exist locally and remain absent from the remote fixture. |
| Is local fallback broken? | **verified by experiment, 0.1.665**: under `local`, only the dependent file runs locally. Under `not-run`, no file runs locally. Clean sibling completion survives in both cases. Background and explicit group lanes behave alike. All eight cases passed. |
| Is refusal an unintended policy regression? | **read in source code, 0.1.665**: the behavior matches 026 D8.3, 021 D10/D11/D13, and row 026-24. The 2026-11-27 human decision recorded in 026 `status.md` and row 026-40 says “Keep refusing”, including explicit `squeal run` and `status --wait` under `not-run`. |
| Does this prove every detail of #308? | **inferred, 0.1.665**: it supports the reported mechanism, not the original real-run cause. The probe supplies closures/observations through fake runner adapters. Original generated bytes, project setup, real runner observation, daemon scheduling and selected-file status output remain unverified. |

## Experiment

The [throwaway probe](probes/issue-308/README.md) uses the existing
`test/runner-host/remote/lane-fixture.ts`: real in-process host, proxy, Git tree
selection, transfer and proof, with fake adapters and temporary directories.
It checks the exact two package paths, both policies and both lane kinds.
For every case it asserts one remote adapter run, no “sending again” log,
preserved sibling completion and the local execution count. The synthetic
adapters report completion; this is not an application test PASS claim.

Commands from the repository root:

```sh
git rev-parse HEAD
node -p 'require("./package.json").version'
cat /proc/loadavg
getconf _NPROCESSORS_ONLN
~/.codex/plugins/data/squeal-hearsay/bin/squeal checks
~/.codex/plugins/data/squeal-hearsay/bin/squeal run tests test/runner-host/remote/lane.test.ts --wait 60000
pnpm exec vitest run --config docs/specifications/026-tiered-and-cloud-execution/research/probes/issue-308/vitest.config.ts docs/specifications/026-tiered-and-cloud-execution/research/probes/issue-308/ignored.test.ts
git diff squeal--v0.1.665 -- src/core/runner-host/remote/lane.ts src/core/runner-host/remote/lane-proof.ts test/runner-host/remote/lane-fixture.ts
```

Results: 16 CPUs; one-minute load 3.05 at source inspection, 2.79 before the
first probe and 1.78 before the final run. The final run passed **8/8**, one
file, in **1.02 s**, exit 0. No load threshold was exceeded. Squeal's selected
existing test file was already current: **0 queued**, no new experiment.
Its overall snapshot had four unrelated unknown files. The custom probe is
outside configured test projects, so the requested experiment ran directly.
Final `squeal status --wait 60000` for the report and probe confirmed no
configured test covers them (exit 3, no verdict). `git diff --check` was clean;
Biome ignored the documentation probe paths and processed zero files.

Two setup corrections preceded the final run: adding `--force` to the Squeal
group command returned usage exit 2; it is unsupported there. The first
probe incorrectly passed the user-config shorthand `lanes: ["all"]` to the
lower-level fixture and failed 8/8 before a remote run. Changing that to its
normalized `lanes: ["background", "group"]` produced 8/8 in 968 ms. Those
initial runs used `research/probes/issue-308/` at the repository root; the
probe was then moved to the owning spec and rerun with the command above.
These were probe setup errors, not product failures.

## Recommendation and boundary

**inferred, 0.1.665:** classify this as recurring friction around the policy
already applied to closed [#280](https://github.com/hearsay-tools/squeal/issues/280),
whose 026-24 repair isolates offending files rather than enabling fallback
under `not-run`. A request for automatic local execution requires a new human
policy decision. Existing holds stand. Do not silently authorize fallback or
exclude genuine build inputs from proof to obtain a pass.

If further diagnosis is approved, obtain a current real-run report to decide
whether a needed input can be built reproducibly on the remote or whether the
project owner wants an explicit local execution policy. Local existence alone
does not establish matching remote bytes.
