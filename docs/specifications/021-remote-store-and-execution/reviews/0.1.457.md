### B1. Proven: an assertion that quotes the phrase is replaced by a local pass

Locations: `src/core/runner-host/remote/lane-repository.ts:18`, `:85`; `src/core/runner-host/remote/lane.ts:377`.

D19.2 limits the guard to a failure saying the directory is not a Git repository, using Git's own diagnostic. The review brief also requires that it cannot hide a real failure that merely mentions Git. The unanchored expression `/not a git repository/i` matches arbitrary assertion text, including quoted expected or received data. The lane removes that file's remote results, reruns it here, and remembers it as a repository reader for the rest of the lane's life.

Independent reproduction through `withRemoteLane` and two real candidate `createVitestAdapter` instances, Vitest 5.0.3:

```ts
it("parser diagnostic", () => {
  expect(process.env.REVIEW_SIDE === "remote"
    ? "not a git repository"
    : "invalid input").toBe("invalid input");
});
```

The two adapter instances receive different `REVIEW_SIDE` values through `childEnv`. This makes a controlled remote-only assertion failure; no Git process runs and no repository read occurs. The lane compares their real runner environments and the same installed fingerprint, and checks the closure's actual blob ids. Only the remote transport/admission is a test double.

Observed:

```text

returned lane results: [pass]
repository hint: test/assertion.test.ts ... add each to remote.needsRepository
```

The genuine failed assertion disappears. A simpler report-level control confirmed that `Git returned an invalid revision` and `git: not found` stay failures; the dangerous case is quoted data containing the precise substring, not every mention of Git.

Fix scope, one guard worker with B2: recognize a Git diagnostic rather than an arbitrary substring in an assertion or unrelated stack text. Preserve those real failures and do not remember their files as repository readers. Add real assertion-message and stack-only negative controls beside the genuine Git diagnostic, file-error and startup-failure controls. Keep the existing local rerun and status hint for actual missing-repository failures.

### B2. Proven: a Git diagnostic in the error's cause bypasses the guard

Location: `src/core/runner-host/remote/lane-repository.ts:85`.

`CheckError` carries a bounded `causes` list. Vitest's `toCheckError` records it, and failure rendering includes it. `carries` reads only `message` and `stack`. A wrapper error with Git's diagnostic as its cause is therefore returned as an ordinary completed failure, with no local rerun and no hint. This violates D19.2's promise to discard and rerun the remote missing-repository failure.

The independent real-adapter probe used this test body on the remote side; the local side would pass:


The report lists the file in `completedFiles` and retains its failed result, so it is eligible for normal storage under the local key. This is the false remote failure D19 was added to prevent. The result is from the real Vitest adapter, not a manually invented cause shape.

Fix scope, same guard worker as B1: inspect the diagnostic evidence preserved in `CheckError.causes` as well as its outer error, with the same narrow recognition rule. Cover test failures, file errors and startup failures wrapped with a cause. Prove that no remote per-file field survives and that the file runs here, is named, and stays here afterwards. No key-format change is needed for the routing correction.
