## Blockers

### B1. Proven: environment equality is cached across later remote runs and installs

Locations: `src/core/runner-host/remote/lane.ts:127`, `:185`, `:199`.

D11.2: “The environment is equal. `compareEnvironment` ... of the host's descriptor against the local one answers `equal`.”

`ready()` checks descriptors only while `state.checked` is false. Nothing clears that flag on invalidation. Pending invalidations, which can install a changed lockfile and recreate a runner, are sent after this check. Later remote runs accept results on blob equality alone. Equal source bytes do not prove equal runner versions, resolved settings, installed dependencies or environment values. The scheduler's local stability check cannot repair a remote descriptor that was never compared.

Probe: complete a remote run with equal descriptors, change the remote adapter's reported runner version, invalidate a path, and run the next background tier. The real proxy/tree proof still accepts its pass:

```text
ENV_AFTER_CHANGE {"remoteVersion":"5.0.2","localVersion":"5.0.3","remoteRuns":2,"localRuns":0,"environmentReads":1,"end":"completed","results":[{"check":{"project":"","testPath":"a.test.ts","kind":"test","name":["proof"]},"outcome":"pass"}],"lastStatus":"remote box: background runs of vitest go there; proven at 2026-11-11T23:49:48.395Z (blob ids equal before and after)"}
```

Fix scope, 021-14: synchronize the pending tree/install before comparing the descriptors for the run. Make equality current for every accepted run, or prove and invalidate a generation that covers every environment input. Refuse a changed descriptor and name the difference. Add a regression that changes environment after a successful connection, including the lockfile/install path. Preserve the before/after blob proof and the one resend limit.

### B2. Proven: a live heartbeat lets a hung unlimited-timeout run hold its tier forever

Locations: `src/core/runner-host/proxy.ts:253`, `src/core/runner-host/host.ts:226`.

D6: “Every request has a deadline the daemon sets.” D13 requires a hung remote to end incomplete. This diff reopens the null-timeout watchdog break from prior review B3 for remote hosts.

With `aliveMs` set and `timeoutMs: null`, the proxy has no total deadline. Its only deadline renews on `alive`. The host emits that event from a timer while awaiting the runner, independent of file progress. An adapter stuck on an unresolved async operation continues to send heartbeats. No file ends, no incomplete report returns, and the tier and its permit remain held. The existing finite `runIdleMs` watchdog for a local null-timeout run is bypassed.

Probe: use a real host and proxy with a runner promise that stays pending, `aliveMs: 1000`, `runIdleMs: 100`, and `timeoutMs: null`. After 2.5 s:

```text
NULL_TIMEOUT_HUNG_RUN {"settled":false,"elapsedMs":2501,"aliveMs":1000,"runIdleMs":100,"aliveFrames":true}
```

Fix scope, 021-14: retain an independent bounded runner-progress watchdog when transport heartbeats are enabled. Heartbeats can prove transport liveness, but must not renew file progress. A hung null-timeout run must end `timed-out` with no keyed results and permit replacement. Add a test where heartbeats continue but no file completes; keep the long, progressing run case.

### B3. Proven: the delivery lease expires before a live handoff, allowing duplicate reports

Locations: `src/core/daemon/write-desk.ts:97`, `:126`, `:164`; `src/core/delivery/daemon-writer.ts:69`; `src/harness/shared/hand-off.ts:138`.

021-16's done-when: “a report is still marked delivered only once the host has it; no duplicate report from two parallel hooks.”

A lease expires after 5 s with no pending socket write. A prepared report waiting to reach its host has no such pending write, and `DaemonWriter` neither renews nor fences its decision. A hook or bridge paused before output can outlive the lease. A second hook takes a new lease and selects the same untold report. The first can resume, output that report, and submit its old batch: the write desk explicitly accepts expired issued tokens. Both hosts receive the same transition. The output timeout starts only when `writeThenCommit` starts, so it does not bound this pause.

Probe with the real hook and a serving fixture daemon:

1. Register a consumer, store a pass, then store its failure.
2. Run `post-tool-batch` with an external `HandOff`; keep its prepared output unsent.
3. Wait 5100 ms, then run a second `post-tool-batch` normally.
4. Successfully write and commit the first handoff.

The test asserted that **both** outputs contain `PASS -> FAIL`; it passed (1 test, 16.00 s). No injected SQL or mocked lease was used.

Fix scope, 021-16: keep a prepared delivery exclusive through the host handoff, or fence and revalidate a stale decision before any output. Preserve dead-client recovery and record delivery only after host receipt. Renewal alone must also account for a suspended process. Add this lease-expiry overlap to the parallel-hook test; retain the ordinary no-direct-write and failed-output cases.

### B4. Proven: the default lost-remote policy does not run the interrupted files locally

Locations: `src/core/runner-host/remote/lane.ts:191`, `:254`; downstream `src/core/scheduler/record-tier.ts:268` and `src/core/scheduler/ledger.ts:575`.

D13: “`local` (default): the lane's files run locally, under the CPU budget of D18.” The coordinator confirmed during review that there is no amendment to this rule.

When the remote dies during a run, `remoteRun` returns the stripped incomplete report. `run` returns that non-null report directly instead of applying the local policy to its files. The scheduler ends retries and removes these unknown files from the ordinary queue at their unchanged key. With no later edit or separate run request, the queue can become idle while those files remain unknown. A later call would run locally, but no call is queued for the interrupted files. Status already says “running here.” Existing loss tests call `lane.run` a second time themselves, so they do not cover the missing automatic fallback.

Probe: kill the real host channel from inside the remote adapter's run, with `whenLost: 'local'`; call the lane once and wait after its report:

```text
LOST_ORIGINAL_LOCAL_POLICY {"end":"crashed","completedFiles":[],"results":[],"localRuns":0,"lastStatus":"remote box unreachable since 2026-11-11T23:49:50.939Z (the vitest runner host exited (signal SIGKILL)); running here"}
```

Fix scope, 021-14: finish the lost attempt as unknown, then arrange a local run of the same still-needed files under the local CPU budget without requiring another edit. Preserve `not-run`, reconnect backoff, and refusal of any pass/fail from the lost attempt. Add a scheduler-level test with one lost tier and no later edits: the original files must reach a local run and the queue must settle.
