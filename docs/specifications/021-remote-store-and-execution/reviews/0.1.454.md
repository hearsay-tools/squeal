### B1. Proven: a restored cache from an earlier release is stamped stale and cannot recover

Locations: `src/core/runner-host/remote/tree-install.ts:65`, `:72`, `:80`; `src/core/runner-host/remote/lane-compare.ts:43`.

Row 021-24's done-when: "A restored remote with changed mtimes reaches proven runs without a manual step." The migration documentation also explicitly supports keeping an existing cache by setting `cache: ".cache"`. The boat trial used a retained custom cache too. Such trees have the earlier `installed.json` shape, `{ locks, modules }`, without `installed`.

For that record, `same` is false because `installed` is absent. The connect therefore runs the install without removing `node_modules`. With pnpm's repeat-install optimization, that command can leave the restored symlinks and stale `lock.yaml` relationship unchanged. The code then saves the stale fingerprint as the new record's `installed`. At the connect comparison, `host.install()` sees that same stale fingerprint and answers `ran: false`. The comparison refuses the remote. Later connects skip installation for the same reason. This keeps the original boat-trial failure for existing retained caches, even though the new default creates a fresh cache.

## Should-fix

### S1. Proven, nonblocking: gzip framing accepts invalid file sizes and unclaimed bytes

Location: `src/core/runner-host/remote/tree-wire.ts:140`.

`unpackFiles` checks the total decompressed length but does not require each `size` to be a nonnegative safe integer. Node's `Buffer.subarray` truncates fractional offsets and interprets negative offsets from the end. A valid gzip stream of `ab`, with the correct individual blob ids, is accepted with sizes `[-1, 3]` or `[1.5, 0.5]`; it returns `a` and `b`, so both blob checks can still pass despite false per-file sizes. Also, `files: []` returns immediately even when `gzip` contains a nonempty stream.

These outcomes were observed through the candidate's `packFiles` and `unpackFiles` on Node 24 and Node 26. The canonical sender only emits real buffer lengths, and every actual file still passes its blob-id check. No wrong stored result or normal transfer failure was proved, so this is not a blocker.

Fix scope, 021-25: reject negative, fractional and unsafe sizes before decompression; require a safe total and the empty payload for a write with no files. Add these malformed-message cases beside the existing short, long and invalid-gzip tests.
