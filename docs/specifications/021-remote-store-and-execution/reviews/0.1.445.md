## Blockers

### B1. Proven: an expired remote reservation runs without a permit

Locations: `src/core/runner-host/host.ts:201`, `:206`; `src/core/runner-host/remote/admission.ts:84`, `:90`; caller `src/core/runner-host/remote/lane.ts:216`.

D18: “A remote runner host (Part 3) counts against its own machine.” Row 021-21: “The remote host admits background runs under its own machine's ceiling.”

Admission holds a lease for 30 s before its run claims it. The timer releases an unclaimed lease. If the run arrives later, `claim()` returns null, and the host still calls `runOf` with the original worker count. It treats a missing or expired reservation like the intentional no-pool case. The run takes no permit and publishes no held background grant. Other users of the remote pool can therefore run alongside it beyond the configured budget.

This can happen on the actual lane: after `admitRun` returns, it reads the local closure bytes through `blobsHere(inputs)` before it sends `run`. A slow read or a suspended local daemon can outlast the remote reservation. The daemon remains connected; the request still carries `admitted: true`; nothing rechecks admission before executing it.

The independent probe used the real `createHostAdmission`, `createPermitPool`, `serveRunnerHost` and proxy, with an injected runner adapter. It did not replace the admission answer or shorten the timeout:

1. Create a remote pool with `hostSlots: 1` and obtain its one permit through admission.
2. Wait `ADMITTED_HOLD_MS + 100` (30.1 s), representing the delay between admission and sending the run.
3. Acquire the now-free permit through a second real pool. Assert its grant is 1.
4. Send the delayed run over the real host/proxy protocol with `admitted: true`, `workers: 1`.
5. Assert that the adapter ran and the report completed while the second pool still held its grant of 1.

All assertions passed in 30.62 s. No pool failure was injected. The existing expiry unit test proves that the reservation is released, but stops before sending the late run. The seam between release and execution is untested.

Fix scope for one 021-21 worker: distinguish a live admission, an explicitly allowed pool failure, and a missing/expired admission. A remote host must refuse or reacquire an expired grant before calling its adapter; the lane must handle that outcome by waiting for admission again, without starting the run deadline or acquiring a local permit. Keep local hosts and the documented pool-failure policy working. Add a regression through the real host/proxy that expires the reservation, gives its permit to another pool, then sends the late run. Assert no remote execution until it obtains a valid grant. Preserve cancel cleanup, the one-permit floor and local fallback admission.
