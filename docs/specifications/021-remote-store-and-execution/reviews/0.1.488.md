## N1: README overstates the log format and bound

**Proven, non-blocking documentation nit.** `README.md:44` promises "each line with the UTC time and its process id" and "at most 8 MiB of log". The brief permits raw Node/crash output without a prefix. Amended 001 D10 says the files stay "near 8 MiB". The implementation follows that amended rule: it checks after its own line and every minute for raw writes, and copies the whole file rather than capping the copy (`src/core/daemon/log-file.ts:49`, `:100`, `:108`).

The timer probe wrote 220 raw bytes against a 128-byte threshold. Rotation retained all 220 bytes in `.1`, without a prefix. The checked-in tests also explicitly allow one line of overshoot. Persistent rotation failures are best effort: the code catches them and retries on the next check, so the bound also depends on successful filesystem operations.

**Small repair:** change this README sentence to say the daemon's own lines carry the prefix, raw output can be unprefixed, and retention is approximately 8 MiB with line/one-minute overshoot. Keep the amended spec and mechanism unchanged. This wording issue does not break the amended product contract.

## What fits

- `daemonLogFor` uses the lock file's worktree id under the common Git directory. The spawner and sink derive the same path.
- `openDaemonLog` catches mkdir/open failures. The spawn still uses ignored stdio when it returns null. Detachment, `.unref()`, environment handling, and the no-readiness-wait behavior remain.
- `spawnLogging` closes the parent's descriptor in `finally`, including a synchronous spawn throw. Closing that copy does not close the child's inherited descriptors.
- Copy then truncate preserves the inode. Append descriptors keep writing at the new end after either startup rotation or live rotation. The checked-in sink loop covers repeated live rotations; the independent timer probe covers raw output with no sink call. No days-long soak was run.
- The sink catches write and size-check failures. A closed descriptor loses a line without throwing into the daemon.
- Prefix selection checks both device and inode. A different regular file, a pipe, and a terminal retain the old `io.stderr` path. The checked-in lifecycle test covers a real spawned CLI's pid/time prefix; the unit test connects a real 300 ms transaction through `logLongWrites` to the sink.
- The reviewed status amendment accepts the missing `ps` path, retention after a worktree is removed, and simultaneous successor rotation losing the previous copy. Copy/truncate can also lose concurrent writes between its two operations, as the worker notes disclose. No new blocker was established from these accepted limitations.
