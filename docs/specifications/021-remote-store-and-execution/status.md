- 2026-11-11, the coordinator: 021-02 landed (`research/remote-execution.md`). Recommendation: no remote runner in Squeal now. The case is real again (this host above 16 busy vCPUs in 10 to 43% of samples per day, 3 to 10 November), but the load is background tiers (94% of Squeal's work above the knee) and agents' own runs, so the cheapest step is the whole workspace and its agent on a second machine, which needs no Squeal change. If a remote runner comes later: background tiers of one runner on one SSH host, a remote blob-id check of each run's closure as proof (Mutagen `flush` is not one), results only on an equal environment descriptor, a deadline on every step. Open for the human: the target (this host or laptops), whether a documented setup is an acceptable answer, and a $20 boat.dev trial or a team machine.
- 2026-11-11, the coordinator: 021-01 landed (`research/store-service.md`). Recommendation: no live store; the git-ref route of spec 018 is enough. The first gap is not transport: in cezar 0 of 195,943 imported results are used, because all worktree sessions run Node 24.22.1 and the CI exports Node 26.13.0. Of the transport gaps only branch results are large (48 to 57% of results reused between worktrees were recorded on branch commits, an upper bound). No engine beats the git ref on the bulk read that matters; SQLite is not a bottleneck. If a team later needs branch results across machines: an opt-in transport over an action cache it already runs (bazel-remote HTTP, verified). Loopback timings not measured (load 30 to 86). The Node mismatch was relayed to the 018 coordinator.
