## Choices the spec did not settle

1. **Working directory.** D6 says the host runs with the root as its working directory. `test/daemon/scratch.test.ts` (spec 001 D10, lessons defect 13) requires that a daemon and its descendants hold nothing inside the root between calls. The host starts in the daemon's working directory and enters the root only while a call is in flight, as `inRootWhileRunning` did in-process. Failure text stays relative to the root (`runner-split.md` Q2); the parity test checks it.
2. **The sweep and `beforeForce` stay in the daemon for a local host.** The host sends a `beforeForce` event and waits for the daemon's `forced` notice; the daemon's `cutReading` reads the same process table. A remote host (021-13) must run the reading and the sweep (`afterEachRun`, `EscapedChildren`) itself, since marks and processes are on the remote.
3. **The host lowers its workers and waits for them.** The daemon's `lowerWhile` and `#workersGone` look only at the daemon's own children; the workers are now the host's. `hostWorkers` runs `lowerWhile` in the host with the run's mark and priority, and waits up to `GRACE_MS` for the lane's workers to exit before it replies. Without the wait the daemon's sweep killed exiting workers and wrote a false "left running" note.
4. **Deadlines** (`HOST_DEADLINES`), all finite: start 300 s, other calls 300 s, cancel 60 s, close 30 s, a run its `timeoutMs` plus 300 s. A run with `timeoutMs: null` gets the host watchdog `runIdleMs`, 30 min: the longest the host may go without answering the run or ending one of its files; each `fileEnded` starts it again. File ends never extend a run that has its own timeout. A host past a deadline is killed and gone (review 0.1.434 B3).
5. **After a host is replaced**, the first `invalidate` reports every project recreated, so the keys are read from the new instance (the retry path of a broken config).
6. **`logDir` and coverage payload paths** are the daemon's absolute paths: right for a local host only. A remote host makes its own and sends the files back (D6); coverage payloads need converting on the remote (open question 4).
7. **Coverage provider failure** (`failed` in `src/runners/vitest/coverage.ts`) is per host now: a replaced host tries coverage again, and may note the failure again.
8. **The host's stderr** is kept as a 2,000-character tail for error texts and otherwise dropped. In-process, it was the daemon's stderr.
9. **The `start` reply** names the host's pid, Node version, platform and arch. The full descriptor comparison (D11) is 021-14's. The Squeal version must match exactly: a daemon whose CLI script was replaced in place by another version gets "could not start" until it restarts.
10. **Launch.** `RunnerHostLaunch` carries the daemon's `process.execArgv`, as the CLI entry's own relaunch does: a daemon from the sources (`node --import tsx src/cli/index.ts`) needs its loader in the host (review 0.1.434 B6). A forwarded `--inspect` would make the host's inspector fail to bind its port, which Node only warns about.
11. **Input end during start.** The host keeps the adapter `start` is building; its shutdown waits for it within `closeMs` and closes it, and a close past the bound still runs. That adapter is never served (review 0.1.434 B4).
12. **Framing.** A frame is what follows the marker anywhere in a line (`frameOf`): output without a newline before it is dropped, not the reply (review 0.1.434 S1). A write that lands inside a frame longer than the pipe's atomic size still corrupts it; that loses the host, which is replaced.
13. **No argv0 label** for the host. The command line stays `node <cli> runner-host <root> --runner vitest` so `squeal ps` can find it (coordinator, decision 4).

## Gaps for the next rows

- `squeal ps` does not show the host; its workers show under the daemon as before. Squeal's CPU and memory totals in `ps` leave the host out (D17, 021-14).
- node:test and pytest (021-12): add each to `HOST_RUNNERS` and `buildAdapter`. Their synchronous answers (`tierWidth` from `runner.tierSize`, `besideBacklog`, `backlogSlot`) come from `createRecoveringRunner`'s options today; check whether any must come from the host's values.
- A test's child with inherited stdio under a threads pool writes to the host's fd 1, the protocol channel. Output before a frame is dropped (choice 12); output inside a long frame loses the host, which is replaced. Vitest's fork workers use pipes, so their output never reaches it.
- `inRootWhileAnswering` duplicates `inRootWhileRunning` (`src/core/daemon/scratch.ts`), which takes a whole `DaemonScratch`. A quality pass can make it take `{ workDir }` and drop the copy.
- The nice-10 check in `test/runner-host/daemon-host.test.ts` does not discriminate under Squeal, whose test processes already run at nice 10; it does under plain `vitest run` and CI.
- The parity test runs six scenarios on the `basic` fixture. The whole `test/runners/vitest` suite was not run through the proxy.
