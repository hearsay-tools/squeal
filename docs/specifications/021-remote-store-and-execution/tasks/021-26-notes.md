## Seam map

- `src/core/daemon/runner.ts`, `createRecoveringRunner`: the states are `inner` (the live adapter), `error` (a failed creation), `replaced` (a gone adapter was dropped, D7), and now `parked` (an idle adapter was closed, D20) with `answered` (the environment `inner` last answered). `idleMs` is the new option. Every call that reaches the adapter goes through `call`, which holds the idle clock while it runs.
- `src/core/daemon/runner-idle.ts`: what a planned close means. `IdleClock` (calls in flight, the timer, a recheck that does not count), `Parked`, `reopened` (the first batch after a close) and `driftedProjects`.
- `src/core/daemon/host-idle.ts`: the key's value check, the default from total memory, and the precedence.
- `src/core/daemon/daemon.ts`: `#hostIdleMs()` beside `#processHost()`; `openedAtStart` (exported for its test) decides which runners open at start; the fast Vitest runner, node:test and pytest get `idleMs` only when hosted. `DaemonOptions.hostIdleMs` is for tests.
- `src/core/daemon/node-test-runners.ts`: `hosted(idleMs)` gives `gone` and `idleMs` to a hosted runner; `pytest-runners.ts` uses it (one line, agreed with the parent).
- The batch order that decides the design: `fetchRunnerPart` in `src/core/scheduler/refinement.ts` calls `invalidate`, then `environment` and `testFiles` only when a project is recreated, then always `affected`.

## Decisions the spec did not settle

1. **The batch that arrives while closed starts the next host at once.** The brief said invalidations are "kept and handed to the next adapter". Every batch calls `affected` right after `invalidate`, so the host starts in that batch anyway. Keeping the paths and reporting at a later `invalidate` would let this batch key with the old environment. So the `invalidate` creates the adapter, hands it the batch, and returns its report.
2. **Environment drift.** Beyond what the new adapter's own `invalidate` reports, a project counts as recreated when its environment differs from the one the closed adapter last answered. This catches what a live adapter would have seen while the host was closed: a pytest interpreter change (its recheck), a node:test `node` that runs again, coverage on or off in Vitest's `resolvedConfig`. No comparison when the closed adapter was never asked for its environment.
3. **A batch that changes `squeal.config.json` recreates every project of the runner.** A live adapter compares the policy with the one it was created under (`vitest.exclude`, `vitest.excludeProjects`, coverage, node:test coverage). A new adapter was created under the new policy and cannot see the change. Cost: one full re-resolve of closures after a close and a policy edit; no rerun unless keys move.
4. **A recheck does not restart the idle time** and does not reopen a closed host; it only holds an open one while it runs. Otherwise the quiet passes would keep every host up.
5. **The synchronous members** (`slowWidth`, `tierWidth`, `tierPart`, `omittedTestFiles`) answer from the closed adapter until another exists (D20.1). Only for a planned close; a gone adapter's values are dropped as before.
6. **A runner never created yet** (no error, not parked): its first `invalidate` still reports every project, as before. The start's listing creates the adapter first, so this path does not change in practice.
7. **The default rounds** `total / 8 GiB`: this host reports 47.04 GiB and gets 6; flooring would give 5.
8. **Precedence** (the parent, 2026-11-12): the user config's `runner.hostIdleMinutes`, read once at daemon start, wins; then `squeal.config.json`'s, read each time the clock starts, so a reload applies at the next idle period; then the default, computed once at daemon start. The policy default is `null`.
9. **Not closed by this rule:** lane instances (slow, group, beside a batch) keep `SlowRelease`; the remote lane is unchanged; runners in the daemon's process (no `runnerHost`) never close and still open at start.
