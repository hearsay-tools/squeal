## Choices the brief did not settle

1. **Where the reinstall decides.** The host decides, not the lane. `installed.json` now also holds `installed`, the host's `installedDependenciesFingerprint` of the root right after its install. An `install` request installs again when the lockfile blobs differ, when `node_modules` appeared or went, or when the fingerprint now differs from `installed`. The lane asks for an install once, when a comparison names `installed dependencies differ` or `no installed dependencies on the remote`, and compares again only when the host answers `ran`. So the host makes at most one install per changed install, and a difference that an install cannot mend stands at once on every later connect. The lane keeps no memory for it. No message changed: `install` still takes no argument, so `host.ts` is untouched.
2. **From scratch.** When the lockfile is unchanged but the install changed, the host removes the root `node_modules` first. A repeat `pnpm install --frozen-lockfile` may leave the folders and `node_modules/.pnpm/lock.yaml` as they are (pnpm's `optimisticRepeatInstall`; pnpm 12.15's changelog). Then the stale check reads the folders again, and the refusal stays. A local probe with a `file:` dependency did rewrite `lock.yaml`, but `file:` dependencies are always imported again, so the probe does not show the registry case. When the daemon wrote a file under `node_modules`, the folder is kept (`keepModules`), and the install runs over it.
3. **The connect comparison.** The lane stays `connecting` until the comparison ends. It says `remote <target>: connected (Node <v>), not yet compared`, then `... go there (Node <v>; environment equal)` or `remote <target> refused: <difference>; running here`. Each run still compares (review 0.1.442 B1). Invalidations that come while the lane connects are queued and sent before the comparison: the tree the connect sent may be older than them. A host that connects after `close` is closed.
4. **The cache default** is `.squeal-remote` under the remote home: Squeal's part is `~/.squeal-remote/squeal/`. The `squeal/` level stays because `bundle.ts` adds it to any `cache`. The trial kept a plain `squeal-cache` under the home across a restore. `.squeal-remote` was not tried on boat.dev. The docs name no version in the migration note, because the release that carries it was not known.
5. **The wire form.** `WireFile.size` replaces `data`, and `TreeWrite.gzip` holds the files' bytes one after another, gzip at the default level, then base64. Writes are still split at 8 MiB before compression. No old form stays, because the daemon copies its own bundle to the remote (D14), so both ends are one version. Estimate for this repository (12,111 tracked files): 234.6 MB of bytes, 312.7 MB as base64, and 84.3 MB as gzip and base64 of one stream. Per-message gzip compresses a little worse. Not measured over a real network.
