## Choices the spec did not settle

1. **The protocol version stays 1.** Every new field is optional, and Vitest sends none of them. A host and a daemon of one Squeal version always agree (the version check at `start`).
2. **Data, policy, events.** As for Vitest: what the adapter takes once is data in `start.options.process` (the project entry, `tempDir`, `cacheDir`, a coverage flag, pytest's latest notes); what it reads per run is the policy (`tierSize` for `concurrency`, `inputs`, coverage's `enabled` and `children`); callbacks are events. The policy fields `observe`, `exclude` and `excludeProjects` are Vitest's; the hosted node:test and pytest send their defaults.
3. **Tier width.** The proxy always answers `tierWidth`, with the grant when the host sends no Vitest widths. `createRecoveringRunner` now asks its `tierWidth` option first (`runner.ts`), so a hosted node:test or pytest runner keeps `runner.tierSize`. Only these two runners give that option; Vitest is unchanged.
4. **pytest's `latestNote`** reads the store, which a host never opens. The daemon reads the project's environment topic once and sends it at `start` (`latestNotes`); the host keeps a copy and updates it from each note it sends on a topic, which the daemon stores. A replaced host reads the store again at its `start`. The topic's name is in `pytestEnvironmentTopic`, which repeats the adapter's own (`src/runners/pytest/adapter.ts`, `topic`); `pytest-parity.test.ts`, "writes an environment note only when it changes the topic's latest", fails when the two differ.
5. **What a hosted pytest adapter cannot take**: `source` (the environment runs inherit) is the host's own environment, which is the daemon's unless `ProcessHost.env` is given; `clock` is the real one; `batchSize` comes from the project entry, as `pytest-runners.ts` gives it (`HostedPytestOptions`).
6. **One host per project entry.** Each `nodeTest` and `pytest` entry has its own recovering runner, so its own host: D8's 26 to 46 MiB is per entry, not per runner kind. A reload that adds or drops an entry adds or closes a host (`createRunnerSet`).
7. **Working directory.** The host's `inRootWhileAnswering` applies to these runners too. Both adapters give every child an explicit `cwd`, so it changes nothing for them; it keeps the host out of the root between calls (spec 001 D10).
8. **Tests start hosts from the sources** (`SOURCE_LAUNCH`: `node --import tsx src/cli/index.ts`), not from a build: same code, no `tsc` per file. `daemon-host.test.ts` and `vitest-parity.test.ts` still cover the built CLI.

## Traps found

- **A pytest run reads its events from its `logDir`.** A test that gives two runs one `logDir` reads the first run's results in the second (the edit case passed with the old code). The daemon gives each run its own; the tests now do too.
- **pytest failure messages hold object addresses** (`<function total at 0x...>`), different in every process. The parity test masks them.
- **Node 26 daemon tests.** `test/daemon/resumed-after-signal`, `start-handoff` and `step-down-keeps` fail under this host's Node 26 daemon from revision 0, before any 021-12 edit, and pass on Node 24.22.1 with these changes.

## Gaps for the next rows

- **Remote (021-13).** `tempDir`, `cacheDir` and every run's `logDir` are the daemon's absolute paths: right for a local host only. A remote host makes its own. pytest's `.venv` must be built on the remote (`runner-split.md` Q5); the parity test checks only that a local host uses the root's `.venv` and leaves it in place. A node:test project's `node` (absolute when given) and its probe run where the host is. pytest's `source` is the remote host's environment.
- **Coverage on a remote lane** (open question 4): a node:test covered file's `payload`, `ownRoot` and `children.dir` are absolute paths of the host's machine.
- **`squeal ps`** shows none of these hosts (D17, 021-14), as for Vitest's.
- **Lanes.** A group lane's run reaches the hosted adapter as `RunOptions.lane`, and the adapter's `groupRun` reads it there, as in process. No test runs a group lane through a host.
