Remote layout: `<cache>/squeal/<version>/` (the bundle), `<cache>/squeal/trees/<key>/root` (the tree), `files.json` (what the host wrote: path, blob, mode), `installed.json` (lockfile blobs, and whether `node_modules` existed after), `runs/<runId>/` (the last run's logs). `<key>` is sha256 of this machine's host name and the worktree root, 16 hex.

## Messages added (additive)

- Requests `tree` (entries; answers what is missing, removes what the host wrote and the tree no longer has), `write` (files base64 with blob ids and modes; removed paths), `blobs`, `install`, `coreEnvironment` (allowlist). A host without `--tree` refuses them: a local host never writes into a worktree.
- `invalidate` takes a second argument, a `TreeWrite` the host writes first: one message per revision.
- `run` options may carry `expected` (path to blob id) and `alive` (ms). The reply may carry `refused` (paths; the run did not start), `proof` (blob ids after the run of expected and observed paths) and `logs`.
- Event `alive` during a run. `Deadline.totalMs` bounds a renewable deadline. `HostDeadlines.aliveMs` (remote only: 30 s; `callMs` 120 s there).
- Proxy options `prepare` (requests before `start`) and `invalidateWith`.

## Choices the spec did not settle

1. **File and keys** (open question 1): `remote.json` beside the user config, `{ "repositories": { "<root path or remote URL>": { "target", "runner", "lanes", "whenLost", "node", "cache" } } }`. A bad entry is left out with one problem (note topic `remote-settings`). `target` refuses a leading `-` and whitespace.
2. **Proof against what**: the daemon hashes the closure paths (`local.closure` of each file plus the config files) from its disk at run start, and the expected plus observed paths again after the run. The tier's own snapshot is not in `RunOptions`; the local stability check still compares the disk with the snapshot after the run, so remote equals snapshot through the disk. A path the daemon reads but git ignores is hashed here and absent there: refused, which is right (the remote cannot hold it).
3. **Two refusals, or an environment refusal**: treated like a lost remote: `whenLost` decides (`local` runs it here). An environment refusal closes the host and retries after the backoff.
4. **Reconnect**: backoff 30 s, 1, 2, 5, 10 min; tried at the next background run once due, no timer.
5. **`not-run`** returns a `crashed` report with the reason; the scheduler marks the files `unknown` and ends their retries (`record-tier.ts` `markUnknown`), so there is no loop.
6. **Status (D17)**: daemon notes under one topic; only the newest shows. Written on state changes and on the first proven run of a connection, not every run (each note is a store write).
7. **Hung remote**: the host sends `alive` every `aliveMs / 4`; a run past `aliveMs` without one is lost (`timed-out`, checks `unknown`); the run's own `timeoutMs + runMarginMs` still bounds the whole. Other remote calls have 120 s.
8. **Install**: `installCommand` of the remote tree (npm ci, pnpm/bun `--frozen-lockfile`, yarn), run with `sh -c` in the root, output to the host's stderr. Its lockfile list is duplicated in `tree-host.ts` (`LOCKFILES`) from `scheduler/install-command.ts`, which does not export it.
9. **Coverage**: off on the remote lane (policy coverage false, no provider sent).
