## Blockers

### B1. An explicit Antigravity setup request is silently discarded when detection finds nothing

**Proven. Blocking.** Row 024-05; `src/cli/setup/harnesses.ts:68`, through `src/cli/setup/questions.ts:71` and `src/cli/setup/plan.ts:277`.

The row's contract requires setup to accept `--harness antigravity` and map that harness to `AGENTS.md`. The CLI documents it as a setup choice. An explicit selection must reach `init --harness antigravity`, including when the user is preparing a repository before installation or the managed CLI is not on PATH.

`antigravityFact` returns no fact when neither CLI nor plugin is detected. `answerPlan` only iterates the plan's facts and intersects them with the explicit choices. It therefore drops the requested harness. The approved `instructionFiles` change also receives no Antigravity id, so no block is offered for that selection. `flow.apply` sees no harness and runs a no-op successfully.

A throwaway probe ran the candidate's unmodified `plugins/antigravity/dist/cli/squeal.mjs` in a scratch git repository with a tracked minimal package, an empty scratch HOME, and `PATH=/usr/bin:/bin`. Neither Antigravity executable nor plugin was present. It invoked the two commands below in order:

| Command | Exit | Config exists afterward | AGENTS.md exists | Install command printed |
| --- | --- | --- | --- | --- |
| `setup --yes --no-warmup --harness antigravity` | 0 | false | false | false |
| `init --harness antigravity` | 0 | true | false | true |

The setup output included `Config: squeal.config.json is missing`, then `Changes: none to tracked files` and `Nothing to commit.` Its stderr was empty. Direct init created the default config and printed `install.sh | sh -s -- --antigravity`, proving that the selected harness's supported setup operation had been skipped.

**Worker-sized fix:** preserve an explicitly requested harness through plan construction and answer selection even when detection finds no installation. Include its instruction-file mapping for that explicit request. Keep the existing default plan unchanged when Antigravity is absent and no Antigravity flag was supplied. Add a setup regression with neither binary nor plugin present, asserting the config, default `AGENTS.md` block and install guidance; also check the explicit-block path. The current `test/cli/setup/antigravity.test.ts:116` setup test has both a fake CLI and a plugin, so it cannot catch this case.
