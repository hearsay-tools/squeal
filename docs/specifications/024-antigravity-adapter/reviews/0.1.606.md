### N1. Existing latency rounding can fail a round that already met the raw budget

**Proven. Non-blocking; unchanged code outside the repair delta.** `test/harness/antigravity/latency.test.ts:188`, `:198`, and `:241`.

The measurement loop stops when the raw p95 is below 80 ms. It then rounds p95 with `Math.round`, and the final assertion requires that rounded value to be below 80. A raw p95 of 79.6 ms stops further rounds but becomes 80 and fails. The sandbox's Stop case exhibited this shape: one completed round, reported p95 80, and a final threshold failure. The three lines are unchanged from the base.

A read-only arithmetic probe returned `{"raw":79.6,"anotherRound":false,"reported":80,"assertionPasses":false}`. This explains that sandbox failure. It does not establish that the local Squeal retry at 84 ms met the budget. All failed runs remain reported above.

If taken as a later worker row, use the same unrounded p95 for round selection and the final budget assertion; round only the displayed table. This note is not a new defect introduced by row 024-09 and does not reopen the prior product review.
