### S1. Two latency cases labelled silent never assert empty stdout

**Proven. Non-blocking.** `test/harness/antigravity/latency.test.ts:166`, with case names at lines 123 and 135.

`round()` enables its silence assertion only when `c.name.endsWith("(silent)")`. The names `pre-invocation (after tools, silent)` and `pre-tool-use (run_command, silent)` both return false for that predicate. Neither case sets `speaks`, so neither checks stdout at all. A hook could print an unexpected injection or denial and still pass these cases. Only `stop (silent)` reaches the silence assertion.

A read-only Node probe evaluated the exact predicate on all three names and returned `false`, `false`, `true`. This is a test gap, not evidence that the product emits unexpected output. The targeted e2e tests separately prove silent repeat delivery and allowed run commands, so this does not block row 024-07.

**Worker-sized fix:** give each latency case an explicit expected output or silence flag and use it in `round()`. Set that expectation on all three silent cases. This keeps test behavior independent of display labels.
