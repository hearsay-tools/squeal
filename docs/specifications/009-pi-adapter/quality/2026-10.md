## Verdict

None of the Pi feature's code is dead, and no feature fails the vision's filter. Every handler, the worker host, the idle wake, the status line and `install.sh --pi` trace to a goal of the spec. The cost of 009 is duplication. Three adapters (Pi, OpenCode and part of Codex) each re-wrote the same small things beside `src/harness/shared/` instead of through it:

- the session-start and prompt bodies, two of them in Pi alone;
- the CLI-command formatter, four times;
- the skill-note build step, twice;
- Pi's settings reader, four times, with 009-26 about to add a fifth;
- the test helpers' child-process plumbing, twice.

`status.md`'s amendments match the code. The spec's D6 sentence "changes none of it beyond what a host that is not a hook process needs" is accurate, but it was met by copying shared functions rather than parameterising them: the first finding.

## Slices

1. **One CLI-command formatter.** `piCommand` (`src/harness/pi/worker.ts:16-18`), `piCliCommand` (`src/cli/pi/status.ts:23-25`) and `opencodeCommand` (`src/harness/opencode/bridge.ts:21-23`) are the same line. `codexCommand` (`src/harness/codex/command.ts:19`) is that line with a literal `node`. Move one `nodeCliCommand(cli, node)` beside `shellWord` in `src/core/delivery/` and have all four call it. Then drop `test/cli/pi-status.test.ts:83`, which only asserts that two of the copies agree.
2. **The skill note in the shared build.** `notePiCommand` (`src/harness/pi/build.ts:35-45`) is `noteCodexCommand` (`src/harness/codex/build.ts:39-49`) with another constant, and `SKILL_SOURCE` is declared in both (`pi/build.ts:17`, `codex/build.ts:19`). Give `PluginBuild` (`src/harness/build.ts:56`) an optional skill note that `buildPlugin` inserts after copying, and drop both wrappers. Both build files are key-guarded sources (`status.md`, wave 0), so re-pin `KEY_FORMAT_VERSION` if it is still unreleased.
3. **One idle-wait bound.** `IDLE_WAIT_MS = 3_540_000` (`src/harness/pi/run.ts:132`) restates, as a literal, Claude Code's `WAITER_TIMEOUT_MS` (`src/harness/claude-code/hooks/waiter.ts:13`); its own comment says so. Make it the shared waiter's default in `src/harness/shared/waiter.ts` and import it in both adapters.
4. **Pi's constants once.** `consumerInput` is defined twice (`src/harness/pi/run.ts:19`, `src/harness/pi/session.ts:18`). Pi's writer set is stated twice: `PI_EDIT_TOOLS` in `run.ts:22`, and again inside `ASKED_TOOLS` in `extension.ts:29`. `extension.ts:2` imports `CustomMessageEntryDraft` from Pi directly, past `api.ts`, which exists to be the one door. Put the consumer mapping and the tool sets in `protocol.ts`, which has no runtime imports and so stays safe for the extension bundle. Route the type through `api.ts`.
5. **One unregistered-session check, one install URL.** `piStatusLine` (`src/cli/pi/status.ts:57-63`) repeats `codexStatusLine` (`src/cli/codex/status.ts:27-33`) line for line up to the text. Extract `sessionUnregistered(cwd, sessionId)` beside them. The latest-release `install.sh` URL is in `src/cli/pi/status.ts:16-17` and again in `src/cli/update.ts:33-34`. Keep one constant in `src/cli/plugin-id.ts`.
6. **Shared child-process plumbing for the harness test helpers.** `textOf`, `collect` and `parseEvent` are the same code in `test/helpers/pi.ts:260`, `:269`, `:346` and `test/helpers/opencode.ts:300`, `:309`, `:333`. The refusal of protected env keys is the same three lines (`pi.ts:172-174`, `opencode.ts:117-119`). Move them to one `test/helpers/child.ts`. That also brings `pi.ts` (361 lines) and `opencode.ts` (340) under the styleguide's ~300.
7. **The launcher copy test misses OpenCode.** Four committed launchers are byte-identical (`plugins/{claude-code,codex,opencode,pi}/bin/squeal-launcher`), but `test/cli/launcher.test.ts:183` checks only `codex` and `pi`, so an OpenCode copy left behind at the next format rise (009-23 N1 had to edit every copy) would pass. Add `"opencode"` to its `it.each`.
