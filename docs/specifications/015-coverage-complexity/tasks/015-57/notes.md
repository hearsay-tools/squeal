## What changed

- **A condition carries its records in hand** (`file.ts`). `FileCondition`'s `pending` and `unknown` gain `ready`, the ready loaders (key and stored time) among the source's loaders. `coverageOf(..., inHand)` leaves out a record that cannot vouch for the source's bytes (no record, the source in its `unread`, another blob) where the full join returns `unread`. Only records at the source's current blob count (D9).
- **An early judgement** (`walk.ts`, `judgeEarly`). A file that is not ready, or ready with a record that cannot vouch (`unread`), is judged from its ready loaders' records when all of these hold: it has at least one ready loader; it has a `crap` or `uncovered` `fail` state; the signature of its ready loaders is not the one its summary entry holds as `early`. It decodes those records within the step's budget, as a full judgement does, and adds a `Judged` with `early: true`. The summary entry stays `pending` or `unknown` and gains `early`, so the file is judged again only when its records in hand change, and in full once every record is in. A recount's file stays in `quiet` until that full judgement, and its early judgement is quiet too.
- **What an early judgement writes** (`judge.ts`, `judgeMeasure`). Only a measure whose last state is `fail` and whose records in hand give `pass`: its state, its FAIL -> PASS transition (none when quiet), and D6's edit mark as a full judgement makes it. Every other state keeps its last judgement: a new failure, a STILL FAIL and a first-seen failure wait for every record. A failure that only a change of `crap.threshold` passes is kept too, since the value in hand is an upper bound and cannot say whether the coverage passed it as well; a judgement with every record then decides it as on main.
- **Evidence** (`walk.ts`, `writeJudgement`; `judge.ts`, `evidenceOf`). An early judgement writes the evidence of the functions it judged over the file's last evidence for the rest. So `PASS uncovered: cold (src/a.ts:2): test/new.test.ts runs it in process` names the test files in hand, in main's words.
- **The failure gate** (`cache.ts`, `StepCache.failing` and `judged`). Whether a file has a coverage failure is read with the existing per-path `states.list(worktreeId, { paths: [path], outcome: "fail" })`, one `work()` unit, once for each path and blob. A move or a removal changes the file's blob, so it is read again. A full or early judgement of the file drops the entry. The early signature has its own memo beside the full one's, cleared by `invalidate`.
- **The summary field** (`summary.ts`). `FileSummary` `pending` and `unknown` gain `early?: string`. No summary version raise; `readSummary` is unchanged and reads a summary with or without it.

## Decisions

1. **The stored field** (request `5f7111dc`, the coordinator's reply: option A). `early?: string` on `pending` and `unknown` in code meta `coverage:<worktreeId>`, the `signatureOf` of the ready loaders the early judgement read. Without it, a quiet recount file judged early would be judged again at each step, and the chain would not end. An older Squeal ignores the field and drops it at its next write; this Squeal then judges that file early once more, with no transition (test: "judges an early file once ... after an older Squeal's summary").
2. **No text change** (same reply). An early PASS uses main's texts with the evidence from the records in hand: `PASS CRAP: cold (src/a.ts:2) is 6, at or under 30`. No text says the value is final. "At most" is not built in this row. The coordinator amends D9 at integration: an early value is an upper bound, shown in main's words, and it can only fall.
3. **Only a failure is judged early** (my choice, sent to the coordinator as progress `0ef8ccd0`). D9 says a function proven at or under the threshold "is judged `pass`". I judge only a `fail` that way. A `pending`, absent, `unknown` or `pass` state keeps its last judgement, as on main. Reasons:
   - Only a failure can be told FAIL -> PASS, so nothing told is lost.
   - Cost. An edit to a widely imported file re-keys most test files, so nearly every source turns pending while most of its loaders stay ready. Each arriving record changes those sources' records in hand. Judged early each time, every source would decode and join its records once per arrival; main judges each source once, when every record is in. The gate limits early work to the files with a failure.
   - A `pass -> pass` rewrite from fewer records would raise the value shown (`squeal code` read 12, then 20 from a subset), against "it can only fall".
   - A bulk read of every failing state per step was ruled out: the store's own comment on `statesOf` measures a scan of a worktree's states at 48 to 65 ms cold, the whole step budget.
