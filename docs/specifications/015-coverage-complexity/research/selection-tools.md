# Reduce runs with structural selection, while keeping omitted results stale

**Adapt Testmon's structural method inside runner adapters; do not reuse old results at changed keys.** The probes show useful skips on ordinary function edits, including real warm Vitest with Squeal's provider. They also prove remaining misses. A project could opt into fewer background runs with explicit validation debt. This is not evidence for unconditional current-result reuse.

## Algorithms, evidence and reuse

**Read in source code**, Testmon stable 2.2.0 (`dccc58d2`) and beta 2.3.0b0 (`94150742`): `process_code.Module.dump_and_block` separates function bodies from surrounding AST structure. Definitions, parameters and module statements remain in the enclosing block. `create_fingerprint` retains block CRC32 checksums intersecting a test's measured lines. `db.check_fingerprint_db` selects a test when its recorded checksums no longer occur in the new module. It therefore catches insertions into an executed function even when the old changed-line intersection is empty. The block counter can make structural rearrangements select more tests. This is not a control-flow or effect analysis, and CRC32 equality is not a collision-free equivalence proof.

**Read in source code:** coverage.py contexts associate executed Python lines with pytest cases. New and previously failing tests run. Local SQLite stores fingerprints and outcomes. Environment names, Python version and installed package information partition evidence; package patch versions are stripped. Testmon does not establish Squeal's complete environment/input identity. An unexecuted function observed through metadata or reflection can lack the required dependency. The real signature case demonstrates this, despite signatures remaining in module structure.

**Verified by experiment:** stable and beta are separate runs using the same Python 3.12.3, pytest 9.0.2 and coverage.py 7.13.1. Both select 1/8 for refactoring a shipping function, changing its result, inserting a failing branch and changing its previously unexecuted branch. Both skip a comment-only shift. Both miss five named cases: function metadata, function constants inspected without calling it, data, child execution and an unkeyed environment variable. Explicit `--testmon-env` invalidation catches the environment case. These adversarial counts do not estimate production failure frequency. The stable source's 19 structural tests pass; its downloaded full test file has two absent-fixture failures. Current open issues [191](https://github.com/tarpas/pytest-testmon/issues/191), [178](https://github.com/tarpas/pytest-testmon/issues/178) and [192](https://github.com/tarpas/pytest-testmon/issues/192) describe related risks; issue reports alone are not independent confirmation.

**Read in source code / official docs**, StrykerJS 10.1.1 tree `c48089a6`: `mutant-test-planner.ts` selects covering test IDs for runtime mutants. Static/module-load mutants use all tests unless explicitly ignored. Missing coverage also broadens execution. Incremental mode **still requires its dry run**. Its docs explicitly exclude changes in nonmutated helpers, environment, dependencies and snapshots from incremental invalidation. Mutation sites are known and instrumented; arbitrary insertions, changed declarations and old coverage across arbitrary edits do not inherit that justification. Reuse its separation of runtime and module-load effects, not its incremental report as a regression-test cache. Its Vitest runner advertises `>=2`, while the checked package develops against 4.1.12; compatibility with this repository's Vitest 5 was not run. No Stryker runtime experiment is claimed.

**Read in official docs**, Wallaby docs fetched 2026-10-27, CLI 1.0.28, CLI skill version 4.0 at `89262b7f`: `wallaby-skill run`, `analyze`, `inspect` and `stop` provide a persistent local instance. `run` returns Markdown reports, exit status and links to scoped results; exclusive file scope differs from project scope. MCP exposes tests, traces, coverage, runtime values and snapshot operations, and requires an already-running editor instance in the examined setup docs. The CLI can start standalone without an editor. Cached startup results are documented as reverified in the background. No exact-key, revision-bound result API suitable for C3/C4 was established.

**Read in official docs / package metadata:** Wallaby's CLI requires Node 22+. Local access uses an existing licensed extension or email-activated free beta access. Container/cloud access requires a token; future separate paid access is possible. Purchased editor licenses cover the purchased version plus 12 months of updates. The inspected CLI tarball has no LICENSE file or package `license` field; that grants no right to embed the engine. **Untested:** no activation, purchase, CLI execution or reliability benchmark. Its fine-grained selection and full-project accuracy statements remain vendor claims, not a verified algorithm or guarantee.

**Read in official docs:** coverage.py is Testmon's collector, not another selector. Its linked trouble page lists tracing conflicts and unobserved execution. Testmon's hidden-dependencies article recommends isolation, reverse order and tools such as pytest-forked/pytest-flakefinder to expose test coupling. These can test a selector's assumptions; they do not select arbitrary source edits themselves.

## Measured reduction and cost

**Verified by experiment:** the independent JS method hashes complete top-level function bodies and a module skeleton that retains signatures and module effects. It uses complete parsing, exact function ranges and input provenance, not lexical hazard scanning. Classes, arrows and nested-function details are conservatively retained in larger blocks. The cold-process probe has 31 cases. Actual Squeal recorder evidence closes its data/descriptor and child-process examples; reflection, raw source text and an unkeyed environment remain escapes. Separate experimental wrappers have narrower coverage and are not product capabilities.

**Verified by experiment:** warm Vitest 5.0.3 uses the actual Squeal `provider.mjs`, `mapScript`, input recorder and Vite import graph. Each arm has an independent persistent instance, one worker, isolation, a cold run and a passing warm baseline. Ordinary files contain three real parameterized utility tests each, with no synthetic delay. The selected arm collects coverage; the exhaustive arm has coverage off; both retain input recording. Payload mapping and selected-run record refresh are included. Counts come from reporter events, not cumulative Vitest state. All evidence, collection diagnostics, worker identities and process-tree timing are preserved.

Five ordinary refactor pairs, median CPU/wall milliseconds:

| Tool/arm | Files / cases executed | CPU | Wall | Collection wall |
| --- | ---: | ---: | ---: | ---: |
| Testmon stable, selected | 1 / 1 | 380 | 380 | Not separately instrumented |
| Plain pytest stable oracle | 8 / 8 | 244 | 245 | Not separately instrumented |
| Testmon beta, selected | 1 / 1 | 373 | 374 | Not separately instrumented |
| Plain pytest beta oracle | 8 / 8 | 252 | 253 | Not separately instrumented |
| Warm Vitest, selected + provider + mapping | 1 / 3 | 200 | 147 | 9.7 |
| Warm Vitest, exhaustive, coverage off | 8 / 24 | 1,380 | 990 | 89.0 |

Warm selection adds a median 1.9 ms outside those run totals. Its all-file baseline costs 1,580 ms CPU / 1,185 ms wall with coverage, versus 1,360 / 976 without it. The host has 24 CPUs; warm-run one-minute load ranges from 5.89 to 8.35. CPU resolution is 10 ms. Vite and its transforms stay warm, but recorded thread IDs show that Vitest replaces isolated test workers between files. This is **not** evidence from one continuously resident test worker. Turning isolation off would disable this provider's per-file collection.

The 18 warm cases include successful shipping and tax body refactors, detected shipping/label regressions, branch insertion, module/signature broadening, data, child execution, a changed gate dependency, stale evidence and syntax errors. Ordinary changes avoid seven files and 21 cases. Reflection and raw-source-read cases select zero and miss one failing file each. Syntax failures occur during collection: eight files attempted, zero test cases executed. [Audited counts and timings](probes/selection-tools/summary.json) retain all denominators.

**Limits:** this is a small shared utility fixture, not a repository sample. Five refactor pairs measure one ordinary shape. No claim follows about production projects, source-map variants, cancellation, parallel file execution, cross-worktree reuse or fleet CPU. The Python fixture shows why fewer tests alone is insufficient: plugin overhead exceeds the saved work for short tests.

## Existing fallback evidence and what is missing

**Read in source code; experimentally checked where noted:**

| Condition | Existing Squeal evidence and limit |
| --- | --- |
| Test, setup, config, package or allowlisted environment changes | C3 environment/full closure keys. Do not narrow these changes using old source hits. An unallowlisted variable remains unsupported. |
| Data or directory changes | Node recorder `fs.cjs` supplies `ObservedInputs.paths/directories`; retain their whole-input hashes. Actual data/descriptor cases work. Python observes imports, not arbitrary file reads; use declared `inputs` or retain broad validation. |
| Child-only execution | Node `spawn.cjs` and `ObservedInputs.direct` retain started-process module paths. The real child case works by keeping the whole child module. Python `sitecustomize.py` reports inherited-environment child imports. Neither provides complete child function coverage; absent observations prove nothing. |
| Other source changes, including branch gates | Static Vite import closure plus recorded inputs, not coverage alone. The warm probe first omitted the static closure and missed a gate edit; adding the actual graph closes it. |
| Missing, stale or incompatible coverage | D8 provider version, source blob, result key, unread records and C3 runtime/environment identity. The prototype tests hash/tag rejection; it does not implement the full acceptance barrier. Require evidence for the exact pre-edit input snapshot. |
| Reflection or source read as data | No general detector exists here. `f` paths combine module loads and reads; `modules` does not prove a module was never read as text. A `toString` wrapper misses other realms and changes observable behavior. The warm probe deliberately preserves these misses. |

## Recommendation and honest status

**Inferred:** adapt the method for JS/TS rather than embed Testmon's Python AST machinery or Stryker's mutant runtime. Acorn and the existing provider/mapper already supply useful parts. Copying Testmon code requires its MIT notice; copying Stryker code requires Apache-2.0 compliance. No external code was copied into this prototype. For pytest, an optional **direct Testmon plugin integration** is preferable to reimplementing its selector, but requires dependency/version negotiation, local per-worktree database ownership, explicit environment identity, and translation of case selections into complete file runs. A deselected case is not a fresh passing result. Wallaby is a possible licensed optional backend, not a library to bundle; provenance and result APIs need validation first.

This research proves **no new cross-key result reuse**. Existing equal-key lookup remains the reuse path. An optional skip-and-stale mode would run structurally affected files and known fallbacks, then leave other changed-key files stale with their old verdict, revision and omission reason. It removes background work rather than merely changing queue order. It also leaves validation debt and can delay failures such as the demonstrated reflection cases. Keep it off by default and outside unsupported project scopes; a policy opt-in is acceptance of that risk, not proof that effects are complete.

Affected status must still select the full C3 closure population. In the ordinary example it reports one current file and seven stale files, not eight current passes. `status <source>` and source-path waits remain incomplete (`selection.result: none`, exit 3), naming omitted files and how to run them. Current C15 lets a wait naming a stale test file itself request one run under its existing unqueued/unclaimed/not-already-requested conditions; source-path waits do not automatically request all readers. Explicit retry/demand must bypass structural skipping. A current-result completion gate cannot accept the stale seven.

An explicit full-suite checkpoint must include every eligible file and bypass the skip policy. It may use only reuse accepted by its existing exact-key/checkpoint rules; it cannot count structural omissions as executed or current. A forced checkpoint runs every requested file. A new edit during verification follows the existing acceptance/revision rules and leaves the new debt visible. No new checkpoint success or PASS transition is minted from a selection decision.

**Bounded next validation:** the real warm-provider fixture is now executed, not deferred. Before a product spec, run a fixed maximum of 20 existing Vitest files and ten ordinary historical edits in an isolated checkout with shadow selection and exhaustive comparison within that sample. Record eligibility, avoided runs, misses and end-to-end CPU with warm workers. Add concurrency/source-stamp acceptance and source-as-data provenance tests. Stop on the first missed regression or two hours. Do not enable current-result reuse or global skipping from this fixture evidence.
