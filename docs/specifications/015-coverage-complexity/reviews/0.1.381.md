Location: `src/cli/code-crap-reason.ts:40`, called from
`src/cli/code-coverage.ts:142`.

The new branch treats a file summary of `judged` at the state's blob as
proof that an unknown CRAP came from an unresolved function join. It is not
sufficient proof. `judgeFiles` skips a function whose complexity state is
unknown due to a parse error (`src/core/code/crap/judge.ts:95`). The file
can become judged while that function keeps an earlier unknown CRAP.

Reproduction with `test/code/crap/rig.ts`:

1. Count `src/a.ts` containing `hot 12 h1 !\n`. The fake counter's documented
   `!` marker puts the function inside a parse error. Complexity is unknown.
2. Add `test/a.test.ts` as a loader of that source, with outcomes
   `["pass", "skip"]` and `sourceOf("src/a.ts", blob, 1, [1])`. Step coverage.
   The file is unknown/skipped. Dropping its previous loader set makes
   `hot`'s CRAP unknown at the source blob.
3. Replace the loader with a new key, a passing result and the same complete
   record, with no skip. Step coverage. The file is now judged at that blob,
   but `judgeFiles` skips `hot` because complexity is still unknown.
4. Read the path report. The new JSON says:

```json
{
  "outcome": "unknown",
  "complexity": 12,
  "coverage": {
    "crap": {
      "outcome": "unknown",
      "value": null,
      "reason": "the coverage records cannot tell whether it ran"
    },
    "uncovered": "unknown",
    "lines": 1,
    "covered": 1,
    "testFiles": 1,

```

The probe also calls `coverageOf` on this count and record. It asserts
`runBy: ["test/a.test.ts"]`, `lines: 1`, `covered: 1`. The join can tell that
the function ran. The missing complexity judgement prevents a CRAP score.

also attributes the unknown to the wrong evidence.
