## Blockers

### B1. Proven: an edited test path loses all but one project from the window total

Location: `src/core/reach/window.ts:46`, `src/core/reach/window.ts:52`.

D11 requires `window.rerunSeconds` to sum “the union of suite test-file seconds re-run by each edit.” A test file's identity includes its project. The new `Map(path -> index)` keeps only the last project instance of a shared test path. Source reach uses all suite indexes, while the edited test's own reach adds just that one surviving index.

Cheap reproduction, run with `pnpm exec tsx --eval '<code below>'` at the candidate:

```ts
import { buildReport } from './src/core/reach/report.ts';
import { snapshot, testFile } from './test/reach/fixture.ts';
const path = 'test/shared.test.ts';
const tests = [
  testFile(path, [path, 'src/a.ts'], { project: 'node', seconds: 2 }),
  testFile(path, [path, 'src/a.ts'], { project: 'browser', seconds: 5 }),
];
const r = buildReport(snapshot(tests, { edits: [
  { at: 1, paths: [path] },
  { at: 2, paths: ['src/a.ts'] },
] }), { paths: null, limit: null, command: 'squeal', listed: 2 });
console.log(r.suite.seconds, r.window?.rerunSeconds, r.byEdits[0]?.editShare);
if (r.window?.rerunSeconds !== 14) process.exitCode = 1;
```

Actual: suite `7`, window `12`, source `editShare` `0.5833333333333334`; assertion exits 1. Expected: both edits re-run both instances, so window `14` and source share `0.5`. Reversing suite order changes the wrong denominator to 9. Every file and gateway share uses this denominator, so the error changes the report's primary cost claims.

Worker-sized fix: index every suite instance by physical path, add all of those indexes to each edit's union, and retain per-edit deduplication. Add an overlapping-project regression that checks the total and file/gateway shares, including reversed suite order and a multi-file edit. Keep each project's recorded seconds separate.

### B2. Proven: factual runtime-read notes discard the observations they describe

Locations: `src/core/reach/entries.ts:81`, `src/core/reach/observers.ts:53`, `src/core/reach/gateways.ts:225`.

D11 requires runtime-read and child-process notes to state recorded facts, including the path, test count and how tests reach it. Sharing a reach set does not prove that files share those observations. The new `noteOf` takes the first file's observers and applies them to every file in a collapsed entry.

Reproduction, also run through `pnpm exec tsx --eval`:

```ts
import { buildReport } from './src/core/reach/report.ts';
import { snapshot, testFile } from './test/reach/fixture.ts';
const paths = ['src/a.ts', 'src/b.ts'];
const tests = [
  testFile('test/x.test.ts', paths,
    { seconds: 4, childProcess: new Set(paths) }),
  testFile('test/y.test.ts', paths,
    { seconds: 2, runtimeRead: new Set(paths) }),
  testFile('test/z.test.ts', paths,
    { seconds: 1, childProcess: new Set([paths[0]]),
      runtimeRead: new Set([paths[1]]) }),
];
const s = snapshot(tests, { edits: [{ at: 1, paths }] });
const o = { paths: null, limit: null, command: 'squeal', listed: 3 };
console.log(buildReport(s, o).files[0]);
console.log(buildReport(s, { ...o, paths }).named?.map(f => [f.path, f.note]));
```

Actual ranked entry collapses both files and says `1 test file reads these files at run time in its own process; 2 test files load these files in a process they start`. The named view correctly says that **b.ts** has **two runtime readers and one child loader**. The ranked note makes a false statement about b.ts. Both text and JSON contain it. This behavior is new in the factual-note implementation; the old blanket note made no such per-file counts.

The same new note machinery also discards project identity. A second probe used two project instances of `test/daemon/shared.test.ts`, with durations 2 and 5 seconds and the same 10 runtime-read modules. The resulting entry has `testFiles: 2`, but its note starts `1 test file reads these files`. `Observers.broad` and the gateway's local `broad` map use only the test path, overwriting one instance. For an observed data-path gateway, `tests.length - broad.size` can then turn the discarded broad reader into a false “own process” count.

Worker-sized fix: preserve `(project, path)` identity while collecting observer evidence. Only reuse a file's factual note for other files when their observer facts agree; otherwise split the entry or state the facts per file. Carry that identity through gateway note counting, while keeping physical paths for display and folder grouping. Add both mixed-observation collapse and overlapping-project regressions. Check ranked, named and gateway notes against the same stored facts.
