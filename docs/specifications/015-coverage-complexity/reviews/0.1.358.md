## Blocker B1: a real tsx map loses its source text, then receives the edited file's blob

**Proven.** `src/core/code/coverage/own.ts:58`, with `src/runners/node-test/runtime/recorder.cjs:56`.

The brief requires that under tsx, "the blob is that of the source the loader read." The worker's proposed D8 text makes the same promise. D8's record identifies the bytes that ran, not the bytes available later.

The recorder deletes `NODE_V8_COVERAGE` before the project's `--import tsx` initializes. In the installed tsx 4.23.15, the transform options include:

```js
sourcesContent: !!process.env.NODE_V8_COVERAGE || /* inspector enabled */
```

With the candidate recorder, a real payload still contains the script's source map and executed line lengths, but its `sourcesContent` is `[null]`. `ownSource` then reads the file on disk at line 58. It uses those bytes both for the blob and as the source text of the old map at lines 66 to 70. An edit between execution and mapping therefore produces a record that labels the old execution with the new blob.

This is different from decision 2's explicit map-time limit **without a map**. Here the loader transformed the file and supplied its own map; the source text was lost because of Squeal's startup change.
