## Blockers

### B1, proven: delayed coverage reuses an own-edit mark after git replaces the body

**Where:** `src/core/code/crap/step.ts:165` and `src/core/code/crap/judge.ts:80`.

**Contract:** D6 says a body git brought is no edit. The 015-41 brief explicitly requires coverage STILL FAIL to occur “never for a body git brought”. Goal 5 applies to the session's first edit that leaves the function failing. The vision also requires code-state provenance to stay truthful.

The new coverage step reads every retained complexity edit of the judged paths. The judge tests only `edit.revision > was.countedAt`. A later git change does not clear the earlier complexity edit. Its retained mark therefore qualifies a different, git-provided body for STILL FAIL at the later judgement's time.

**Reproduction:** use `coverageRig`, `sourceOf` and `consumer` from `test/code/crap/rig.ts`. Mirror each fake worktree revision into the main store, so the registered session has `{ since: 1, gaps: [] }`, rather than relying only on timestamps.

1. At revision 1, commit/count `src/a.ts` as `cold 6 c1\n`. Store a current loader record for that blob with no hit. Judge coverage: CRAP is 42 and uncovered fails. Register the session.
2. At revision 2, make an own edit to `cold 5 c2\n`. Run the complexity pass. Give the loader a new queued key, with no results or record, and run the coverage step. The coverage states keep their revision-1 judgement. The own edit would give CRAP 30 with no coverage, at the threshold, if judged.
3. At revision 3, use the rig's `pull` to commit/count `cold 8 c3\n`. This is a changed body git brought. Assert the persisted pulled record is `[["src/a.ts", 3]]` and the retained complexity edit is revision 2.
4. Store only the revision-3 blob's current no-hit record and run the coverage step. Deliver to the session.

Expected: no STILL FAIL caused by this git body. Actual:

```text
STILL FAIL CRAP: cold (src/a.ts:1) is 72 after the edit; it was already over 30 before it (CC 8); no in-process test that Squeal runs reaches it; Squeal stays quiet about it until it is at or under 30, and squeal code src/a.ts shows its CRAP.
STILL FAIL uncovered: cold (src/a.ts:1): no in-process test that Squeal runs reaches it after the edit; none reached it before it either (CC 8); Squeal stays quiet about it until an in-process test runs it, and squeal code src/a.ts shows its coverage.
```

The candidate test for a git body starts with no outstanding own edit, so it misses this sequence. The independent passing control keeps revision 2 pending across two unrelated file edits, then judges its own blob; it receives both expected STILL FAIL lines. A second passing control registers another session at revision 2 before judgement: that session gets neither line, while the original session gets both.

**One-worker repair:** make the coverage edit mark apply to the body being judged. Suppress or invalidate an older own-edit mark when a later git change replaced that body. The existing persisted pulled provenance can distinguish the demonstrated case; preserve an own edit across unrelated revisions and delayed records. Add the sequence above beside `still-fail.test.ts`, including an own edit after the pull to prove that delivery resumes. Do not change git FAIL/recovery rules or complexity-only output.
