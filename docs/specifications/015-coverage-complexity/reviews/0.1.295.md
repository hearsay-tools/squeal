## Blockers

### B1: proven: the import rewrite can erase real functions between two strings

Location: `src/core/code/count/parser.ts:46` and `:61`.

D3 requires the counter to count every function like ESLint. The 015-29 done-when also requires strings, comments and templates to stay intact. The regex runs over the whole file without lexical context. Its single-quoted alternative allows double quotes. It can therefore start inside one double-quoted string and finish inside another, consuming actual code between them.

This valid JavaScript reproduces the break through `countFile(text, "typescript")` at the candidate:

```js
const s = "typeof import('"; function hidden(a) { return a ? 1 : 2; }; const t = "')";
```

```text
candidate countFile: functions: [], errors: []
same TSX grammar and counting rules, without the rewrite:
  hidden, complexity: 2, decisions: { ternary: 1 }, errors: []
```

The replacement preserves offsets but removes the function from the parse. This can silently retire a known code check. Reading names and hashes from the original text does not repair a node that no longer exists. The current string test covers a quoted key whose token boundaries survive. It does not cover a match that crosses token boundaries.

Fix in one worker: restrict the rewrite to actual import/type syntax, with a token or tree scan that preserves strings, comments, templates and regular expressions. Keep the same-length replacement and original-text names/hashes. Add this regression and retain both type-import fixtures. Raise `COUNTER_VERSION` when the stored count's meaning changes.

### B3: proven: a cancelled run can store a coverage record
