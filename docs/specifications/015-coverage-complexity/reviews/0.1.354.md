## Blocker

### B1, proven: preserve measured function evidence beside an unmeasured loader

Location: `src/cli/code-coverage.ts:88` and `:108`.
Producer: `src/core/code/crap/file.ts:71`.

`FileSummary.runners` names any loader whose runner gives no record. It does
not prove that every loader is such a runner, or that no current record measures
a particular function. `notMeasuredBy` treats its presence as that proof.
`coverageByFunction` then returns only `notMeasured`, before reading the
function's judged states and evidence.

This breaks the boundary the brief sets: the new wording is for functions
that **only** tests without coverage run. D9's **A pass proven early** keeps a
pass that current records prove even while another loader makes the source
unknown. D6's details command must expose that evidence. The new JSON field's
own contract at `src/cli/code-coverage.ts:42` says "only runners whose runs give
no record load it". The implementation does not establish that fact. Vision
principle 2 requires Squeal to distinguish what it has validated from what it
has never checked.

Reproduction using the existing `coverageRig` and `sourceOf` helpers:

1. Count `src/a.ts` containing `hot 12 h1\n`. Give its Vitest loader an empty
   record and step. Its states are `hot fail 156` and `hot fail -`.
2. Add a node:test loader of that source in project `node`. Give the existing
   Vitest loader a new current key with a record whose `sourceOf` entry covers
   line 1 of the source's current blob.
3. Step with a `ClosureIndex.environment` that returns `node-test` for project
   `node`, and `vitest` for the Vitest project. Keep both closures and keys
   current. The source is unknown due to node:test. The early judgement correctly
   writes `hot pass 12` and `hot pass -` and retains its current evidence.
4. Read `readCodeReport` with `paths: ['src/a.ts']` and format it. Actual output:

   ```text
   Complexity: 1 function in src/a.ts, threshold 20
     src/a.ts:1  hot  CC 12 (if 11), at or under; not measured: node:test gives no coverage
   ```

   Actual per-function JSON: `{ "notMeasured": ["node:test"] }`. It omits the
   proven CRAP pass and the evidence that Vitest ran the function.

The probe uses the real loader builder, coverage step, store and public report
functions. Its assertion expects the report to retain the proven pass instead
of setting `notMeasured`, and fails at this candidate.

Fix size: one worker. Restrict the new label to functions without usable measured
evidence. Keep the current early-pass states and their evidence visible in mixed
projects. Keep the node:test-only wording unchanged. Add a regression test with
one Vitest loader and one node:test loader that checks both text and JSON. Check
the no-path aggregate too, since `coverageReport` uses the same file-level helper.
No runner coverage implementation or key change is needed.
