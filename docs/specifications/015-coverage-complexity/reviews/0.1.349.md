## Should-fix

### S1. Proven: concurrent adapters can emit distinct fallback notes

**Proven behavior.** Locations: `src/runners/vitest/coverage.ts:81`, `src/runners/vitest/adapter.ts:688`, and the unchanged `noteOnce` helper at `src/runners/vitest/optimizer.ts:94`.

Two already-open adapters can run before either records a provider failure. They share one `VitestCoverage` object, as the daemon's fast and slow instances do. If the two load failures have different causes, each call to `recordProviderFailure` adds the same object to the WeakSet and returns a fresh note. `noteOnce` deduplicates the full text, so both notes are emitted. It does not preserve one first failure for the shared object.

The real-Vitest probe used one copied `client-env` fixture root, one shared coverage object and two adapters. It passed `childEnv: { SQUEAL_REVIEW_VARIANT: "fast" }` to one and `"slow"` to the other. The provider lived outside the root. Its main-process sibling re-exported the real provider. Its content was:

```js
const sibling = import.meta.url.replace(
  /provider\.mjs$/,
  "sibling-" + (process.env.SQUEAL_REVIEW_VARIANT ?? "main") + ".mjs",
);
const { default: provider } = await import(/* @vite-ignore */ sibling);
export default provider;
```

Only `sibling-main.mjs` existed. Both adapters were opened and their environments read before `Promise.all` ran `test/plain.test.ts` on both. Actual output:

```text
ends: ["crashed", "crashed"]
notes[0]: coverage is off until the daemon restarts: ... sibling-slow.mjs ... (ERR_MODULE_NOT_FOUND) (spec 015 D8)
notes[1]: coverage is off until the daemon restarts: ... sibling-fast.mjs ... (ERR_MODULE_NOT_FOUND) (spec 015 D8)
```

This probe supplies different causes deliberately. It does not show that the current bundled provider produces different causes in normal operation, or that a subsequent coverage-off run loses a verdict. Its scratch was removed. W1 says "keep coverage off for the adapter's life, note it once"; the implementation extends the failed state to the daemon's shared coverage object. The coordinator explicitly confirmed one note per adapter life in reply `95d20a17-2a81-4952-9009-c299b3e7640b` to review request `d45832e2-f96b-43d0-8507-13b77ab55944` (2026-10-26). One note each, then quiet with coverage off, meets the row. The coordinator assigned the shared-object note ownership improvement to a later 015 row. This is nonblocking.

A bounded follow-up: keep note ownership with the first failure on the shared coverage object. Keep failure recognition separate, so every already-running failed instance still closes and reports its own run failure. Do not return `null` for a later recognized failure merely to suppress its note. Add a regression with both adapters open before concurrent failures with distinct causes.
