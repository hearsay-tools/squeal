**Location:** `src/core/code/pass/stage-edit.ts:60`, with move matching at lines 70–74 and removal judgement at lines 76–83. **Contract:** row 015-55 says the states, transitions and edits must equal main's. The review brief also requires equal moves between parts and one transaction. D2 says the moved check takes over the old state and delivery view.

Each part reads `before` in SQLite order, but `gone` concatenates the parts in the plan's JavaScript string order. The one-transaction path reads all old states in SQLite `BINARY` order (`store/states.ts:88`). UTF-16 and UTF-8 order differ for paths containing supplementary characters versus U+E000–U+FFFF. When the two paths fall in different parts, `matchMoves` can choose another source for an equal body hash. This is the worker notes' order caveat, now verified to change more than the move report.
