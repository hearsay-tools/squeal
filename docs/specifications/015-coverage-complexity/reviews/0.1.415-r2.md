## Remaining blocker

### B2. The same environment hash can still resolve identical importer bytes to different files

**Proven.** `src/core/store/import-edges.ts:51`, `218`–`235`; `src/core/store/import-graph.ts:80`–`85`, `120`–`126`.

The repaired key is `(path, blob, project, environment)`. It separates aliases encoded in different configs, but resolution also depends on source-file presence. Those files are not in the project's environment hash. A conflicting walk still overwrites the sole row, which the other worktree reads as current.

Reproduction:

1. Create two roots with identical package, Vitest config, setup and reporter bytes. Give both the same core environment inputs and installed-dependency identity. Use one shared store.
2. In both roots, write `src/gateway.ts` as:

   ```ts
   export { value } from "./leaf.js";
   ```

3. Both roots contain `src/leaf.ts`, exporting `value`. Root two also contains `src/leaf.js`. Root one has no `src/leaf.js`.
4. A real Vitest test imports `gateway.ts`. Read each adapter's `closure()` and `environment()`, calculate the environment hash, and persist each part through `recordImportGraph`.
5. Read root one's targets again after root two writes.

Actual evidence:

```text
Both gateway sha1 values: bc32424c0345467f6661f998d41aa0b0f04a65b2
Real closure one: static ["src/leaf.ts"]
Real closure two: static ["src/leaf.js"]
Both environment hashes:
  dad12ddcaa68b8f4f00ac07c7170b301c59d75ca4e552a4d2e11ed68a5279663

readImportGraph(store, rootOne, "one").targets("src/gateway.ts", ""):
  {static:["src/leaf.js"],dynamic:[]}
readImportGraph(store, rootTwo, "two").targets("src/gateway.ts", ""):
  {static:["src/leaf.js"],dynamic:[]}
```

Root one's current closure resolves to `leaf.ts`, but its current graph now names a file absent from that root. No importer or environment file changed there. This is the same last-writer provenance failure as round 1, through file resolution rather than a config alias. It breaks the requirement that stale or incompatible edges never read as current.

**Repair, one worker:** bind a worktree/project's selected edge variant to recorded resolution evidence from its own walk. Content-addressed edge payloads may still be shared, but `(importer bytes, environment)` alone cannot select the variant. At minimum, conflicting variants must read not recorded until that worktree's variant is known. Do not change result keys or the main schema version. Add the equal-environment `.js`/`.ts` fallback reproduction alongside the alias and multi-project cases. Checking only whether an output target exists is insufficient when different valid candidates exist in both roots.

## Note from the R1 delta

### R2-N1. The config scanner treats quoted example text as an actual import edge

**Proven note.** `src/core/store/config-imports.ts:28`–`41`, `75`–`82`. This concerns the new scanner, not the repaired transport of the original B3 fixture. It does not add a separate blocker to this bounded re-review.

Use these valid config sources:

```ts

import Reporter from "./config/bridge.js";

// config/bridge.ts

// src/reporter.ts

```

A real Vitest adapter lists all three files as config dependencies. After persisting its environment, the scanner records both `config/bridge.ts` and `src/reporter.ts` as direct targets of `vitest.config.ts`. The shortest chain becomes:

```text

Reported chain: vitest.config.ts -> src/reporter.ts
Suggestion: vitest.config.ts imports src/reporter.ts: name it by path, or load it only where it is used
```

The quoted example is not an import. Filtering candidates against the flattened dependency list does not validate which file imported which. The report gives a false gateway and an option aimed at an import statement that does not exist.

**Suggested follow-up, one worker:** tokenize enough JavaScript/TypeScript syntax to distinguish code from strings, templates and comments before accepting an edge, or keep unsupported edges not recorded. Preserve the hook bundle's dependency constraint. Add a real-adapter regression with a transitive dependency also named in quoted text. No result-key change is needed.
