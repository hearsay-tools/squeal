## Blockers

### B1. Proven: a later record can turn an early CRAP pass into a failure at the same source blob

Location: `src/core/code/crap/walk.ts:122`, `src/core/code/crap/file.ts:114`. The existing join's executable denominator is at `src/core/code/crap/join.ts:204`.

The 015-59 brief requires: "with records still to come, a function told FAIL -> PASS never reads `fail` again at the same blob" and "A shown value never rises after an early judgement." D9's early pass relies on more records only lowering CRAP. The new path does not establish that premise.

`coverageOf(..., true)` runs the same join over only the records in hand. The join unions both covered lines and executable lines. A source blob identifies the source bytes, not the transform's executable-line set. Two Vitest projects can transform the same source differently. A later record can add uncovered executable lines, reduce the coverage ratio and raise CRAP.

Reproduction with real transforms and records:

```js
globalThis.__reviewF = function f(x) {
  if (FEATURE) {
    if (x === 1) return 1;
    if (x === 2) return 2;
    if (x === 3) return 3;
    if (x === 4) return 4;
    if (x === 5) return 5;
    if (x === 6) return 6;
    if (x === 7) return 7;
    if (x === 8) return 8;
  }
  return 0;
};
```

1. Count these bytes with `countFile`: `f` has CC 10. Keep the same bytes and SHA-1 stamp for both transforms.
2. Transform them with `esbuild.transform(text, { define: { FEATURE: "false" }, minifySyntax: true, sourcemap: "external", sourcefile: path })`. Execute the generated code and call `__reviewF(0)` while Node inspector precise coverage is on. Pass that payload, the generated code, source map and original byte stamp to `buildRecord`.
3. Do the same with `FEATURE: "true"`, but do not call the function. Both records confirm blob `d37b57a2e48f8763f17048daa8517a8c424d7025`. The first record has `lines: "AQg="`, `covered: "AQg="`; the second has `lines: "/Qs="`, `covered: "AQ=="`. Their mapped `f` entry is `[1,23,13,0,1]` and `[1,23,13,0,0]`, respectively. No fabricated coverage bitset is needed.
4. In `coverageRig`, edit `src/a.ts` to those bytes and recount with `{version: COUNTER_VERSION, count: countFile}`. Store the second record for `test/full.test.ts` and step. CRAP is `fail 110`. Register a consumer.
5. Mark that loader queued at a new key. Add `test/new.test.ts` and store the first record for it. Step and deliver: `PASS CRAP ... is 10`, while the old loader is pending.
6. Store the second record at the queued key. Step and deliver: `FAIL CRAP ... is 61.2`. The source bytes, counter, threshold and first record did not change. Only the missing record arrived.

The worker notes identify this possibility, but neither the brief nor the W1 agreements accept an unsound early pass.

One-worker repair: make the early CRAP calculation a conservative upper bound even if later records add executable lines. One option is to bound the denominator by every possible own source line from the count's ranges, treating lines not yet proved covered as uncovered. Keep the full judgement's calculation and text unchanged. The early `uncovered` recovery can still use a confirmed hit. Add the two-transform regression above and assert that completing the fixed set of loaders cannot raise the early value or re-fail the function. Do not repair this by suppressing a later true failure.

### B2. Proven: quiet recounts bypass the early threshold guard

Location: `src/core/code/crap/judge.ts:113`.

The 015-59 brief requires: "a failure that only a threshold change passes, keep[s] [its] last judgement until every record is in." W1's accepted agreement narrows early judgement to the failing measures the records prove pass.

The ordinary early path checks `kindOf`, which tests the value against the stored threshold. But `passed` accepts `quiet === true` as an alternative. Every file in a recount is quiet until its full judgement. That flag controls transition delivery. It is not proof that coverage passed a failing measure. During a quiet recount a threshold-only pass is therefore written early.

Minimal reproduction with `coverageRig`:

```ts
const rig = coverageRig();
await rig.edit({ "src/a.ts": "big 35 b1\n" });
const blob = rig.store.files.list(WT, ["src/a.ts"])[0]!.blob;
const record = [sourceOf("src/a.ts", blob, 1, [1])];
rig.loader("test/a.test.ts", { closure: ["src/a.ts"], record });
rig.step(); // big fail 35 at threshold 30
await rig.recount(counterV2({})); // same CC, new counter version
rig.loader("test/a.test.ts", {
  closure: ["src/a.ts"], key: "waiting", pending: "queued",
});
rig.loader("test/b.test.ts", { closure: ["src/a.ts"], record });
rig.step({ threshold: 40, reseed: true });
// Required: big fail 35 until every record is in.
// Actual: big pass 35, with source pending, waiting:1 and quiet:["src/a.ts"].
```

No coverage improvement can pass CC 35 at threshold 30. The change to 40 alone passed it. The write is quiet, but it changes the state read by `squeal code` before the allowed full judgement.

One-worker repair: check early eligibility against the stored threshold independently of `quiet`. Apply `quiet` only when deciding whether to append a transition. Add the recount-plus-threshold regression and keep the last state until all loaders are ready. Keep the full judgement's existing threshold-change behavior.
