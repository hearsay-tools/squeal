## Findings

- **F1. On a cold baseline every Jest file ran twice (fixed in `0.1.653`).** In `0.1.651`, one `squeal run --all --wait` at revision 0 made 470 file runs for 258 files: the 192 passing Jest files ran twice, the 10 failing ones three times (twice plus the failure confirmation), the 56 pytest files once (no environment). The second pass started at about 103 s, when the first had ended, inside the same checkpoint. The daemon noted "coverage: 128 completed test files got no record since this daemon started: 128 no-result (its run's result was not found at its key)": Run 1's results were discarded as `first-seen` because `observe-runtime.cjs` left `Symbol.for("squeal.currentTestFile")` set while Jest's `ScriptTransformer`, `Resolver` and ESM check probed absent Babel, Browserslist, `package.json` and extensionless module candidates, and `source-map-support` probed `node:internal/...`. Fixed in `0.1.653`: `observe-runtime.cjs` pauses the current-file mark during transformer, resolver and ESM checks while recording successful reads of existing files (`ts-jest` `.d.ts` reads, existing `.babelrc`) and transformed modules; `adapter.ts` drops non-existent `node:` probes; `environment.ts` adds `babel.config.ts/.mts`, `.babelignore` and Browserslist configs to environment files. Pinned by `test/runners/jest/cold-first-seen.test.ts` and `test/e2e/spec-028-jest.test.ts` (asserts 3 file runs for 3 files on a cold baseline on Jest 29 and 30).
- **F2. Jest coverage records were stored but reported as not measured (fixed in `0.1.653`).** In `0.1.651`, Jest runs wrote V8 coverage records, but `RECORDING_RUNNERS` in `src/core/code/coverage/runtime.ts` listed only `vitest` and `node-test`. Fixed in `0.1.653`: `jest` added to `RECORDING_RUNNERS`, `squeal impact` coverage proposal reads `recordingNames()`, and `test/e2e/spec-028-jest.test.ts` asserts `squeal code packages/core/src/helper.js` measures Jest coverage with no `not measured` or `Jest gives no coverage` line.
- **F3. The setup instruction block did not name Jest (fixed in `0.1.653`).** In `0.1.651`, `BlockRunners` in `src/cli/setup/block.ts` had no `jest` field, so a Jest-only repo got Vitest text and `saas-boilerplate` got pytest-only text. Fixed in `0.1.653`: `BlockRunners` gains `jest`, `blockText` names every detected runner in `DESCRIPTIONS` order, `apply.ts` passes `jest`, and `test/e2e/spec-028-jest.test.ts` asserts `AGENTS.md` names Jest and not Vitest.
- **F4. Peak memory of warm Jest workers (observation, follow-up).** Right after the 78-file edit the daemon's tree held 20 warm Jest workers using 10,324 MB in all (about 516 MB each), beside 17 Jest runner hosts at 1,980 MB: 13.1 GB for one worktree. Each worker stays below the recycling ceiling of D7.2 (`min(1024 MiB, 10% of host RAM)`), so none was recycled. They left on their own within about 5 minutes. On a 16 GB machine the peak alone would be most of its memory; a worktree-wide warm-worker cap is a follow-up candidate.
- **F5. 14 of 78 files ran again on the revert (root cause fixed with F1 in `0.1.653`).** The revert restored the exact baseline content, yet 14 files ran instead of taking their stored pass because failing tests and different batch orders probed different absent `browserslist`, `jest-resolve` and `source-map-support` (`node:internal/...`) paths in `0.1.651`, shifting each file's observed input set and key. Pausing the current-file mark during transformer/resolver/ESM checks and dropping non-existent `node:` probes in `0.1.653` removes this probe drift between passing and failing runs (pinned in `test/runners/jest/cold-first-seen.test.ts`).
- **F6. The 10 baseline failures are the repository's own.** Each fails the same way under plain Jest without Squeal: 8 `webapp-sso` files with "Configuration error: Could not locate module react-markdown mapped as ... node_modules/react-markdown/react-markdown.min.js" (the shared `webapp-api-client` setup file reaches `webapp-core/src/utils/mentions.tsx`, and `webapp-sso`'s `moduleNameMapper` points at a file that is not installed), and 2 `tools` files with `ts-jest` type errors (`TS2741` and `TS2554` in `executors/setup/executor.spec.ts`, `TS2305` in `generators/webapp-lib/generator.spec.ts`). Squeal's failure line for the `webapp-sso` files shows only the headline "Configuration error:" with the location `mentions.tsx:3:1`; the line that names the missing module is not in it. Minor.
- **F7. Minor setup notes.** The setup plan's warm-up estimate said "runs all 56 test files": it counted the pytest files and left out the 202 Jest files. The seeded `packages/backend` pytest `exclude` lists `**/__pypackages__/**` twice.
- **What worked as the spec says.** Discovery skipped the empty root config and seeded the 17 package configs without Nx (D1.2). Results matched plain Jest exactly: 202 files, 808 passed, 4 skipped, the same 10 failed files (D4, D5). The `webapp-core` edit selected files in 12 packages through workspace imports and the shared setup file, and left the others current (D3). The `ts-jest` `.d.ts` edit re-keyed and failed exactly the one test file whose type check reads it, and its revert took the stored pass (D3.2). `squeal stop` left no Squeal, runner host or warm worker process (D7).

## End-to-end suite (`test/e2e/spec-028-jest.test.ts`)

One test per Jest major, on Jest 29.7.0 and 30.5.2, against the plugin's `dist/` built by `buildPluginDist` with the Jest runtime copied in (as `spec-027-docker.test.ts` does), a real daemon and the plugin's hook bundles. The fixture is `saas-boilerplate`'s shape in small: an empty root `jest.config.mjs` above `packages/core` and `packages/app`, whose test imports the core helper by its workspace name through a `node_modules/@mono/core` link. Each test:

1. runs `squeal setup --yes --no-warmup` with a `PATH` holding only `git` and asserts both package projects are seeded and the root config is skipped with its note;
2. runs a foreground `squeal run --all --wait` (3 files, 6 passing checks);
3. edits the core helper and asserts `squeal status --wait 60000 <helper>` selects the two importing files across both packages, fails both, and keeps the third file current; the revert passes them again;
4. with `testCommand.denyWhenCurrent: true`, runs the SessionStart hook and then PreToolUse: `jest test/alone.test.js` from `packages/app` is denied with the current-results reason, and `jest test/alone.test.js | tail`, `pnpm nx run app:test` and the same `jest` command again run;
5. checks that Jest runner hosts and warm Jest workers sit below the daemon, runs `squeal stop`, and waits until every process below the daemon is gone.

`TMPDIR=/tmp pnpm exec vitest run test/e2e/spec-028-jest.test.ts`: 2 tests passed in 15.6 s.
