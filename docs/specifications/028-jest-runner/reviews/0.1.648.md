## Blocker

### B1 — Proven: Node's module cache survives source invalidation and can publish a false pass

**Location:** `src/runners/jest/runtime/warm-worker.cjs:144` (`freshTransforms`, called at line 175), with the source-change reuse path in `src/runners/jest/adapter.ts:196`.

**Contract:** Spec 028 D7.3 says, “Source and manual-mock edits are visible immediately on the next run.” The vision also forbids presenting an old result as current truth. D3 requires observed runtime inputs to keep selecting and keying their test file.

`freshTransforms` clears Jest's `transformedFiles` map and creates a fresh resolver. It leaves Node's `require.cache` intact. A transform can therefore ask its cache-key function again and still read the previous batch's exports from a required worktree helper. Ordinary `kind: "change"` invalidation does not retire the worker for that helper. The tests added here read side inputs with `fs.readFileSync`; they do not exercise a cached `require` of those inputs.

**Reproduction on both supported majors:** create an isolated project linked to the existing Jest fixture, with the following files. Keep the fixture cache unchanged.

```js
// jest.config.cjs
module.exports = {
  testEnvironment: "node",
  testMatch: ["<rootDir>/test/**/*.test.js"],
  transform: { "\\.js$": "<rootDir>/transform.cjs" },
};

// helper.cjs
exports.valid = true;

// transform.cjs
module.exports = {
  getCacheKey(text, file) {
    return file + text + require("./helper.cjs").valid;
  },
  process(text) {
    if (!require("./helper.cjs").valid) {
      throw new Error("edited helper rejects this source");
    }
    return { code: text };
  },
};

// test/a.test.js
test("a", () => expect(1).toBe(1));
```

Open `createJestAdapter` with `{ name: "app", config: "jest.config.cjs", include: [], exclude: [], args: [], env: {} }`, the scratch root and a scratch cache directory. Run `[{ project: "app", path: "test/a.test.js" }]` with a unique `logDir` and `timeoutMs: 30000`. Then change only `helper.cjs` to `exports.valid = false;`, call `invalidate([{ path: "helper.cjs", kind: "change" }])`, and run that file again on the same adapter. Finally run the edited tree through a separate adapter with `warm: false`.

This is a source edit already present in the first run's observed module set. Its re-run can store a false pass under the changed input. It also loses that dependency from the next report because Node serves the cached module without a new load. A transform that imports the helper at module scope also reproduced the stale pass.

**One-worker fix:** give native worktree modules loaded by Jest's transform/environment/resolver machinery a freshness owner. Track their dependency paths and retire/rebuild the affected warm context when one changes, or implement equivalent complete module-and-transform cache invalidation. Keep cached, still-used native dependencies represented in each batch's observations. Preserve reuse for ordinary source and manual-mock edits inside Jest's VM. Deleting only the helper's `require.cache` entry is insufficient when the transformer has already captured its exports at module scope.

Add regressions to `test/runners/jest/warm.test.ts` on both majors for the dynamic `require` case above and a module-scope helper import. Assert the first run observes the helper, the edit produces the fresh-process error on the next run, and recovery after a further edit remains correct. Verify that a still-used helper remains in the report. Keep the existing same-PID source/mock tests and K8 checks green.
