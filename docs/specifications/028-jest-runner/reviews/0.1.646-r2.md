## Blockers

### B2 remains: inline execution drops the root global config that its environment keys

**Proven on Jest 29.7.0 and 30.5.2.** `src/runners/jest/run/wrapper-config.ts:138` selects only the inline object and returns it at `:141`. `src/runners/jest/environment.ts:124` retains the root `globalConfig` while replacing only `projectConfig` at `:130`.

The original inline-object dropping is fixed in discovery. The remaining failure is at the execution seam added by that repair: an inline project's wrapper discards the root's global options. Jest's `readConfigs` uses the root's global config for its child projects. Squeal's reader does the same for keying, but its wrapper executes a new config containing only the selected child.

This is within B2's requested preservation of resolved projects through discovery, execution, and environment hashing. Spec D4.1 requires the wrapper to preserve "every user option". The vision requires trustworthy results tied to their actual inputs. A pass executed without a configured timeout is not evidence for a run with that timeout, even when the environment key names it.

Minimal fixture:

```js
// jest.config.cjs
module.exports = {
  testTimeout: 25,
  projects: [{
    displayName: 'unit',
    rootDir: '.',
    testEnvironment: 'node',
    testMatch: ['<rootDir>/*.test.cjs'],
  }],
};
// a.test.cjs
test('respects root timeout', async () => {
  await new Promise(resolve => setTimeout(resolve, 150));
});
```

The probe makes a temporary fixture for each major, links only its existing Jest install, and compares:

1. `node <fixture>/node_modules/jest/bin/jest.js --config jest.config.cjs --runInBand --ci --cacheDirectory <fixture>/direct-cache --json`, with `cwd` set to the fixture.
2. `createJestAdapter({ name: 'unit', config: 'jest.config.cjs', project: 'unit', include: [], exclude: [], args: [], env: {} }, { root, cacheDir: <fixture>/squeal-cache, observe: () => false })`, then `testFiles()`, `environment()`, and `run(files, { runId: 'r2', logDir: <fixture>/logs, timeoutMs: 30000 })`.

Actual output, summarized without temporary paths and stacks:

| Major | Direct Jest | Adapter | Environment |
| --- | --- | --- | --- |
| 29.7.0 | Exit 1, `Exceeded timeout of 25 ms for a test.` | `end: completed`, `respects root timeout: pass`, no file errors | `resolvedConfig` contains `"testTimeout":25` |
| 30.5.2 | Exit 1, `Exceeded timeout of 25 ms for a test.` | `end: completed`, `respects root timeout: pass`, no file errors | `resolvedConfig` contains `"testTimeout":25` |

The both-major adapter regressions preserve inline `globals` and test selection, but put no behavior-changing global option on the root. They cannot catch this mismatch.

**One-worker fix:** preserve the root global scope when running the selected inline project. A wrapper retaining the root config with only the selected child in `projects` can keep that separation; inject the observing runtime into that child. Keep the shared selector rule, root-relative paths, and config-dependency tracking. Make the reader and execution agree with Jest's `readConfigs`; do not merge all root project options into the child indiscriminately. Add both-major native-Jest versus adapter regressions for a root `testTimeout`, asserting the same failing outcome and the matching keyed configuration. Keep the current setup/apply/identity tests.
