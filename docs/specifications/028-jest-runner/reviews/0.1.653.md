### B3. Proven: an async transform hides concurrent reads by the test itself

**Location:** `src/runners/jest/runtime/observe-runtime.cjs:171`, especially `:175` and `:195`.

The pause is process-wide and lasts until a returned promise settles. The test's own async continuation can run during that interval. Its absent reads and metadata operations then see an unset mark, although they are not Jest probes. Refcounting restores the mark after completion but cannot isolate the concurrent execution.

**Contract:** D3.2 requires per-test fs attribution. The brief explicitly requires user-code absent reads to remain observed and first-seen. Vision principle 2 forbids the resulting stale pass.

**Reproduction:** Run Jest 29 with `--experimental-vm-modules`, `.mjs` test matching and a local `.mjs` transformer. Its `processAsync` delays 200 ms only for `src/slow.mjs`, then returns the source. Use this test:

```js

test("user absent read", async () => {
  const loading = import("../src/slow.mjs");
  await new Promise((resolve) => setTimeout(resolve, 50));
  expect(fs.existsSync(new URL("../user-absent.txt", import.meta.url))).toBe(false);
  await loading;
});
```

The initial test passes. Record its observed growth through `WorktreeKeys`, create `user-absent.txt`, reconcile and invalidate, then force a second run. On **Jest 29.7.0**:

**Worker-sized fix:** Make suppression apply to the transform/resolver execution context rather than unrelated user continuations. An async-context attribution mechanism or a narrower observation boundary must preserve the test's own absent reads while a transform promise waits. Add a controlled overlapping-import regression that proves the missing file enters the closure and its creation invalidates the stored pass. Keep nested-call, rejection and teardown checks.
