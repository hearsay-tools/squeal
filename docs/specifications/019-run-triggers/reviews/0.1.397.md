## Should-fix

### S1. A stalled group request bypasses the CLI wait's deadline and verdict path

**Proven; nonblocking.** Locations: `src/cli/run-group.ts:89`, `:91`, `:161`; `src/cli/daemon-access.ts:44`.

Reproduction: configure test group `e2e`, put a live socket in the worktree's daemon record, answer `ping`, and accept `run-group` without answering. Run the candidate's shipped CLI as `run e2e --wait 100`. It took **2157 ms**, printed an `ETIMEDOUT` stack for the fixed 2000 ms socket timeout and exited **1**. It supplied no `No verdict` line. The source `main` promise rejects in this case.

`runGroupCommand` computes a deadline but passes no remaining budget to socket discovery, the initial request or status polls. `askDaemon` throws on a timeout, so it bypasses this command's `noVerdict` handling. This contradicts the new command's documented one-budget and exit-3 behavior for an unavailable verdict, but does not produce a false pass or affect Stop's corrected budget. The normal daemon, older-daemon response and ordinary verdict-code cases pass.

Small fix: bound the group's socket operations and sleeps by one deadline, and convert transport failures into the existing no-verdict path with `--wait`. Keep non-wait behavior and `run --slow`'s pinned output. Add initial-request and status-poll socket-stall tests against the shipped CLI, asserting exit 3 and no stack trace.

### S2. A configured group's line can disappear while a same-key retry is queued

**Proven; nonblocking display inconsistency.** Locations: `src/core/state/groups.ts:62`, `src/core/state/slow.ts:94`, `src/core/state/group-text.ts:43`.

Reproduction: configure `e2e` at Stop; land a current failing result for its one file at key `slow1`; queue that file again at the same key while retaining its current failure, as a retry does. Read one header. `header.testFileCounts` reports one pending file, but `header.groupTiers[0]` reports `{ testFiles: 1, current: 1, pending: 0 }`, and `groupTierLines` returns `[]`.

The new configured-group reader reuses the existing slow classifier, which considers `row.pending` only when no known checks exist. With known current checks, it classes the file current despite the queued or running retry. The group line therefore gives no account of the pending work that the main status counts. The failing result is still current evidence and remains visible in known failures; this does not establish a false successful verdict or a missing first validation. The default slow classifier's pre-existing behavior is outside this review.

Small fix: for configured-group display, give a queued or running file precedence over current known checks, using the same file classification as the main status. Preserve the no-`checks` golden texts and existing Stop behavior. Add queued and running same-key retry cases that assert agreement between the main counts and the group's line.
