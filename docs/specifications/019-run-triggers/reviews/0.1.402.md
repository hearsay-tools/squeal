## Blockers

### B1. A config-key cache hit bypasses the commit's lint news

**Proven.** `src/core/lint/pass/commit-entry.ts:98` and `:158`, at the seam with `src/core/lint/pass/run.ts:88` and `rekey.ts`'s `judgeAll`.

The repair removes quiet marks only after `rekey` has judged cache hits. A first/config keying judges those hits with cause `config`, with no transition. `commitHold` then builds `waiting` from checks still pending or stale. A cache-hit failure is already settled, so `releasedNow` drops its release before `committedNews` can act. No later pass creates the missing transition.

Independent reproduction, using the real lint pass and store with `FakeProvider`:

1. Create a donor tree in the shared lint store. Its `eslint.config.js` is `export default [{ rules: {} }];` and `src/a.js` is `bad no-undef`. Run its ordinary lint pass to store the failing result.
2. Create a target tree sharing that store, with the original config `export default [];`, clean `src/a.js` and clean `src/b.js`. Give it a lint group at `commit`. Run its first keying, then register a consumer. Its files are held pending.
3. In the target, change the config to the donor's config and `a.js` to the donor's failing text. Revise. Release `a.js` at its current blob through `release`, exactly as the commit entry does.
4. Run the target pass and call `tellLint` for that consumer with every revision treated as its own.

Actual output:

```text
news: null
calls: []
transitions: []
states: src/a.js fail; src/b.js pending
```

This breaks 019-43's P12 requirement: the consumer registered before the change and never learns which finding the commit counts. It also demonstrates why the summary is no fallback. `keyingLinted` at `src/core/lint/surface/snapshot.ts:119` includes untouched held `b.js`, so the summary waits without bound unless a later commit or explicit request happens to lint it. Its pending state is intentional; using its eventual lint as the only fallback for newly committed news is the break.

**Worker-sized repair:** apply commit provenance when judging a released check, including a stored-result hit during first/config keying. Preserve that provenance until the result has a delivery path; do not discard it merely because the keying made the check settled. Ensure the keying's transition cut does not then hide that news. Keep request releases quiet and retain the consumer's existing deduplication. Add the donor/target regression above, including a held miss so a summary cannot mask the lost entry.

### B2. The two-second timeout makes a clean converted file read as unstaged

**Proven.** `src/core/commit/stored.ts:18` and `:51`. This violates this review brief's explicit clean-tree requirement for a slow but working git. The worker's notes acknowledge the trade-off; they do not supply approval to relax that requirement.

The timeout returns an empty normalization map. `differingPaths` keeps every requested path different and has no way to distinguish a timeout from real unstaged bytes. The path then makes its dependent test file not determined for the commit.

The independent probe used a real temporary git repository, no git shim:

```text
git config filter.slow.clean 'sleep 2.3; tr a-z A-Z'
.gitattributes: a.txt filter=slow
a.txt on disk: hello\n
a.txt in HEAD: HELLO\n
```

After add and commit, age the file's mtime by one minute so it is outside the racy window. `git status --porcelain` returned empty. A direct `git hash-object a.txt` returned exactly `HEAD:a.txt`. Give `differingPaths` the cached raw hash of `hello\n`, the committed blob, and the real `storedBlobs` callback. Actual result:

```text
{ gitClean: true, differences: ['a.txt'], ms: 2008.94 }
```

The filter completes successfully when allowed 2.3 s. The new bound kills it at 2 s and labels the path different. Before this diff, the same conversion had a 30 s budget. This is a correctness regression for a working conversion, not only a latency improvement for a hung command.

**Worker-sized repair:** separate the scheduler-lock budget from normalization completion. Keep the short lock hold, but let a bounded conversion finish outside the lock and apply it only with the existing cached-hash and stat proof intact. Arrange a report completion/update for the same HEAD when that evidence arrives. If it cannot complete, expose the unavailable normalization evidence explicitly rather than asserting unstaged changes. Add both a slow successful filter case and the existing hung-command case; neither may turn into an unbounded scheduler wait.

### B3. The control erases a retry hint changed to another fixture file

**Proven.** `test/e2e/run-triggers-control.test.ts:125` and `:145`.

`FAILED_FILE` accepts every fixture file, independently of the failure whose facts contain the hint. `loadNamed` checks only the load threshold, then removes the whole hint. Thus changing a hint's target to another fixture test file produces the same normalized string. The new negative test uses `other.test.ts`, which is outside the allowed set and misses this case.

The independent probe extracted the exact `FAILED_FILE`, `LOAD_READING` and `loadNamed` implementation from the candidate, removing only TypeScript annotations. It compared these two inputs, with the same failure header:

```text
FAIL test/e2e/flow.test.ts
... load 0.42 per CPU when it ran; no retry asked at these inputs

FAIL test/e2e/flow.test.ts
... load 1.37 per CPU when it ran; no retry asked at these inputs; if the changed files are not the cause, `squeal retry test/strings.test.ts --reason load` runs it once more when the one-minute load average is below the CPU count
```

Both became:

```text
FAIL test/e2e/flow.test.ts
... load <n> per CPU when it ran; no retry asked at these inputs
```

This violates the brief's requirement that the repaired control still reject changed and disagreeing hints. The passing end-to-end run cannot establish that property because this normalizer removes the disagreement before comparison.

**Worker-sized repair:** normalize each failure's load reading together with its hint only after validating that the hint targets that failure's file and keeps the expected command and reason. Preserve a hint that fails that check. Add mutations to every other valid fixture path, alongside the unknown-path, missing, extra and wrong-reason cases.
