## Blocker

### B1, proven: the control can fail on valid asynchronous delivery

Location: `test/e2e/run-triggers-control.test.ts:43`, `:69`, `:119`.
Contract: Part A must prove the no-`checks` control through both plugins;
the review brief explicitly requires tests deterministic enough for CI.

The first exact-candidate run failed Codex's final text comparison:

```text
- SQUEAL · 2 checks changed (2 tests) at revision 1; 1 lint change
+ SQUEAL · 2 checks changed (2 tests) at revision 1
...
+ SQUEAL · 1 lint change at revision 1
+ FAIL lint: src/strings.ts (oxlint): 1 finding, +1 eslint(no-debugger)
```

The old session delivered lint with the test failures at the edit boundary.
The candidate session delivered the same lint failure at a later boundary
after the commit. The run lists and Stop decisions had already compared
equal, and the final status was equal. The isolated rerun passed both
plugins. This is a false failure of the new test, not evidence of changed
no-`checks` behavior.

`settled` accepts `lint.pending === 0`, or even absent lint, without requiring
the new lint finding. Zero pending does not prove that lint has keyed and
judged this edit: the previous pass can still satisfy it. Test results and
lint advance separately. Comparing an array entry for each fixed tool
boundary then treats a valid delivery schedule as a regression.

Repair size: one test-file repair. For the edit step, wait for the known
lint outcome (`failing === 1`, no pending or stale lint) as well as the two
current test failures before taking the boundary. Require the expected lint
baseline too. If registration can straddle readiness, establish its state
explicitly or compare equivalent delivered events across boundaries while
preserving the text checks. Do not hide this with a larger fixed sleep or
an automatic retry. Run the two Part A files three times consecutively,
including together under normal concurrent execution.

## What fits

### SlowTier.next: decisions preserved

Compared the old method with each extracted helper, including its callers
and the final selection under the lock. The split preserves these decisions
and effects in order:

| Decision | Base and candidate |
| --- | --- |
| Closed, candidates, missing group, preemption | End deferral; return `again` when closed; read candidates under the lock; unmark an empty lane; reject changed preemption. |
| Load guard | Requested or marked lanes and groups without a guard skip it. Otherwise read the first file's lane and use the same guard. `DEFERRED` returns before runtime/hold reads. |
| Runtime and holds | Await runtime presence first, then hold state; each decision also checks preemption. A held slot is handled only after these checks. |
| Width | Normal priority is wide. Low priority is wide only when the guard reads idle and `normalIdle()` is true. Limit wanted files by `fullWidth` and candidate count. |
| Slot | Same yield-to-waiter decision, owner, permit acquisition and no-slot fallback; same mark clearing and miss counters. |
| Launch and failure | Select and launch under the same lock. `claimed` returns null; pool contention publishes `pool` and returns null; an empty selection returns `again`. `finally` releases every slot that did not fly. |

The unchanged final selection still checks halt, hold, predecessors, queue
ownership, trigger and key claims. The unchanged slow-tier and parallel
tests are current passes. No changed scheduling decision was found in the
split itself.

### Width, permits and normal work

`#normalIdle` now calls the existing `#groupHolds`. For `edit`, `pause` and
`stop`, `holdsFollowers()` still counts every queued file; it does not
filter those moments by whether they can start now. For `commit`, it counts
only files with a commit ask, a group request or an explicit checkpoint.
Every normal tier in flight still counts. Thus the changed case is exactly
the unasked commit backlog, as the brief requires.

The change only decides whether low work asks for one or several files.
`fullWidth` bounds the request; `acquireSlowSlot` takes no more than the
group's `maxParallel` permits. Selection uses the actual held permits,
rechecks normal work under the lock, applies the runner's simultaneous
width, trims to the worker-pool grant, and shrinks the slot to the files
started. One tier per group remains enforced by `#laneMayStart`.

The low group's pool request still uses the slow waiter order; normal
waiters retain priority in `PermitPool.acquire`. No normal eligible work
was newly excluded from the busy test. A low tier already running when
normal work arrives still completes, as D3 specifies. No new permit excess
or normal-work starvation path was found.
