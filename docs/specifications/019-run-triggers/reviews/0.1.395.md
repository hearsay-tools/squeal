## Should-fix

### S1. A pending runner part can cause an empty slow request

**Proven; nonblocking.** `src/harness/shared/stop-slow.ts:253` uses `!complete(last)`, which includes `runnerPartPending`, rather than testing for open slow files. Reproduction in each harness: use `repo(harness, { requireSlowSuite: true, slowWaitMs: 150 })`, call `landSlow(r, "pass")`, set `refinedMetaKey(r.worktreeId)` to `"0"`, and attach `listenAsDaemon` with a counter returning `{ revision: 1, queued: 0 }`. `stopThenWait` sends exactly one `run-slow` despite zero open slow files, then blocks on the pending runner part at the bound.

This does not establish an extra test run or an incorrect completion decision. The listing is unresolved, so the wait itself is correct. A complete, refined tier sends no request, and `asked` prevents repeated requests during polling.

Small fix: send when an open slow file first appears, keeping the one-request guard unset while only the runner part is pending. Add a regression for a pending runner part that later lists an unqueued slow file. Keep the live-revision completion check.

### S2. The socket budget can exceed a short configured wait

**Proven; nonblocking bounded latency defect.** `src/harness/shared/stop-slow.ts:255` awaits `sendRunSlow` before evaluating the remaining time at line 261. `src/core/slow/stop-wait.ts:74` always gives the request 2000 ms. With `requireSlowSuite: true`, `slowWaitMs: 0`, a pending slow file and a live socket that accepts but never replies, both harnesses spend about 2.1 s across the quick and waiting entries before blocking. The probe asserted one `run-slow` and at least 1900 ms elapsed. A normal front desk acknowledges promptly and does not show this delay.

The source comment says request time counts against the wait bound, but a bound below 2000 ms cannot constrain that await. This does not change the policy-off or no-edit guards, admit stale results, or threaten the one-hour hook limit; the excess is at most the socket budget, apart from ordinary process/store overhead.

Small fix: give the request the remaining wait budget, with an explicit zero-budget path, and keep its time inside the one deadline. Test an accepting, non-answering socket with a short bound. Preserve one request and truthful pending output on timeout.
