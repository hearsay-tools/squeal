## Prior blockers

### B1 closed: cache hits keep a delivery path

**Proven closed.** `src/core/lint/pass/commit-entry.ts:78`, `src/core/lint/pass/commit-news.ts:110` and `:133`, and `test/lint/pass/commit-provenance.test.ts:58`.

Commit provenance is now separate from the queue release. `releasedNow` may consume the latter when keying settles a cache hit; it no longer consumes the former. After keying writes its transition cut, `committedNews` gives a settled failing result a visible transition. A pending result loses its quiet mark and retains its release at the committed bytes. A later config keying cannot silently consume that path's news.

The three regression cases cover the original donor/config hit, a hit judged before the commit, and a config cut between lint and delivery. Each delivers one finding with a held pending file beside it. Repeated reads, another commit of identical bytes, and registration of a later consumer remain quiet where tested. The existing commit-entry tests also keep ordinary misses and request-only releases correct. This meets 019-43's requirement: the agent learns the finding, not just its count.

A dependent test file with no independently differing tracked path reads `not determined (git did not answer)`; a genuinely differing neighbour still reads as unstaged. The hung-command scheduler test still checks that a watch batch proceeds within its fixed 5 s outer allowance. Existing CRLF, autocrlf, cached-byte, racy-stat and non-regular-file checks pass.
