## B1-R1 — a relative test filename starting with `-` becomes a CLI option

**Proven.** `src/cli/status-wait-groups.ts:139` makes each test path relative to the wait's directory, then `:140` shell-quotes it. That preserves its bytes but does not keep a leading `-` from being read as a CLI option. `src/cli/run-group.ts:67` rejects any remaining argument starting with `-`.

Reproduction: a manual Vitest group `browser` owns `test/**`. Its test `test/-core.test.ts` imports `src/core.ts`. Start a named wait in `<worktree>/test` for `../src/core.ts`. The wait correctly leaves `test/-core.test.ts` and says its printed command runs it now and waits for its result. The command ends with:

```text
run browser -core.test.ts --wait 60000
```

The independent probe used the real Codex command name, `node --disable-warning=ExperimentalWarning <absolute candidate Codex bundle>/cli/squeal.mjs`, extracted the full command and executed it unchanged in that same directory. Actual result:

```text
exit 2
squeal run: unknown argument "-core.test.ts" with a group
runner log: []
```

The file remains non-current. Changing only the argument to `./-core.test.ts` gives exit 0 and runner log `["test/-core.test.ts"]`. Thus the path is valid and supported; the new printed spelling is the failure. This breaks the repair's done-when and amended D6 promise that the command runs the left files it names. It is on the changed B1 boundary, not a separate review of an old parser rule.

**Repair sized for one worker:** after making a test path relative, prefix `./` if its first character is `-`, then shell-quote it. Add a subdirectory regression that executes the printed command, including the existing `--wait` suffix, and confirms the named file runs. Quoting alone does not solve option parsing. Keep the ten-file bound, project-path deduplication and whole-group fallback.
