## Blocker

### B2-R1. Proven: a completed lint failure uses the last hold before required tests start

Location: `src/harness/shared/stop-decide.ts:241`, in `lintFailing`.
The new quick-entry required lint hold checks only `requiredLintOpen`
before spending the shared hold budget. Required test files can still be
not current. With the waiting entry known, `required` is null in the quick
entry, so its `heldFor` read does not include those test files either.

019 Goal 4: “Stop waits for every check of a group at Stop. It starts the
checks that are not queued”. D4 step 1: “Before it waits, the waiting entry
asks the daemon to run every required check that is not current”.

Reproduction in **both Claude Code and Codex**:

```json
{
  "lint": { "enabled": true, "blocking": true },
  "checks": [
    { "name": "lint", "lint": true, "at": "stop" },
    { "name": "unit", "runner": "vitest", "tests": ["src/math.test.ts"], "at": "stop" }
  ],
  "stop": { "maxHolds": 1, "slowWaitMs": 1000 }
}
```

1. Start a turn over initially passing lint and tests. Mark the waiting
   entry as known for that session/version.
2. Edit `src/a.js` to `bad no-undef`. Give the required unit test a new key
   with no result. Exercise both a queued key and a lookup-only key with
   `pending: null`.
3. Explicitly release/run `lint` and let it finish before Stop. Leave the
   unit test not current. Serve a daemon socket whose `requestGroup` would
   run that test and store a passing result.
4. The first quick Stop blocks for the lint failure and uses hold 1/1.
5. After that continuation, quick Stop is silent. The waiting entry sees
   the spent budget and returns before `requestGroups`.

Actual output for each harness and each pending mode:

```text
asked: []
quick: {}
waiting: {}
test file: src/math.test.ts, key: unit-new, pending: queued | null
expected [] to include 'unit'
```

The unit test has no result at its new key when Stop completes. In the
lookup-only case it has not even been queued. On pre-repair `65936c173`,
the same four tests pass: the next Stop asks for `unit`, the daemon stores
its passing result, and Stop decides after that request.

This is within the brief's explicit “test groups at stop” neighbour check.
The B2 change reopens that behaviour: it makes the precompleted lint
policy block consume the budget before the remaining required checks get
their waiting-entry request. The original B2 count defect itself is fixed.

Fix sized for one worker: defer the quick-entry completed-lint hold while
any required test is not current or its runner part is still pending.
Retain the required-tool exclusion from general `lintStopReasons`, and
keep the one shared hold budget. Let the waiting entry request and wait
for the required checks, then make the combined required-check decision.
Keep the precompleted lint-only case at exactly `maxHolds`, with and
without a known waiting entry. Add the mixed queued/lookup-only cases in
both harnesses, and a runner-part-pending case.
