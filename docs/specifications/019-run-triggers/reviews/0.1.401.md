## Blocker

### B1. Normalizing a later disk read loses the result's provenance

**Proven.** `src/core/commit/compute.ts:82`, through `src/core/commit/stored.ts:29`. Breaks vision principle 2, “An old result never gets to pose as the current truth,” and D5 step 2's requirement to report from the committed keys.

`CommitView.hashOf` explicitly means “The hash the keys were made of.” The new comparison first finds a difference using that cached hash. It then asks Git to hash the **current disk file** and removes the difference when Git's answer matches the commit. Nothing proves that Git read the bytes represented by the cached hash and test result.

A restore between reconciliation and this new read is enough. The scheduler lock serializes cache changes, not external writes. The following controlled scheduler experiment used a real repository, store and Git commands, and the existing fake runner:

1. Start `catchUpSide` with `test/a.test.ts` importing `src/a.ts`, using `RUN_MISSING`. Save the original source bytes.
2. Mark the fake runner's test failing, call `side.edit("watch", "src/a.ts")`, and await `scheduler.idle()`. Its current failure now belongs to the edited source key.
3. Advance HEAD with `git commit --allow-empty -qm 'advance HEAD'`. The committed source remains the original file.
4. Collect a real stat candidate for `src/a.ts` while disk still matches the dirty cache. Run `handleBatch({ trigger: "interval", paths: candidates })`.
5. Control an external restore at the asynchronous boundary after the real `committedBlobs` read, before normalization. The probe wraps that function only to restore the original bytes at this point. No cache, key, state or report is modified by the wrapper. The restored file's watch batch has not run yet.
6. The tree is clean, but the report counts the dirty key's failure as the commit's. With `differingPaths` extracted unchanged from `git show a9170ad10:src/core/commit/compute.ts`, the same test keeps the difference and reports the file not determined.

Observed counts:

The first regression assertion failed as expected. A separate two-case diagnostic asserted these actual outcomes and passed. The final experiment includes the real pre-restore stat candidate; it does not depend on supplying an empty reconciliation batch.

**Worker-sized fix:** confine the repair to the normalized-blob comparison and its tests. Remove a difference only when normalization is proven to describe the bytes of the cached key. Keep the difference if the disk snapshot has moved. Reuse the existing stable-read/stat checks where possible. Preserve the batched Git call, timeout, no-call path for equal raw hashes, CRLF/autocrlf behavior, and conservative fallback. Add the controlled restore case above and its inverse with a cached passing result. Do not fix this by clearing the count or trusting Git cleanliness alone; neither proves which bytes the recorded result tested.
