## B. A retry before the daemon lists a new test file

Row: gh-76. Related: 011-16 (0.1.216), 011-27 (0.1.231), 011-63 (0.1.242), 011-67 (W2 of wave 18, running).

Facts. In a cezarion worktree at revision 0, the reporter added `packages/web/e2e/session-footer.e2e.ts`, which matches the declared browser suite, and ran `squeal retry` on it at once. It exited 1: "Not retried: packages/web/e2e/session-footer.e2e.ts is not a test file Squeal has keyed in this worktree." The next report showed revision 1 and 83 pending slow files, this one among them, with no retry. A later retry recognized it and named `squeal status --wait 60000 <file>`. Not reproduced (load 25.19). The issue reports CLI 0.1.265, but it was filed at 13:43:22Z, before 0.1.265's tag commit (14:11:48Z) and its release (14:20:53Z): the CLI was not the release build (a candidate or a local copy; not determined).

Read in source. `notKeyed` (`src/cli/retry.ts:271`) gives one refusal to every path with no keyed test file and no failed global setup. A missing path, a path outside the test patterns and a matching file in a revision the daemon has not listed read the same. Status already knows the last case: "revision N is not listed yet, so test files it adds are not counted" (`src/core/status/checks.ts:144`).

Which fix the report predates. None: 011-16 (a retry queues a keyed file with no result), 011-27 (every file without a verdict names what advances it) and 011-63 (a named wait holds for its matched files) all shipped before 0.1.265. Nothing since changes `notKeyed`.

Overlaps. 011-16 and 011-27 own the retry's refusals. 011-63 owns the named selection, matched and unmatched. 011-67 (running) edits retry guidance in `src/core/retry/text.ts`, not `src/cli/retry.ts`: no shared file.

Recommendation. Approve the explicit pending-discovery reply as one 011 row, and decline the bounded wait. A new matching file runs without a retry, as the report's next status shows, so a retry that waits for discovery would block only to queue a file that is queued anyway (inferred from the report and 011-16). When the path exists, matches a configured test pattern and has no key while the newest revision is not listed, `retry` says so, names that revision and `squeal status --wait 60000 <file>`, with a first line and exit status other than the invalid-path refusal's. A missing path and a path outside the patterns keep their own errors.

Cost. One C5 sentence; `notKeyed` and the read of the listed revision; three tests: a new matching file before listing gets the pending reply with its command; a missing path and an out-of-pattern path each get their own error; after listing, `retry` is unchanged. Whether the CLI can test a path against the patterns without the daemon is the row's first question (not checked here). No key change.

Cheaper. Wording only: every not-keyed refusal adds "if you just created it, the daemon may not have listed it yet" and the `status --wait` command, with no pattern or revision check. Price: a mistyped path gets the same hint, so the issue's second acceptance line is met only in part.

## C. Focused checks inside one test file, asked again

What the hold's research adds. 001-381's yield rule (011-51) shortens the wait behind another tier, not the named file's own run. On cezar the named file's own tier took p50 184 s and p90 604 s, "the larger part of a named wait", which belongs to tier sharing or per-file storing (`running-tier-yields.md`, open questions). 011-119 measured watch mode 0.3 to 2.9 s faster to a first result inside the import graph and wrong outside it (15 false passes in 15 edits), and recommends handing nothing to watch mode. Read in source. `RunOptions` (`src/core/types/runner.ts:215`) has no name filter, and no `testNamePattern` is in `src/`. `squeal failures --check` selects stored failures only.

Which fix the report predates. 011-51 (0.1.237), 011-107 (0.1.265) and 011-112 (0.1.266) let a named file run sooner while another tier runs; 011-55 (running) extends that to another worktree's claim. None narrows the file's own run, so none answers #64.

Cheaper. Keep the hold and answer #64: the yields of 0.1.237, 0.1.265 and 0.1.266 shorten the wait behind other tiers, not the file's own run, and the hold stands until a report on 0.1.266 or later shows that the file's own run is the cost.
