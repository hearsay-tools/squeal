# Policy

## When an edit is denied

With policy `interrupt.onRegression` on (the default), the first file edit after a regression is denied once: a check that passed in this worktree, or passed where its result was inherited from, fails now. The denial lists those checks and says the edit was not applied. A failure first observed, from Squeal's run at start or from a test file just written, never denies; it arrives with the next tool call. The same edit can be re-issued; the same regression does not deny twice.

## When Stop keeps you going

`stop.blockOnKnownFailures` and `stop.requireFullSuite` can keep you going at Stop, once per stop. The message names the failures, or the missing full-suite checkpoint. Failures whose re-run is still pending are named as pending, with the revision they last failed at, and do not block.

Stop also waits for the checks of the groups at `"stop"` in `checks`, and for the slow files under `stop.requireSlowSuite`. It keeps you going when one of them fails, or when some are still not current at `stop.slowWaitMs`, at most `stop.maxHolds` times in one turn. Squeal counts these holds from your prompt, not per stop: a Stop after another Squeal message still waits while holds remain. The message names the group and its command, such as `squeal run e2e --wait`; for slow files it names `stop.requireSlowSuite` and `squeal run --slow --wait`.

## Policy keys

`squeal.config.json` at the repository root, committed. Every key is optional; `squeal init` writes all of them with their defaults.

Until the waiting hook has run once in the worktree (a Codex user trusts it first, with `/hooks`), it does not wait: it keeps the agent going right away while a slow file is not current, up to `stop.maxHolds` times in one turn. | `stop.maxHolds` | `1` | How many times Stop may keep the agent going in one turn for the checks it waits for (the groups at `"stop"` in `checks`, and the slow files under `stop.requireSlowSuite`): a failure among them, or checks still not current at the bound. Unset, every test group whose moment is not `"manual"`, so with no `checks` every test file. A list replaces that default; the default groups `tests` and `slow` count. A name that is not a test group there, or a lint group, is a problem on stderr and is dropped. `--group <name>` adds a group for one run. The daemon does not read it. |
| `baseline.onStart` | `"lookup-only"` | On daemon start, reuse the results stored at each test file's inputs and run no other test file, except one whose stored result is another worktree's failure: it runs once here, to confirm or clear that failure. Your edits' tests still run. `"lookup-then-run-missing"` also runs every test file without a result at its inputs. |

A result is stored under a key that includes what its run read. Not seen, so name them in `inputs`: what a non-Node child reads (a shell script's `cat`), native file access (`node:sqlite`), Vitest's own process (`globalSetup`, plugins), gitignored files and files outside the worktree. `false` keys by imports and `inputs` only. |

| `runner.backlogTierSize` | `200` | Test files per run while only backlog work is queued (the baseline, an environment change, `run --all`), up to 300 s of last known file time or half of `runner.timeoutMs`. An edit cancels such a run; the files it finished keep their results. |

| `nodeTest` | `[]` | node:test projects validated beside Vitest. A bad entry is skipped with a note in `squeal status`; the other projects are kept. |

## Host config

`~/.config/squeal/config.json` (under `$XDG_CONFIG_HOME` when set), per user and never committed: settings of the machine, not of the repository.

| Key | Default | Meaning |
| --- | --- | --- |
| `capacity.groupSlotScope` | `"repository"` | Where `slow.maxParallel` and each check group's `limits.maxParallel` count: `"repository"`, across the worktrees of one repository, so two repositories' slow files may run at once; `"user"`, across every repository of the user, for suites that share fixed ports or a database between repositories. |

## Remote runs

`~/.config/squeal/remote.json` (under `$XDG_CONFIG_HOME` when set), per user and never committed, sends one repository's background Vitest runs (the start and restart baselines and the backlog) to an SSH host you name. Edit tiers, named waits, slow files and check groups stay on your machine. Nothing goes remote until you name a repository here, and a repository's `remote.allowed: false` forbids it.

```json
{ "repositories": { "/home/me/app": { "target": "build-box" } } }
```

| Key | Default | Meaning |
| --- | --- | --- |
| `target` | required | The SSH destination: a `Host` of your ssh config, or `user@host`. Squeal runs your own `ssh` in batch mode with your configuration: a key that needs a passphrase prompt, or an unknown host key, fails with ssh's own text. |
| `runner` | `"vitest"` | The runner whose background runs go there; only Vitest for now. |
| `lanes` | `["background"]` | The runs that go there; only `"background"` for now. |
| `whenLost` | `"local"` | When the remote does not answer within its deadline, or is refused: `"local"` runs those files here; `"not-run"` leaves them not run, their checks `unknown`. Squeal tries the remote again later. |
| `node` | `"node"` | Node on the remote, a name on its login `PATH` or a path. Its version must equal this worktree's, or the remote is refused. |
| `cache` | `".squeal-remote"` | The remote directory, relative to the remote home or absolute, where Squeal keeps its own copy (`squeal/<version>/`) and one tree per worktree (`squeal/trees/`) with its installed dependencies. Keep it where the host keeps files across a stop and restore: hosts such as boat.dev drop `~/.cache`, and a lost cache means Squeal's copy, the whole tree and the install are sent and made again at the next connect. |

A repository is named by its root path or by one of its remote URLs. At first connect Squeal copies itself to the remote and sends every tracked file and every untracked file git does not ignore, never an ignored one, then installs from the lockfile with the project's package manager, which runs the project's install scripts there. Each edit's changed files follow. A remote result is kept only when the remote's files of the run equal yours before and after the run, and its environment (Node, platform, installed dependencies, Vitest config) equals yours; a run over different files is sent again and retried once. `squeal status` names the remote: connecting, connected and not yet compared, proven, refused with the difference, or unreachable since a time. Its environment is compared as soon as it connects, so a refusal shows before any run. When only its installed dependencies differ, as after a restore onto a new machine, which changes the installed files' times, the remote installs again once from the lockfile; a difference that remains is refused. `squeal ps` shows each runner host under its daemon, `local` or `remote <target> (ssh)`. Coverage is not taken on the remote.

Earlier versions of Squeal kept the cache in `".cache"`. A remote that holds `~/.cache/squeal` from an earlier version gets a new copy and tree under `~/.squeal-remote/squeal/` at its next connect; remove `~/.cache/squeal` there, or set `"cache": ".cache"` to keep using it on a host that keeps `~/.cache`.

## Complexity

With `complexity.enabled`, Squeal counts the cyclomatic complexity of each function in the files it sees after each edit, with no test run: ESLint's classic `complexity` rule for `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs` and `.cjs`, radon's for `.py`. A function over `complexity.threshold` fails, and its state is kept as a test's is.

- The session's first message counts the functions over the threshold and never lists them: `Complexity: 62 functions over 20; squeal code lists them.` While the first count runs, it says `Complexity: counting, 340 of 600 files.`
- A function that goes over, or a new one over, arrives with the next tool call after any test failure: `FAIL complexity: selectTier (src/core/scheduler/tiers.ts:120) is 23, over 20 (ESLint rule)`. One that goes back at or under arrives as `PASS complexity: ...`, and a failing one that is removed as `RESOLVED complexity: ... is no longer in the code`. A message lists at most 5 of them and counts the rest: `and 14 more complexity changes; squeal code --changed lists them.` A move or a rename that keeps the function's body says nothing.
- A count that changes while the function stays over says nothing, with two exceptions, each said once. The first edit in a session to a function already over: `STILL FAIL complexity: selectTier (src/core/scheduler/tiers.ts:120) is 23 after the edit; it was already over 20 before it (ESLint rule); Squeal stays quiet about it until it is at or under 20, and squeal code src/core/scheduler/tiers.ts shows its count.` The first edit after a `FAIL` that leaves the function over: `STILL FAIL complexity: selectTier (src/core/scheduler/tiers.ts:120) is 22 after the edit, over 20 (ESLint rule); Squeal stays quiet about it until it is at or under 20, …`. After a `STILL FAIL`, Squeal says nothing more about that function until it is back at or under the threshold, so a later edit that leaves it over is quiet; `squeal code <path>` shows its count at any time.
- Test news can end with a changed standing summary: `Code: 2 functions over 20 that this session was told about; squeal code --told lists them.` It counts functions you heard of as `FAIL` or `STILL FAIL` that still fail, including CRAP and untested functions; functions over since before your session are not in it. It also names changed files that were not judged. Each session gets the line once per change of its counts, thresholds or not-judged files. An unchanged summary stays quiet across test results and a session resume. A recovery without a `Code:` line can leave that earlier summary standing; `squeal code --told` gives the current state. After complexity news alone, `Tests: 3 known failures; squeal status lists them.` comes while tests have known failures.
- A change of the threshold or of the files counted is one line, such as `Complexity threshold is now 15: 117 functions over; squeal code lists them.`
- A file over `complexity.maxFileBytes` is not counted; the first edit to it in a session says so once.
- A complexity failure never denies an edit and never counts in `Known failures`. It keeps you going at Stop only with `complexity.blocking`, and then only for a function that went over since the session started.

| Key | Default | Meaning |
| --- | --- | --- |
| `complexity.enabled` | `true` | Count complexity per function and keep its state. Off, Squeal counts nothing and keeps no code store. |
| `complexity.threshold` | `20` | A function fails when its complexity is above this. |
| `complexity.include` | `["**/*.{ts,tsx,mts,cts,js,jsx,mjs,cjs,py}"]` | Globs, worktree-relative, of the files counted. Files under `node_modules` and files git ignores are never counted. Test files are counted, and each test file measures its own callbacks. |
| `complexity.exclude` | `["**/dist/**", "**/build/**", "**/vendor/**", "**/*.min.js"]` | Globs left out of `include`; a project's list replaces the default. |
| `complexity.maxFileBytes` | `524288` | A larger file is not counted, and `squeal code` names it. The line for such a file names this key, as in `src/big.ts is 600 KiB, over the 512 KiB limit (complexity.maxFileBytes); its functions are not counted.` Set a larger value in `squeal.config.json` to count larger files. |
| `complexity.blocking` | `false` | Stop also names each function that went over since the session started, and keeps you going once. A function already over at the session's start never blocks. |

## Coverage

Coverage is on by default. To turn it off, set `"coverage": { "enabled": false }` in `squeal.config.json`. With `coverage.enabled`, Squeal takes coverage in its own Vitest and node:test runs and judges two checks per function beside complexity: CRAP, which is high for a complex function that tests run little, and `untested`, a function no test runs in the test's own process. Without `coverage.children`, a function that only a child process runs reads `untested`; `coverage.children` measures it, or `coverage.exclude` leaves such files out. Switching a check off, or excluding files, drops their states with one line, such as `Coverage checks changed: CRAP off (crap.enabled).` Setting `crap.enabled` or `coverage.untested` while `coverage.enabled` is `false` does nothing, and `squeal status` says so. `squeal code <path>` gives a CRAP it cannot score yet one short reason, as in `CRAP unknown: a test file that loads this file skipped a test`, and `--json` gives it as `crap.reason`; `cause unknown` means Squeal does not know why. A function whose CRAP is not judged yet, such as one an edit just added, reads `CRAP pending:` with what it waits for, as in `CRAP pending: waits for a test file to run; squeal run --all runs it` or `CRAP pending: the coverage step has not judged this file's current bytes yet`, and `--json` gives `crap.outcome` `pending` with that `crap.reason`. A current result for the test files you named does not make CRAP ready: it waits for every test file that loads the file, and then for the coverage step.

| Key | Default | Meaning |
| --- | --- | --- |
| `coverage.enabled` | `true` | Take coverage in Squeal's Vitest and node:test runs and judge the checks below. Needs `complexity.enabled`. Switching it on or off runs each Vitest and node:test test file again once. |
| `coverage.untested` | `true` | The `untested` check. Needs `coverage.enabled`. |
| `coverage.exclude` | `[]` | Globs, worktree-relative, of files that keep their complexity but get no CRAP or `untested` check. Test helpers shipped inside a package, which only a manual or built-output run uses, are measured as product code: no runner here lists them as tests, and Squeal measures only its own runs. Exclude them explicitly here, with globs that leave product helpers checked. It is also the skip list of `squeal code --base`: a changed function in a matched file reads `skipped` there, keeps its CC check, gets no CRAP, never counts as pass and does not block. List here the files Squeal cannot measure yet, such as browser specs, or, without `coverage.children`, scripts that tests start only as a separate process. A pattern such as `test/**` also skips the test callbacks' CRAP there. |
| `coverage.children` | `false` | Also take coverage in the processes and worker threads a test starts: Squeal points `NODE_V8_COVERAGE` at a directory of the test file's own and reads it when the test file ends. Needs `coverage.enabled`. Coverage is then a lower bound: a process that is killed, outlives its test file or gets an environment without `NODE_V8_COVERAGE` is not counted, and the sources of a bundle with several of them are not read. A child's coverage file over 64 MiB, or one that does not parse, is dropped alone. Tests can see the variable, so a test that starts a process that reads its own coverage, such as a nested Vitest, must remove it. A file that only a child runs gets the test file that starts it as its loader while `observe.runtimeInputs` is on (the default); with it off, such a file reads not measured. Each child process costs about a quarter more CPU. `squeal code --base` reads this key at the merge base. Switching it runs each Vitest and node:test test file again once. |
| `crap.enabled` | `true` | The CRAP check: complexity² × (1 − share of its lines run)³ + complexity. Needs `coverage.enabled`. |
| `crap.threshold` | `30` | A function fails CRAP when its score is above this. |
